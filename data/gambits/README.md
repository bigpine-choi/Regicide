# 갬빗 후보 지식 그래프

`catalog.json`은 기존 `data/openings/`의 고정 Lichess 카탈로그에서 생성한 후보 그래프다. 출처 커밋은 `a6189a30dc273ccb21fc2536a9a2fefd5592a67a`, 이용 조건은 **CC0-1.0**이며 [원문 라이선스](../openings/LICENSE)와 [원 출처](https://github.com/lichess-org/chess-openings/tree/a6189a30dc273ccb21fc2536a9a2fefd5592a67a)를 함께 보존한다. 원본 파일을 수정하지 않는다.

1,315개 명명 수순을 630개 이름 기준 계열 그룹으로 묶고, 3,411개 위치와 3,467개 후속 연결을 만들었다. **630개 서로 다른 갬빗을 능숙하게 둔다거나 이론이 검증됐다는 뜻은 아니다.** 같은 큰 계열 안의 하위 갬빗 이름도 별도 그룹이며, 목록은 카탈로그의 이름 분류다. 이름의 현재 계열 뒤에 붙은 표현만 기준으로 수락 179개·거절 241개·방어 68개를 구별한다. 예를 들어 상위 `Queen's Gambit Declined`라는 이름을 하위 Albin Countergambit의 거절 근거로 쓰지 않는다.

위치는 기물 배치·차례·캐슬링 권리·합법적인 앙파상 권리로 연결한다. 실제 대국의 전체 합법 수 이력을 별도로 확인한다. 전치는 현재 위치가 같고 실제 계열 기점을 거쳤을 때 허용하며, 반복·체크·비표준 시작이나 보드의 기록되지 않은 변경은 후보를 내지 않는다. 수락/거절 이후 카탈로그가 끝나면 후속 수를 발명하지 않고 자체 탐색으로 돌아간다.

기존 저작 갬빗의 기점과 주체는 기존 정의를 우선한다. 새 계열의 주체는 가장 짧은 카탈로그 수순의 마지막 착수자로 추론하며 `anchor_source`와 `owner_inference`로 표시한다. 이는 희생의 타당성이나 실제 수락을 증명하지 않는다. `context()`의 `captured_anchor_piece`는 기점에서 둔 기물이 움직이지 않은 채 실제 상대에게 잡힌 사실만 기록한다. 그 기물이 움직이면 제안은 소멸한다. 확정된 기존 저작 기점에만 `offer_captured`를 참/거짓으로 반환하고, 추론한 기점은 `null`로 구별한다.

모든 후속 수는 자체 Regicide 탐색으로 확인할 **후보**다. 카탈로그 이름이나 마지막 수가 새로운 무제한 손실 희생을 허가하지 않는다. 추가 검증과 기존 안전 한도를 통과해야 실제 착수에 사용한다. 이 파일에는 외부 평가, 사람 승률, 학습 목표나 학습된 가중치가 없다. 전용 학습 산출물은 별도 파일과 실험 기록으로 구별한다.

재생성: `.venv-tests/Scripts/python.exe scripts/gambit_knowledge.py`. 원 출처 5개 파일의 SHA256을 확인한 뒤 파생 파일과 manifest를 다시 만든다. 같은 원본에서 결과 바이트가 재현되는지 자동 검사한다.
