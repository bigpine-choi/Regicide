# 자체 연구로 보강한 갬빗 후속 수순

2026-11-05. 기존 CC0 카탈로그와 원본 라이선스·manifest는 그대로 두고, 별도 `native_continuations.json`에 **50개의 자체 탐색 후보**를 보존했다. BDG·모라·에번스·킹스·부다페스트의 명명된 방어 2개씩, 총 10개 시작 수순에서 연구했다. 무작위 합법 수를 수집하지 않았다.

전체 기존 `position_keys`와 비교하면 연구한 50개 상태 중 **42개가 새 국면**, 8개가 기존 국면이다. 기존 8개 중 6개는 후속 연결이 없던 말단이며, 2개는 다른 기존 후보가 있던 선택 지점이다. 저장한 상태·수의 연결 50개는 모두 기존 그래프에 없던 연결이다. 이는 수 선택 기회의 확대이며 승률·Elo 상승을 입증한 결과는 아니다.

## 자료와 실행

접두 수순은 고정 Lichess CC0-1.0 카탈로그의 검증된 행에서 가져왔다. 해당 행의 URL·라이선스·커밋·전체 수순은 `source_prefixes`에 보존하고, 로더가 원본 카탈로그와 다시 대조한다. 그 이후의 내 수·상대 수는 모두 자체 Regicide가 선택했다. 새 외부 기보·교사 수·Stockfish 평가·신경망 가중치를 사용하지 않았다.

교사는 기존 활성 Regicide SHA256 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`, 고전 활동성 평가, Hash 16MiB, 단일 검색이다. 질의마다 새 UCI 게임으로 시작했다. 목표 깊이 7과 질의당 최대 1,000,000노드를 함께 제한했다.

각 시작 수순에서 내 첫 수를 탐색한 뒤, 상대의 자체 기본 응수와 그 수를 제외한 제한 검색의 대안 응수를 각각 이어 연구했다. 제한 검색은 대안 분기를 찾는 용도로만 사용하며, 그 점수를 제한 없는 최선수 평가로 쓰지 않는다. 각 갈래에서 내 후속 수 두 번을 연구해 계열당 10개, 총 50개 상태·후보가 생겼다.

- 실제 질의 92회, 상대 응수 갈래 20개.
- 완료 깊이: 5가 11회, 6이 72회, 7이 9회. 목표 깊이 7을 모두 완료했다고 표시하지 않는다.
- 기록된 소비 노드 합계 90,154,338. 연구 시간 13:37:01~13:40:49 UTC, 한국시간 22:37:01~22:40:49로 약 3분 48초다. 속도 비교 실험은 아니다.
- 저장한 내 착수 전 이력은 최대 26반수다. 부다페스트의 카탈로그가 최대 8반수였던 데 비해 새 후보는 최대 11반수 위치에서 12번째 착수까지 연결한다. 에번스는 최대 26반수 위치에서 27번째 착수까지 연결한다. 다른 계열에서는 기존 최장 변형보다 길어졌다는 주장 대신 새 방어 갈래와 미포함 후속 수가 생긴 것으로 구분한다.
- 소유한 교사 엔진의 종료 코드 0을 확인했다. 기존 운영 기억과 `policy.json`의 실험·비활성 상태는 바꾸지 않았다.

시작 수순과 모든 후속 갈래는 이 연구의 교육·개발 자료다. 기존 순위 모델에서 보류했던 계열이라도 이번에 연구한 뒤의 결과를 미사용 검증 자료로 부르지 않는다.

## 실제 수 선택과 검증

기존 `gambit_knowledge.proposals()`는 고정 카탈로그 전용 의미를 유지한다. 커리큘럼의 byte 재생성과 과거 자료의 출처를 새 지원 자료 때문에 바꾸지 않는다. 실제 대국은 `runtime_proposals()`를 사용해 정확한 전체 이력이 일치하는 자체 연구 후보를 공급하고, 기존 운영 기억과 함께 검토한다. `has_catalog_continuation`·`has_native_continuation`·`has_any_continuation`을 나누고, 이전 `has_continuation`은 카탈로그 의미를 유지한다.

이 자료가 새로 공급하는 독립 후보는 `source=native_gambit_continuation`, `candidate_only=true`, `loss_cap_cp=0`이다. 저장 점수는 현재 수를 선택하거나 희생을 허가하는 값으로 전달하지 않는다. **같은 수를 독립적으로 유효한 기존 운영 기억도 제안하면 기존 출처를 보존**한다. 후발 연구가 기존 기억의 출처와 허용치를 덮어쓰지 않으며, 검증할 수는 하나로 합친다.

기존 기억은 자료의 승인 상태·현재 전체 이력과 FEN·런타임 엔진 식별자를 확인해 생성되며, 실제 선택 전에 `valid_proposal`로 권위 있는 원본 행과 다시 대조한다. 같은 UCI라는 이유만으로 미검증 출처의 허용치를 가져오지 않는다. 보존한 기존 기억은 종전 검증과 상한을 유지하고, 새 연구로만 제안되는 독립 후보는0cp 상한을 유지한다. 상한 값이나 특정 수·국면 예외를 새로 조정하지 않았다. 자체 연구 후보에는 지원 파일의 ID·manifest 해시를 보존하며, 메모 식별에는 해당 manifest와 선택·운영 측정 정책 버전, D+1 실험 활성 여부도 포함한다.

현재 기본 정책은 **`regicide-gambit-repertoire-play-v7`의 동깊이 독립 검증과 기존 유효 출처 보존**이다. `ENABLE_STUDIED_FINALISTS=False`이며, 아래의 D+1 공동 검색은 기본 선택에 사용하지 않는다. 기본 검색의 완료 깊이를 D라고 할 때 다음 절차를 따른다.

1. 후보의 출처와 현재 전체 이력을 다시 확인한다. 기본 수와 다른 후보 중 최대2개를 검토하며, 각 후보에 기물 손실 사전 검사를 적용한다. 검증할 대안이나 충분한 근거가 없으면 원래 기본 수를 보존한다.
2. 각 후보의 첫 수만 고정해 자체 엔진에 **기본 검색과 같은 D 깊이**를 요청한다. 이후 상대 응수는 제한하지 않는다. 후보 사전 검사와 개별 검색·결과 검증은 기존 공통 추가 시간 예산 안에서 수행한다.
3. 후보가 실제 반환 수와 일치하고, D의 정확한 완료 점수와 합법 예상 수순을 얻어야 한다. 후보의 최종 보고도 D 이상이어야 하며 같은 깊이의 점수 충돌을 허용하지 않는다. 미완료·불법 수순·경계 점수·오류·시간 초과는 교체의 근거가 되지 않는다.
4. 새 연구로만 제안되는 독립 후보는 **동깊이 비교에서 손실 0cp**를 요구한다. 현재 기본 점수보다 낮은 새 후보를 저장된 연구 점수나 운영 점수로 승인하지 않는다. 추가로 더 깊은 최종 보고가 있다면 그 악화도 거부 조건에 포함한다. 같은 수의 기존 운영 기억이 독립적으로 유효해 보존됐다면 그 출처의 종전 상한을 적용한다. 최종적으로 보존한 출처의 실제 검증 없이 다른 출처의 상한을 빌리지 않는다.
5. 상대 응수 근거와 비종결 수순을 확인한다. 운영 계획이 적용되는 위치에서는 교환·체크 정산이 완료돼야 한다. 운영 점수가 좋아지거나, 같은 운영 점수에서 현재 자체 평가가 좋아져야 한다. 또는 현재 자체 비교에서 최소10cp 개선을 얻으면 기하적 운영 점수가 낮다는 이유만으로 막지 않는다. 어느 경우든 정산 미완료는 거부한다. 통과한 대안이 없으면 기본 수를 유지한다.

이 기본 경로의 `loss_cp`와 `reference_delta_cp`는 같은 완료 깊이 D의 기본·후보 점수로 계산한다. 독립적인 자체 연구 출처로 채택되면 손실 상한 때문에 `loss_cp=0`이다. 기존 운영 기억의 출처로 채택되면 종전 허용 범위의 손실이 기록될 수 있다. 이것은 그 검색 자료의 비교 기준이며 실제 기력·수의 객관적 안전성을 보장하는 값은 아니다.

### v6 중복 출처 처리의 실패

v6은 D+1 공동 검색을 끄고도 같은 수의 새 연구 출처가 기존 운영 기억을 덮어쓰도록 했다. 실제 Budapest 비교에서 기존 기억의 `Ngxe5`는 기본 `g6`보다 자체 동깊이 점수가1cp 낮았지만 종전35cp 상한 안에서 허용되던 수였다. v6에서는 같은 수가 새 출처의0cp 상한을 적용받아 거절됐고, 외부 감사 손실이 **6→108cp로102cp 악화**됐다. 출처를 추가한 일이 기존 선택을 막은 회귀였다.

v7은 이 결과를 숨기거나 개별 정답 수를 등록하지 않고, 중복된 같은 수의 기존 유효 출처를 보존하는 일반 합성 규칙으로 수정했다. v5·v6의 실패 기록과 v7의 실제 재검증 결과는 [별도 실행 기록](../../docs/checks/2026-11-05-gambit-opening-growth/README.md)에서 구분한다. 규칙 수정이나 단위 검사 통과만으로 회복·기력 향상을 확정하지 않는다.

### 비활성 D+1 공동 검색 실험

v5에서는 기본 수와 연구 후보를 한 번의 후보 제한 검색에 넣고, 같은 추가 예산으로 D+1 완료를 요구했다. 기본 수를 포함해도 실전 품질 향상은 확인되지 않았다. 교육50국면의 실제 전후 비교에서 선택이4개 바뀌었고, 선택 후 외부 감사는 **1개 개선·3개 악화**, 변경4개의 손실 합은 **167→196cp**였다. 따라서 이 방식을 기본 적용에서 제외했다. 이는 변경된 교육 국면 부분집합의 결과이며50개 전체 평균이나 미사용 검증 성능은 아니다. [실행 조건과 실패 결과](../../docs/checks/2026-11-05-gambit-opening-growth/README.md)를 별도로 보존한다. 외부 감사 점수는 실전 선택에 사용하지 않았다.

실험 코드는 재현을 위해 남겨 두었으며, 관련 단위 검사는 실험 플래그를 명시적으로 켠 범위에서만 이 경로를 검사한다. 기본값은 꺼져 있고, 플래그 값과 v7 정책 버전이 메모 식별에 들어가므로 실험이나 이전 버전에서 저장한 선택을 현재 기본 경로의 선택으로 재사용하지 않는다. v7 기본 절차의 실전 전후 비교 결과와 v5·v6 실험 결과를 섞지 않는다.

보존된 D+1 실험이 대안을 채택한 기록에서는 `loss_cp`와 상위 기록의 `reference_delta_cp`가 `null`이다. 서로 다른 깊이의 점수를 빼지 않는다. 별도 `selected_vs_finalist_best_loss_cp=0`은 기본 수를 포함한 해당 완료 검색의 후보 집합 안에서 반환된 최선수라는 뜻이며, 앞의 실제 실패 결과가 보여 주듯 실전 개선의 증거가 아니다. 기록의 `deeper_native_comparison_including_baseline`·`baseline_included_in_same_completed_native_search`는 이 비활성 실험을 식별한다.

로더는 원본 카탈로그 해시, 실제 전체 수 이력·FEN·계열·주체, 제한 없는 완료 검색의 수·깊이·점수 형식·합법 PV를 검사한다. 내용 또는 manifest가 바뀌면 캐시를 갱신하고, 이전 지원 후보를 거부한다. 손상되거나 현재 이력이 없으면 이 지원 후보를 반환하지 않는다.

원시 UCI, 최초 연구 보고서, 최종 공개 데이터, seed와 최종 생성기를 `native_continuations_evidence.zip`에 보존했다. `publication.json`은 실행 완료 후 고정 카탈로그의 `source_prefixes`를 추가한 출처 후처리를 별도로 설명한다. 최종 생성기 스냅샷은 그 출처 추가를 포함한 버전이며 사전 캡처된 실행 소스라고 주장하지 않는다. 원본 질의·착수·점수는 변경하지 않았고, 자동 검사가 모든 92개 질의의 실제 `position`·`go`·완료 점수/PV·`bestmove`를 원시 로그와 대조한다. 중간 Windows 문자 인코딩으로 변형됐던 표시명도 최초 UTF-8 보고서에서 복원했고 실제 질의와 수에는 변화가 없다.

재실행은 기존 결과를 덮어쓰지 않는 새 폴더에 한다.

```powershell
.\.venv-tests\Scripts\python.exe scripts/train_gambit_knowledge_support.py --binary build/runtime-engines/5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba/regicide.exe --output build/new-native-support-study --depth 7 --nodes 1000000
.\.venv-tests\Scripts\python.exe -m unittest discover -s tests -p gambit_knowledge_support_tests.py -v
.\.venv-tests\Scripts\python.exe -m unittest discover -s tests -p gambit_opening_quality_tests.py -v
```

현재 자료가 실전 선택을 바꾸는지와 그 수가 더 나은지는 별도 production 경로의 전후 비교로 판정해야 한다. 후보 수, 저장 행 수, 실제 교체 횟수를 같은 효과 지표로 세지 않는다.
