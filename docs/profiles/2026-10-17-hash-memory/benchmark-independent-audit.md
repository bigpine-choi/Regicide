# 전이표 메모리 재사용: 속도 자료 독립 감사

생산 코드와 벤치마크 원자료를 수정하거나 엔진 대국을 실행하지 않고, 저장된 JSON을 별도 스크립트로 재계산했다. `benchmark-independent-audit.py`와 상세 `benchmark-independent-audit.json`을 함께 보존한다.

250쌍 모두 정확한 점수·최선 수·완료 깊이·노드·최대 깊이·PV·기존 TT 조회/적중/차단/저장 횟수가 일치했다. 준비 탐색 4회와 측정 탐색 500회의 PV 총 **728수**를 합법 수로 독립 재생했다. 측정 노드는 각 조건의 양쪽 모두 7,550 / 7,550 / 170,370개로 같았다. 세 조건 모두 위치별 중앙값이 악화된 위치는 없었다. 깊이 3의 한 측정 쌍은 개선판이 느렸다.

엔진 해시, 선언한 소스 커밋, 원자료의 깨끗한 체크아웃 기록, 위치 파일 해시, 두 엔진의 공통 기본 옵션과 명시적 옵션 없음, 시드로 재현한 위치 순서·엔진 순서·전체 반복을 확인했다. 기준 별도 소스와 개선 체크아웃의 관련 파일 각각 17개를 줄바꿈 정규화 후 해당 커밋과 대조했다. 실행 파일을 별도로 재빌드해 출처를 증명한 것은 아니다.

기준 소스는 `ef52f14569222acbfaa512245bab81558795180f`, 개선 소스는 `4a0f95a035b1cc0eff8e8d56a14ea898621eab64`다. 바이너리 SHA256은 각각 `620cdba22750978898809e32711cb117a0f4f74a08a6ab8dffe7de9046ba5340`, `0bac627c4b7eb8425e6812a64dad5546ed1a7e24dd603cb365f12dd569ffd2e9`와 일치했다.

## 최초 할당과 재사용 구분

- 준비 탐색이 없는 개선판 100회 중 최초 1회는 할당 1·재사용 0, 이후 99회는 할당 0·재사용 1이었다. 이는 독립적인 콜드 시작 100회가 아니다.
- 그 첫 측정은 폰 엔드게임이며 기준/개선 4.4376/4.1412ms, 가속 1.0716배였다. 4.1015배 중앙값을 최초 할당 자체의 가속으로 해석하지 않는다.
- 준비 탐색 1회 조건의 개선판은 준비 탐색에서 한 번 할당하고, 측정 구간에서는 모두 할당 0·재사용 1이었다. 깊이 1은 재사용 100회, 깊이 3은 50회다. 준비 탐색은 별도 기록되며 측정 합계에서 빠졌다.
- 물리 전체 초기화는 모두 0회다. 논리 세대 변경과 구분한다. 메모리 최고값은 16,777,208바이트이며 합산하지 않았다.
- 기준 v0.4는 메모리 통계를 보고하지 않으므로 `None`을 유지했다. 기준의 검색마다 할당한다는 설명은 소스 구현 근거이며 새 통계가 관측한 값은 아니다.

기준·개선 모두 `run-tt-layout-probe.cmd`의 MSVC 네이티브 검사에서 **엔트리 56바이트·299,593슬롯·16,777,208바이트**로 확인됐다. 기준·개선 헤더를 각각 사용하고 해당 빌드의 `transposition.obj`와 연결한 결과다. 엔진 바이너리를 재빌드한 검사는 아니다. 감사 스크립트가 저장된 `tt-layout-probe.jsonl` 두 줄을 검증했고 상세 JSON의 `native_layout_probe`는 `passed`다.

## 해석의 한계

깊이 1 개선판의 보고 탐색 시간은 두 조건 모두 100회 중 99회가 정수 밀리초의 0이었다. 깊이 3은 50회 중 10회가 0이었다. 따라서 주된 시간 비교는 UCI 요청·응답과 게임 초기화를 포함하는 벽시계다. 밀리초 정수 시간을 세밀한 계산 비용으로 해석하지 않는다.

10개 고정 위치의 반복 측정이다. 반복은 시간 변동을 관측하며 독립 위치 수나 경기력 표본을 늘리지 않는다. 검색 그래프가 같은 상태에서의 메모리 비용 감소를 확인한 결과이며, Elo·인간 상대 강도나 대국 결과는 이 감사의 범위가 아니다.
