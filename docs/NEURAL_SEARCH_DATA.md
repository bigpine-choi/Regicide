# 자체 고정 노드 탐색 학습 자료

새 생성기는 자체 Regicide가 둔 위치에 **그 위치에서 수행한 자체 탐색의 점수**를 붙인다. 기존 768×16 신경망, v2 가중치 형식, 학습 코드, 기본 평가기는 변경하지 않는다. 이번 단계의 목표는 자료 수집의 정확성과 비용을 확인하는 것이다.

## 원리와 입력

예를 들어 정적 평가가 백의 폰 하나 우세를 보여도, 탐색 중 폰을 잃는 수순이 보이면 탐색 점수는 달라질 수 있다. 이 점수를 원래 위치의 정답으로 저장하면 이후 신경망이 자체 탐색의 판단을 근사하도록 학습할 수 있다. 탐색 점수는 최선의 수를 안다는 보장이나 실전 승률이 아니다.

- 시작 자료는 `scripts/neural_search_data/seeds.json`의 프로젝트 자체 작성 8계열이다. 정상 시작 위치에서 합법적인 예시 4반수 수순을 둔 4계열과, 기물 8~9개인 합성 종반 4계열을 포함한다. 후자는 실전 기보에서 추출한 종반이 아니다.
- 각 위치를 자체 기존 평가기와 자체 탐색으로 검색하고 그 최선 수를 둔다. 같은 검색 결과를 수 선택과 정답에 사용한다. 외부 엔진·기보·모델·테이블베이스를 사용하지 않는다.
- 기본값은 검색당 10,000노드, 계열당 최대 96반수, 3반수마다 채집, 최대 768검색, 총 180초, 검색당 10초이다. 1반수는 한쪽이 한 번 둔 수다. 총 노드 상한도 사전에 기록한다.
- 옵션은 기존 위치 평가·quiescence·TT·PVS·SEE를 켜고 신경망 평가는 끈다. 각 검색에 새 game token을 주어 TT를 비운다. 시간 제한 검색과 노드 제한 검색을 혼용하지 않는다. 벽시계 제한에 걸려 중단한 검색은 정답에서 제외한다.
- 기본 자료 생성에는 별도 정적 평가 대조값도 저장한다. `eval-batch`의 진짜 기존 정적 점수이며 탐색 정답과 다른 필드다.

정상 시작 자체 대국과 합성 종반의 family를 각각 섞어, 생성 전에 학습·검증에 배정한다. 같은 family의 파생 시작 위치는 같은 분할에 둬야 한다. 전 자료에서 기물 배치와 색·랭크 반전까지 중복 제거한다. 현재 v2 입력에 없는 손번·캐슬링 권리·앙파상·카운터 차이도 이 입력 중복 판단에서는 구분하지 않는다. 원래 상태와 전체 수순은 별도로 보존한다.

## 실행

저장소 루트에서 실행한다. 필요한 파이썬 패키지는 기존 `requirements-test.txt`의 `chess==1.11.2`뿐이다. C++ 엔진 자체의 의존성이 아니다.

```powershell
.venv-tests/Scripts/python.exe -m scripts.neural_search_data generate `
  --engine build-neural-precision-runtime/regicide.exe `
  --output build-search-data/first `
  --nodes 10000 --max-plies 96 --sample-every 3 `
  --seed 20261019 --validation-fraction 0.25 `
  --max-searches 768 --max-seconds 180 --search-timeout 10

.venv-tests/Scripts/python.exe -m scripts.neural_search_data check build-search-data/first
```

기존 출력 폴더는 덮어쓰거나 이어서 생성하지 않는다. 새 경로를 사용한다. 엔진 시작 전에 `plan.json`에 설정·분할·출처·실행 파일 SHA·소스 SHA·환경을 저장한다. 제공한 실행 파일의 SHA와 현재 소스 체크아웃은 별도 증거이며, 현재 HEAD를 그 실행 파일의 빌드 커밋으로 간주하지 않는다.

종료 상태 `complete`는 계획한 모든 시작 위치를 지정한 반수 상한 또는 실제 게임 종료까지 처리했다는 의미다. 모든 게임이 승패까지 끝났다는 뜻은 아니다. `budget_exhausted`나 `error`에서는 이미 완료한 검색과 부분 수순을 보존하고 비정상 종료 코드 2를 반환한다. 기본 로더는 이런 시도를 거부한다. 조사할 때에만 다음과 같이 명시적으로 읽는다. 빈 분할이 있을 수 있으며 학습 가능하다는 판정이 아니다.

```powershell
.venv-tests/Scripts/python.exe -m scripts.neural_search_data check build-search-data/first --allow-partial
```

총 시간 상한에는 사전 준비와 정적 평가 대조값 계산이 포함된다. 중단 후 프로세스 정리와 기록 저장에는 짧은 추가 시간이 필요하다. 노드 제한만 둔 python-chess 탐색에 기본 `SimpleEngine.timeout`이 적용되지 않으므로, 별도 비동기 제한과 프로세스 종료를 사용한다.

## 저장 형식과 검사

| 파일 | 내용 |
|---|---|
| `plan.json` | 실행 전에 확정한 설정, 원본 시작 위치, family 분할, 실행 파일·소스 SHA, 환경 |
| `queries.jsonl` | 모든 검색의 원래 FEN·전체 수순·노드·완료 깊이·PV·점수 종류·필터 사유·원시 UCI 범위 |
| `games.jsonl` | 전체 게임 수순, 원래 시작 위치, 중단 사유, 확인된 실제 결과 |
| `train.jsonl`, `validation.jsonl` | 중복 제거와 필터를 통과한 원래 위치 및 백 관점 정답 |
| `uci.jsonl` | 송수신한 UCI 원문과 시각·순서 |
| `manifest.json` | 최종 상태, 파일 SHA, 행 수, 분포와 소요 시간 |

검색 점수는 둘 차례인 쪽 관점의 `score.stm`/`search_stm_cp`다. 학습용 `target_white_cp`는 백이면 그대로, 흑이면 부호를 바꾼다. PV 끝 위치에 원래 위치의 점수를 붙이지 않는다. 탐색 도중 메이트 점수나 상·하한 점수가 나온 경우 종류를 원자료에 유지하며 cp 학습 정답에서는 제외한다.

체크 중인 위치, 최선 수가 잡는 수 또는 승격인 위치, 완료 깊이가 0인 검색, 미완료·불법 PV·노드 상한 위반을 표본에서 제외한다. 깊이 0에서 합법 대체 수만 반환한 경우 대국을 계속할 수 있으나 정답으로 쓰지 않는다. 선택 간격과 중복도 이유별로 기록한다. 같은 위치라도 수순에 따라 반복 판정이 달라질 수 있으므로 초기 FEN과 전체 수순을 함께 전송하고 저장한다.

게임 결과는 `outcome(claim_draw=True)`로 확인한 경우만 기록한다. 반수·노드·시간 상한으로 끝난 게임의 결과는 `null`이다. 그 게임에서 이미 완료한 유효한 검색 정답은 쓸 수 있지만, 종료되지 않은 게임을 무승부 정답으로 만들지 않는다. 메이트 검색 점수를 cp로 바꾸거나 부분 게임의 WDL을 추정하지 않는다.

`load_dataset()`는 SHA 검사 외에 전체 수순의 합법성, 실제 다음 수와 검색 bestmove의 연결, 초기 family 배정, 채집·제외·중복 정책, 정수 타입, 백/흑 점수 관점까지 다시 검사한다. 검색과 정적 평가를 혼동하지 않도록 기존 schema 1의 `classical_stm_cp` 필드를 허용하지 않는다. 새 데이터는 schema 2이며 기존 `neural_training.read_dataset()`로 직접 읽지 않는다. 새 로더가 반환하는 행의 `fen`과 `target_white_cp`는 기존 `pack_records()`로 포장할 수 있다. 실제 학습 명령과 QAT 후보 비교는 후속 작업이다.

## 재현과 한계

```powershell
.venv-tests/Scripts/python.exe -m unittest discover -s tests/neural_search_data -v
.venv-tests/Scripts/python.exe tests/neural_search_data/integration.py `
  --engine build-neural-precision-runtime/regicide.exe `
  --output build-search-data/replay --nodes 10000 --max-plies 48 --max-seconds 120
```

통합 검사는 조건을 먼저 기록한 뒤 두 번 생성한다. 학습·검증 파일과 수순·정답의 의미 해시가 정확히 일치해야 한다. 원시 로그 시각과 실제 실행 시간은 당연히 달라지므로 파일 전체의 일치를 요구하지 않는다. 새 CI 파일도 단위검사와 더 작은 통합 검사를 실행하도록 추가했다. 원격 CI 실행 결과와 로컬 실행 결과는 별도다.

8계열의 작은 표본은 생성기 확인용이다. 가족 단위 분리와 입력 중복 제거가 유사 위치 전체의 통계적 독립성을 보장하지 않는다. 현재 교사는 자체 기존 평가기와 작은 노드 예산에 의존하며 깊이도 위치마다 다르다. 조용한 위치만 남기는 필터는 전술 장면을 줄인다. 합성 종반, 반복으로 끝난 수순, 제한된 시작 계열도 편향을 만든다. 검증 자료를 반복해서 설정 선택에 사용하면 별도의 새 보류 자료가 필요하다.

현재 v2는 실제 손번·캐슬링·앙파상·반복 이력을 입력으로 배우지 못한다. 검색 정답에는 이 상태가 영향을 주므로 일부 차이는 현재 모델로 설명하기 어렵다. 이를 이번 단계에서 새 구조나 가중치 변경으로 감추지 않는다. 이 자료를 확대하고 정적 정답 대조군과 동일 조건에서 학습하는 것이 다음 단계이며 기력 향상은 이후 별도 대국으로 판단한다.

자료의 원천은 자체 작성 위치와 자체 탐색이다. 합성 위치의 합법성 검사는 실제 과거 게임에서 도달했다는 증명이 아니다. 외부 의존 라이브러리 python-chess의 출처와 이용 조건은 설치 패키지의 메타데이터 및 해당 프로젝트의 GPL-3.0-or-later 라이선스를 따른다. 기존 외부 보류 기보나 공개 엔진의 가중치를 새 학습 자료로 가져오지 않았다.
