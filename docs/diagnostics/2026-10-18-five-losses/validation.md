왕 이동과 체크, 캐슬링, 앙파상, 승격, 체크메이트·스테일메이트, 50수·75수 규칙, 3회·5회 반복 및 수 실행/되돌리기를 검사한다. 탐색 검사에는 중단·계산 한도·이력별 저장표 분리와 기존 LMR 보호 조건을 포함한다. 평가 함수 검사는 보존한 v0.5.4·v0.5.6 기준 구현과 독립적인 폰 구조 기준값을 계속 비교한다.

Windows는 기존 빌드 스크립트의 엄격한 경고 설정과 최적화 빌드를 사용했다. Linux는 Ubuntu 24.04 계열 WSL2의 GCC 13.3.0에서 C++20, `-O2 -Wall -Wextra -Wpedantic -Werror`로 빌드·실행했다. Linux 로그의 핵심 코드·기존 검사 파일 해시도 기록했다.

## 추가한 진단 도구 검사

최종 진단 corpus 6개 위치를 생성한 뒤 Windows에서 새 검사 **21개를 모두 실행해 통과했다. 실패 0, 건너뜀 0**이며, 실제 실행 시간은 로그상 1.536초다. [최종 실행 로그](diagnostic-tests-final.log)에 각 검사 결과를 보존했다. 자료가 없어서 건너뛴 사전 검사나 중간 도구 검사 결과는 이 최종 수치에 합산하지 않는다.

새 회귀 검사는 다음을 확인한다.

- 승인된 브라우저 종료 후 재대국의 JSON·PGN 해시, 5패의 게임 번호, 전체 수 이력과 합법 PV가 원본과 일치하는지 검사한다. 제외된 재대국은 원본에 포함하지 않는다.
- CLI의 기물 점수와 메이트 점수를 구별하고, 차례에 따른 부호·메이트 0의 부호 모호성·계산 한도·미완료 깊이를 보존한다. CLI가 발행하지 않은 상한·하한 표시는 임의로 만들어 내지 않는다.
- python-chess의 누적 정보에 이전 상한·하한 표시가 남는 현상을 재현하고, **최종 점수와 같은 원본 UCI 한 줄**에서 읽은 표시로 교정하는지 검사한다. 서로 다른 점수·모순된 표시·이전 방식의 보고서·부분 보고서는 거부한다.
- 정확한 cp 점수끼리만 차이를 계산하고 메이트를 임의의 cp 값으로 바꾸지 않는다. 첫 유의미한 위치, 가장 큰 차이, 동률이면 이른 수, 게임당 최대 2곳 및 중복 제거라는 선정 규칙을 검사한다.
- C++ 정적 관찰 도구의 전체 이력 재생, 현재 반복·50수 주장, 차례, 합법 수 개수와 왕 앞 폰 방패·폰 구조 평가의 네 조합을 검사한다. 각 조합의 차이를 가법적인 기여도로 가정하지 않는다.
- 최종 진단 corpus의 모든 위치를 실제 C++ 도구에 전체 이력으로 전달하고 Python 보드와 상태를 대조한다. 같은 위치를 실제 엔진으로 깊이 2·최대 5,000노드·LMR OFF에서 재생해 합법 최선 수/PV, 계산 한도와 LMR 미사용을 검사한다.
- 잘못된 입력·실패한 프로세스의 원문 보존과 기존 출력 파일 보호를 검사한다.

이 검사들은 **기록과 진단 절차의 정확성**을 지킨다. 과거에 둔 나쁜 수를 앞으로도 정답으로 고정하지 않는다. [corpus](../../../tests/data/lmr_loss_positions_2026-10-18.json)의 6개 위치는 5패에서 각각 선정한 위치 5개와 선후공 교대 게임의 보조 비교 위치 1개다. 여섯 번째 패배로 세지 않는다.

자료에 남긴 `quality_goal`과 진단 분류는 추후 엔진 개선으로 확인할 별도 목표이며, 이 회귀 검사의 통과만으로 해결되었다고 보지 않는다. 예컨대 보조 위치 `pair2-p74`에서 LMR ON이 같은 노드·깊이 조건에서 더 나쁜 대안을 고르는 관측과, 계산량을 늘리면 다른 수로 회복되는 관측은 함께 남긴다. `search_budget_recovers`는 계산량을 늘린 실험에서 회복했다는 뜻이며 배포 엔진을 수정했다는 뜻이 아니다. 평가와 탐색 지평선의 영향을 분리하지 못한 위치는 `unresolved`로 남긴다.

## 실행 범위와 남은 한계

새 정적 관찰 도구는 Windows에서 선택 빌드되었고 Linux에서도 엄격한 경고 설정으로 컴파일되었다. 새 Python 진단 검사와 실제 도구 재생 검사는 Windows 실행 결과로 보고한다. Linux 로컬에는 python-chess가 설치되지 않아 해당 Python 검사를 실행하지 않았다.

기존 GitHub Actions의 두 운영체제 규칙·UCI·관련 클라이언트 검사는 모두 유지했다. 여기에 기본 빌드에서 제외된 정적 관찰 도구를 별도로 빌드하고 새 진단 검사를 실행하는 단계만 추가했다. **원격 CI는 아직 실행·확인하지 않았으므로 이 문서는 원격 통과를 주장하지 않는다.**

규칙·메모리·이력 검사의 통과는 수 선택의 강도나 평가 함수의 옳음을 입증하지 않는다. 제한된 참조 탐색과 자체 엔진의 의견 차이는 진단 근거이며, 외부 참조도 전체 해답을 증명하지 않는다. 정적 관찰 위치나 공개된 PV 끝의 점수는 실제 탐색 중 사용한 모든 말단 점수를 대표하지 않는다. 미해결 수 선택 약점은 별도 결과 문서와 corpus에 남겨 다음 개선의 검증 대상으로 사용한다.
