# 통과폰과 폰 구조 평가

v0.5.6은 폰이 어디까지 전진했는지에 더해, 앞길을 막을 적 폰과 주변 자기 폰의 배치를 평가한다. 기존 왕 앞 폰 방패와 함께 동작한다.

## 통과폰

같은 세로줄과 양옆 줄의 앞쪽에 적 폰이 없어, 적 폰이 전진 경로를 막거나 잡기 어려운 폰을 통과폰이라고 한다. 예를 들어 백 e5 폰 앞의 d·e·f줄에 적 폰이 없으면 통과폰 조건을 만족한다. 다른 기물의 공격이나 봉쇄는 여전히 가능하므로 승격을 보장하지 않는다.

| 백 기준 위치 / 흑은 반대 방향 | 중반 가산점 | 종반 가산점 |
| --- | ---: | ---: |
| 2번째 랭크 | 0 | 0 |
| 3번째 랭크 | 5 | 10 |
| 4번째 랭크 | 10 | 20 |
| 5번째 랭크 | 20 | 40 |
| 6번째 랭크 | 35 | 70 |
| 7번째 랭크 | 60 | 120 |

100점은 폰 한 개의 기본 가치다. 기존 폰 가치와 전진 점수에 이 항목을 더하며, 바로 앞 칸이 어떤 기물로든 막혔으면 가산점을 절반 줄인다. 같은 줄에 자기 폰이 여러 개라면 가장 앞의 폰만 가산점을 받는다.

## 겹친 폰과 고립폰

- **겹친 폰:** 한 줄에 두 폰이 있으면 추가 폰 하나, 세 폰이면 추가 폰 둘로 세어 중반8/종반12점씩 감점한다.
- **고립폰:** 양옆 줄 어디에도 자기 폰이 없으면 해당 폰마다 중반10/종반12점을 감점한다. 같은 줄의 자기 폰은 고립을 해소하지 않으며 겹침과 고립 감점은 함께 적용할 수 있다.

이 점수는 단순한 초기 기준이다. 폰을 겹치는 수가 기물 획득·왕 공격 등으로 충분히 보상될 수 있고, 실제 수 선택은 상대 응수를 읽는 탐색이 함께 결정한다. 중반/종반의 점수는 기존 국면 비율로 섞는다.

## 설정과 검증

기본 켬이다. UCI `setoption name UsePawnStructure value false` 또는 콘솔 `search 3 --no-pawn-structure`로 새 구조 항목만 끌 수 있다. C++에서는 `evaluate_position(board, shield, false)` 또는 `SearchOptions::pawn_structure=false`다. `UsePawnShield`와 독립이며 `UsePositionalEvaluation=false`에서는 두 항목을 사용하지 않는다.

실제 대국과 추천 수 모두 자체 Regicide의 새 평가를 사용한다. [개발 계획](experiments/2026-10-18-pawn-structure-plan.md)과 [검증 기록](experiments/2026-10-18-pawn-structure.md)에 수행한 검사·비용·미검증 기력을 구분한다.

v0.5.7은 위 점수와 설정을 그대로 유지하며 폰 파일의 반복 계산을 줄인다. [동값 최적화 기록](experiments/2026-10-18-pawn-opt.md)에 수정 전 함수·독립 참조와의 점수 대조 및 비용 측정을 남긴다.
