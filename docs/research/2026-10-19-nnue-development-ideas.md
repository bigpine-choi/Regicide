# Regicide NNUE 개발 아이디어와 공개 연구 자료

작성·자료 확인일: 2026-10-19 (Asia/Seoul)  
문서 상태: 연구 방향 및 후속 실험 제안. 구현 현황은 아래 고정 스냅샷의 문서를 참조한다.

## 1. 권고 방향과 결정 상태

NNUE 평가기와 자체 탐색기를 중심으로 개발하고, 정확성·실행 비용·실제 대국 성적을 따로 측정한다. 작은 기준 모델에서 시작해 모델 용량과 학습 자료를 단계적으로 바꾼다. 최종 선택 기준은 사용자 하드웨어에서의 동일 시간 대국 성적이다.

| 항목 | 상태 |
| --- | --- |
| NNUE 방식으로 개발 | 사용자와 논의한 개발 방향 |
| 작은 기준 모델부터 크기를 비교 | 권고안. 최적 크기는 미확정 |
| GPU 학습, CPU 대국 추론 | 후속 구성 제안. GPU 학습 환경·처리량 미검증 |
| 외부 평가값·공개 기보 사용 | 비교할 선택지. 데이터 채택은 미확정 |
| 자기대국 자료로 반복 학습 | 후속 실험 방향. 실행 횟수에 따른 향상은 보장하지 않음 |
| PyTorch 또는 Bullet 도입 | 검토 대상. 기존 학습 도구를 교체하기로 확정하지 않음 |

NNUE는 평가망을 빠르게 실행하기 위한 구조다. 자기대국은 학습 자료를 만드는 방법이고, 강화학습은 학습 접근법이다. NNUE를 선택해도 자기대국 데이터를 이용한 학습을 함께 연구할 수 있다. [S1][S3]

## 2. 확인한 저장소 현황

확인 시점의 기본 브랜치 main에는 초기 README와 프로젝트 지침·로드맵이 있다. 실제 개발 이력은 별도 브랜치에 존재한다. 초기 README만으로 프로젝트 전체의 구현 여부를 판단하지 않는다.

이번에 확인한 구현 스냅샷은 **feat/nnue-incremental, c8cc439bd9107a51caa5db7aba8dad478c9dc3e1**이다.

- [NNUE 구현 설명: v0.6.6](https://github.com/bigpine-choi/Regicide/blob/c8cc439bd9107a51caa5db7aba8dad478c9dc3e1/docs/NNUE.md)
- [기존 작은 신경망과 최초 학습 기록](https://github.com/bigpine-choi/Regicide/blob/c8cc439bd9107a51caa5db7aba8dad478c9dc3e1/docs/NEURAL_EVALUATION.md)
- [NNUE 정확성·실행 비용 검증 기록](https://github.com/bigpine-choi/Regicide/blob/c8cc439bd9107a51caa5db7aba8dad478c9dc3e1/docs/checks/2026-10-19-nnue-incremental/README.md)

위 문서에는 기존 768→32→16→1 평가망에 선택적 첫 층 고정소수 계산과 증분 누산기를 연결한 내용이 있다. 누산기는 이전 계산 결과를 보관하고 한 수로 바뀐 부분만 갱신하는 장치다. 뒤층은 기존 double 계산을 사용하며, Stockfish의 전체 정수 추론과 같은 구성으로 간주하지 않는다.

해당 스냅샷에서는 UseNeuralEvaluation과 UseNNUE가 모두 기본 false라고 문서화되어 있다. 기존 학습·대국 실행기가 NNUE를 자동 활성화하지 않으므로 비교 실험에서 실제 옵션을 확인해야 한다.

검증 기록은 개발 환경의 정확성 및 비용 검사이며 새 모델 학습·기력 대국·사용자 OMEN 설치를 수행하지 않았다고 명시한다. 이번 문서 작성 작업에서도 빌드·학습·대국을 재실행하지 않았다. 따라서 후속 목표는 이미 있는 기반을 활용한 모델·학습·실행 성능 개선이다.

## 3. 신경망 크기와 실행 자원

큰 모델은 복잡한 기물 관계를 표현할 여력이 있지만 학습·추론 비용과 데이터 요구가 커질 수 있다. 작은 모델은 빠른 반복 실험과 탐색에 유리하지만 표현력이 제한될 수 있다. 어느 쪽이 강한지는 통제된 대국으로 판단한다.

NNUE에서는 파라미터 수와 파일 크기만으로 평가 속도를 예측할 수 없다. 희소 입력의 활성 특징 수, 첫 층과 뒤층의 폭, 정수 표현, 메모리 접근, 증분 갱신과 CPU 구현도 중요하다. 큰 첫 층을 갖더라도 매번 그 가중치를 전부 계산하지 않을 수 있다. [S1]

| 역할 | 우선 검토할 실행 장치 | 측정할 항목 |
| --- | --- | --- |
| 신경망 학습 | NVIDIA GPU | 배치 처리량, VRAM, 학습 시간, 검증 오차 |
| 대국의 탐색·NNUE 평가 | CPU | 평가 지연, 전체 탐색 시간, 초당 탐색량 |
| 데이터 처리·저장 | 시스템 RAM·SSD | 전처리 시간, RAM·저장 공간 사용량 |

사용자가 공유한 장비는 HP 2025 OMEN MAX 16, Ryzen AI 및 RTX 5070 Ti 구성이다. 정확한 CPU 모델, 시스템 RAM, GPU VRAM·전력 제한, 운영체제·드라이버·CUDA 환경은 확인하지 않았다. 현재 자체 학습 문서는 NumPy CPU 학습을 설명한다. GPU 학습 시간이나 가능한 최대 모델 크기는 실제 환경 확인과 소규모 측정 후 정한다.

## 4. 단계별 개발·실험 과제

| 단계 | 해결할 문제와 가설 | 작업 | 완료 기준 |
| --- | --- | --- | --- |
| A. 기준 고정 | 비교 조건이 달라지면 개선 원인을 구분하기 어려움 | 기준 커밋·모델·옵션·빌드와 사용 장비 기록 | 같은 조건으로 기존 결과를 재현할 수 있음 |
| B. 평가 정확성 | 증분 계산·정수 표현의 오류가 탐색을 왜곡할 수 있음 | 전체 재계산과 증분 계산 비교, 수 적용·되돌리기와 특수 수 검사 | 동일 계산 규약에서 일치. 부동소수 경로와의 차이는 별도 정량화 |
| C. 학습 파이프라인 | 데이터 품질과 학습 구현이 일반화 성능을 제한할 수 있음 | 기존 학습기 기준 확보, 필요시 PyTorch 또는 Bullet과 작은 실험 비교 | 모델 내보내기·엔진 로딩·출력 교차 검증, 학습 재현 정보 확보 |
| D. 모델 크기 비교 | 용량 증가의 판단 이득이 실행 비용을 상쇄할 수 있음 | 입력·학습 예산을 명시하고 작은 모델과 확장 후보 비교 | 검증 오차·CPU 비용·동일 시간 대국 성적을 함께 보고 |
| E. 자체 데이터 개선 | 국면 다양성과 정답 품질 개선이 용량 증가보다 효과적일 수 있음 | 국면 분포·교사 탐색 예산·샘플링 변경을 각각 실험 | 새 검증 자료와 대국에서 가설 평가 |
| F. 채택과 유지 | 학습 오차 감소만으로는 기력 향상을 입증할 수 없음 | 고정 기준 버전과 후보를 통제 대국으로 비교 | 사전에 정한 채택 기준을 충족한 후보만 승격 |

정확성 검사는 백·흑 점수 관점, 수 적용·되돌리기, 포획, 캐슬링, 앙파상, 승격·승격 포획, 모델 교체를 포함한다. 정수 범위와 오버플로, 학습 프로그램과 엔진의 출력 차이도 확인한다.

현재 스냅샷의 입력에는 킹 위치별 버킷이 없다. 나중에 킹 위치 의존 특징을 도입하면 킹 이동 시 누산기를 전체 재계산해야 하는 범위가 생길 수 있으므로 갱신 규칙과 검사를 함께 바꾼다.

학습 모델·양자화 전체 재계산·증분 계산 사이에서 허용 오차를 각각 정의한다. 서로 다른 계산 규약의 비트 단위 일치를 가정하지 않는다.

## 5. 데이터와 모델 크기 실험 설계

다음 선택은 서로 구분해 비교한다.

| 데이터 선택 | 기대할 수 있는 이점 | 검증할 문제 |
| --- | --- | --- |
| 자체 엔진의 대국과 탐색 평가값 | 생성 조건을 통제하고 반복 생성 가능 | 현재 엔진의 오류·국면 편향을 반복 학습할 가능성 |
| 외부 엔진이 평가한 위치 | 더 강한 교사의 평가값을 활용할 가능성 | 평가 비용, 버전·깊이·점수 관점과 출처 관리 |
| 공개 기보·평가 데이터 | 다양한 위치를 확보할 가능성 | 품질 편차, 중복, 권리·입력 정보 누락과 이용 조건 |

외부 교사의 평가값을 학습에 사용하는 것과 외부 엔진이 실전에서 수를 대신 선택하는 것은 별도 설계 사항이다. 학습 데이터와 실제 수 선택 구현의 출처를 각각 기록한다.

한 대국의 인접 위치나 같은 입력으로 변환되는 위치가 학습·검증·최종 시험에 섞이지 않도록 분할한다. 모델 선택에는 검증 자료를 사용하고, 최종 시험을 본 뒤 설정을 다시 조정하면 새로운 시험 자료를 확보한다.

조용한 위치만 학습할지, 체크·전술 국면을 얼마나 포함할지는 입력·정답·탐색 방식과 함께 실험한다. 공개 데이터의 모든 평가값을 같은 품질로 취급하지 않는다.

크기 비교에서는 입력 특징, 학습 위치 수·배치·반복 횟수·시드, 최적화 방법, 양자화 방식을 기록한다. 같은 데이터와 학습 단계 수를 사용하는 실험과 같은 학습 시간 예산을 사용하는 실험은 질문이 다르므로 구분한다. 특징·용량·정답 생성 방법을 동시에 바꾸지 않는 비교부터 수행한다.

## 6. 검증과 실험 기록

| 검증 축 | 지표 예시 | 해석 범위 |
| --- | --- | --- |
| 평가 정확성 | 독립 계산과의 차이, 별도 자료에서의 평가 오차 | 계산·학습 품질 |
| 실행 성능 | 평가 1회 지연, 전체 탐색 시간, 초당 노드 수 | 해당 장비·빌드·옵션의 실행 비용 |
| 대국 기력 | 승·무·패, 점수율, 불확실성 | 명시한 상대·시작 위치·시간 제한에서의 경기력 |

주 평가는 동일 시간 제한 대국으로 한다. 고정 노드 비교는 탐색량당 평가 효과와 실행 비용을 살피는 보조 실험으로 구분한다. NNUE 활성 여부와 실제 모델을 양쪽 대국 실행기에 명시하고, 시작 위치마다 선후공을 교대한다.

실험에는 최소한 아래 정보를 남긴다.

- 실험 목적과 채택 기준, 기준·후보 코드 커밋 및 모델 SHA-256.
- 상대 엔진 버전, 실행 옵션, 실제 평가 경로와 모델 형식.
- CPU·GPU·RAM, OS·컴파일러·빌드 플래그, 스레드·해시 메모리.
- 시간 제한 또는 노드 제한, 오프닝 집합·해시, 선후공 배분, 대국 수.
- 데이터 출처·버전·해시·분할, 교사 예산, 시드, 학습 환경과 설정.
- 원본 기보·측정 결과, 중단·제외 기준과 실제 제외 사유.

평가 오차 감소나 속도 향상만으로 Elo 향상을 주장하지 않는다. 대국 수와 통계적 불확실성을 밝히며, 엔진 비교 Elo를 인간의 FIDE 또는 Lichess 레이팅으로 직접 환산하지 않는다.

SPRT는 대국 결과가 쌓이는 동안 미리 정한 가설과 오류 확률에 따라 비교를 계속하거나 종료하는 통계적 검증 방식이다. 작은 표본의 우세를 확정적인 향상으로 보고하지 않는다.

공개 자료는 설계·비교·검증과 학습 도구로 활용한다. 직접 작성한 엔진, 외부에서 가져온 코드, 학습 도구, 데이터, 모델 가중치를 별도 항목으로 기록한다. 코드의 공개 라이선스가 모든 관련 가중치·데이터에 자동 적용된다고 가정하지 않는다.
