# SEE: 구현 전에 고정하는 비교 계획

기준은 **Regicide v0.5.1, `1441d5ec23733af570b05521620935619c39cefa`**다. 후보 v0.5.2에는 한 칸에서 기물을 번갈아 잡은 뒤의 손익을 추정하는 **SEE(Static Exchange Evaluation, 정적 교환 평가)**를 수 정렬에만 추가한다. 유리한 교환부터 탐색했을 때 같은 깊이의 계산 비용과 같은 시간의 대국 결과가 어떻게 달라지는지 각각 확인한다. 이 계획은 후보 구현과 측정 전에 커밋으로 고정한다.

## 변경 범위와 정확성

- `UseSEE` 켬/끔 옵션을 두고 기본값을 켬으로 한다. 잡는 수의 순서를 교환 손익에 따라 바꾸되 불리한 교환도 계속 탐색한다. SEE에 따른 가지치기, 수 생략, 깊이 축소, 평가 항목 추가는 하지 않는다.
- PVS, 평가 함수와 기물 위치 점수, 안정화 탐색의 수 범위와 체크 예산, 무승부·반복 판정, 전이표 크기·이력·세대 정책, 시간 관리를 유지한다. 정렬 외의 차이는 새 기능을 정확히 계측·설정하기 위한 인터페이스와 테스트로 한정한다.
- 양측의 기물, 가림 기물 이동 뒤 새로 열리는 공격선, 왕·핀의 합법성, 앙파상·승격 등 특수 수를 검증한다. 기존 규칙·perft·합법 수 차등, 탐색·평가·보드·전이표·UCI·대국·Godot 검증을 유지한다.
- `UseSEE=false` 후보가 기준의 고정 깊이 선택 수·점수·노드·PV·기존 탐색 계측을 재현하는 대조 검사를 둔다. SEE 켬의 수·PV 차이는 동점 수와 실제 점수 차이를 구분하고, 점수 차이는 숨기거나 유리한 위치만 제외하지 않는다. 정렬 변경과 현재 선택적 안정화/전이표의 상호작용을 포함해 원인을 조사한다.

## 재사용하는 시작 위치

이전 PVS 비교와 **동일한** [8개 시작 수순](../../tests/data/pvs_openings_2026-10-18.json)을 사용한다. SHA256은 `e0a6072ecbee74da029d7e57352feac42a24db17df597d592596097429d75c95`다. 백 차례 4개·흑 차례 4개이며, 전체 8개에서 선후공을 바꿔 각 2판씩 **100ms/수 16판**, 같은 전체 8개에서 다시 **1,000ms/수 16판**, 합계 **32판**을 진행한다. 결과를 보고 시작 위치·판수·시간·구현을 조정하지 않는다.

이 수순은 이미 PVS 개발에 사용된 비교 자료다. **새로운 보류 표본이나 독립적인 일반 강도 검증이라고 부르지 않는다.** 같은 조건에서 이전 버전과 차이를 관찰하는 개발 비교이며, 각 시간 조건을 따로 보고한다.

## 고정 깊이 계산 비용

기존 [10개 개발 위치](../../tests/data/profile_positions.json)를 깊이 **3과 4**, 엔진·위치별 **5회**씩 측정한다. 파일 SHA256은 `e0c395ad2d531646c7ccee9d3a156f7580500f59af62186a533a49989e440905`다. 각 묶음 시작의 엔진별 워밍업 **1회**는 기록하되 요약에서 제외한다. seed **20261018**로 위치 순서를 섞고 반복별 기준/후보 실행 순서를 교대한다. 새 대국 신호와 전체 수순으로 전이표의 앞선 대국을 논리적으로 비우며 엔진 프로세스는 유지한다.

깊이별 기준 대 SEE 켬 비용 측정과, 같은 두 깊이의 `UseSEE=false` 대조를 모두 수행한다. 노드·완료 깊이·seldepth·점수·선택 수·PV·전이표 및 SEE 계측·내부 시간·UCI 요청/응답 벽시계를 보존한다. 전체 노드 비율과 쌍별 벽시계 비율을 구분해서 보고한다. SEE 계산 비용 때문에 노드 감소가 곧 시간 감소를 뜻하지는 않는다. 모든 점수 차이와 느려진 위치를 남기고 조사한다.

## 동일 자원과 실행 동결

- 같은 Windows PC에서 같은 MSVC C++20 Release **`/O2 /DNDEBUG`**로 기준 커밋의 별도 소스 아카이브와 후보의 깨끗한 동결 커밋을 각각 재빌드한다. 엔진 소스·도구·설정 커밋, 실제 바이너리 SHA256, 시작 위치 파일 해시, 컴파일러·OS·CPU·RAM·Python·규칙 라이브러리 버전을 기록한다.
- 양측 단일 탐색 스레드, **Hash 16 MiB**, **Move Overhead 20ms**, PVS 켬이다. 요청 100/1,000ms에 내부 할당 80/980ms를 유지한다. 후보의 `UseSEE`를 제외한 실제 옵션을 일치시키고 원자료에 남긴다.
- 시간 대국 전 사전 검색을 하지 않아 첫 표 할당 비용을 포함하고, 프로세스는 묶음 동안 유지한다. 매 수 전체 이력을 전달한다. Python은 통신·합법성·판정만 담당하고 수 선택은 자체 C++ 엔진이 수행한다.
- 현재와 예정 수의 반복/50수 무승부 청구 정책은 항상 청구(`claim`), 최대 **500반수**다. 한도 도달·중단·오류는 정상 완료나 무승부로 바꾸지 않는다.
- 순서는 고정 깊이 비용과 끔 대조 → 100ms 전체 → 1,000ms 전체다. 빌드·Linux 검증·다른 엔진 분석을 동시에 하지 않는다. 기존 사용자 엔진 프로세스의 CPU 스냅샷을 측정 전·중·후 기록한다. 시작 전 연산이 감지되면 임의 종료하지 않고 유휴 상태까지 기다리거나 사용자와 조율한다. 실행 중 부하가 관측되면 영향 구간을 공개하고 기존 결과를 유리한 재실행으로 대체하지 않는다.
- 절전 억제는 실행 중에만 임시 적용하고 정상 종료와 예외 모두 `finally`에서 이전 상태 복구 성공 여부를 기록한다. 영구 전원 정책은 변경하지 않는다.

## 보고와 실패 처리

규칙 정확성, 같은 깊이의 노드·시간 비용, 같은 시간의 관측 완료 깊이와 승·무·패를 구분한다. 시간 대국의 평균 깊이·노드는 서로 다른 진행 위치에서 측정되므로 고정 깊이 가속의 증거로 대체하지 않는다. 내부 시간·벽시계 및 예산 초과 수를 모두 보존한다.

각 시간의 후보 승·무·패와 득점률, 같은 시작 위치의 선후공 2판을 묶은 seed **20261018**, **20,000회** 참고 부트스트랩 구간을 제시한다. 8쌍은 체스 전체의 무작위 대표 표본이 아니므로 일반 강도의 보편적 신뢰구간 또는 Elo로 환산하지 않는다. 개선·열세·불확실성을 그대로 보고한다.

PGN·수별 JSON·PV·옵션·해시·버전·종료 이유·검증 로그를 보존하고 독립 감사기로 시작 위치·선후공·전체 합법 수·최종 FEN·판정·득점·해시·동결 상태를 재계산한다. 실패하면 원본을 덮어쓰지 않고 원인·영향을 기록한다. 수정이 필요하면 변경 내용과 재실행 범위·동결 버전을 먼저 기록하고 해당 전체 묶음을 새 파일로 실행한다. 기존 PVS 원자료와 문서는 수정하지 않는다. 결과를 보고 일부 판이나 위치를 골라 버리지 않는다.
