# v0.6.4 신경망 평가 비용 최적화 사전 계획

기준 코드는 `00dec89b08de4e5f573b18b440a93cd82f4b3311`(v0.6.3)이다. 이 계획은 시간 측정 전에 작성한다.

## 가설과 유지 조건

첫 층의 가중치를 모델을 읽을 때 입력 특징별로 연속 배치하면, 실제 평가에서 메모리 접근과 반복 비용을 줄일 수 있다. 각 뉴런의 bias, 보드 칸 순서, double 덧셈 순서와 ReLU 시점을 유지한다. 둘째·셋째 층, 반올림, V1 점수 제한, V2 수식 평가와 100cp 보정은 유지한다. V2에서 결과에 쓰지 않는 material 합만 생략한다. 정수화·빠른 수학 옵션·증분 합산·학습·가중치 변경은 하지 않는다.

체스 규칙·탐색·학습 데이터·보류 자료·모델 채택 정책 소스는 변경하지 않는다. 영속 시도번호4와 기본 수식 평가 상태를 유지한다. 실행 속도 개선은 새 모델의 채택 근거로 사용하지 않는다.

## 검증 순서

1. 기존 규칙/탐색/평가/학습/서버/화면 자동 검증을 유지한다. v0.6.3의 독립 스칼라 구현과 V1/V2 점수를 정확 비교한다. 임의 합법 위치, 평가 옵션 네 조합, 실제 학습 모델, 상쇄·반올림 경계·승격·보드 불변성을 포함한다.
2. 네이티브 평가 함수 비교: 같은 프로세스에서 이전/새 함수를 별도 번역 단위로 호출하고 LTO를 사용하지 않는다. 학습 V1, 이전 학습 V2, 품질 개선 V2와 출력0 V2를 각각 검사한다. 준비 계산과 모델 읽기는 제외한다. 준비 반복, 고정된 반복 수, 균형 잡힌 순서와 블록별 원자료를 기록한다.
3. 실행 파일 비교: 이전/새 실행 파일 두 개를 지속 실행하고, 같은 모델·옵션·위치·전체 이력·새 논리 대국/빈 TT를 사용한다. 개발용 12위치, 6회 반복, 시드20261019, 깊이3/10,000노드/100ms를 비교한다. 수식 평가 대조군, V1, 두 학습 V2와 출력0 V2를 포함한다. 고정 작업에서 수·정확 점수·PV·노드·완료 깊이·TT 작업이 하나라도 다르면 실패한다. 시간 제한에서는 같은 작업을 요구하지 않고 탐색 노드와 시간을 기록한다.
4. 알려진 브라우저·외부 엔진 부하와 감시 공백을 기존 감시기로 검사한다. 부하가 섞인 전체 블록은 유효한 속도 결과로 사용하지 않는다. 다른 임의 부하·온도·감시 사이의 짧은 프로세스는 완전히 배제하지 못한다. 하드웨어·컴파일러·코드/실행 파일/모델/위치 해시를 남긴다.
5. 측정 후 로컬 실행 파일을 백업하고 v0.6.4를 설치한다. 학습 저장소 바이트, 시도번호, champion 부재, 기본 수식 평가, 소스/실행 파일 해시를 확인한다. 결과를 커밋·푸시하고 Windows/Ubuntu CI를 확인한다.

## 판단

점수와 고정 작업 일치가 우선 조건이다. 평가 함수의 비용과 전체 탐색 비용을 따로 보고한다. 실제 학습 V2의 고정 노드 중앙 시간 비율이1보다 작으면 이 환경에서의 비용 개선 근거로 삼되 위치/반복/블록의 분산도 공개한다. 부하 감지·불일치·실패 결과도 보존한다. 전체 기력 향상이나 Elo는 이 실험으로 주장하지 않는다. 모델 채택 아레나는 수행하지 않으며 기준을 완화하지 않는다.
