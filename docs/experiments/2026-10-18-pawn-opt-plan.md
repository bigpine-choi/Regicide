# 폰 구조 평가 동값 최적화 계획

기준일: 2026-10-18 한국 시간. 기준은 v0.5.6 `09090d0c35aed9ae1643fa1785203ac5b87e678e`이며 실행 코드 커밋은 `132f45451d0af68168cfe15507a3fdc069c86d9c`다. 후보는 v0.5.7이다. 이 계획은 새 시간 측정 전에 고정한다.

## 변경 범위와 가설

통과폰·겹친 폰·고립된 폰과 왕 앞 폰 방패의 점수, 기본값, 국면 혼합·정수 반올림, 탐색·합법 수·특수 규칙을 그대로 유지한다. 새 기능이나 강도 대국은 추가하지 않는다.

기준 구현은 색별 8파일 순회마다 적의 같은/인접 폰 마스크 방향을 반복 변환하고, 파일별 폰 수의 감점과 최전방 랭크의 보너스를 매번 조합한다. 이 중 정해진 입력에 대한 산술과 방향 변환을 작은 constexpr 표에 옮기거나 같은 파일의 중간 결과를 공유하면 함수 비용을 줄일 수 있다는 가설이다. 실제 병목의 비중과 전체 탐색 효과는 측정으로 구분한다. 새 보드 전체 스캔·동적 메모리·이력 캐시·컴파일러 전용 명령·거대 테이블은 도입하지 않는다.

## 정확성·비용 확인

1. 수정 전 v0.5.6 평가 함수를 독립 동결 참조로 보존한다. include·공개 함수 이름 외 수식·제어 흐름을 바꾸지 않는다. 기존 v0.5.4 동결 참조와 독립 scalar 폰 참조도 유지한다.
2. 기존 13,177위치와 추가 마스크 경계 구성에서 방패/구조 네 옵션 모두 동값을 요구한다. 양색, 파일 경계·전방/같은/뒤·고립/겹침 합산·봉쇄, 국면·반올림·승격·앙파상·되돌리기를 포함한다.
3. 기존 Windows/Linux 핵심6종, 독립 규칙2,997사례, UCI23그룹과 대국·형세·추천·핸디캡·보관함 검증을 유지한다. Linux 평가/탐색 ASan·UBSan을 실행한다.
4. 함수 단독 비교는 이미 고정한 자체58위치 `pawn_structure_profile_2026_10_18.fens`를 재사용한다. 별도 번역 단위·LTO OFF, 동일 호출 수, 9블록×4균형 순서로 v0.5.6/후보와 방패 OFF/ON 네 변형을 측정한다. 구조는 ON이다. 시간 전에는 구조까지 포함한 네 옵션과 동결 참조 동값을 확인하고, 시간 중 old/new 체크섬 일치를 요구한다. 이전 기능 ON/OFF 측정과 구분한다.
5. 고정 깊이는 전체10 `profile_positions.json`, Hash16MiB, Move Overhead20ms, seed20261018, warmup1을 재사용한다. 기본 양쪽ON 깊이3/4 각5회와 깊이5 3회(130쌍), 구조OFF·방패OFF·둘다OFF 깊이3 각3회(90쌍), 총220쌍의 수·점수·깊이·노드·최장 깊이·PV·TT 통계를 정확 대조한다. 시간과 노드가 없는 표본은 임의 추정하지 않는다.
6. 테스트/컴파일과 측정은 겹치지 않는다. 프로세스 CPU 누적량을 약500ms 간격으로 표본 수집하고 브라우저·다른 대국 부하 및 신규/종료 프로세스·온도/클럭 관측의 한계를 밝힌다. 무부하나 기력 상승을 추정하지 않는다.
7. 구현 고정 커밋·바이너리·컴파일 설정·측정 명령과 원자료·공개 사본 해시를 보존하고 별도 검토로 수치와 동일성을 재확인한다. 함수 비용 감소와 전체 탐색 시간 변화는 별도로 보고한다.
8. 설치본·바로가기·개인 기보를 로컬 백업하고 검증한 후보를 반영한다. 실제 대국 창·추천과 기보 해시를 확인한 뒤 코드·기록을 커밋·푸시하고 개발/설치/GitHub SHA 및 깨끗한 작업 폴더를 확인한다. 개인 기보·접속 파일·토큰·경로는 공개 증거에서 제외한다.
