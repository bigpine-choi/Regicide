# v0.6.2 신경망 약화 진단과 보수적 보정 계획

2026-10-19 KST. 기준 소스는 `8298d65a41729414014d0146f79daa8a054bd6c9`(v0.6.1)다. 사용자 요청은 약한 신경망의 원인을 분석하고 개선하되 기존 규칙 검증과 모델 채택 기준을 유지하는 것이다.

## 관측과 가설

- 이전 유효 비교는 후보 8승 10무 46패였다. 아레나의 개별 위치·교사 점수·승패를 새 학습 자료나 후보 선택 자료로 가져오지 않는다.
- 코드에서 확인한 V1은 기존 위치 평가 전체를 `기물 점수 + 600*z`로 대체한다. 왕 위치·왕 앞 폰·폰 구조·통과폰에 대한 기존 지식이 신경망에 자동으로 보존되지 않는다.
- 누적 train979개/59판에 학습 파라미터25,153개다. 이전 시험 오차는 기물 점수만의 기준보다 악화됐다. 적은 자료와 일반화 부족은 관측이며 각 패배의 단일 원인이 입증된 것은 아니다.
- 짝수 반수의 시작 뒤 매4반수 표집은 한 차례에 고정된다. 실제 train의 백954/흑25, validation과test 전부 백이었다. 입력은 차례 기준으로 정규화되므로 이를 단순한 색상 버그로 부르지는 않는다. 실제 상대 차례 위치를 거의 뽑지 않는 표집 편향을 고친다.
- 종국 승패20% 혼합은 그 전에 동등하던 위치에도 승패 방향의 점수를 주며, 제한된 대국의 결과와 해당 위치의 전술적 가치가 다를 수 있다.
- 이전 로그의 가중 NPS는 수식516,674/신경망459,378, 평균 깊이는 둘 다4.434였다. 다른 위치이므로 순수 추론 벤치가 아니며 속도 차이가 패배 전체의 원인이라고 단정하지 않는다.

## 이번에 고정하는 수정

1. V1 파일과 수치 경로를 그대로 지원한다. 새 의미의 모델은 `REGICIDE_NN_V2 768 32 16 600 100`으로 명시한다. 기존 파일을 새 의미로 재해석하지 않는다.
2. V2는 `기존 전체 위치 평가 + 100*tanh(z)`를 사용한다. 기존 지식을 보존하고 보정은 폰 한 개(100cp) 범위로 제한한다. V1의 기존±10,000cp 제한은 유지한다. V2는 합법적인 다중 승격 위치에서도 기준 평가를 보존하도록 정적 점수 자체를±10,000cp로 자르지 않는다. 모든 평가에 적용되는 탐색의 메이트 점수 대역 제한과 메이트/무승부 우선 처리는 유지한다. 이 경계 수정은 코드 리뷰에서 발견했고 실제 새 학습/대국 전에 반영한다.
3. V2 출력층을0으로 시작해 epoch0은 기존 평가와 같다. V2 정답은 `tanh(기존 자체 교사의 탐색값/600)`으로 고정하고 종국 승패 혼합을 제거한다. 기보의 실제 승패 라벨은 그대로 보존한다.
4. V2의 가중치 행렬에 L2계수0.0001을 고정한다. 100epoch, 학습률0.003, batch64를 유지하고 검증 MSE로만 체크포인트를 선택한다. epoch0도 후보이며 시험 자료로 설정을 다시 고르지 않는다.
5. 짝수 표집 간격에는 블록별offset0/1을 교대한다. 간격4의 실제 상대 반수는0,5,8,13,…이다. 홀수 간격은 기존 정규 간격으로 이미 차례가 교대한다. 차례만 뒤집고 교사 점수를 부호 반전하는 가짜 표본은 만들지 않는다.
6. 실제32판을 더 수집하고 완료된 기존 자료와 누적한다. 기존 bootstrap 검증96개/시험125개, 전체 수순·해시·누설 배제는 유지한다. 새로운 수집의 보류 계열은 누적 학습에 사용하지 않는다.

위 설정은 새 후보와 새 아레나 결과를 보기 전에 고정한다. 여러 설정을 대국시켜 가장 좋은 것을 고르는 실험은 하지 않는다. 자료 규모 확대·전용 입력·정수 추론·NNUE 누산은 별도 후속 가설이다.

## 검증과 채택

- C++/Python의 전체 수식 기준 평가 일치, V1 수치 호환, V2 경사 수치 미분·보정 범위·모델 파서·옵션·불변 세션을 검사한다.
- 기존 C++ 규칙·수 상태 복원·탐색·평가·SEE·전이표·신경망, 독립 규칙2,997사례, 기존 클라이언트와 Godot 검증을 유지한다. 새로운 기능의 검사와 기존 결과를 구분해 기록한다.
- 기존 `learning_arena.py`, `learning_registry.py`, 예약 시작 위치 파일과 채택 수식은 바꾸지 않는다. 기존 영속 시도 번호2를 이어 다음은3이다.
- 후보와 소스를 고정한 후 새 난수를 뽑는다. 최소32쌍/64판, 수당100ms 이상, 같은 실행 파일·Hash16MiB·단일 스레드·양색 대국·자원 감시를 유지한다.
- `alpha_k=0.05/(k*(k+1))`, 쌍별 Hoeffding 단측하한0.5초과 기준을 그대로 유지한다. 미완료·오염·오류는 무효, 미통과 후보는 미채택이다. 새 모델이 약한 기존 V1보다 개선되는 것과 수식 챔피언을 넘는 것은 별개다.
- 기존 시험 자료는 이미 관측됐음을 밝힌다. 새 수집의 검증/시험 계열은 후보 선택 종료 후 보조 보고에만 사용할 수 있다. 실제 기력 판단은 새 고정 후보의 아레나로 한다.
- 결과와 소스·환경·모델 해시를 보존하고 로컬 설치 후 커밋·푸시, 원격/로컬 동일 SHA와 깨끗한 작업 상태를 확인한다.

일반 학습·추론 개념 참고는 [원저자 저장소의 NNUE 설명](https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md)이다. 이 변경의100cp 보정·자체 수식 기준·표집 방법은 Regicide 자체 설계이며 외부 코드·가중치·기보를 가져오지 않는다.
