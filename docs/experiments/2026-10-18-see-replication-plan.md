# SEE 재현 비교: 새 시작 위치와 외부 엔진 부하 통제

이 계획은 새 위치에서 엔진 평가나 대국을 실행하기 전에 고정한다. 기존 SEE 결과를 보고 엔진을 조정하지 않고, **같은 v0.5.2가 이전 v0.5.1보다 유리한 결과를 다시 내는지** 확인한다. 이전 실험의 기보와 결과는 그대로 보존한다.

## 버전과 변경 범위

- 기준 엔진: PVS v0.5.1, `1441d5ec23733af570b05521620935619c39cefa`.
- 후보 엔진: SEE v0.5.2, `0edc06e437b934d177fc1e9b0907600b6287be72`. 결과 보관 커밋 `6c865e236bd343a57d9be2d8cb6665ecb21043f0`과 엔진 코드는 같다.
- 이전 측정의 바이너리를 그대로 사용한다. 기준 SHA256 `c333ccfa7ec3efbaa7f52df4c007875e64f68d0816a847c1390aa3213d0e427b`, 후보 `2ba41c8303f266149323b55186f5c6a806c33f73d529d6911d6ca4b33bfa53db`를 매 묶음 전후 확인한다. 원래 빌드의 소스·환경·명령은 [기존 기록](2026-10-18-see.md)에 있다.
- 실제 수 선택·평가·SEE·시간 관리·전이표 코드는 바꾸지 않는다. 실험 실행기와 외부 부하 감시·독립 감사·새 데이터·문서만 추가한다. 실험 도구의 깨끗한 동결 커밋은 엔진 소스 커밋과 구분해 기록한다.

## 새 위치와 판수

[새 시작 수순](../../tests/data/see_replication_openings_2026-10-18.json) 8개를 개발자가 손으로 작성한다. 엔진의 평가·추천 수·탐색 결과·승패를 선택에 사용하지 않는다. 구현은 이미 고정되어 있으며, 이 표본은 이번 비교 전에는 후보 검색에 사용하지 않는다. 여러 초반 폰 구조를 포함하고 백 차례 4개·흑 차례 4개를 선택한다.

파일 SHA256은 `e12daff0f80ba3e2a09b2c4e9105f5b897763a777d7a2ede46e40012d2003289`다. 사전 합법성 검사는 이전 JSON 71개·PGN 240판에서 얻은 339개 고유 시작/기준 위치와 대조했고, 새 최종 8위치는 모두 달랐다.

python-chess로 전체 수의 합법성·진행 가능 상태·내부 중복을 확인한다. 이전 시작 위치 파일과 저장된 실험의 선택 위치를 대조해, 기물·차례·캐슬링·유효 앙파상이 같은 최종 위치를 제외한다. 같은 계열의 오프닝을 쓸 수 있지만 이전 위치에 단순히 다른 이름을 붙이지 않는다. 파일 해시는 사전 고정 커밋과 검증 로그에 보존한다.

같은 전체 8개에서 양쪽 엔진의 선후공을 바꿔 **100ms/수 16판**, 다시 같은 전체 8개에서 **1,000ms/수 16판**, 총 **32판**이다. 모든 위치를 파일 순서대로 사용하며, 결과에 따라 판수나 위치를 바꾸지 않는다. 이는 손으로 정한 작은 새 비교 표본이며 체스 전체의 무작위 대표 표본은 아니다. 이후 엔진 조정에 재사용하면 개발 자료로 취급한다.

## 같은 시간·자원·판정

동일 PC와 위 고정 바이너리, 양측 단일 탐색 스레드·Hash 16MiB·Move Overhead 20ms·PVS 켬이다. 후보만 SEE 켬이며 그 외 옵션은 같게 확인한다. 요청 100/1,000ms의 내부 할당 80/980ms를 유지한다. 같은 시간 조건의 기존 비교와 동일한 UCI 통신·수 선택·판정 경로를 사용한다.

시간 대국 전 후보 검색 워밍업을 하지 않아 첫 전이표 할당도 포함한다. 프로세스는 각 묶음 동안 유지하고 매 수 전체 이력을 전달한다. 현재·예정 수의 반복/50수 무승부는 항상 청구(`claim`), 최대 500반수다. 한도 도달·오류·중단을 무승부로 바꾸지 않는다. 요청/내부 할당 초과는 수별로 보존하고, 기존 비교에 없던 별도 강제 몰수 시계를 추가하지 않는다.

## 규칙 검증과 동시 부하 통제

기존 C++ 규칙·탐색·평가·보드·전이표·SEE 검사, 외부 합법 수 차등, UCI·대국·Godot·무르기·핸디캡·기보 회귀를 먼저 다시 실행한다. 통과 요약에 실제 바이너리 해시와 로그 해시를 남긴다. 그 후 빌드·검증·다른 에이전트의 엔진 계산을 끝내고, 100ms 전체 → 1초 전체를 순차 실행한다.

Windows 가상환경 실행기 → 실제 Python → 두 비교 엔진의 계층을 정확히 분류한다. 이름이나 실행 경로가 같다는 이유만으로 다른 프로세스를 소유 엔진으로 제외하지 않는다. 실제 UCI transport의 PID와 생성시각·부모 관계를 교차 확인한다. 감시에는 저비용 운영체제 프로세스/CPU API를 사용하고 약 0.5초 간격 스냅샷과 수·판 경계 확인을 기록한다.

다른 Regicide 및 감지 가능한 알려진 체스 엔진은 시작 전 연속 유휴 상태를 확인한다. 사용자 대국을 닫거나 외부 프로세스를 정지·종료하지 않는다. **측정 중 외부 엔진의 CPU 누적 시간이 한 tick이라도 증가하거나 감시가 실패하면 그 시간 묶음을 유효 결과로 채택하지 않는다.** 새 외부 엔진의 출현이나 기존 엔진의 관측 불능도 안전하게 중단하는 쪽으로 처리한다. 감지까지 계산된 수와 현재 미완료 판을 보존하고 다음 판은 시작하지 않는다.

오염된 묶음은 원본 폴더에 남기고, 유휴 조건이 회복된 뒤 **해당 시간의 전체 16판**을 새 순번 폴더로 재시작한다. 결과가 좋거나 나쁘다는 이유로 재실행하지 않는다. 이미 깨끗하게 완료한 다른 시간 묶음은 다시 고르지 않는다. 모든 시도·오염 이유·재시작·채택 여부를 최종 보고한다. 외부 계산이 계속되면 측정을 강행하지 않고 사용자와 유휴 시간을 조율한다.

최종 채택에는 전 구간의 외부 CPU 관측 증가 0과 정상 감시를 요구한다. 샘플 사이 생겼다 사라지는 프로세스, 다른 앱·열·전력 상태까지 완전히 증명하는 스케줄러 추적은 아니므로 관측 범위를 명시한다. 절전 억제는 실행 중만 임시 적용하고 정상/실패/중단 모두 이전 상태 복구를 기록한다.

## 결과 해석과 독립 감사

100ms와 1초의 후보 승·무·패·득점률을 각각 보고한다. 각 시작 위치의 선후공 두 판을 묶고 seed **20261019**, **20,000회**의 참고 부트스트랩 구간을 제시한다. 이전 재사용 표본 결과와 새 결과는 구분하고 유리하게 합산하지 않는다. 양 조건에서 50% 초과가 다시 관측되면 그 범위의 재현으로, 동률/열세면 재현되지 않은 것으로 보고한다. 작은 표본의 구간이 넓거나 50%를 포함하면 일반적인 우위의 불확실성을 명시한다. Elo로 환산하지 않는다.

평균 완료 깊이·노드·내부 시간·벽시계와 초과 수를 보존한다. 서로 다른 진행 위치의 평균 깊이나 노드를 같은 위치의 탐색 가속 증거로 대체하지 않는다. 이번에는 비용 결과를 다시 선택할 고정 깊이 벤치마크를 추가하지 않는다.

독립 감사는 엔진을 실행하지 않고 실제 수·PV·최종 FEN·결과·선후공·득점·새 위치 해시·엔진/도구 커밋·옵션·바이너리·원자료 해시·부하 감시·시도 기록·규칙 검증 gate를 대조한다. 원자료 JSON/PGN·부하 로그·검증·실행 상태를 줄바꿈 변환 없이 보존하고 개인 대국은 포함하지 않는다. 실행기 오류를 고치면 실패 원본·수정 이유·새 도구 동결 커밋을 기록하고 해당 전체 묶음을 다시 실행한다.
