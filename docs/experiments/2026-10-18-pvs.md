# PVS v0.5.1: 같은 깊이 비용과 같은 시간 대국

기준은 v0.5.0 `8820094588cddadff39bc7cac7c19f92ed522822`, 후보는 v0.5.1 `366aaa4090058ceb1e0bc2232502656f9a5f1e96`다. 사전 계획과 새 시작 위치는 후보 구현 전에 `6ed8b94fd7084726c3b1b8b4ef0b1b4bb5468e44`로 고정했다. 결과를 본 뒤 평가·정렬·시간 관리·시작 위치·PVS 구현을 조정하지 않았다.

**계산 비용은 감소했다. 100ms 표본에서는 우세했고 1초 표본에서는 동률이었다. 일반적인 경기력 향상은 확정하지 않는다.**

## 구현과 의미

정상 탐색의 첫 후보는 기존 alpha-beta 범위를 사용하고, 이후 후보는 1점 폭으로 먼저 검사한다. alpha를 개선하고 beta에 못 미치면 정상 범위로 다시 탐색한다. 예정 수의 무승부 청구 값은 재탐색 판단 전에 반영한다. 안정화 탐색의 전술 범위와 체크 예산, 평가, 수 정렬, 전이표의 이력/세대 정책은 유지했다. `PVS=false` 대조로 기존 탐색 경로를 남겼다. 외부 엔진 코드는 가져오지 않았다.

## 환경과 버전

AMD Ryzen AI 7 350, 논리 CPU 16개, RAM 33,598,976,000바이트, Windows 11, MSVC 19.51.36260.0 C++20 `/O2 /DNDEBUG`, Python 3.13.16 및 python-chess 1.11.2다. 두 엔진 모두 단일 탐색 스레드, Hash 16MiB, Move Overhead 20ms다. 요청 100/1,000ms에서 내부 할당은 80/980ms다. 절전 억제는 실행 중만 임시 적용했고 종료 코드 0 및 이전 상태 복구 성공을 기록했다. 영구 전원 설정은 바꾸지 않았다.

기준 SHA256은 `80b16d9b398c14fff0cd5a780657a87c8278a533c2b5a63db7f4d0614832c591`, 후보는 `7afd48aa37c94380380e324cd2a3bf7acd2a34d0d8e853b8bec216f8b2d50982`다. 기준은 해당 커밋을 git archive로 추출해 재빌드했고 후보는 동결한 깨끗한 체크아웃에서 같은 컴파일 명령으로 재빌드했다. 실행 중인 기존 대국 파일의 Windows 잠금을 피하기 위해 후보 출력 경로만 `build-pvs-native/`로 바꿨다. 기존 대국 창과 개인 기보는 수정하지 않았다.

## 계산 비용

10개 개발 위치 × 5회, 깊이 3·4 각각 50쌍이다. 엔진별 워밍업 1회는 요약에서 제외했고 seed 20261018로 순서를 섞고 기준/후보 순서를 교대했다. 점수 차이는 두 깊이 합계 100쌍 모두 0이다. PVS를 끈 두 대조도 각각 50쌍에서 수·점수·노드·PV·기존 TT 계측을 재현했다.

| 깊이 | 전체 노드 기준→PVS | 전체 노드 감소 | 쌍별 벽시계 가속 중앙값 |
|---|---:|---:|---:|
|3|364,310→262,675|27.90%|1.17875배|
|4|1,723,125→1,046,725|39.25%|1.32511배|

중앙 시간 비율을 시간 감소로 표현하면 대략 15.16%와 24.53%다. 전체 노드 합계 비율과 위치별/쌍별 시간 비율 중앙값은 서로 다른 통계다. 일부 위치는 PVS가 느렸고, 재탐색 비용이 있어 모든 위치의 가속을 보장하지 않는다. PVS 끔 대조의 시간 비율은 약 1.009와 0.997이다.

## 측정 중 관측된 외부 부하

에이전트의 빌드·Linux 검증·다른 분석은 측정 전에 모두 종료하고 비용→100ms→1초를 순차 실행했다. 다만 기존 사용자 대국 창의 엔진 한 프로세스에서 측정 전 누적 CPU 시간 68.8125초가 측정 중 최소 113.25초로 증가(44.4375초 증가)한 것을 감지했다. 사용자에게 비교 중 다른 창에서 수 두기를 쉬도록 안내했으며 에이전트가 해당 창을 강제 종료하지 않았다. 이후 해당 프로세스는 목록에서 사라졌다. 나머지 기존 엔진 세 개는 관측 스냅샷에서 CPU가 고정되어 있었다.

따라서 완전히 배타적인 PC 부하를 확보했다고 주장하지 않는다. 100ms 및 1초 초반 일부 구간에는 사용자 엔진 연산이 겹쳤을 가능성이 있다. 특히 이 구간의 벽시계·시간 대국 수치는 데스크톱 동시 부하와 스케줄링의 영향을 받을 수 있다. 고정 깊이의 노드 감소·점수 일치와 벽시계·시간 대국 결과를 구분한다. 이 사유로 유리한 실행을 골라 대체하거나 이미 완료한 결과를 버리지는 않았다.

## 규칙·회귀 검증

Windows와 Linux에서 규칙 20그룹·8,325검사, 탐색 37그룹·9,451검사, 평가 6그룹·400검사, 보드 10그룹·18,974검사, 전이표 8그룹·97검사를 통과했다. 외부 규칙 차등 2,997사례와 UCI 17그룹, 대국 11/비교 10/비용 9검사를 통과했다. 사용자 대국 25, 핸디캡 19, 기보 20(Windows에서 심볼릭 링크 권한이 없어 1개 건너뜀), 부트스트랩 3검사를 유지했다. Linux Debug ASan/UBSan 탐색도 37그룹·9,451검사 오류 없이 통과했다.

새 PVS 검증은 수 정렬·PVS·TT 없는 작은 완전 탐색과 점수/최적 후보 집합을 대조한다. 전이표 켬/끔, 한 수 뒤 청구, 메이트, 안정화 체크 예산, 옵션/이력/중단 이후 메모리 재사용을 검사한다. 중단 전용 시험은 scout·재탐색 진입 직후 첫 중단 검사에서의 복원을 입증하며 하위트리 중간 중단 전체를 입증한 것으로 확대하지 않는다. 기존 노드/PV 고정 회귀는 PVS를 명시적으로 끈 경로로 보존했다.

동결 후보의 GitHub Actions 39049055626은 Windows·Ubuntu 모두 성공했고 기보·무르기·핸디캡·Godot 장면/실엔진 연결 검사를 포함했다. 원시 로그와 소스/바이너리 해시는 함께 보존한다.

## 시간 대국

사전 고정한 8개 위치 × 선후공 2판을 100ms와 1,000ms에서 각각 실행했다. Python은 전체 수순 전달·규칙 판정만 담당하고 수 선택은 두 자체 C++ 엔진이 수행한다. 반복/50수 무승부는 현재·예정 수 모두 청구하고 500반수 한도·실패 보존을 적용한다.

두 시간 조건에서 각각 16판을 모두 완주했다. 불법 수·오류·미완료·미대국 및 내부/벽시계 시간 예산 초과 수는 모두 0이다.

| 요청 시간/수 | PVS 후보 승·무·패 | 득점률 | 시작 쌍 참고 95% 구간 | 원자료 |
|---|---:|---:|---:|---|
|100ms|9승 4무 3패|68.75%|50.00% ~ 84.375%|[PGN](../matches/2026-10-18-pvs/time100.pgn) / [JSON](../matches/2026-10-18-pvs/time100.json)|
|1,000ms|6승 4무 6패|50.00%|25.00% ~ 75.00%|[PGN](../matches/2026-10-18-pvs/time1000.pgn) / [JSON](../matches/2026-10-18-pvs/time1000.json)|

**고정 깊이 계산 비용 감소는 확인했다. 100ms의 이 표본에서는 우세했지만, 1초 경기력 향상은 확인하지 못했다.** 100ms의 참고 구간 하한도 50%이므로 일반적 강도 향상을 확정하지 않는다. PVS는 개발 후보와 켬/끔 옵션으로 보존하고 현재 바탕화면 대국용 v0.5.0 설치본은 교체하지 않았다.

100ms 평균 완료 깊이는 기준 3.8010 → 후보 3.7887, 1초는 5.8644 → 6.1098이다. 서로 다른 진행 위치에서 나온 평균이며 같은 시간에 항상 더 깊어지거나 더 강해진다는 뜻이 아니다. 평균/최대 벽시계는 100ms에서 기준 81.767/84.499ms·후보 81.746/82.944ms, 1초에서 기준 981.905/983.298ms·후보 981.926/983.168ms다.

독립 감사는 실제 3,296반수와 PV 17,355수를 재생하고 최종 FEN·종료 이유·선후공·득점·버전·옵션·커밋·바이너리 해시·기록 당시 깨끗한 체크아웃을 확인했다. [감사 결과](../matches/2026-10-18-pvs/independent-audit.md)와 [기계 판독 결과](../matches/2026-10-18-pvs/independent-audit.json)를 보존한다. 100ms는 메이트 12/반복 4, 1초는 메이트 12/반복 3/50수 무승부 1이다.

최초 감사 실행은 결과 JSON·Markdown 저장 후 Windows cp949 콘솔의 en-dash 출력에서 실패했다. UTF-8 환경의 재실행은 성공했고 JSON은 SHA256까지 동일했다. 이어 감사기의 구간 표시만 ASCII로 고쳐 기본 콘솔에서도 종료 코드 0을 확인했다. 이 수정은 엔진·벤치마크·대국 원자료를 바꾸지 않으며 결과를 다시 선택한 실행이 아니다. 8개 고정 시작 쌍은 체스 전체를 대표하는 무작위 표본이 아니며 일반적인 강도나 Elo로 환산하지 않는다. 사전 고정 seed 20261018·20,000회 쌍 부트스트랩과 기존 도구의 seed 20261017 요약은 구분한다.

## 원자료와 재현

[전체 증거 폴더](../matches/2026-10-18-pvs/)에는 비용 50쌍씩 4묶음, 32판 기보/수별 JSON, 빌드 조건/소스 해시, 절전 복구/단계 상태, Windows/Linux 검증 로그를 보존했다. [사전 계획](2026-10-18-pvs-plan.md)과 [PVS 원리](../PVS.md)를 함께 읽는다. 동결 엔진 커밋의 [Windows/Linux CI](https://github.com/bigpine-choi/Regicide/actions/runs/39049055626)도 성공했다.

재현은 동결 후보 366aaa4의 별도 깨끗한 체크아웃에서 시작한다. 기준 8820094를 `build-pvs-baseline/source`에 git archive로 추출하고 해당 `scripts/build.ps1`로 빌드한다. 후보는 `scripts/build.ps1 -Test`로 빌드한 뒤 실행 파일을 `build-pvs-native/regicide.exe`에 복사한다(실행 중인 대국의 파일을 덮어쓰지 않는 새 체크아웃을 사용). 테스트용 Python 환경을 준비한 후 실행한다.

```powershell
./scripts/run_pvs_comparison.ps1 -CandidateCommit 366aaa4090058ceb1e0bc2232502656f9a5f1e96
$env:PYTHONIOENCODING='utf-8'
./.venv-tests/Scripts/python.exe tests/audit_pvs_results.py build/pvs-evidence --candidate-commit 366aaa4090058ceb1e0bc2232502656f9a5f1e96 --output build/pvs-evidence/independent-audit.json
```

기존 출력은 덮어쓰지 않는다. 최신 HEAD의 결과 문서·감사 출력 호환성 수정과 동결 엔진 커밋을 구분한다. 시간 기반 대국 수순과 재빌드 바이너리의 타임스탬프/해시는 환경에 따라 달라질 수 있으며, 새 실행은 그 실행의 소스·실행 파일 해시를 별도로 기록한다. 추후 강도 검증에는 더 많은 새 시작 쌍과 배타적인 부하 조건이 필요하다. 이번에는 다른 외부 상대와 Elo를 평가하지 않았다.
