# v0.5.8 보수적인 LMR 개발·검증

기준일: 2026-10-18 한국 시간. [사전 계획](2026-10-18-lmr-plan.md)에 고정한 조건으로 구현·검증했다. LMR은 뒤쪽 일반 수를 한 반수 얕게 먼저 읽고 유망하면 정상 깊이로 확인하는 선택적 탐색이다. 평가식·폰 구조·왕 앞 방패·합법 수와 특수 규칙은 유지한다. [쉬운 원리·설정](../LMR.md)을 함께 읽는다.

## 고정한 코드와 안전 경계

PVS와 일반 수 정렬이 켜진 비PV 노드의 남은 깊이4 이상·다섯 번째 이후·나이트/비숍/룩/퀸의 일반 수만 감축한다. 루트·주요 수순·체크 회피/체크 주기·캡처/앙파상/승격·폰/킹 이동·우선수/두 killer·현재/의도된 무승부 청구·메이트 점수 창은 보호한다. 유망한 감축 결과는 정상 깊이로 재검사해야 한다. 미검증 감축 실패는 best/PV에 채택하지 않는다.

첫 독립 검토에서 서로 다른 깊이를 섞은 실패 상한을 낮은 깊이의 TT 점수로 저장하는 위험을 발견했다. **이 결과의 TT 저장을 완전히 생략**하도록 수정한 뒤 최종 검증을 다시 실행했다. 낮은 저장 깊이가 안전성을 증명하지 못하는 이유와 수정 확인을 [독립 코어 검토](../checks/2026-10-18-lmr/independent-core-review.md)에 남겼다. 수정 전 코드를 설치하거나 비교 결과에 합산하지 않았다.

기본은 켬이며 UCI `UseLMR=false`, 콘솔 `--no-lmr`로 기존 탐색을 선택한다. 실제 감축/정상 깊이 재검사 시도를 두 카운터로 기록한다. 기존 UCI 마지막 TT 정보는 유지하며, 별도 [실험 수집기](../../scripts/lmr_experiment.py)가 각 수의 전체 이력·선택 수·노드·깊이·LMR 계수를 보조 JSON에 기록한다. 원래 비교 실행기의 PGN/JSON과 종료 코드는 유지한다. 구버전에 없는 통계는 `null`이며 0으로 추정하지 않는다.

## 같은 깊이의 계산 비용

Ryzen AI 7 350, 16논리CPU, Windows, 단일 탐색 스레드, Hash16MiB, Move Overhead20ms다. 기존 전체10위치 `profile_positions.json`, 깊이별3회·warmup1·seed20261018을 사용했다. 표본은 각 검색의 TT 기록을 초기화하고 버퍼 메모리만 재사용한다. 쌍 안의 실행 순서는 고정 시드로 섞는다. UCI 거래 시간은 엔진 프로세스 기동을 제외하고 검색 초기화·입출력을 포함한다.

**v0.5.7 대 v0.5.8 LMR OFF:** 깊이3/4/5 각30쌍, 총90쌍에서 수·점수·깊이·노드·seldepth·PV·TT 카운터가 전부 같았다. 새 기능을 끄면 기존 검색 그래프를 재현했다.

**같은 v0.5.8의 LMR OFF 대 ON:** 깊이5/6 각30쌍을 비교했다. ON은 선택적 탐색이므로 점수 차이를 허용하도록 미리 정했다. 이번60쌍에서는 점수 차이가 없었지만 보편적인 동값을 증명하지는 않는다.

## 같은 시간 대국과 배포

기준 v0.5.7 기본 설정 대 후보 v0.5.8 LMR ON을 새 자체8시작 수순에서 선후공을 바꿔 비교했다. 양측200ms/수·Hash16MiB·Move Overhead20ms·단일 탐색 스레드·claim 무승부 정책·최대300반수로 고정했다. 4개 시작점은 백 차례, 4개는 흑 차례이고 모든8개를 사용했다. 이미 중단했던 v0.5.0/v0.5.3 대국 비교를 재개한 것이 아니다.

**새 후보는 4승6무6패, 7/16점(43.75%)**이었다. 모두 실제 체크메이트/반복 등 규칙으로 종료했고 미완료0·불법 수/엔진 오류0이었다. 선택 수는 양측 각723회이며 후보의 감축 시도84,420회·정상 깊이 재검사649회가 기록됐다. 16판 전체 PGN과 각 검색의 이력·수·노드·깊이·계수를 보존한다.

이 표본은 기력 향상 가설을 지지하지 않는다. 동시에 8개 고정 시작점의 작은 표본이므로 일반적인 기력 저하나 Elo 변화도 확정하지 않는다. 고정 깊이6의 비용 감소와 같은 시간 대국의 성적은 구분한다. 표본을 본 뒤 조건이나 시작점을 골라 재경기하지 않았다. 더 긴 시간·새 보류 시작점·독립 외부 상대 검증은 아직 수행하지 않았다.

컴파일·회귀 검사와 시간 측정/대국을 겹치지 않았다. CPU 표본에서 검색71.33초 동안 브라우저6.328 CPU초, 대국270.40초 동안 **브라우저1,265.141 CPU초**가 관측됐다. 대국의 관측 전체1,633.016 CPU초, Regicide225.859 CPU초이며 Regicide 합계에는 비교용 두 엔진이 포함된다. 대국 중 브라우저 부하가 상당했으므로 전용 무부하 환경의 기력 비교로 표현하지 않는다. 16논리CPU의 여러 코어에 걸친 누적량이므로 CPU초는 벽시계 시간보다 클 수 있다. 새로 시작/종료·접근 불가 프로세스, 온도·클럭과 부하가 수 선택에 미친 영향은 완전히 관찰하지 못하며, 패배를 부하 탓으로 단정하지 않는다.

독립 감사13,222항목은 실패0으로 통과했다. OFF90쌍·ON60쌍, 16판 전체 합법 수/종료, 각 역할723회의 검색과 총1,446개 보조 기록의 전체 이력·선택 수·노드·깊이·시간·카운터가 서로 대응했다. [감사 보고서](../checks/2026-10-18-lmr/independent-lmr-audit.md)는 정합성의 통과이며 기력 상승 판정은 아니다.

요청에 따라 개발 후보 v0.5.8을 로컬 `desktop/conservative-lmr`에 반영했다. 기존 실행 파일·바로가기·개인 기보144파일을 백업하고 백업 사본 및 기존144파일의 해시가 모두 일치함을 확인했다. 실제 대국 창의 버전과 backend 소스/실행 파일 식별자를 확인하고, 초기 위치에서 Nf3 추천 문구·화살표와 ON/OFF를 직접 확인했다. 마지막 상태는 착수0·추천 OFF·오류없음이며 UCI 기본 `UseLMR=true`다. [공개 설치 확인](../checks/2026-10-18-lmr/installation-verification.json)에 개인 경로/기보 없이 결과를 보존한다. 기존 실행 파일과 Git 기준 버전은 백업/이력으로 보존하며, 기력 향상 미확정인 개발 후보라는 상태를 유지한다.
