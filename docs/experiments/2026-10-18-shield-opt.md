# v0.5.5 폰 방패 효과를 유지하는 평가 최적화

기준일: 2026-10-18 (한국 시간). 기준은 `07321d8b27b95dad9a1fc66c9170ab8085829868`의 v0.5.4, 후보 엔진·검사·프로파일 소스는 `9dce742339428a4d3a449494f7284b6f66d9d7d6`이다. [사전 계획](2026-10-18-shield-opt-plan.md)에 따라 원본 점수와 탐색 결과를 유지하는 비용 최적화를 했다. 외부 엔진 코드·점수 표·가중치를 가져오지 않았다.

## 확인한 비용 원인

이전 v0.5.4 OFF/ON 비교에는 평가 변경에 따른 다른 탐색 트리와 평가 한 번의 추가 비용이 섞여 있었다. 기존 기록의 French 위치는 깊이3 노드가 OFF 8,700에서 ON 14,297로 늘었고, Sicilian 위치는 6,375에서 5,209로 줄었다. 이는 정적 점수가 바뀐 결과이며, 같은 효과를 유지하는 이번 최적화에서는 이 노드 차이를 없애지 않는다.

함수 자체는 기물 분류에 `std::tolower`를 반복하고 기물 위치 수식을 매번 계산했다. MSVC 19.51의 실제 `/O2 /GL-` 어셈블리에서도 소문자 변환 호출이 남았다. 호출 분기로 산출하면 방패 OFF는 기물당 3회, ON은 폰 4회·나머지 기물 5회이며 초기 위치는 96회 대 144회다. 이것은 컴파일된 호출 경로로 산출한 수이며 동적 계수 추적 결과가 아니다. GCC의 같은 호출 횟수라고 일반화하지 않는다.

같은 보드만 평가하는 별도 프로파일에서 Windows의 기존 ON/OFF 대응 비용 비율은 중앙 1.28172였다. 보드 생성·I/O·탐색을 뺀 이 입력 집합에서도 방패 ON 비용이 늘어나는 것을 확인했다. 추가 변환 호출뿐 아니라 방패 정보 누적·국면 처리·분기도 포함하므로 한 가지 명령의 단독 비용이라고 해석하지 않는다.

## 바꾼 부분과 보존한 부분

- 기물 문자→종류·색·기물 가치·국면을 작은 constexpr 표에서 한 번 조회한다.
- 기존 자체 수식의 6종×64칸 중반 기본점수·종반 점수·미전개 보정 계수를 컴파일할 때 계산한다. 룩·퀸의 실제 미전개 기물 수 보정은 기존 계수로 적용한다.
- 표는 해당 MSVC/GCC 환경에서 합계 6,656바이트다. 실행 중 동적 할당·보드 캐시는 추가하지 않았다.
- 왕 앞 폰 거리의 0/4/8/12cp, 상대 국면/12 감점, 전체 국면/24 혼합, 양색 점수 합산·정수 나눗셈·부호 순서를 유지한다. 탐색·규칙·시간 할당·노드 제한은 바꾸지 않는다.

기준 평가 원문은 `tests/reference_evaluation_v054.cpp`에 include와 공개 함수명만 바꿔 동결했다. 새 평가의 기물 표나 수식을 참조 오라클에 재사용하지 않는다. 비교용 `UsePawnShield`, `--no-pawn-shield`, `UsePositionalEvaluation` 정책도 같다.

## 평가 함수 단독 프로파일

`tests/data/evaluation_profile_2026_10_18.fens` 42위치를 시간 관측 전에 고정했다. 기존 프로파일 10위치와 색 반전, 자체 방패·종반·특수 위치로 구성한다. 보드는 미리 생성하고 서로 다른 번역 단위의 이전 OFF/ON·후보 OFF/ON을 LTO 없이 호출한다. 각 10,000회 준비 후 이전 ON으로 동일 호출 수를 한 번 정한다. 9블록마다 ABCD/DCBA/BADC/CDAB 네 순서를 모두 실행해 변형별 순서를 균형화한다. 각 실행은 144개 원시 샘플이며 시간 안에는 평가 호출·입력 순환·체크섬 누적만 들어간다.

| 별도 환경 | 기존 ON 중앙 ns/회 | 후보 ON 중앙 ns/회 | 대응 블록의 후보/기준 비율 중앙 |
| --- | ---: | ---: | ---: |
| Windows MSVC `/O2 /GL-` | 236.80 | 88.13 | 0.37423, 약 62.58% 감소 |
| WSL2 GCC `-O2 -fno-lto` | 139.82 | 96.38 | 0.67315, 약 32.69% 감소 |

ns/회의 중앙값과 블록별 비율의 중앙값은 서로 다른 집계이므로 위 두 시간의 단순 나눗셈과 비율 열에 차이가 날 수 있다.

각 실행에서 84개 사전 점수 비교의 불일치가 0이었고, ON/OFF 각각 이전·후보의 모든 시간 측정 체크섬이 일치했다. 이 84개 비교는 개별 점수 모두를 로그에 저장하지 않고 불일치 목록을 저장한다. 독립 감사는 Windows 144개 샘플의 순서·체크섬·비율을 원자료에서 재계산하고, 별도 scalar 평가 수식으로 기대 체크섬을 대조했다. 더 넓은 동값 근거는 위 16,860개 보드의 독립 원본 오라클 검사다.

OFF도 빨라진 공통 평가 경로 최적화다. 후보 ON/OFF의 상대 비율이 Windows 1.42461, GCC 1.49876으로 여전히 1보다 크다는 사실은 방패가 공짜가 됐다는 뜻이 아님을 보여준다. 새 ON이 이전 ON보다 빠른 것과 ON/OFF 상대 비율을 혼동하지 않는다. 평가 단독 감소율을 전체 탐색이나 기력으로 환산하지 않는다.

## 같은 결과의 전체 탐색 비용

기존 `profile_positions.json` 전체 10위치, Hash16, Move Overhead20, warmup1, seed20261018, 양쪽 같은 방패 옵션으로 실행했다. ON은 깊이3/4 각각5회, OFF는 깊이3 3회다. 총130쌍 모두 수·점수·깊이·seldepth·노드·PV·TT 정보가 정확히 일치했다.

| Windows 조건 | 쌍 수 | 후보/기준 벽시계 비율의 중앙 | 후보가 느린 쌍 |
| --- | ---: | ---: | ---: |
| 방패 ON, 깊이3 | 50 | 0.92761, 약 7.24% 감소 | 6 |
| 방패 ON, 깊이4 | 50 | 0.93894, 약 6.11% 감소 | 11 |
| 방패 OFF, 깊이3 | 30 | 0.93554, 약 6.45% 감소 | 5 |

이 표는 원시 `후보 시간/기준 시간` 쌍별 비율의 중앙이다. 짝수 표본에서 도구가 출력하는 `기준/후보 중앙`의 역수와 아주 작은 차이가 날 수 있다. 독립 감사는 130쌍과 양 엔진 PV 942반수를 공통 도구 함수 없이 재생·대조했다. 느린 22쌍과 모든 원자료를 보존했고 결과에 따라 표본·반복 수·계수를 바꾸지 않았다.

## 환경·한계·배포

주 측정 PC는 AMD Ryzen AI7 350 / 16논리 CPU다. Windows 평가/탐색 측정 중 프로세스 CPU를 약500ms 간격으로 샘플링했다. 브라우저 작업이 각각 약1.27/3.94 CPU초 관측됐고 모니터 자체 비용도 있어 완전한 외부 부하 통제라고 주장하지 않는다. WSL 프로파일의 Windows 측 부하 샘플은 후반부 일부만 덮으며 VM 내부 전체 부하를 측정하지 않는다. 주파수·열·스케줄링도 통제하지 않았다. 특히 짧은 탐색의 통신·OS 잡음과 반복된 개발 위치의 일반화 한계가 있다. 같은 깊이에서 빨라졌다는 결과이며 같은 시간 대국의 강도 증거가 아니다.

검사·프로파일·어셈블리·원자료·환경·독립 감사·해시는 [검증 폴더](../checks/2026-10-18-shield-opt/)에 보존했다. 공개 복사에서는 사용자 로컬 경로만 `$REPO`/`$BASELINE_REPO`로 바꿨다. 원본과 상세 배포·기보 백업 기록은 ignored 로컬 빌드 폴더에 남긴다.

검사한 Windows 실행 파일 SHA256은 `002b0875a3ecdc5298e060902f4e9578addbd3798242c7ff34dce054bf82aaa1`이다. 이전 실행 파일·바로가기·기보를 백업하고 로컬 v0.5.5로 반영했다. 바탕화면 바로가기에서 버전과 추천 ON·화살표·OFF를 확인했으며 자동 착수는 없었다. 이전 기보 파일128개의 원본/백업 해시를 대조해 보존했다. 문서·증거 후속 커밋은 엔진 코드를 바꾸지 않는다.

재현은 `scripts/build.ps1 -Test`, Python `tests/differential.py`·`tests/engine_integration.py`와 기존 대국 검사를 실행한다. 평가 프로파일은 `scripts/profile_evaluation.ps1` 후 `build-shield-profile/profile_evaluation.exe --fen-file tests/data/evaluation_profile_2026_10_18.fens --output 새파일.json`으로 실행한다. GCC는 `-O2 -fno-lto`로 `scripts/profile_evaluation.cpp`, `tests/reference_evaluation_v054.cpp`, `src/evaluation.cpp`, `src/board.cpp`를 `-Iinclude -Itests`와 별도 번역 단위로 연결한다. 고정 깊이 명령·부하 모니터·Linux 검증 스크립트도 검증 폴더에 남긴다.

**판정: 폰 방패 점수·규칙·고정 깊이 탐색 결과를 유지하며, 이 표본에서 평가 함수와 전체 탐색 비용을 줄였다.** 기존에 중단한 강도 대국 비교는 재개하지 않았고 기력 상승·Elo는 검증하지 않았다.
