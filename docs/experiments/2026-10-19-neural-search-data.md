# 2026-10-19 자체 탐색 학습 자료 생성기

## 결과

자체 실전 수순과 합성 종반을 모아 자체 고정 노드 탐색의 점수를 저장하는 생성기와 엄격한 로더를 구현했다. 최종 확인에서 **학습 49개·검증 22개**, 합계 **71개 고유 입력**을 얻었다. 12기물 이하 위치는 학습 21개·검증 11개다. 같은 조건의 두 번 생성에서 학습·검증 JSONL의 바이트와 수순·정답 의미 해시가 정확히 일치했다.

이번 작업은 자료 생성의 정확성과 비용 확인이다. 모델 학습·모델 교체·기력 대국·승률 또는 Elo 추정은 수행하지 않았다. 현재 1/32 모델과 기존 평가기는 그대로다. 기존의 게임 중 생각 시간 설정 변경과 장시간 대국 기록 등 미커밋 작업도 이번 구현에서 수정하지 않았다. 커밋·푸시는 요청되지 않아 수행하지 않았다.

## 구현

- `scripts/neural_search_data/`: 설정과 상한을 먼저 기록하고 자체 UCI 탐색으로 수를 둔다. 초기 FEN·전체 수순·원래 위치의 탐색 점수·깊이·노드·PV·원시 송수신을 보존한다.
- `seeds.json`: 정상 시작의 자체 작성 4반수 예시 4계열, 직접 작성한 8~9기물 종반 4계열. 합성 종반은 실제 기보에서 추출한 위치와 구분한다. 외부 엔진·기보·모델·테이블베이스는 쓰지 않는다.
- whole-family 분할은 생성 전에 source kind별로 수행한다. 기존 v2 입력에 맞춰 기물 배치와 색·랭크 반전의 중복을 학습·검증 전체에서 제거한다. FEN·수순 해시는 별도로 남긴다.
- cp 정답만 백 관점으로 변환한다. mate·bound·깊이 0·외부 중단·불법 PV·노드 상한 위반은 학습에서 제외한다. 체크·잡는 수·승격과 샘플 간격·중복도 제외 사유를 기록한다.
- 매 검색에서 TT를 초기화하고, 노드 제한에 별도 벽시계 제한을 둔다. python-chess의 노드 제한 검색에는 기본 timeout이 적용되지 않으므로 비동기 제한과 프로세스 정리를 추가했다.
- 반수·예산으로 중단한 게임은 결과를 `null`로 남긴다. 실제 종료한 게임만 `outcome(claim_draw=True)`로 결과를 기록한다. 부분 게임의 완료된 검색 정답을 보존해도 WDL을 추정하지 않는다.
- 원래 정적 평가의 대조값은 `classical_static_stm_cp`/`classical_static_white_cp`, 탐색 정답은 `search_stm_cp`/`target_white_cp`로 구분한다. 새 schema 2를 기존 정적 schema 1로 위장하지 않는다.
- 단순 SHA뿐 아니라 수순·검색·정답·분할·중복·타입·점수 관점의 연결을 검증한다. 기존 출력은 덮어쓰지 않는다. 새 CI 파일은 단위 검사와 작은 실제 엔진 확인을 실행하도록 설정했다. 원격 CI 실행은 아직 확인하지 않았다.

## 사전 고정 조건

최종 실행 전 [protocol.json](../checks/2026-10-19-neural-search-data/final/protocol.json)에 확정했다. 동작 확인 후 검증 점수를 보고 설정을 바꾸거나 좋은 위치만 골라내지 않았다.

| 항목 | 최종 확인 조건 |
|---|---|
| 시작 자료 | 8계열 전부, 계열당 1게임 |
| 교사·수 선택 | 자체 기존 평가기 + 자체 탐색 |
| 검색 | `go nodes 10000`, 시간 검색 혼용 없음 |
| TT | 검색마다 새 game token |
| 최대 반수 | 게임당 48반수 |
| 채집 | 생성된 0, 3, 6, … 반수의 원래 위치 |
| 상한 | 실행당 384검색·384만 노드·120초, 검색당 10초 |

하드웨어는 AMD Ryzen AI 7 350, 8코어·16논리 프로세서, 메모리 약 32GB이며 Windows 11에서 Python 3.13.16/chess 1.11.2를 사용했다. 엔진은 단일 프로세스로 순차 실행했다. 다른 프로그램의 CPU 사용을 격리하거나 감시한 성능 실험은 아니므로 시간은 이 PC에서 관측한 생성 비용이다.

실행 파일 SHA256은 `598ebec433334b2ce053d0ed6b143fbfd34f9dd3a76557adb62764dcd940c705`다. 기존 정밀도 단계의 실행 파일을 재사용했으며 새 C++ 빌드는 하지 않았다. [기존 빌드 증거](../checks/2026-10-19-neural-precision/build-provenance.json)의 14개 파일 SHA를 모두 다시 확인했다. 현재 체크아웃 HEAD `5ff2074aa142f915260739a8f0f3c2ddb8586ee5`와 소스 SHA·dirty 상태는 별도 기록이며 이를 실행 파일 빌드 커밋으로 주장하지 않는다.

현재 학습 모델 SHA256은 `c9ca5f35bb0ef0f61fca9b7eba10cd01d4320cf6c2a1dd4863630b7f87baaa92`로 유지됐다. 파일·옵션·소스·환경의 상세값은 각 실행의 plan/manifest와 [verification.json](../checks/2026-10-19-neural-search-data/verification.json)에 있다.

## 검사 범위와 증거

- 새 단위검사 **40개 통과**: 루트 점수 관점, 메이트·bound 구분, depth 0 fallback, 합법 전체 수순, 캐슬링·앙파상·승격 이력 전송, 반복 이력, family·반전 중복, 재해시한 거짓 정답·수순·제외 사유·bool 정답 거부, 미완료 결과와 timeout 프로세스 종료, 기존 출력 보호. 일부는 의도적으로 작은 가짜 UCI 프로세스와 합성 fixture를 사용한다.
- 기존 학습 단위검사 **7개 통과**. 기존 데이터·학습 경로를 수정하지 않았다. 전체 C++/UI 테스트나 새 모델 학습은 이번에 다시 수행하지 않았다.
- 최종 실제 엔진 2회: 각 원시 UCI 마지막 info의 점수·깊이·노드·PV·bestmove를 파싱해 JSON과 대조했다. 매번 새 TT·노드 명령·전체 position history를 확인했다. 엄격한 로더로 수순·표본·분할을 다시 검사하고 JSONL 바이트 일치를 확인했다.
- 작은 CI 조건도 로컬에서 2회 실행했다: 2,000노드·24반수, 실행당 192검색. 학습 39·검증 14개가 재현됐으며 2.38/2.08초였다. 이는 별도 정확성 smoke 자료로 최종 데이터와 합치지 않는다.
- `pilot/`는 최종 전의 첫 확인 기록이다. 최종 전송 기록 대조 강화와 빈 PV fallback을 읽는 로더의 일관성 수정 전의 시도를 그대로 보존했다. 최종 기준은 `final/`이며, canonical 학습 자료 경로는 `final/first/`다.

## 해석과 다음 단계

종반 자료 공백과 백 차례만 채집하던 편향을 작은 확인 자료에서 해소했고, 정적 평가와 구분되는 자체 탐색 정답을 재현 가능하게 저장할 수 있게 됐다. 71개 표본과 8계열은 학습 규모나 일반화 성능을 판단하기에 부족하다. 낮은 노드 예산, 합성 종반, 자기대국의 반복 무승부, 조용한 위치 필터는 자료 편향을 남긴다. 가족 분리와 완전 중복 제거만으로 모든 유사 위치가 독립되는 것도 아니다.

현재 v2 입력에는 실제 손번·권리·반복 이력이 없으므로 탐색 정답의 일부 상태 의존성을 설명하지 못한다. 새 schema 2는 기존 정적 학습 로더에 직접 넣지 않는다. 새 로더의 `fen`/`target_white_cp` 행을 기존 포장 함수로 연결할 수 있는 상태이며, 실제 학습 명령 확장과 동일 데이터의 정적 정답/탐색 정답 대조 학습은 다음 작업이다. 이 확인용 검증 자료로 설정을 계속 선택한 뒤 새 보류 성능이라고 부르면 안 된다.
