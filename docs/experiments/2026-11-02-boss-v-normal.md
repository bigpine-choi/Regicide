# 보스 대 앱 기본 모드: 16판 직접 비교

2026-11-02 KST. **이번 맞대결은 보스 7승 7무 2패, 10.5 대 5.5점으로 보스 우세**였다. 보스의 득점률은 65.625%다. 고정된 8개 시드의 선후공 교대 16판이며, 이 결과만으로 다른 생각 시간·개시·상대에서도 보스가 항상 더 강하다고 확정하지 않는다.

9판은 체크메이트, 6판은 청구 가능한 3회 반복, 1판은 기물 부족 무승부로 끝났다. 오류·불법 수·미완료는 0판이다. 300반수 제한이나 엔진 점수로 결과를 임의 판정한 판은 없다. 본 대국의 최초 시작부터 마지막 종료까지 약11분35초였으며, 4개 그룹을 병렬 실행한 경과시간이다. 준비·사전 검사·보관 시간은 제외한다.

선후공 두 판씩 묶으면 보스 우세 4쌍, 열세 0쌍, 동률 4쌍이다. 동률을 제외한 양측 exact sign test는 p=0.125이며, 독립적·교환가능한 쌍이라는 가정 아래의 보조 통계다. 8쌍 기준 보수적인 Hoeffding 95% 범위도 약17.61~100%로 넓다. 이번 표본의 점수 우세는 관측했지만, 일반화된 기력 우세를 정밀하게 인증하는 규모는 아니다. Elo로 환산하지 않는다.

## 무엇을 비교했는가

[실행 전 계획](2026-11-02-boss-v-normal-plan.md)에 따라 생산 코드를 바꾸지 않고 실제 앱의 두 `HumanGame` 경로를 사용했다. 생성자 설정은 양쪽 모두 오프닝 다양성과 활동적인 수 선택을 켰다. 실제 정책은 보스 설정에 따라 보스 정책 또는 기본의 dynamic 정책이 우선 적용된다. 기본의 dynamic 정책 내부에 오프닝 처리가 있으므로, 최종 기록의 별도 opening enabled가 false여도 오프닝 기능이 꺼진 비교는 아니다.

동일한 Regicide 0.7.0-dev 바이너리, 고전 평가, `UsePieceActivity=true`, Hash 16MiB, 단일 스레드를 사용했다. 신경망이나 외부 엔진은 실제 수 선택에 사용하지 않았다. 화면 평가·힌트용 보조 엔진만 검색 없는 표시용 대체물로 비활성화했다. 매 수 양쪽 호스트의 전체 이력·보드와 독립적인 규칙 보드를 대조했다.

양쪽 화면 기준 생각 시간은 1000ms다. 기본은 초반 추가 최대1000ms, 중반 추가 최대500ms를 사용할 수 있고, 보스는 조건에 따라 관찰·갬빗/미끼 검사에 합계 최대1000ms를 더 쓴다. **같은 앱 시간 설정의 비교이며, 동일 실제 CPU 시간을 통제한 비교는 아니다.** 추가 검증과 시간 배분도 현재 모드의 동작에 포함했다.

| 모드 | 실제 착수 횟수 | 평균 처리 경과시간 | 중앙값 |
| --- | ---: | ---: | ---: |
| 보스 | 952 | 1192.81ms | 1159.48ms |
| 기본 | 948 | 1269.87ms | 1086.93ms |

이는 `engine_move` 호출의 경과시간으로 자체 저장 비용을 포함한다. 상대 호스트에 수를 전달한 시간은 별도로 기록했다. CPU 시간이나 탐색 속도 측정이 아니며, 서로 다른 국면의 평균 비용만으로 실행 효율 개선을 주장하지 않는다.

모든 판은 표준 시작 위치였다. 강제 오프닝을 쓰지 않고 사전 고정된 8개의 시드 쌍을 사용했으며, 각 쌍에서 모드별 시드를 유지하고 선후공을 바꿨다. 마스터 시드는 `20261102boss-v-normal-v1`, pair ID는 1~8이다. 실제 시드와 수순은 원자료에 있다. 고정 시드라도 시간 제한과 공유 PC 부하 때문에 동일 기보의 결정적 재현은 보장하지 않는다. 중간 결과에 따라 판수를 늘리거나 줄이지 않았다.

환경은 Ryzen AI 7 350, 8코어·16스레드, RAM 약31.29GiB, Windows, Python 3.13.16, python-chess 1.11.2다. 기존 사용자 게임을 종료하지 않았으며 호스트의 전체 부하·열을 격리한 실험은 아니다.

## 갬빗이나 미끼 때문에 이겼는가

보스는 **952수 중 942수(98.95%)에서 자기 기준 탐색의 수를 유지**했다. 다른 10수는 모두 오프닝 도입이었고 실제 갬빗 희생 성립은 0회였다. 41턴에서 미끼 후보/포획 분기 82개를 검토했다. 10개는 희생 비용 비교가 불충분해 제외했고, 포획 후 검색까지 진행한 72개는 짧은 전술 이득을 증명하지 못했다. **검증 미끼 선택과 실제 미끼 포획은 0회**였다.

기본은 948수 중 899수(94.83%)에서 자기 기준 탐색 수를 유지했고, 오프닝 대안 37회·중반 활동적 대안 12회를 선택했다. 보스가 기준수를 더 자주 유지했다는 관측은 가능하지만, 이를 승리 원인으로 확정하지 않는다. 예를 들어 11번 경기에서 기본은 72수 모두 자기 기준수를 유지했는데도 졌고, 4번 경기에서는 보스가 60수 모두 기준수를 유지했는데도 졌다. 같은 국면·탐색 상태에서 선택 정책 하나만 바꾼 원인 분리 실험은 하지 않았다.

결론은 **현재 앱 설정의 이 16판에서는 보스가 앞섰다**는 것이다. 함정 특화가 승률을 높였다거나 사람을 더 잘 속인다는 결과는 아니다. 우세 원인을 좁히려면 별도로 오프닝 선택·활동적 대안·상대 관측의 효과를 하나씩 통제해야 한다. 이번에는 짧은 직접 비교 범위를 지켰으며 추가 실험이나 모드 정책 수정은 하지 않았다.
