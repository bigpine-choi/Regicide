# 전이표 메모리 재사용: 사전 검증 계획

비계측 벤치마크와 대국 결과를 보기 전에 엔진·도구·이 계획을 커밋해 고정한다. 기준은 검색마다 전이표를 만들던 **v0.4.0**, 소스 `ef52f14569222acbfaa512245bab81558795180f`다. 개선 **v0.4.1**은 이 계획을 포함한 코드 커밋으로 고정한다. 평가 계수, 안정화 탐색, 기존 전이표의 점수·경계값·깊이 정책과 기본 Hash 16 MiB를 유지한다.

## 구현 가설

같은 크기의 전이표 저장 공간을 UCI 세션 동안 재사용하고, 각 탐색마다 세대 번호를 바꾸면 전체 배열 초기화 비용을 피할 수 있다. 이전 점수·최선 수는 재사용하지 않는다. 슬롯의 세대가 현재 탐색과 다르면 빈 슬롯으로 취급한다. 따라서 옵션·반복 이력·시간 한도가 달라져도 이전 탐색의 값이 섞이지 않아야 한다.

- 최초 사용과 실제 Hash 크기 변경은 새 할당이며 탐색 예산에 포함한다.
- `ucinewgame`과 `Clear Hash`는 메모리를 유지하고 논리적으로 기록을 지운다.
- 세대 번호가 돌아오는 경계에서는 물리적으로 전체를 지워 오래된 기록의 재등장을 막는다.
- TT 비활성 중에는 보유 메모리를 읽지 않는다. 보드·반복 규칙 구현은 변경하지 않는다.
- 전이표 슬롯의 크기·용량·주소 계산을 유지하면 고정 깊이의 점수뿐 아니라 노드·수·PV·TT 작업량도 같아야 한다.

## 정확성

기존 규칙/perft 8,325개, 외부 기준 2,997사례와 모든 기존 탐색·평가·대국 도구 검증을 유지한다. 세대별 무효화·오래된 깊은 기록의 교체·세대 순환·예외·크기 축소를 추가한다. 재사용한 컨텍스트와 새 컨텍스트를 비교해 반복 이력·FEN·50수 카운터·평가/안정화/TT/빠른 적용 옵션·Hash 크기·중단 경로의 수·점수·완료 깊이·노드·PV·TT 작업량이 일치하는지 확인한다.

UCI에서는 반복 짧은 검색의 최초 할당 1회와 후속 재사용, Clear Hash·새 대국·옵션 변경 중 작업 합류, 종료·비활성 상태의 통계를 검사한다. Windows와 Linux의 엄격 Release, Linux Debug ASan/UBSan 검사도 실행한다.

## 시간 비용

같은 Windows PC·MSVC C++20 `/O2 /DNDEBUG` Release, 단일 탐색 스레드, 기본 옵션을 사용한다. 기준 커밋을 별도 `git archive`에서 빌드한다. `tests/data/profile_positions.json` 전체 10개 위치는 변경하지 않는다.

1. 깊이 1, 각 10회, `--warmup 0`: 첫 측정에 최초 할당을 포함하며 프로세스별 탐색 순번으로 첫 요청과 나머지를 구분한다. 최초 할당 비교는 엔진당 한 표본이므로 일반적인 초기 속도를 추정하지 않는다.
2. 같은 깊이 1·10회, `--warmup 1`: 각 엔진에 기록된 준비 탐색 1회를 수행한 뒤 100쌍을 측정한다. 짧은 반복 검색의 주 비용 비교다.
3. 깊이 3, 각 5회, `--warmup 1`: 50쌍으로 더 큰 트리에서도 비용과 탐색 동작을 확인한다.

`scripts/benchmark_search.py`의 시드 20261017, 위치 셔플·쌍별 순서 교대, 매 표본 `ucinewgame`, 별도 실행 프로세스를 유지한다. 준비 탐색은 원자료에 남기고 주 통계에서 제외한다. `--require-same-search`로 점수·최선 수·깊이·노드·seldepth·PV·기존 TT 4개 통계의 완전 일치를 요구한다. 벽시계는 UCI 요청·대국 재설정·초기화를 포함하고 프로세스 시작 시간은 제외한다. 할당·재사용·물리 초기화·사용 바이트를 기록하며 이전 버전에 없는 메모리 통계는 0이 아닌 ‘없음’으로 둔다. 중앙 가속과 위치별 결과, 느려진 사례도 보존한다.

## 같은 시간 대국

- 기준 v0.4.0 대 개선 v0.4.1, 양쪽 UCI **40ms/수 16판**, **100ms/수 16판**, 총 32판.
- 기존 `tests/data/comparison_openings.json`의 8개 시작 수순 그대로, 각 선후공 교대. 전체 이력을 전달한다.
- 양쪽 Move Overhead 20ms, 내부 탐색 할당 각각 20/80ms. 첫 할당도 해당 수의 예산에 포함하며 대국 전에 준비 탐색하지 않는다. 프로세스는 대국 묶음 동안 유지한다.
- 대국·벤치마크·다른 부하 검증을 동시에 실행하지 않는다. 결과를 본 뒤 설정·판수·시작 위치를 바꾸지 않는다.
- 가능한 현재/예정 수 3회 반복·50수 청구를 항상 처리한다. 자동 종료 별도, 500반수 안전 한도. 오류·미완료·미실행을 완료 무승부로 바꾸지 않는다.
- Python chess 1.11.2는 통신·검증·판정만 수행하며 두 자체 엔진이 수를 선택한다.

실행 파일 해시, 소스 커밋, 환경·옵션·시간·노드·기보를 저장하고 PGN/JSON을 독립 재생한다. 같은 시작 쌍을 묶은 참고 부트스트랩 범위를 기록하되, 작은 개발 표본의 결과를 일반적인 강도·Elo·외부 엔진이나 인간 상대 성능으로 일반화하지 않는다. 비용 감소와 대국 성적은 별도로 결론을 내린다.
