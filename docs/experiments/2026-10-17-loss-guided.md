# v0.5.0: 100ms 패배 분석과 탐색 개선

분석 대상은 이전 [100ms 전체 재측정](../matches/2026-10-17-hash-memory/time100-retry.pgn)의 v0.4.1 패배 1·2·6·7·10·11·13번이다. 7판 781반수를 재생하고 후보가 둔 372개 위치에서 제한된 외부 진단을 수행했다. 2·6번은 28반수 뒤 같은 위치와 93반수 후속 수순을 공유하므로 서로 다른 약점 두 개로 세지 않았다.

## 무엇을 먼저 고쳤는가

**조용한 체크의 전술 연장과 일반 수 정렬**을 우선했다. 후반 승격 패배가 여러 판에 있지만, 그 전에 생긴 기물 손실·킹 공격을 먼저 검토했다. 기보 끝의 강제 희생을 최초 실수라고 부르지 않았다.

| 사례 | 실제 수순·검토 결과 | 우선순위에 주는 근거 |
|---|---|---|
| 11번, 30.Nxe7 | `...Nf3+`, `...Nxd2+`, 다시 `...Nf3+`, `...Rxe7`. 당시 +98cp, 더 깊은 자체 깊이 5도 이 수를 선택. 외부 50만 노드 진단은 최선 후보 +175cp, Nxe7 강제 -716cp | 단순히 한 깊이를 더 읽는 것만으로 해결되지 않은 체크 연쇄. 안정화 범위 보완 우선 |
| 13번, 9.O-O-O | `...Ng4` 뒤 `...Nxf2`가 퀸·룩을 포크. 자체 깊이 4는 캐슬링, 깊이 5는 Qb5로 변경. 외부 진단의 최선 후보 +67cp, 캐슬링 강제 -321cp | 체크가 아닌 위협까지 도달하도록 일반 탐색의 수 순서 개선 |
| 7번, 21.h4 | 당시 완료 깊이 2. 자체 깊이 3 이상에서 Qf3를 선호 | 같은 시간에 완료할 수 있는 일반 탐색 깊이의 영향 |
| 10번, 22...Rac8 | 앞선 ...cxd4·...Bxb5 뒤 c3가 b4 나이트를 가둠. ...Rac8 당시 깊이 2, 더 깊게는 다른 수 | 갇힌 기물도 약점 후보. 실제 첫 손실은 더 앞선 교환 선택까지 검토해야 함 |
| 2·6번, 39...Nxd3 | 기물을 얻지만 Rc7+·Rxg6+ 등 킹 공격. 외부 최선 후보 0cp, 강제 Nxd3 -514cp | 킹 공격과 물질 이득의 충돌이 반복. 늦은 ...Rg2+는 이미 생긴 메이트 위협의 방어 |

외부 값은 Stockfish 16의 유한 탐색 판단이며 Regicide 점수와 직접 비교할 척도가 아니다. 같은 위치에서 최선 후보 검색과 실제 수 강제 검색에 각각 500,000노드를 사용했으며 이 값은 정확한 최선 수의 증명이 아니다. 메이트 점수를 숫자로 변환한 원시 `drop`은 일반 cp 손실로 해석하지 않았다.

## 자체 구현과 외부 참고의 경계

[원리·옵션](../LOSS_GUIDED_SEARCH.md)에 구현을 설명한다. 새 가지치기나 평가 계수 조정 없이, 안정화 경로당 비캡처 체크 예산 1회와 검색마다 초기화하는 killer/history 수 정렬을 추가했다. 잡기·승격은 체크 예산을 소비하지 않으며 체크 중에는 예산 0이어도 모든 회피를 탐색한다. 기존 전체 안정화 한도·노드/시간·반복/무승부·전이표 격리를 유지한다.

Stockfish 16은 별도 프로세스로 기보만 진단했다. Ubuntu `16-1build1`, Threads 1, Hash 32MiB, 기본 내장 NNUE, 위치 전후 각 50,000노드 및 선택 위치 각 500,000노드다. Regicide에 외부 엔진 코드·평가 표·신경망 가중치를 가져오지 않았다. [Stockfish sf_16](https://github.com/official-stockfish/Stockfish/releases/tag/sf_16)은 [GPLv3](https://github.com/official-stockfish/Stockfish/blob/sf_16/Copying.txt)이며, 실행 파일·패키지를 이 저장소에 재배포하지 않는다. 확인일 2026-10-17.

원시 [외부 진단](../matches/2026-10-17-loss-guided/analysis/coach-analysis.json), [자체 깊이 비교](../matches/2026-10-17-loss-guided/analysis/own-engine-queries.json), [전체 기물·기보 분석](../matches/2026-10-17-loss-guided/analysis/independent-loss-analysis.md), 해시·패키지 메타데이터를 보존했다. 분석 스크립트는 실행 당시 경로를 담은 원본이다. 재현 시 저장소의 `build/loss-analysis/` 아래에 해당 스크립트를 복사하고 Ubuntu 패키지를 `stockfish/extracted/`에 추출한 뒤 Windows Python 환경에서 `coach_analysis.py`를 실행한다. WSL 배포판 이름은 Ubuntu-24.04다. 개별 유한 탐색 결과는 빌드·플랫폼에 따라 달라질 수 있다.

## 사전 고정과 대국 조건

[사전 계획](2026-10-17-loss-guided-plan.md)과 새 8개 시작 위치는 후보 구현 전에 `f4c5e03d2440618aa3e178932ed3e3a708561359`로 고정했다. 패배 분석·개발 위치에서 구현과 검증을 마친 뒤 후보를 고정하고, 기존 8개 × 선후공 교대 16판을 개발 진단으로, 새 8개 × 2판을 주 비교로 수행한다. 두 묶음을 보류 표본의 한 승률로 합산하지 않는다.

기준은 v0.4.1 `a31091548033d538e01d2c194f05bada403d5263`를 별도 아카이브에서 재빌드한다. 같은 PC·MSVC 19.51.36260 C++20 `/O2 /DNDEBUG`, 단일 탐색 스레드, 양측 기본 Hash 16MiB, Move Overhead 20ms다. 요청 100ms/수에서 내부 할당은 80ms다. 첫 검색의 표 할당 비용을 포함하고 묶음 동안 프로세스를 유지한다.

AMD Ryzen AI 7 350, 논리 CPU 16개, RAM 33,598,976,000바이트, Windows 11, Python 3.13.16, python-chess 1.11.2를 사용한다. Python은 전체 이력 전달·합법성·현재/예정 수 무승부 청구·종료 판정만 담당하고 양쪽 자체 엔진이 수를 고른다. 500반수 한도와 실패·미완료 보존 정책을 유지한다. 모든 시간 대국 중에만 일시적으로 시스템 유휴 절전을 억제하고 `finally`에서 이전 실행 상태로 복원한다. 빌드·다른 탐색 부하와 동시에 측정하지 않는다.

## 개발 위치의 판단 변화와 계산 비용

전체 이력을 복원한 네 위치에서 깊이 3을 고정하고 기준·후보 및 두 기능의 켬/끔을 비교했다. 모든 새 기능을 끈 후보는 네 위치 모두 기준의 수·점수·노드를 정확히 재현했다. [20회 질의 원자료](../matches/2026-10-17-loss-guided/analysis/development-probes.json)에 전체 수순·옵션·바이너리 해시·합법 PV를 보존했다.

| 위치 | v0.4.1 | 체크 연장만 | 일반 수 정렬만 | 두 기능 기본 |
|---|---|---|---|---|
| 11번, 30수 백 | Nxe7 +98, 18,639노드 | Bf4 +94, 44,291 | Nxe7 +98, 10,679 | Bf4 +94, 33,116 |
| 13번, 9수 백 | O-O-O +1, 4,897 | O-O-O +1, 12,395 | O-O-O +1, 3,332 | O-O-O +1, 6,097 |
| 7번, 21수 백 | Qf3 -30, 50,843 | Qf3 -30, 137,161 | Qf3 -30, 29,858 | Qf3 -30, 84,759 |
| 10번, 22수 흑 | Bc5 -16, 34,525 | Bc5 -16, 90,985 | Bc5 -16, 28,506 | Bc5 -16, 87,767 |

체크 연장은 11번 함정을 피했지만 계산량을 늘렸다. 일반 수 정렬은 이 네 사례의 같은 깊이 계산을 줄였다. 13번의 체크가 아닌 포크 준비는 이 깊이에서 해결되지 않았다. 이 표는 개발 위치의 판단·노드 비교이며 실행 시간이나 전체 경기력 개선의 증거로 바꾸지 않는다.

## 실제 검증과 대국 결과

후보 동결 뒤 원시 기보·검증 로그·결과와 한계를 이 절에 기록한다. 기존 규칙·perft·특수 수와 2,997개 외부 교차 검증은 유지한다. 새 기능의 작은 독립 탐색·상태 보존·옵션 전환 검증, 개발 위치 판단 변화, 같은 시간 대국은 각각 구분한다.
