# 왕 앞 폰 방패 동값 최적화 계획

기준일: 2026-10-18 (한국 시간). 기준 코드 `07321d8b27b95dad9a1fc66c9170ab8085829868`, v0.5.4. 최적화 후보는 v0.5.5로 식별한다. 기존 폰 방패 계수·효과, 일반/안정화 탐색·규칙을 유지한다.

## 원인을 분리하는 방법

이전 OFF/ON 비교는 점수와 탐색 트리가 달랐고 외부 부하가 통제되지 않은 짧은 요청이었다. 새 정적 점수 때문에 방문한 위치 수가 바뀌는 효과와 평가 호출 비용을 분리해야 한다.

1. v0.5.4 평가 원문을 함수명만 바꿔 독립 참조로 동결한다. 보드 생성·I/O 없이 같은 FEN 집합의 이전 OFF/ON과 새 OFF/ON을 같은 프로세스의 다른 함수로 호출한다.
2. 기물 분류의 반복 `tolower` 호출 및 좌표별 점수 수식은 병목 가설이다. 컴파일된 코드와 평가 단독 계측으로 확인한다. 소스의 호출 개수를 실제 CRT 호출 횟수라고 단정하지 않는다.
3. 기존 수식으로 생성한 작은 constexpr 기물 정보·기물 위치 표를 사용해 반복 분류·중앙성·위치 점수 산술을 조회로 바꾼다. 미전개 경량기물 수에 비례하는 룩·퀸 보정은 그대로 계산한다. 방패의 거리·양색 국면·정수 나눗셈 위치·전체 국면 혼합은 유지한다. 보드 변경 캐시는 추가하지 않는다.

## 동값·규칙 gate

- 원본 참조와 새 함수의 ON/OFF 점수를 수천 개 이상의 결정적 합법 수순·직접 구성한 경계 위치에서 정확 대조한다. 왕의 모든 칸·폰 거리·양색·국면·전개·승격·앙파상·반복 이력·상태 불변을 포함한다.
- 기존 6개 C++ 검사와 Python 독립 규칙 교차검증, UCI·사람 대국·형세·추천·핸디캡·보관함의 기존 회귀를 유지한다. Windows Release 및 Linux GCC, 평가·탐색 ASan/UBSan을 확인한다.
- `tests/data/profile_positions.json`의 전체 10위치에서 Hash16, Move Overhead20, warmup1, seed20261018, 깊이3/4 각각 repeats5로 기준 v0.5.4 ON과 후보 ON의 수·점수·깊이·seldepth·노드·PV·TT 카운터 정확 일치를 요구한다. 같은 전체 표본의 깊이3 repeats3을 OFF끼리도 대조한다. 총130쌍이며 실패 표본을 결과에 따라 제외하지 않는다.

## 평가 함수 단독 비용

프로파일 FEN은 기존 10위치와 자체 방패·종반·특수 위치를 결과 관측 전에 생성하고 고정한다. 기본 warmup10,000회 후 이전 ON 기준으로 동일 호출 수를 한 번 정하며, 9블록에서 4가지 균형 순서 ABCD/DCBA/BADC/CDAB를 모두 실행한다. A/B/C/D는 이전 OFF/이전 ON/새 OFF/새 ON이다. 매 측정 체크섬과 호출 수를 저장하고 ON/OFF 각각 참조와 새 값의 일치를 요구한다. 마이크로벤치마크가 전체 탐색 개선이나 기력 상승을 증명하지는 않는다.

MSVC `/O2 /DNDEBUG`와 GCC의 동등 최적화로 동일 코드·입력을 비교한다. 계측 중 컴파일·테스트를 중지하고 알려진 대국·브라우저 프로세스의 CPU 변화와 시스템 CPU 부하를 샘플링해 남긴다. 이 샘플은 모든 외부 작업·열·주파수·스케줄링의 완전한 통제가 아니다. 동시 부하가 있으면 수치의 한계를 밝히며 사용자에게 허락 없이 다른 앱의 계산을 끄지 않는다.

## 완료·배포

원본 점수와 고정 깊이 탐색 결과 일치를 필수로 하고, 유한한 평가 프로파일에서 새 ON 호출 비용이 감소하는지 확인한다. 전체 탐색 시간은 별도로 제시하고 혼재된 결과도 보존한다. 이전에 중단한 강도 대국 비교는 재개하지 않으며 Elo나 기력 향상을 주장하지 않는다.

이전 설치본·실행 파일·개인 기보를 백업하고 검증한 v0.5.5를 로컬에 반영한다. 실제 창·추천 기능·이전 기보 해시를 확인한다. 소스·검사·프로파일·환경·원자료·한계·해시를 커밋하고 GitHub 푸시 후 로컬/원격 SHA 및 깨끗한 작업 폴더를 확인한다.
