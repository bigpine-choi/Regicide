# 보수적인 LMR 개발·검증 계획

기준일: 2026-10-18 한국 시간. 기준 v0.5.7은 `5b5b5deedbef96133836609ec00229c7a548a15a`, 후보 v0.5.8이다. 기존 폰 구조·왕 앞 방패·평가 수식·합법 수·특수 규칙은 유지한다. 다음 조건과 표본은 새 탐색 결과를 보기 전에 고정한다.

## 구현 범위

LMR은 뒤쪽 일반 수를 한 반수 얕게 먼저 읽고 유망하면 원래 깊이로 다시 확인하는 선택적 탐색이다. 평가식을 바꾸지 않지만 같은 명목 깊이의 수·점수가 달라질 수 있다. PVS는 좁은 점수 창을 사용하는 기존 기능이고, LMR은 탐색 깊이를 줄이는 별도 기능이다.

- 기본 켬, UCI `UseLMR`, 콘솔 `--no-lmr`, C++ `SearchOptions::lmr`로 선택한다.
- PVS와 일반 수 정렬이 모두 켜진 경우에만 적용한다. 둘 중 하나가 꺼지면 LMR도 아무 감축을 하지 않는다.
- 루트와 주요 수순(PV) 노드는 보호한다. 남은 깊이4 이상인 비PV 노드의 정렬상 다섯 번째 이후 후보만 대상이다.
- 현재 체크 중이거나 체크를 주는 수, 포획·앙파상·승격, 폰/킹 이동(캐슬링 포함), TT/PV 우선수와 두 killer 수는 보호한다. 킹·폰만의 종반에서도 감축하지 않는다.
- 현재/의도한 수의 무승부 청구와 메이트 점수 근처 창은 보호한다.
- 감축은 한 반수로 고정한다. `depth-2` 좁은 창 탐색이 alpha를 넘으면 반드시 정상 `depth-1` 좁은 창으로 재검사하고, 필요하면 기존 PVS의 전체 창 재검사를 거친다.
- 검증되지 않은 감축 fail-low는 best/PV를 갱신하지 않는다. 이런 가지를 포함한 비PV 노드가 컷오프 없이 끝나면 alpha를 반환하되 TT에 저장하지 않는다. 서로 다른 깊이가 섞였으므로 낮은 깊이의 상한으로 저장하는 방식도 안전하지 않다는 독립 검토를 반영했다. 검증한 정상 깊이 컷오프의 lower는 원래 깊이를 기록할 수 있다. 감축 child 자체는 실제 요청 깊이로 저장한다.
- `lmr_reductions`와 `lmr_researches`로 실제 감축·정상 깊이 재검사 횟수를 기록한다. 중단 경로·반복 심화 결과에도 누적량을 전한다. 옵션 OFF는 기존 탐색 그래프를 재현한다.

별도 가상 패스, 추가 평가 항목, 확률적 선택·학습·병렬 탐색은 도입하지 않는다. 공개 Stockfish 구현의 LMR·재검색 개념을 참고하되 조건·코드·계수는 Regicide에 맞게 직접 작성한다. 외부 엔진 코드를 가져오지 않는다. 참고: [원저자 탐색 소스](https://github.com/official-stockfish/Stockfish/blob/master/src/search.cpp).

## 검증과 측정

1. 기존 Windows/Linux 핵심6종·독립 규칙2,997사례·평가 참조·UCI/CLI·추천·형세·핸디캡·기보 보관함 회귀를 유지한다. 기존 검색 오라클·PVS/SEE 그래프 검사는 LMR OFF를 명시해 의미를 보존한다.
2. ON은 적용되지 않는 얕은 깊이·보호 위치·PVS/정렬 OFF, 합법 PV·메이트/무승부 우선·중단/복원·TT 세대/옵션 변경을 검사한다. 실제 감축과 재검사 카운터가 발생하는 결정적 위치를 별도 검사한다. ON 전체에 기존 깊이의 점수 일치를 요구하지 않는다.
3. Linux 엄격 경고와 평가/탐색 ASan·UBSan·누수 검사를 수행한다. 로컬 검사와 원격 CI는 구분한다.
4. 기존 전체10 `profile_positions.json`, Hash16MiB, Move Overhead20ms, seed20261018, warmup1로 v0.5.7 대 후보 LMR OFF 깊이3/4/5 각3회(90쌍)의 수·점수·깊이·노드·최장 깊이·PV·TT 정확 일치를 요구한다.
5. 같은 후보의 LMR OFF/ON은 깊이5/6 각3회(60쌍) 비교한다. 점수 차이는 허용하고 감축·재검색·노드·시간·PV 합법성과 재검색 비용을 따로 기록한다. 더 높은 완료 깊이나 노드 감소를 기력 상승으로 환산하지 않는다.
6. 새 자체 시작 수순8개 `lmr_openings_2026-10-18.json`을 전부 선후공 교대하여 200ms/수, Hash16MiB, Move Overhead20ms, 단일 탐색 스레드, 무승부 청구 정책, 최대300반수의 16판을 초기 기력 관찰로 실행한다. 수 제한은 미완료 `*`이며 무승부로 세지 않는다. 소표본·미완료·시간/부하의 한계를 공개하고 Elo나 일반적 기력 상승을 확정하지 않는다. 기존에 중단한 v0.5.3 비교를 재개하는 것은 아니다.
7. 테스트·컴파일과 시간 측정/대국은 겹치지 않는다. 프로세스 CPU 표본과 알려진 대국 엔진의 누적량을 관찰하고 외부 부하·절전·클럭·신규/종료 프로세스 관측 한계를 기록한다. 사용자 대국이 계산 중이면 비교 전에 잠시 멈추도록 요청한다.
8. 독립 검토에서 규칙·재검색·TT 경계와 기록을 확인한다. 명백한 기능/전술 회귀는 해결한 뒤 배포하며 작은 대국 표본을 근거로 강해졌다고 단정하지 않는다. 기존 설치·바로가기·개인 기보를 백업하고 검증된 개발 후보를 로컬에 반영한 뒤 실제 창/추천과 기보 해시를 확인한다. 커밋·푸시 후 개발/설치/GitHub SHA와 깨끗한 작업 폴더를 확인한다.
