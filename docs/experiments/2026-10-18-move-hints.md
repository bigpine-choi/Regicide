# 사람의 다음 수 추천 기능 검증

기준 코드 `e28b9a002ffe943ddc2a6015a5ca6b58b8672ed8`에서 대국 중 켜고 끄는 추천 수 기능을 추가했다. C++ 규칙·탐색·평가 구현과 실행 파일은 변경하지 않았다. 실제 수 선택과 사람의 추천은 자체 Regicide 0.5.3이 수행한다. 사용한 실행 파일 SHA256은 `98457ff8798c75614716f654ceef682919e1e40700cb85743ba1320571f89c58`이다.

## 구현

- 기본 OFF이며 사람이 둘 차례에만 별도 Regicide 프로세스로 유한 시간의 추천을 계산한다. 실제 대국은 자동 착수하지 않는다.
- 추천용 프로세스·작업자·잠금은 실제 상대 엔진과 분리한다. 전체 수순의 복사본을 사용하고, OFF·위치 변경·종료 시 계산을 취소한다. 작업자 하나가 최신 요청만 처리하며 시간 초과와 프로세스 회수를 처리한다.
- 인증된 `/api/hint` GET/POST는 추천 조회와 선호 설정만 담당한다. 상대 탐색이 대국 잠금을 점유해도 ON/OFF가 응답한다.
- Godot은 추천 수의 SAN·좌표·승격 기물과 방향 화살표를 표시한다. 브라우저는 출발·도착 칸과 문구를 표시한다. 대국 ID·revision·FEN·합법 수를 확인하며, 끈 뒤 도착한 응답을 버린다.
- 추천의 점수를 기존 형세 막대에 넣지 않는다. 무르기·새 대국·핸디캡·종국·복기에서는 이전 추천 표시를 지운다.

실제 화면의 버튼을 Computer Use로 눌러 추천이 나타나는 것, 시점 뒤집기 후 화살표 방향, OFF 즉시 표시 제거와 정상 종료도 확인했다. 이 검증은 자동 UI 입력이며 사람이 수동으로 끝까지 대국한 검증은 아니다. 개인 기보 대신 별도 검증 폴더를 사용했다. 종료한 검증 세션의 임시 접속 파일 삭제는 자동 승인 검토에서 정책상 차단되어 ignored 검증 경로에 남겼으며, 저장소·설치본·증거 폴더에는 포함하지 않았다.

브라우저의 실제 Chromium 화면 렌더링은 수행하지 않았다. Windows/Ubuntu에서 같은 신규 검사를 실행하도록 CI를 추가했으나 원격 CI 실행 결과는 이 로컬 작업에서 확인하지 않았다. 엔진 경기력 비교와 C++ 전체 회귀의 재실행은 이번 변경의 범위가 아니다.
