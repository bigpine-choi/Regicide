# 신경망 계산 비용·판단 차이 분리와 교사 라벨 품질 개선 사전 계획

2026-10-19 KST. 기준은 v0.6.2 / `25d37d8173da9e72bbc4b20178e2933ac4640911`이다. 사용자 요청은 계산 비용과 판단 오류를 분리하는 실제 실험, 학습 정답의 품질 개선, 기존 규칙 검증·모델 채택 기준 유지, 로컬 반영과 커밋·푸시다.

## 관측과 가설

- 이전 V2 후보는 수당100ms의64판에서11승18무35패였다. 그 경기와 예약 위치는 학습·설정 선택에 사용하지 않는다.
- 이전 실제 대국의 후보 탐색량이 적었지만 다른 탐색 트리를 비교했으므로 순수 추론 비용과 보정 오류의 기여는 분리되지 않았다.
- 현재 교사 라벨은 제한된 자체 수식 탐색이다. 더 많은 노드에서도 수와 점수가 안정되는지 확인하면 불안정한 정답을 줄일 가능성이 있다. 안정성이 참정답이나 경기력 향상을 보장하지는 않는다.

## 고정할 구현과 실험

1. 같은 실행 파일의 기존 전체 평가 / 출력층0인 V2 / 이전 학습V2를 비교한다.0모델은 기존 모델의 사본에서 출력층만0으로 만들고 실제 신경망 연산 경로를 통과한다. 평가·탐색·100cp보정한도·학습목표는 변경하지 않는다.
2. 새 자체 개발용 위치12개를 진단 전에 고정하고, 기존 학습·보류 자료 및 예약 대국 위치와 같은 보드/같은 신경망 입력은 거부한다. 학습에 쓰는 위치와 진단용 위치는 분리한다. 파일·모델·바이너리·코드 해시와 전체 옵션을 기록한다.
3. 같은 깊이, 같은 노드, 같은 시간 조건을 별도 보고한다. 기본 깊이3, 노드10,000, 시간100ms, 반복6회와 균형 역할순서를 사용한다. 매 검색은 전체 이력과 새 논리 대국으로 TT를 비운다. 기존평가/0모델은 시간·메모리재사용통계 외 수·점수·PV·노드·TT작업통계 동등성을 확인한다. 그 쌍의 시간비로 계산 비용을 분리한다.
4. 학습V2의 같은 노드 수 선택을 따로 보고한다. 자체 수식교사100,000/200,000노드 검색 뒤 공통 완료깊이에서 선택수 집합을 강제 탐색한다. 정확한 유한 점수, 동일 완료깊이와 합법 PV를 확인하지 못하면 후회값은 unavailable로 기록한다. 이 유한 자체교사는 절대 정답·독립 기력 기준이 아니다.
5. 시간 측정에는 기존 자원 감시를 적용한다. 알려진 외부 엔진·브라우저 CPU 증가나 감시 공백이 있으면 시간 비교는 무효다. 모든 호스트 부하·온도까지 완전히 통제한 것으로 표현하지 않는다. 이 진단의 점수·속도는 모델 채택이나 Elo 근거가 아니다.
6. 새 품질 도구는 기존 완결 자료의 train만 자체 수식교사10,000→50,000→200,000노드로 다시 확인한다. 전체 수순·새 논리 대국·빈 TT·정확 유한 CP·합법 PV를 보존한다. 마지막 두 검색 모두 완료깊이3이상, 최선 수 동일, 점수차30cp이하이면200,000노드 라벨을 사용하고, 나머지train은 이유와 함께 제외한다. 자료별 원래 라벨·단계별 원시검색·해시·정책을 보존한다. 체크/메이트/점수bound를 임의 CP로 바꾸지 않는다.
7. validation/test 전체 행과 기존 원본 self-play/loss/corpus 자료는 바꾸지 않는다. 새 품질 dataset을 별도 경로에 만들고 기존 strict 검증을 통과시킨다. 학습표본이 전부 제외되면 훈련·대국 전에 실패로 닫는다.
8. 자동 순환은 기존 누적 corpus 다음에 품질단계를 추가하고 훈련 입력만 바꾼다. 카탈로그에는 기존 원본자료/진단만 등록한다. 파생 품질자료도 가중치와 함께 동결하고 arena 전/중 변조 시 채택을 막는다. 매순환 재점검의 추가 계산 비용은 기록하며 캐시는 이번 범위에 넣지 않는다.

## 실제 실행과 채택

- 기존 영속 저장소의3시도를 보존하고 다음 시도4에서 기본32판 수집·패배분석·누적·품질검사·V2학습을 한 번 실행한다. 기존100epoch/Adam학습률0.003/batch64/L2=0.0001과 고정 검증MSE 선택(epoch0포함)을 유지한다. 원래 검증 라벨이 얕은 교사였다는 한계를 기록한다. 결과를 보고 같은 시도의 설정을 재선택하지 않는다.
- 최종후보 고정 뒤 새 난수로 기존 예약 분포에서32쌍/64판·수당100ms·Hash16MiB·단일스레드 비교한다. 기존 `learning_arena.py`, `learning_registry.py`, 예약 오프닝 파일과 alpha/하한 조건은 변경하지 않는다. 자원 감시가 무효면 채택하지 않는다.
- 기존 네이티브 규칙·상태복원·탐색·평가·SEE·전이표·신경망, 독립 규칙 대조, UCI, 기존 클라이언트/Godot 회귀와 새 도구의 의미있는 실패경계 검사를 수행한다. 실수오차·실행비용·대국결과는 구분해 보고한다.
- 실제 실험 결과와 원자료·해시·한계를 남긴 뒤 로컬 설치와 원격 커밋 일치/깨끗한 작업 상태를 확인한다. 미통과 모델은 기본평가에 적용하지 않는다.

NNUE의 계산비용/증분 계산 원리는 [원저자 설명](https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md)을 참고한다. 이번에는 증분추론/정수화나 외부 코드·기보·가중치를 도입하지 않는다.
