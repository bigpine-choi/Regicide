# PVS: 구현 전 고정하는 비교 계획

기준은 **Regicide v0.5.0, `8820094588cddadff39bc7cac7c19f92ed522822`**다. 이 커밋은 기보 보관함까지 포함한 현재 안정 버전이며, 자체 C++ 엔진의 탐색은 v0.5.0이다. 후보는 첫 후보를 정상 범위로 탐색하고 후속 후보를 좁은 창으로 검사한 뒤 필요할 때 정상 창으로 다시 탐색하는 **PVS(Principal Variation Search)**만 추가한다. 목표는 같은 깊이의 탐색 비용을 줄이고, 같은 시간에 완료하는 탐색과 실제 대국 성적이 개선되는지 구분해서 확인하는 것이다.

## 변경 범위와 정확성

- PVS 켬/끔 옵션을 제공하고 기본값을 켬으로 한다. 첫 수와 재탐색 조건, 중단 처리 및 전이표에 저장하는 상한·하한·정확한 값의 의미를 검증한다.
- 평가, 기물 위치 점수, 안정화 탐색 범위와 체크 예산, 수 정렬, 반복·무승부 판정, 전이표 크기와 재사용 정책, 시간 관리는 바꾸지 않는다. aspiration window, SEE, LMR 및 새로운 가지치기는 이번 후보에 넣지 않는다.
- 기존 규칙·perft·특수 수·합법 수 교차 검증, 탐색·평가·전이표·상태 보존·UCI 및 대국 도구 검사를 유지한다. 새 기능은 작은 독립 탐색 오라클, 좁은 창의 fail-high/fail-low, 재탐색, 메이트, 이력, 중단 및 전이표 켬/끔에 대한 회귀 검사로 확인한다.
- PVS를 끈 후보가 기준의 고정 깊이 수·점수·노드·PV·기존 탐색 계측을 재현하는 대조 검사를 둔다. PVS를 켰을 때 수나 PV가 달라졌다는 이유만으로 오류 또는 개선으로 단정하지 않는다. 동점 수의 차이와 실제 점수 차이를 구분하고, 예상하지 못한 차이는 작은 오라클·전이표/선택적 안정화 동작으로 조사한다.

## 시작 위치 사전 고정

새 [8개 시작 수순](../../tests/data/pvs_openings_2026-10-18.json)은 후보 구현·검색·대국 결과를 보기 전에 직접 작성했다. 외부 오프닝 북이나 강한 엔진으로 고르지 않았으며, 이름은 구조를 설명할 뿐 최선 수순이라는 뜻이 아니다. `comparison_openings.json`과 `heldout_openings_2026-10-17.json`의 최종 위치와 겹치지 않는지 독립 규칙 라이브러리로 확인하고, 백 차례 4개·흑 차례 4개를 유지한다.

이 계획과 수순 파일을 먼저 소스 커밋으로 고정한다. 후보 개발 중 이 8개에서 후보의 점수나 대국 결과를 보아 수순·설정·구현을 조정하지 않는다. 후보 동결 뒤 전체 8개 × 선후공 교대 2판을 **100ms/수 16판**, 다시 같은 전체 8개 × 선후공 교대 2판을 **1,000ms/수 16판**, 합계 **32판** 진행한다. 각 시간 조건을 별도로 보고하며 합쳐서 하나의 승률로 제시하지 않는다. 첫 비교 뒤에는 이 표본도 개발 자료가 되므로, 결과를 보고 수정한 다음 같은 표본을 새로운 보류 검증이라고 부르지 않는다.

## 고정 깊이의 계산 비용

기존 `tests/data/profile_positions.json`의 전체 10개 위치에서 깊이 **3과 4를 각각 고정**하고 위치별·엔진별 **5회** 측정한다. 각 측정 묶음 시작에 선언된 첫 위치로 엔진별 워밍업 **1회**를 기록하되 요약에서 제외한다. 위치 순서는 seed **20261018**로 섞고, 같은 위치의 반복에서 기준/후보 실행 순서를 교대한다. 새 대국을 알리고 전체 수순을 전달하여 전이표의 이전 대국 정보를 논리적으로 비우며 엔진 프로세스는 유지한다. 시작 프로세스 비용은 제외하고 UCI 요청·응답 벽시계와 엔진 내부 시간을 모두 보존한다.

기준 대 PVS 켬 후보를 두 깊이에서 측정하고, 같은 두 깊이에 PVS 끔 후보의 기준 재현 대조도 수행한다. 노드·완료 깊이·seldepth·점수·선택 수·PV·전이표 계측·시간을 원자료에 남긴다. 반복별 차이를 보존하고 깊이별 전체 노드 비율과 위치별 시간 중앙값을 요약한다. 점수 차이는 숨기거나 유리한 위치만 제외하지 않는다. 이 묶음은 개발 비용 진단이며 새로운 경기력 표본이 아니다.

## 동일 자원과 동결

- 같은 Windows PC에서 같은 MSVC C++20 Release **`/O2 /DNDEBUG`**로 기준과 후보를 각각 깨끗한 소스에서 재빌드한다. 기준은 위 커밋의 별도 아카이브를 사용하고, 후보는 엔진·도구·설정이 고정된 소스 커밋을 사용한다. 소스 커밋·실행 파일 SHA256·시작 파일 SHA256·컴파일러·OS·CPU·RAM·Python/규칙 라이브러리 버전을 기록한다.
- 양측 단일 탐색 스레드, **Hash 16 MiB**, **Move Overhead 20ms**다. 요청 100ms/1,000ms에서 내부 할당은 각각 80ms/980ms다. PVS 외 모든 UCI 옵션은 동일하게 유지하고 실제 옵션을 원자료에 남긴다.
- 대국 묶음에는 사전 준비 검색을 하지 않아 첫 표 할당 비용을 포함하고, 엔진 프로세스는 묶음 동안 유지한다. 모든 수에 전체 이력을 전달한다.
- `python-chess`는 통신 보조·합법성·현재/예정 수의 반복/50수 무승부 청구·자동 종료 판정만 수행하고 두 자체 C++ 엔진이 실제 수를 선택한다. 무승부 정책은 항상 청구(`claim`), 전체 수순을 포함해 **500반수 한도**다. 한도 도달·중단·오류를 무승부나 정상 완료로 바꾸지 않는다.
- 실행 순서는 고정 깊이 비용/대조 검사 → 100ms 전체 대국 → 1,000ms 전체 대국이다. 빌드, 다른 엔진 분석 또는 다른 측정 부하를 동시에 실행하지 않는다. 절전 방지는 측정 실행 중에만 임시 적용하고 종료·예외 시 이전 상태를 복원한다. 영구 전원 정책은 바꾸지 않는다.

## 보고와 실패 처리

규칙 정확성, 고정 깊이 계산 비용, 같은 시간의 완료 깊이, 실제 승·무·패를 별도로 보고한다. 시간 대국의 평균 깊이·노드는 서로 다른 진행 위치의 관측치이므로 고정 깊이 비용 개선과 같다고 해석하지 않는다. 내부 시간과 요청·응답 벽시계, 예산 초과 수를 함께 남긴다.

시간 조건별 후보 승·무·패와 득점률을 제시하고, 같은 시작 위치의 선후공 2판을 한 쌍으로 묶어 seed **20261018**, **20,000회** 참고 부트스트랩을 계산한다. 8쌍이 체스 전체를 무작위로 대표하지 않으므로 이 구간은 일반 강도의 보편적인 신뢰구간이나 Elo가 아니다. 소수 대국에서 우위·열세·불확실성을 있는 그대로 보고하며 세계 정상급 성능을 주장하지 않는다.

PGN·수별 JSON·PV·옵션·버전·해시·종료 이유와 검사 로그를 보존하고 독립 재생으로 합법성·최종 판정·시작 수순·색 교대·득점을 재계산한다. 오류가 생기면 원본을 덮어쓰지 않고 원인과 영향 범위를 기록한다. 재측정이 필요하면 수정 내용·재실행 범위·동결 버전을 먼저 추가 기록한 뒤 전체 해당 묶음을 새 파일로 실행한다. 결과를 보고 판수·시간·시작 위치를 바꾸거나 유리한 실행만 고르지 않는다.
