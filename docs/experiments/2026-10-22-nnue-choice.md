# 실제 탐색에서 경쟁하는 수의 점수차 학습

2026-10-22. 점수 오차 감소가 추천수 증가로 이어지지 않은 원인을 이전 기록으로 분석하고,
각 후보 수의 탐색점수를 실제로 뒷받침한 평가 위치쌍을 학습하도록 구현했다.
후보 학습은 한 번, 32.78초 진행했다. 수정된 가중치가 모두 기존 검증 보호 기준을 넘어
시작 모델을 복원했다. 새 미학습16위치는 조회하지 않았고 조건부16판 대국도 실행하지 않았다.
기본 게임 모델은 유지한다.

## 점수 오차와 추천수 일치가 함께 개선되지 않은 이유

이전 보존 후보의 기존263위치 MSE는62,807.95→62,230.91, leaf 선택32위치 MSE는
146,450.88→144,329.25로 줄었다. 그러나 미학습16위치에서 추천수 일치는4→4개였고,
실제로 바뀐 두 수도 교사 추천수와 일치하지 않았다. 교사 평가상 평균 이득은4.375cp였다.

이전 실제 leaf 자료126개는 다양한 탐색 가지에서 뽑은 위치다. 이 중 최종 선택수 가지에
속한 표본은53개, 완료된 탐색 회차의 표본은42개였으며, 최종 root 점수와 같은 정적 값을
재현하는 표본은0개였다. 모두 실제로 평가한 위치이지만 최종 경쟁수의 백업 점수차를
직접 가르치는 자료는 아니었다. 당시 비교26/16쌍도 leaf 추가 전의 즉시 자식 쌍과
바이트 단위로 같았다. 전체 평균 오차를 줄이는 것과 경쟁수의 순서를 뒤집는 것은 다르다.

이전 선택용16쌍에서 예측 점수차의 변화는 평균 절댓값3cp였고, 순서 오답10개가
그대로였다. 이전 미학습16위치의 실제 탐색점수 변화도 평균 절댓값7.69cp, 최대16cp였다.
교사와 다른12위치 중11곳은 교사 추천수의 즉시 자식 점수도 여전히 낮게 평가했다.
예를 들어 한 위치의 교사 수 열세는368cp에서359cp로 줄었지만 순서는 바뀌지 않았다.

다만 이전 출력 PV의 끝을 정적으로 평가하면 두 모델의32회 모두 root 점수와 수치상
일치했다. 따라서 PV 끝이 항상 잘못됐다고 결론 내리지 않는다. 새 구현은 수치 일치를
추정하는 대신 실제 평가 호출·완료 회차·전체 기보가 일치하는 영수증을 요구한다.
이 진단은 기존 공개된 결과만 읽었으며 추가 엔진 실행·교사 질의·학습은0회였다.

## 구현: 후보 수별 탐색 끝 위치를 검증한 비교 MSE

같은 root에서 교사 추천수와 현재 Regicide가 선택한 수를 각각 첫 수로 강제한다.
깊이3, 최대10,000노드로 탐색하며 TT·PVS·LMR을 끄고 root 전체 점수 범위를 사용한다.
깊이를 완료하지 못하거나 무승부 조정·메이트·체크 상태·점수 제한이 개입한 결과는 제외한다.
일반 대국의 탐색 코어와 선택 규칙은 바꾸지 않았다.

채택하려면 최종 PV의 끝이 그 회차에서 실제 호출된 NNUE 평가 위치여야 한다.
초기 FEN부터 전체 기보를 재생하고, native 전체 평가·Python 정수 평가·기록된 값이
같으며 그 값이 후보 수의 최종 root 점수까지 백업됐는지 확인한다. 관측값 전체를
덤프하지 않고 확인된 증거와 관측 수를 저장한다.

학습 정답은 두 첫 수를 둔 직후 위치의 Stockfish18 확정 점수차다. 학습 입력은
각 강제 탐색을 뒷받침한 leaf다. 따라서 이 정답은 **root 자식의 가치를 대응시킨
대리 목표**이며, Stockfish가 해당 leaf를 직접 평가한 점수라는 뜻은 아니다.
고정된 현재 탐색 경로를 통한 수 선택 개선 가설이다. 재학습 뒤 최선 경로가 달라질 수
있으므로 실제 수 선택은 별도로 검증해야 한다. 교사 점수차의 부호를 임의로 바꾸거나
교사 추천수가 항상 더 좋다고 가정하지 않는다.
여기서 확정 점수는 탐색 로그에 상한·하한 표시가 없는 CP라는 뜻이며, 제한된 교사
탐색이 체스의 완전한 정답이나 해당 수의 절대적 우위를 증명한다는 뜻은 아니다.

## 자료와 재현성

기존 점수 자료는 TRAIN1,520개·선택369개·기존 사후점검69개를 바이트 그대로 사용한다.
이 안의 실제 탐색 leaf94/32개는 이전에 수집한 자료다. 이번에 새로 추가한 point는0개다.
기존 즉시 자식 비교26/16쌍도 그대로다.

이번 수집은 기존64개 root의 일반 수 선택64회, 강제 후보 탐색84회,
Stockfish root64회·root 자식80회로 진행했다. 이미 교사와 같은 수를 고른22개,
완료된 백업 증거가 없는2개는 신규 비교에서 제외했다. 교사는 깊이10 또는100,000노드
중 먼저 도달하는 한도에서 멈추고, 마지막 점수 패킷의 확정 CP만 사용한다.

최초 `data-001`에는 새 비교32/8쌍이 있었다. 검증 단계에서 기존 비교와 root·후보 수
조합이 같은 TRAIN3쌍이 확인됐다. `data-001`과 원래 영수증·소스는 보존하고,
완료된 자료에서 중복만 제거한 `data-002`를 정식 학습 자료로 고정했다. 추가 질의·탐색·학습은
하지 않았다. 최종 신규 비교는29/8쌍, 기존 자료와 합치면55/24쌍이다.

root·직접 자식·native PV·교사 PV·leaf의 기물 입력과 선후공 반전 입력을 정규화해
분할 간 중복과 새 검사 위치 중복을 확인한다. 같은 입력으로 합쳐지는 두 leaf도 거부한다.
새 검사16위치는 기존 M2 계열의 고정된 합법적 조용한 수4개로 연장해 사전에 분리했다.
root와 모든 합법 자식604개 입력은 기록된 과거 노출과 겹치지 않는다. 개시 계열 자체가
외부의 완전히 새로운 표본이라는 뜻은 아니다.

## 유지한 학습 조건과 보호

NNUE v3의 기물768+상대 차례1·은닉16·S32, MSE, Adam·학습률·시드20261020·배치128을
유지한다. 기존 TRAIN1,426개에서 시작 모델 출력과의 보존 MSE 가중치4도 그대로다.

```text
학습 손실 = 교사 위치 MSE
          + 기존 즉시 자식 쌍과 새 백업 leaf 쌍의 점수차 MSE
          + 4 × 기존 TRAIN에서 시작 모델 출력과의 MSE
```

계열을 섞어 각 비교를 회차마다 한 번 사용한다. 정수 TRAIN 손실이 늘어나는 제안은
축소하거나 건너뛰고, 선택 자료는 미분에 사용하지 않는다. 5회마다 선택 위치+점수차 MSE를
확인하되 기존263위치 MSE가 시작값62,230.91을 넘으면 채택하지 않는다. epoch0 보호,
조기 중단·최적 가중치 복원·미학습 검사와 분리한 모델 선택을 모두 유지한다.

SHA256은 `85e3032a87f3145670aa666f8e1359a610c08937f5f0a20cb14ad81dfd507b33`이다.
표의 중간 가중치는 채택된 최종 모델의 개선치가 아니다. 이번 기록은 현재 절차가
새 비교 학습과 기존 검증을 동시에 만족하지 못했다는 근거이며, 현재 구조에서 개선이
불가능하다는 증거나 강화 성공의 증거는 아니다.

## 미학습 검사·대국·정확성

새16위치 검사는 후보를 고른 뒤 한 번만 실행하고, 확정 점수12위치 이상·추천수 일치
2개 이상 증가·평균20cp 이상 개선·200cp 이상 악화0개·계산 불일치0개를 모두 만족해야
기본 Regicide와16판을 두도록 미리 고정했다. 이번에는 다른 후보를 얻지 못해 검사
위치의 교사 질의와 native 탐색을 모두0회로 남겼다. 검사 실패로 측정한 것이 아니라
**검사 전 보호 기준에서 탈락**한 결과다. 새 검사와 조건부 대국은0회·0판이다.

Python·native 전체·증분 계산은2,078위치에서 불일치0개였다. native 모델 검사는
13개 그룹·25,521개 단언·실패0개다. 새 수집기의 별도 검사는6개 그룹·72개 단언으로
특수 수·완료 회차·백업 증거·잘못된 PV 거부와 기본 탐색의 동등성을 확인했다.
계산 정확성 통과를 수 선택 또는 경기력 개선으로 해석하지 않는다.

다음 가설은 **입력·은닉 표현을 고정하고 기존 출력 가중치16개만 보정하는 제한 학습**이다.
입력 가중치·은닉 bias·차례 가중치는 고정한다. 현재 모델에는 별도 출력 bias가 없으며
이를 추가하지 않는다. 현재 구조와 MSE·보존 손실·모든 보호 기준을 유지하면서 공유
표현 전체가 흔들리는 범위를 줄일 수 있는지 한 번 확인하는 방향이다. 효과는 아직
실험하지 않았으며 이번 작업에서 추가 구현·학습은 진행하지 않았다.

원자료와 영수증은 `docs/checks/2026-10-22-nnue-choice/`에 있다.
핵심 파일은 `diagnosis.json`, `data-002/manifest.json`, `data-002/assembly-receipt.json`,
`attempt-001/training.json`, `attempt-001/selection.json`, `attempt-001/validation.json`,
`attempt-001/screen-decision.json`, `peer-review.json`이다.
