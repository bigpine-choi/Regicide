# 통과폰·폰 구조 평가 동값 최적화 v0.5.7

기준일: 2026-10-18 한국 시간. [계획](2026-10-18-pawn-opt-plan.md)에 따라 기존 폰 평가의 점수와 설정을 유지하며 반복 계산을 줄였다. 일반 기력이나 Elo를 측정하지 않았고, 중단했던 강도 대국을 재개하지 않았다. [폰 평가 원리](../PAWN_STRUCTURE.md)와 [원자료·재현 방법](../checks/2026-10-18-pawn-opt/README.md)을 함께 보존한다.

## 원인 조사와 구현

v0.5.6은 파일별로 폰 수를 세어 겹침·고립 감점을 만들고, 적의 같은/인접 파일을 자기 방향으로 각각 반전한 뒤 통과 조건을 검사했다. 이 과정의 고정된 산술·방향 변환을 줄이는 가설을 세웠다. 이전 기능 ON/OFF의 약24% 추가 비용은 전체 평가 함수의 차이이며 특정 연산 하나의 비용을 분리한 프로파일은 아니다.

첫 후보는 32바이트 표 항목과 백·흑 공유 순회를 사용했다. 동값 검사를 통과했지만 함수 단독 비용이 기본 설정에서 약5.1%, 방패 OFF에서 약7.5% 증가했다. `4db4d83d11a2070118ad5a5d9d1ffe63ca2a04b9`의 첫 측정과 채택하지 않은 결정을 보존했고, 로컬 설치는 하지 않았다.

두 번째 후보 `87943a6fb733323791f60cc83531fb49cd7d9030`은 다음을 적용했다.

- 원래 색별8파일 순회와 빈 자기 파일 건너뛰기를 유지한다.
- 폰 감점·최전방 보너스·적 전방 조건·앞 칸 오프셋을 256개의 **8바이트 항목**에 미리 계산한다. 감점 최저−96, 보너스 최고120, 마스크 최고127로 현재 저장 범위에 들어간다.
- 적 파일들을 합친 원래 방향의 마스크에 전방 조건을 AND한다. 반전 조회3회와 랭크 시프트를 매번 하지 않는다. 같은 랭크·뒤의 적 폰을 제외하는 조건은 정확히 같다.
- 통과 보너스가0인 랭크는 적 폰과 앞 칸을 검사하지 않는다. 보너스가 양수인 경우 기존 `/2`와 같은 0/1비트 이동으로 봉쇄 반감을 적용한다. 감점은 반감하지 않는다.
- 폰 표는 첫 후보8,192바이트에서2,048바이트, 전체 정적 표 합계는14,912에서8,768바이트다. 새 전체 보드 스캔·캐시·할당·외부 코드나 데이터는 추가하지 않았다.

표 크기와 순회를 함께 바꿨으므로 두 요인의 비용 기여를 개별적으로 확정하지 않는다. 이 후보는 함수 비용은 줄였지만 전체220쌍의 시간은 기본 깊이3/4/5에서 약0.93/0.45/1.66% 증가하는 방향이었다. 전체 탐색 개선으로 채택하지 않고 [후속 계획](2026-10-18-pawn-opt-followup-plan.md)과 원자료·독립 감사를 보존했다.

최종 후보 `4ee6dde974c6e250c93d52d2ae812586d92f7dce`는 압축 폰 표를 유지하고, 기물 위치 표에 **색·실제 칸·점수 부호**도 미리 계산한다. 예전과 같은 수식의 값을 조회하므로 흑 기물마다 좌표를 뒤집거나 점수 부호를 다시 곱하지 않는다. 기물 가치 합은 국면 혼합 밖에 따로 두어 정수 반올림을 보존했다. 전체 표는13,376바이트로15KiB 한도 이내다. 통과폰·겹친 폰·고립된 폰과 왕 앞 방패의 계수·중반/종반 수식·마지막 단일 나눗셈·기본 옵션 및 탐색 규칙은 유지한다.

## 함수 단독 비용

Ryzen AI 7 350(8코어/16논리CPU), Windows11, MSVC C++20 `/O2 /W4 /WX`, 각 소스 별도 객체 `/GL-`에서 측정했다. 자체 고정58위치, 동일 호출 수·9블록×4균형 순서를 사용한다. 보드 생성·입출력은 시간에서 제외한다. 측정 전에 v0.5.6과 네 옵션232회 및 기존 v0.5.4와 구조 OFF116회가 일치했고, 시간 중 old/new 체크섬도 방패별로 일치했다.

각 열의 중앙값 비율과 쌍별 비율의 중앙값은 계산 방식이 다르다. 첫 실패 후보·두 번째 후보·최종 후보의 절대 시간은 서로 다른 실행이므로, 각 실행 안의 균형 비교 비율을 해석한다. 두 번째 후보의 함수 비율0.936486/0.917432와 전체220쌍 결과도 별도로 보존한다. 이 결과는 기존 v0.5.5 비용으로 완전히 돌아갔거나 전체 엔진이19.57% 빨라졌다는 뜻은 아니다.

**220쌍 전부 같은 계산 결과**였다. 고정 깊이 표본에서는 기본 전체 시간이 약1.7~2.7% 줄었으나, 함수 단독의 약19.6% 감소가 전체 탐색에 그대로 적용되지는 않는다. 빠른 기능이 전체에서 차지하는 비중은 제한적이며 탐색·수 생성·통신 등의 비용이 남는다. 같은 시간 대국의 기력 향상이나 모든 위치에서의 개선을 입증한 결과는 아니다.

500ms 목표 CPU 표본에서 최종 함수 측정18.52초 동안 브라우저0.328 CPU초, 탐색21.19초 동안0.594 CPU초를 관측했다. 사용자가 대국을 멈춘 뒤 탐색을 측정했으며 당시 기존 설치 엔진은 실행되어 있지 않았다. 다른 프로그램의 부하는 존재했고 신규/종료·접근 불가 프로세스와 온도·클럭을 완전 관찰하지 못한다. 함수 측정과 전체 측정을 전용 하드웨어의 무부하 결과로 표현하지 않는다.

추천 장면 검사에서는 취소된 테스트 HTTP 연결의 응답 중 `WinError10053` 로그가 있었지만 synthetic38/live35 검사는 실패0으로 종료했다. 실제 설치 창에서 추천 ON/OFF도 별도로 확인했다. 모든 표준 오류가 빈 로그였다고 주장하지 않는다. 기존 v0.5.6 기록의 Godot 합계 오기는 원본637+40+82+38+35+53+78=963으로 바로잡았다.

기존 설치본·바로가기·개인 기보138파일을 백업했다. 최근 대국은 이미 종료되어 저장된 상태였으므로 그 원본을 보존했다. `desktop/pawn-structure-opt`에 검증한 v0.5.7을 반영했고, 기존138파일과 바로가기의 해시가 유지됨을 확인했다. 개인 경로·기보·접속 파일·토큰은 공개 증거에 넣지 않는다. 검증/설치 실행 파일의 SHA256은 `b9a7c733388714f4b11d4678f270cc56d8c68e4bc015992e6e08a7b4bf2ab6dc`다. 실제 창의 버전·backend 코드/바이너리 식별자, 기본 옵션, Nf3 추천 화살표 ON/OFF를 확인하고 착수0·추천 OFF로 두었다. [공개 설치 확인](../checks/2026-10-18-pawn-opt/installation-public.json)에 결과를 남긴다. 이후 기록 커밋은 실행 코드를 바꾸지 않으며, 원격 CI 결과와 로컬 검증을 구분한다.
