# NNUE 참패 진단과 MSE 학습 조기 중단

2026-10-22 KST. 이전0승1무15패의 기보·학습·자료를 분석하고, 검증 오차가 나빠지면
학습을 중단해 최적 가중치를 복원하도록 구현했다. **MSE와 현재 v3 NNUE 구조는 유지했다.**
새16판은 기본 수식 Regicide에 **2승3무11패·3.5/16점(21.875%)**,141.704185초였다.
오류·미완료·미시작0, 독립 감사PASS. 직전보다 높은 점수지만 표본이 작아 일반적인
기력 개선을 확정하지 않는다. 이번 후보도 기본 엔진에 열세라 기본 모델은 유지한다.

## 무엇이 확인됐나

1. **훈련 자료에만 맞춰지는 현상.** 학습350위치에500회 학습하고 마지막 모델을 쓰면서
   학습 MAE205.48→78.22cp, 검증158.06→221.73cp가 됐다. 자기대국 위치와 합성 종반
   양쪽에서 검증 오차가 악화됐다. 자료 평균 기물 수16.2개,28개 이상은41개여서 초중반
   대표성이 제한적이다. 자료 분할의 기보 계열·기물 특징 중복은 없었다.
2. **실전의 낙관적 오평가 사례.** 첫 판 `4.Qd2`에서 실패 망의 백 점수는+220→+313cp였지만
   Stockfish 진단은-48→-174cp였다. `8.Nh4`도 Stockfish는-76→-232cp인데 실패 망은
   +254→+431cp였다. 평가가 나쁜 수를 오히려 좋게 보는 구체적 사례다.
3. **전면적인 부호 오류나 속도 병목의 증거는 부족.** 시작 배치의 기물 제거30검사에서
   평가 부호는 모두 정상이다. 두 쪽 평균 노드·응답 시간도 비슷했다. 다른 검색 나무라
   이것만으로 속도 동등성을 입증하지는 않지만, 속도 부족을 참패 원인으로 볼 근거는 없다.

진단에는 기존 자료와16회 Stockfish10,000노드 질의만 사용했다. 진단 질의는 학습 라벨로
추가하지 않았다. 위 사례는 전체15패의 원인을 모두 규명했다는 뜻이 아니다.
[상세 진단](../checks/2026-10-22-nnue-overfit/diagnosis/README.md)에서 확정 사실과 가설을 구분한다.

## 구현한 과적합 억제

`neural_stm_guarded.py`는 기존 MSE·정수 QAT·Adam·배치 순서를 유지하고 다음만 추가했다.

- 학습 전 가중치를0회째 후보로 보존한다. 실패한500회 모델을 초기값으로 사용하지 않는다.
- 매5회마다 역전파에서 제외한81위치의 실제 정수 예측 MSE를 계산한다.
- 가장 작은 MSE의 가중치를 별도로 복사한다. 동점이면 먼저 나온 모델을 유지한다.
- 5번 연속 평가에서 유의미한 개선이 없으면 중단한다. 중단 판단의 최소 개선폭은1cp²다.
  이보다 작은 개선도 최적 체크포인트에는 저장한다.
- 종료 시 마지막 모델 대신 저장한 최적 가중치를 복원한다.

원리는 [검증 기준 조기 중단과 최선 가중치 복원](https://keras.io/api/callbacks/early_stopping/)과
같으며 기존 NumPy 학습 코드에 직접 구현했다. 새 라이브러리나 신경망 층은 추가하지 않았다.

이전과 동일한350학습·81선택용 위치, 초기 실수 배열, seed20261020·batch128·최대500회,
입력/편향/손번 학습률0.0002·출력0.005·S32를 고정했다. 실제 학습은1회0.232204초,
**40회에서 중단하고15회째 모델을 복원**했다. 기존500회 학습 기록의 첫40회와 새 기록이
정확히 일치한다. 이는 중단·선택 외의 계산을 바꾸지 않았다는 추가 증거다.

| --- | ---: | ---: |
| 학습 전 가중치 | 205.4771cp | 158.0617cp |
| 이전 마지막500회 모델 | 78.2200cp | 221.7284cp |

선택 MSE는 초기46,871.81→45,014.38cp²로 줄었다. 이전 실패 모델은76,281.93cp²다.
81개는 이미 분석한 자료를 이번 선택에 사용했으므로 **새 독립 검증이 아니라 튜닝 자료**다.
이 수치의 개선 자체를 일반화나 Elo의 증거로 삼지 않는다. 추가 시드·재학습·설정 탐색은 없다.

선택 후 기존 노출 진단 사례를 다시 평가한 결과 `Qd2`는-70→-106cp, `Nh4`는-169→-190cp로
나쁜 방향을 반영했다. 오평가 방향은 개선됐지만 Stockfish와 손실 크기까지 같아진 것은 아니다.
이 재검사는 모델 선택에 사용하지 않았고 새로운 탐색이나 라벨 생성도 하지 않았다.

## 정확성과16판

조기 중단 단위9개를 통과했다. 기존 Adam과의 일치, 최적/0회째/동점 가중치 복원,
중단 조건, 체크포인트 복사, 검증 자료의 역전파 제외를 확인했다.
새 가중치477위치의 Python/전체/증분 점수0불일치, native 모델13그룹25,521단언0실패였다.
기존 실행 파일과 모델 호환성 회귀는 해시로 재사용했다.

기본 쪽은 classical profile 전체 옵션과 같고 NNUE/보정망을 끈다. 후보 쪽은 NNUE 활성과
모델 파일만 바꾼다. 양쪽 같은 `build-m3-stm/regicide.exe`,100ms·Move Overhead20·Hash16·
검색1스레드·8개시 각 양색16판·claim 무승부·500ply 상한이다. AMD Ryzen AI7 350,
8코어16논리CPU의 Windows 공유PC를 사용했다. 새 감시·부하 중단 체계는 만들지 않았다.

13판 체크메이트·3판 반복무승부로 종료했다. 독립 감사1회4.55초에서 고정 입력24개,
원본 교사 질의·라벨·수순·선택 규칙·기존 학습 기록과의 일치, 대국1,816ply·검색1,724회·
PV9,116ply·최종FEN·규칙 종료·2승3무11패를 확인했다.

학습 코드 커밋 `fcc378537efe03aaefd288932db1307f2531664d`, 실행 계획 커밋
`6333ea7a9576ce8f1e647ae3e568c5da00a6b363`. 대국 시작 시 작업 트리는 깨끗했다.
