# 최근 5패 핵심 위치 진단·회귀 계획

2026-10-18 한국 시간. 대상은 채택된 브라우저 제거 재대국 `docs/matches/2026-10-18-lmr-idle-rematch/match-200ms.json/pgn`의 v0.5.8 패배 game1·3·9·13·16이다. 제외된 재시도와 최초 부하 대국은 대상에 합산하지 않는다. 이 계획은 새 외부 분석 결과를 보기 전에 고정한다.

## 질문과 변경 범위

같은 평가 함수에서 더 많은 탐색으로 문제 수를 피하는지, LMR ON만 놓치는지, 정적 평가/탐색 경계에 설명되지 않은 불일치가 남는지를 구분한다. 외부 엔진 불일치만으로 평가 버그를 확정하지 않는다. 엔진의 수 선택·평가 계수·LMR 조건은 바꾸지 않고 진단 도구·회귀 자료만 추가한다. 로컬 대국 설치본은 교체하지 않는다.

## 고정 입력과 표본 선정

- Regicide v0.5.7 SHA256 `b9a7c733388714f4b11d4678f270cc56d8c68e4bc015992e6e08a7b4bf2ab6dc`, v0.5.8 SHA256 `17b079ba319ba7ce8a94c0a78a201d40840b57cda452c9965d5a3d0039400ed1`의 기존 실행 파일을 재사용한다. 소스 기준은 각각 `5b5b5deedbef96133836609ec00229c7a548a15a`, `157305d804bc1828641a7e8d9b9b793b7746bcc3`이다.
- 독립 참고는 기존 Ubuntu Stockfish16 `16-1build1`, 바이너리 SHA256 `00628bd9c9855c1b7ff93d7f8d51b413586cdc6336fe637f9a14a61531a05aca`다. 단일 스레드·Hash32MiB·기본 NNUE·강도 제한 OFF·테이블베이스 미사용, 매 질의 캐시 초기화로 고정한다. GPLv3 외부 분석 도구이며 코드/가중치/실행 파일을 Regicide에 통합하거나 재배포하지 않는다. [원저자 출처](https://github.com/official-stockfish/Stockfish/releases/tag/sf_16).
- 5패의 모든 후보 착수 직전 위치를 전체 실제 수 이력으로 재생하고, Stockfish 각각50,000노드의 자유 검색과 실제 수 강제 검색을 한다. cp와 mate·상하한을 분리한다.
- 각 패배에서 외부 유한 탐색의 최선값이 -300cp 이상인 상태의 첫100cp 이상 하락 후보와 그 조건에서 가장 큰 cp 하락 후보를 고르고 중복 제거한다(최대2개/판). 방어 가능한 위치에서 강제 패배 메이트로 바뀌는 신호도 첫 후보로 삼는다. 조건에 맞는 후보가 없으면 유한 cp 하락 최대 위치1개를 대체 표본으로 표시하며 이미 불리한 상태였는지 공개한다.
- 보조 위치는 game3/4가 공유하는73반수 뒤 흑 차례다. 실제 v0.5.7의 `f3f2`와 v0.5.8의 `d1e2` 분기를 비교하되 이를 여섯 번째 패배로 세지 않는다. game1/2·9/10·13/14의 동일 전체 수순도 LMR 고유 손상 판정의 대조 자료로 삼는다.
- 선정 위치 각각에서 외부 자유/실제 수 강제를1,000,000 및4,000,000노드로 재검사한다. 두 한도의 판단이 불안정하면 원인 미확정으로 둔다. 유한 외부 점수는 정확한 최선 수나 공통 cp 척도가 아니다.

## 자체 탐색과 정적 관찰

- v0.5.7, v0.5.8 LMR OFF/ON을 원대국의 기록 노드 한도와250,000·1,000,000·3,000,000노드에서 비교한다. 시간으로 중단하지 않는다. 동일 노드가 동일 시간/깊이라는 뜻은 아니다. 원래 시간 중단 위치와 노드 한도 재생의 선택이 다르면 그 사실도 남긴다.
- 선정 위치에 깊이6·최대5,000,000노드의 별도 비교를 둔다. 요청 깊이를 완료했는지 구분하고, ON의 같은 명목 깊이를 OFF와 동일 탐색으로 간주하지 않는다. v0.5.7과 v0.5.8 OFF의 수·점수·노드·깊이·PV·TT 동작 일치는 자체 진단기의 검증 기준이다.
- 자체 UCI는 `searchmoves`를 지원하지 않는다. 대안을 둔 자식 위치를 탐색하면 전체 이력을 보존하고 관점과 메이트 거리를 보정하지만, 루트 강제 검색과 같은 실험이라고 부르지 않는다. 필요한 후속 질의는 별도 위치/예산으로 명시한다.
- 선택 전후·주요 수순 끝의 정적 평가와 방패/폰 구조 네 설정 값을 진단 전용 도구로 관찰한다. 주요 수순 끝은 TT 등에 의해 실제 평가 말단과 다를 수 있다. 설정 차이는 정수 반올림 때문에 정확히 가법인 평가 분해가 아니다. 체크/종료/청구 상태와 외부 판단을 함께 기록한다.

## 분류·회귀·완료 기준

1. **탐색 누락 근거:** 같은 평가·더 큰 예산에서 대안을 발견하고 외부 두 예산도 그 개선을 지지. LMR 영향은 ON/OFF의 같은 위치/자원 대조로 별도 판정한다.
2. **평가/탐색 경계 한계 후보:** 더 깊게 읽어도 문제 수를 선호하고 안정된 후속 위치의 정적 판단과 독립 근거가 어긋남. 외부와 다르다는 이유만으로 계수 오류를 확정하지 않는다.
3. 공유 취약점·강제 패배 전환·미확정/혼합을 허용한다. 5판의 패배를 반드시 서로 다른 원인5개로 분류하지 않는다.
4. 전체 이력·FEN·선택/PV 합법성·관점/메이트/상하한·출력 보호·부분 실패를 자동 검증한다. 알려진 약점 목록과 해결을 요구하는 확정 전술 회귀는 분리한다. 재현 검사 PASS를 기력 문제 해결로 표현하지 않는다.
5. 기존 Windows/Linux 핵심 규칙·탐색·평가와 독립 규칙 비교/UCI 검증을 유지한다. 새 도구 테스트와 기존 검사 결과를 구분한다. 시간 성능·대국 강도 재측정은 이번 범위에 없다.
6. 원자료·입력 해시·예산/옵션·도구/출처·해석·미해결 문제를 보존하고 독립 검토를 받는다. 개인 기보·접속 정보·외부 실행 파일은 공개하지 않는다. 검증 뒤 GitHub에 커밋/푸시하고 실제 원격 SHA를 확인한다.
