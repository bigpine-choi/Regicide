# 1/32 학습 모델의 첫 동일 시간 대국 계획 — 2026-10-19

이 계획과 입력 해시는 첫 대국 전에 고정한다. 학습·보류 자료의 정적 점수 오차 개선이 실제 같은 시간의 수 선택에서도 유리한지 확인하는 첫 시범 비교다. 대국 결과를 보고 모델·탐색·시작 위치·판수·시간 조건을 바꾸지 않는다.

## 비교 대상

- 양측은 같은 MSVC 최적화 실행 파일의 두 복사본이다. SHA256은 모두 `598ebec433334b2ce053d0ed6b143fbfd34f9dd3a76557adb62764dcd940c705`다. 별도 경로는 기존 CPU 감시기가 두 UCI 역할을 구분하기 위한 것이다.
- 기준은 기본 기존 평가기(`UseNeuralEvaluation=false`), 후보는 전체/증분 일치를 검증한 학습 모델을 증분 평가로 사용한다.
- 모델: `docs/checks/2026-10-19-neural-precision/selection/model.nnue`, SHA256 `c9ca5f35bb0ef0f61fca9b7eba10cd01d4320cf6c2a1dd4863630b7f87baaa92`, 체크섬 `12850805878070247189`.
- 실제 UCI 파일 불러오기 응답을 첫 대국 전에 보존한다. `configure()` 반환만으로 모델을 불러왔다고 판단하지 않는다.
- 양쪽 단일 탐색 스레드, Hash 16MiB, Move Overhead 20ms, PVS·SEE·안정화·조용한 체크·수 정렬·빠른 수 적용은 같은 기본값이다. 후보만 NeuralModelFile 및 신경망 평가를 지정하며 증분 평가는 기본 true와 같게 명시한다. 실제 광고 기본값과 유효 옵션을 비교한다.

## 새 시작 위치와 판수

[시작 수순 8개](../../tests/data/neural_strength_openings_2026-10-19.json)는 엔진의 점수·검색·수 추천·대국 결과 없이 손으로 정했다. Italian, Alapin, QGD, KID, Caro, French, English, Reti 계열의 13~17ply 위치다. 백 차례 4개·흑 차례 4개이며 각 위치에서 후보 백 → 후보 흑의 두 판을 진행한다. 한쪽의 초기 이점을 그대로 후보 효과로 세지 않는다.

오프닝 파일 SHA256은 `a52e4bff47b28499a242288612cc745da53075ebe0c7d99080c5288863e271e3`다. 과거 338개 대국 궤적·563개 오프닝 선 및 학습/검증/보류 5,686행 등에서 얻은 고유 기물 입력 26,735개와 색·랭크 반전까지 대조해 중복 0을 확인했다. 출처 154개 파일의 해시와 정확한 수집 범위를 `openings-audit.json`에 기록한다. 이전 무작위 학습 원자료의 미채집 위치 전부까지 검사했다는 뜻은 아니다.

처음 검토한 순수 무작위 합법 8~12ply 안은 SAN·기물 배치만 살핀 단계에서 정상 오프닝 시범 비교와 거리가 있어 폐기했다. 이후 고른 손수순의 KID 끝 위치가 과거 대국 입력과 겹쳐, 점수·결과를 보기 전에 `c6e7 f3e1`을 추가했다. 다른 7개 수순은 그대로 유지했다. 이 설계 변경의 시점과 이유를 감사 기록에 남겼다.

고정한 전체 8개로 **100ms/수 16판**, 이어 같은 8개로 **1,000ms/수 16판**, 총 **32판**이다. 작은 수작업 표본이며 체스 전체의 대표 확률 표본이 아니다. 시간 조건마다 독립 비교 단위는 시작 쌍 8개다. 결과에 따라 추가 판수나 위치를 고르지 않는다.

## 시간·종료·실행 조건

요청 시간 100/1,000ms에 동일한 20ms 여유를 빼므로 내부 예산은 80/980ms다. 매 수 실제 전체 이력을 보낸다. 각 판 시작에는 새 game token으로 `ucinewgame`을 보내며 전이표를 초기화한다. 각 시간 묶음의 두 프로세스는 유지하고, 첫 전이표 할당을 숨기는 별도 탐색 워밍업은 하지 않는다.

기존 `compare_engines.py`가 python-chess로 합법 수·승패를 판정하고 PGN/JSON을 저장한다. 현재 또는 합법적인 예정 수로 가능한 3회 반복·50수 무승부는 항상 청구한다. 최대 총 500ply이며, 한도·오류·중단은 무승부가 아닌 미완료 `*`로 보존한다. 묶음 16판이 모두 정상 종료하지 않으면 그 묶음을 유효 비교로 채택하지 않는다.

이 실행기는 엄격한 벽시계 시간패 대회가 아니다. 수별 요청 시간·엔진 보고 시간·실제 경과를 보존하고 초과 분포를 보고한다. python-chess 통신 제한은 요청 시간에 30초를 더한 값이며, 기존 실험에 없던 별도 강제 몰수 시계를 추가하지 않는다. 종료가 빨라 요청 시간을 덜 쓴 수 역시 그대로 기록한다.

실행 환경은 AMD Ryzen AI 7 350, 8코어/16스레드 Windows 11, Python 3.13.16·chess 1.11.2다. 두 엔진은 차례로 생각한다. 정확한 환경·컴파일 근거·실행 명령을 원자료에 저장한다.

## 사전 검증·동결·부하 감시

엔진 코드는 수정·재빌드하지 않는다. 직전 정밀도 실험의 빌드 소스/실행 파일 해시가 현재와 같음을 확인하고 같은 파일을 복사한다. 새 대국 전 규칙 8,325개, 실제 모델 26,566개, 규칙 차등 2,997사례, 엔진 통합 19그룹, 기존 비교기 10사례와 CPU guard 18검사 및 새 driver 검증을 확인한다. 새 시작 위치는 이 검증의 탐색 입력으로 사용하지 않는다.

`freeze.json`은 엔진 커밋, 런타임·대국·감시·감사 소스 해시, 바이너리·모델·오프닝·시작 위치 감사·사전 검증 해시, 옵션·시간·판정·통계 설정을 묶는다. 새 실험 도구는 이번 작업 트리의 정확한 바이트로 식별하며 엔진 소스 커밋과 구분한다. 각 묶음 전후 해시와 HEAD를 확인한다. 모델·엔진·선택 결과는 변경하지 않는다.

기존 native Windows CPU 감시기의 의미를 유지한다. 각 묶음 전 10초 연속 유휴, 약 0.5초 샘플·수/게임 경계 확인, 최대 2초 샘플 간격, 비교 엔진은 PID·생성시각·부모 관계와 실제 UCI transport로 두 역할을 확인한다. 소유 엔진 외 알려진 엔진의 누적 CPU 증가를 0 tick까지 요구한다. 외부 엔진의 출현·소멸·접근 불능 또는 감시 실패도 정상 비교로 처리하지 않는다.

외부 부하/신원 변화/샘플 간격 실패 등 사전에 구분한 기술적 감시 실패만 해당 시간의 전체 16판을 새 순번 폴더에서 다시 시도할 수 있다. 최대 시도는 시간 조건별 3회다. 첫 정상 묶음만 채택하고, 깨끗하게 끝난 불리한 결과는 재실행하지 않는다. 모든 실패 시도는 삭제하지 않고 이유·부분 수순과 함께 보존한다. 엔진 오류·500ply 한도는 단순히 좋은 결과를 얻기 위한 재시도 사유가 아니다. 한 조건의 실패는 다른 사전 계획 시간 조건의 실행을 취소하는 이유로 삼지 않는다.

사용자 대국이나 외부 프로세스를 중지·종료하지 않는다. 계속된 외부 부하로 유효 비교가 불가능하면 유효 결과가 없다고 보고한다. 절전 억제는 실행 중 임시 요청이며 종료·실패 모두 이전 상태를 복원한다. 다른 앱의 CPU 부하, 열·전력·스케줄링, 샘플 사이 잠깐 실행된 미관측 프로세스까지 배제하는 계측은 아니다.

## 결과·한계·독립 감사

각 시간 조건의 신경망 승·무·패·득점률과 색상별·시작 쌍별 결과, 미완료·오류·시간 초과를 따로 보고한다. 두 시간 조건을 독립 32게임 집단으로 합쳐 기력 향상을 주장하지 않는다.

기존 비교기의 시작 쌍 전체를 복원 추출하는 seed `20261017`·20,000회 percentile bootstrap 구간을 기술 통계로 제시한다. 시작 쌍이 8개뿐이고 표본 분산이 작으면 구간이 퇴화할 수 있으므로 이를 일반적인 신뢰구간이나 Elo로 바꾸지 않는다. 50%를 포함하거나 조건별 결과가 엇갈리면 우위를 입증하지 못한 것으로 보고한다. 유리한 작은 표본 결과라도 보편적인 기력 향상·안정판 승격은 별도 판단이다.

모델이 다른 위치의 평균 노드·깊이 차이는 같은 위치의 탐색 속도 증거가 아니다. 별도 고정 깊이 벤치마크나 경기 중 모델 조정은 하지 않는다. 비교기는 같은 모델의 증분/전체 일치 실험과 분리된 실제 승패 증거를 만든다.

경기가 끝난 후 독립 감사 도구가 모든 실제 수·PV·종료·반복 청구·FEN·PGN·득점·시간과 시작 위치·색상·옵션·모델·소스 해시, PID 및 CPU 감시 원자료를 대조한다. 모든 시도와 채택 이유를 기록하고 원자료·사전 계획·검증·감사 결과를 함께 보존한다.
