# 분석모드 오프닝 통계 구현·검증

- 기준: `feat/nnue-incremental`, `c8cc439bd9107a51caa5db7aba8dad478c9dc3e1`.
- 환경: Linux x86-64, GCC 13.3, Release, Python 3.12.14, `chess==1.11.2`, 공식 Godot 4.7.2.
- 범위: Godot 분석·기보 재생의 포지션 통계. C++ 엔진 수 선택은 변경하지 않음.

## 구현

1. 대국과 별도 보드·revision을 가진 자유 분석. 양측 착수, 한 수 무르기·다시
   두기, 초기 배치, FEN 시작, PGN 내보내기.
2. 내 완료 PGN의 포지션별 표본·결과·다음 수 집계. 미완료·핸디캡 제외,
   수순 전환·반복·파일 변경 반영.
3. 선택형 Lichess 마스터 API. 백엔드 환경 토큰, 요청 직렬화·중복 합치기·LRU
   캐시·429 대기, 별도 실패 상태.
4. 350ms 조회 지연과 FEN·출처·요청 세대 검사. 대국·추천·형세와 분석 상태를
   분리하고 통계 조회에서 대국 잠금을 사용하지 않음.

실제 통합은 격리된 테스트 PGN 3판을 사용했다. UI에서 분석 시작 후 e4로 표본
3판에서 2판, e5로 1판이 되었고 무르기·다시 두기에서도 2판·1판으로 복원됐다.
시점을 뒤집어도 백승 100%의 의미가 유지됐다. 토큰을 명시적으로 비워 온라인
출처의 인증 안내를 확인했고 외부 네트워크 호출은 0회였다. 전후 실제 대국의
전체 상태와 보관 폴더 파일 바이트가 같았다.

검증 로그는 실행 시 `build/opening-stats-validation/`에 생성한다. CI의 기존
Linux/Windows 검증에도 신규 테스트를 연결했다. 여기에 기록한 실행 결과는
Linux 검증이며 Windows CI 완료를 주장하지 않는다.

## 검증 한계

인증된 Lichess 성공 응답은 고정 데이터 주입으로 검증했다. 실제 무인증 요청은
401을 확인했으며 사용자 토큰으로 성공 응답을 실조회하지 않았다. 네이티브
렌더링 스크린샷 검증은 수행하지 않았다. 통계는 과거 기보의 관측 결과이며
승률 예측이나 Regicide의 Elo 향상에 대한 실험은 아니다.
