# 갬빗 보스 대 Stockfish 18 제한 강도: 20판 탐색 결과

2026-11-02 KST. 이번 고정 수당 시간 조건에서 현재 보스 모드는 **Stockfish 제한 강도 설정 기준 대략 2400~2500 부근**으로 요약할 수 있다. 이는 Chess.com·Lichess·FIDE 레이팅이나 신뢰구간이 아니다. 20판 전체의 로지스틱 보조지표는 2481.9, 비슷한 상대를 탐색한 2차 8판만 사용하면 2426.4다. 설정당 4판뿐이므로 정밀한 기력 인증으로 해석하지 않는다.

## 실제 결과

모든 수는 앱과 같은 `HumanGame`의 보스 선택 경로에서 생성했다. Stockfish는 상대 역할만 수행했으며 보스의 수 선택에 사용되지 않았다. 표준 시작 위치에서 설정별 백 2판·흑 2판을 진행했다. 무승부는 0.5점으로 집계했다.

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1차 | 1320 | 4 | 0 | 0 | 100% | 0 |
| 1차 | 1700 | 4 | 0 | 0 | 100% | 0 |

| 2차 | 2500 | 0 | 3 | 1 | 37.5% | 0 |

16판은 체크메이트, 4판은 청구 가능한 3회 반복으로 끝났다. 점수 기반 승패 판정이나 임의 기권은 사용하지 않았다. 최대 300반수 제한에 도달한 판은 없었다. 사전에 정한 1차 12판이 전승이어서 상위 두 설정으로 확대했다. 이는 결과를 보고 상대를 선택한 탐색적 실험이며, 사전에 고정된 20판 리그는 아니다. [실행 전 계획](2026-11-02-boss-strength-plan.md)을 함께 보존한다.

## 실행 조건

- 보스 기능 기준: `4c2a0cedbe2f6b0eef32acf96f7d6bd8755d6be3`. 실험 하네스 포함 동결 커밋: `245231e33e250f7486133c169ae160894ff056f1`. 실험 중 실제 대국 소스 8개와 바이너리 2개가 변하지 않았음을 해시로 확인했다. 2차 시작 시 CI에 두 테스트 명령을 추가한 미커밋 변경은 있었으며 대국 소스는 동일했다.
- Regicide 0.7.0-dev: 고전 평가, `UsePieceActivity=true`, Hash 16MiB, 단일 스레드. 신경망 비교 실험이 아니다.
- Stockfish 18: `UCI_LimitStrength=true`, 설정별 `UCI_Elo`, Threads 1, Hash 16MiB, ponder 끔. UCI로 실제 설정과 광고된 범위를 확인하고 저장했다.
- 보스 기준 탐색 1,000ms + 상대 관찰·갬빗/미끼 검증 합계 최대 1,000ms. Stockfish는 수당 2,000ms 요청. 이는 명목 탐색 예산이며, 같은 실제 CPU 시간이나 같은 총시간 시계의 대국은 아니다.
- 실제 호출 경과시간 평균: 보스 1,175ms, Stockfish 1,938ms. 중앙값은 각각 1,128ms와 2,049ms다. 호스트 처리 시간과 통신 비용을 포함하며 CPU 시간 측정이 아니다.
- Ryzen AI 7 350, 8코어·16스레드, RAM 약 31.29GiB, Windows, Python 3.13.16, python-chess 1.11.2. 설정별 그룹을 병렬 실행했고 기존 사용자 게임은 종료하지 않았다. PC 전체 부하·열·스케줄링을 격리한 실험은 아니다.
- 시작 국면을 강제 갬빗으로 바꾸지 않았다. 실제 갬빗 선택, 상대 관측, 미끼 빈도 조절을 그대로 사용했고 매 대국 상대 프로필을 초기화했다. 같은 색 교대 쌍에는 같은 보스 시드를 적용했다.
- Stockfish의 약화 수 선택은 고정할 수 없는 난수를 포함한다. 보스 시드·환경·옵션을 기록했지만 동일 기보의 완전 결정적 재현을 약속하지 않는다.

## 수치의 의미와 한계

설정값 E의 상대에게 보스의 기대 득점을 `1 / (1 + 10^((E - R) / 400))`로 놓고 실제 득점과 맞춘 보조지표가 R이다. 전체 20판에서 2481.9이며, 별도 계산으로도 동일 값을 얻었다. 2500·2800과의 8판만 보면 2426.4다. 따라서 **2400~2500 부근**이라는 반올림된 설명을 사용하며 이 구간을 오차 범위로 제시하지 않는다.

전체 자료의 작업 모형상 likelihood 95% 범위는 2231~2730으로 넓다. 이 계산은 색 교대 쌍의 상관, 무승부 분포, 사후 수준 선택과 반복 관측을 보정하지 않았다. 통계적으로 보정된 Elo 신뢰구간으로 사용하지 않는다. 전승인 하위 설정의 정규 근사 득점 구간이 퇴화하더라도 확실성을 뜻하지 않는다.

[Stockfish 공식 UCI 안내](https://official-stockfish.github.io/docs/stockfish-wiki/UCI-Protocol-and-Stockfish-Commands.html#uci_elo)의 보정 조건은 120초+1초 및 CCRL 기준이다. 이번 고정 수당 시간 조건과 달라 사람의 온라인 레이팅으로 변환할 수 없다. [공식 강도 제한 설명](https://official-stockfish.github.io/docs/stockfish-wiki/Stockfish-FAQ.html#how-do-skill-level-and-uci_elo-work)에 있는 약화 방식 역시 사람의 실수를 그대로 재현하는 모형은 아니다. 보스도 상대의 실수 관측에 따라 위험 감수 빈도를 바꾸므로 하나의 고정 기력이라는 가정에 한계가 있다.

## 갬빗·함정이 실제로 사용됐는가

845회의 실제 보스 착수에서 등록 오프닝 도입 수는 16회였지만, 레퍼토리의 갬빗 희생 성립 지점에 도달한 경우는 **0회**였다. 단순 `e4`·`d4` 같은 준비 수가 등록 오프닝 선택으로 기록돼도 갬빗 성공으로 세지 않았다.

검증된 중반 미끼는 **2경기에서 3회** 선택했다. 상대가 기록된 미끼를 먹은 경우는 **0회**였다. 1700의 3번 경기에서 `cxb5`와 `Ra2`는 b5 폰을 `...axb5`로 잡으면 a파일이 열려 룩을 잃는 같은 구상이며, 상대는 각각 `O-O`, `Bb7`로 진행했다. 2500의 2번 경기에서 `d3+`는 e3 비숍을 `Kxe3`로 잡는 응수를 노렸지만 상대는 기록된 방어 분기의 첫 수인 `Kxd3`를 선택했다. 조건부 포획 분기를 독립적으로 다시 검증했으며 실제 미끼 포획 성공과 구분했다.

따라서 이 결과는 **현재 보스 모드 전체의 기력**이다. 갬빗이나 미끼가 승률을 높였다는 효과, 사람이 더 잘 속는다는 효과, 3~4수 뒤의 예술적인 응징을 실전에서 성공했다는 효과를 입증하지 않는다. 이번 표본에서는 원하는 갬빗 보스의 개성이 충분히 드러나지 않았다. 다음 개발 가설은 강한 상대라는 초기 가정과 오프닝 빈도 제한이 실제 갬빗 진입을 과도하게 막는지 확인하는 것이다. 이번 실험 중 정책은 수정하지 않았다.

## 검증과 원자료

새 하네스 단위검사 9개와 집계 단위검사 12개가 통과했다. 실제 경로의 짧은 2판 실행 검사에서는 길이 제한에 걸린 판을 승패에 섞지 않는 것을 확인했으며, 이 실행 검사는 위 20판에서 제외했다. 서로 다른 감사 작업으로 전체 PGN을 다시 재생하고 실제 보스 결정·이력·동일 깊이의 상대 관측·시드·옵션·종국·해시를 대조했다. 1,685반수 모두 기록과 일치했다.

[원자료 폴더](../matches/2026-11-02-boss-strength/)에 설정별 `match.json`·`match.pgn`, 전체 원본 파일을 담은 `raw-records.zip`, 파일별 해시 목록, 단계별·통합 집계, 두 종류의 독립 감사, 실제 경과시간 분석을 보관한다. 압축파일의 모든 항목을 원본 해시와 대조했다. 실행 파일은 포함하지 않았다. 기존 수정파일 16개와 바로가기 3개의 보존 감사도 함께 보관한다.

재실행 예시(출력 폴더는 항상 새 경로):

```powershell
.venv-tests\Scripts\python.exe scripts/boss_strength_match.py --stockfish build-m2-opponents/stockfish18/package/stockfish/stockfish-windows-x86-64.exe --elo 2500 --games 4 --boss-ms 1000 --stockfish-ms 2000 --threads 1 --hash-mb 16 --max-plies 300 --seed 20261102boss-phase2-2500 --classical --output-dir build/boss-strength-rerun-2500
```

실제 1차 시드는 `20261102boss-1320`, `20261102boss-1700`, `20261102boss-2100`; 2차는 `20261102boss-phase2-2500`, `20261102boss-phase2-2800`이다. 집계기는 `scripts/boss_strength_summary.py`이며 여러 `match.json`과 새로운 `--output` 경로를 받는다. 코드·대국 조건·보스 정책을 바꾸면 별도 실험으로 기록한다.
