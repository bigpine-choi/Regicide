# 2026-10-17 규칙 코어 검증

## 목적과 코드 식별

초기 합법 수 20개와 정확한 상태 복원을 첫 확인점으로 삼고, 특수 규칙을 포함한 합법 수 생성의 첫 기준 구현을 검증했다. 경기력 실험은 수행하지 않았다.

- 기준 저장소: `bigpine-choi/Regicide`.
- 구현 시작 기준 커밋: `241c95b328e848f06db9f79416b2f7b1a5a5220f`.
- 구현 브랜치: `feat/rules-core`. 이 기록을 포함한 커밋으로 버전을 고정한다. 문서만 뒤따라 바뀌면 구현 파일의 마지막 변경 커밋도 함께 확인한다.
- 핵심 언어: C++20, 외부 엔진 의존성 없음.
- 외부 검증: Python 3.13.16, `chess==1.11.2`; 시드 `20261017`, 32개 수순, 수순당 최대 100반수.
- 날짜: 2026-10-17, Asia/Seoul.

- CPU: AMD Ryzen AI 7 350 w/ Radeon 860M.

추가 확인:

- C++ 테스트 **20개 그룹, 8,325개 assertion, 실패 0**. perft, 깊이 3 divide 합계, 각 기준 포지션 깊이 2까지 수 적용/되돌리기 전체 상태 비교, 특수 수, 체크, 종료, 반복/수 카운터, 입력 거부를 포함한다.
- Windows CMake/CTest **1/1 통과**. 하나의 CTest 항목이 위의 모든 C++ 테스트 그룹을 실행한다.
- Linux AddressSanitizer/UndefinedBehaviorSanitizer: 위 C++ 테스트 전체 통과, 보고된 메모리/정의되지 않은 동작 오류 없음.
- Python 교차 검증: **2,997개 사례 모두 일치**. FEN, 합법 수의 정확한 집합, 종료 상태, 반복 횟수, 현재 위치의 무승부 청구 가능 여부를 비교했다. C++ batch 도구는 각 사례에서 모든 합법 수를 적용·되돌려 내부 이력까지 원상 복구되는지도 검사했다.
- 검증 사례는 표적 FEN의 모든 첫 응수, 시드로 고정한 합법 무작위 수순, 반복 수순과 50/75수 경계다. 무작위 수순은 경기력 평가가 아니다.

검증 중 핀 나이트가 공격하는 칸과 비숍의 칸 색을 테스트 작성자가 잘못 지정한 두 사례를 수정했다. 기준 perft 및 외부 기준 비교에서 수 생성 불일치는 발견하지 못했다. 이는 모든 포지션의 정확성을 증명한 결과는 아니다.

## 남은 제한과 다음 가설

- 복잡한 죽은 포지션은 일반 판정하지 못한다. 자동 판정 범위는 명확한 기물 구성 일부로 제한하고 API 이름에도 표시했다.
- FEN 이전의 반복 이력은 알 수 없다. 완전한 대국의 반복 판정에는 첫 위치부터의 수순을 보관해야 한다.
- 대국 관리자, UCI, 기보 저장, 탐색·평가·시간 관리는 아직 없다. Elo·최정상 인간 상대 경기력을 측정하거나 주장하지 않는다.
- 다음 가설: 검증된 합법 수 생성에 작은 기물 가치 평가와 alpha-beta 탐색을 붙이면 외부 엔진을 통해 수를 선택하지 않고 대국을 진행할 수 있다. 우선 완료 기준은 GUI/실행 도구 연결, 불법 수·크래시 없는 대국 완주 및 기보 보존이다.

검증 명령과 외부 자료·라이선스는 [규칙 코어 문서](../RULES_CORE.md)에 기록했다.
