# 통과폰·폰 구조 평가 v0.5.6

기준일: 2026-10-18 (한국 시간). [사전 계획](2026-10-18-pawn-structure-plan.md)에 따라 통과폰·겹친 폰·고립된 폰 평가를 구현했다. [사용법과 점수](../PAWN_STRUCTURE.md), [검사·원자료·재현 방법](../checks/2026-10-18-pawn-structure/README.md)을 함께 보존한다. 기존 왕 앞 폰 방패·규칙·탐색 방식은 유지한다. 일반 기력 향상과 Elo는 측정하지 않았으며, 사용자가 중단한 강도 비교를 재개하지 않았다.

## 구현과 기준

- 기준: v0.5.5 `585710724e93329a8f8baddfbc82724db4a4ce2a`.
- 새 코드와 검사 고정: `132f45451d0af68168cfe15507a3fdc069c86d9c`. 후속 기록 커밋은 실행 코드에 영향을 주지 않는다.
- 자체 초기 계수: 통과폰은 전진할수록, 종반일수록 보너스가 커진다. 바로 앞이 막히면 절반, 같은 파일에서는 가장 앞 폰만 보상한다. 추가 겹친 폰은 중반8/종반12cp, 고립된 각 폰은 중반10/종반12cp 감점한다. 통계적 조정이나 외부 코드·데이터 도입은 하지 않았다.
- 기존 수집 루프의 파일별 폰 마스크를 공유한다. 추가 보드 전체 스캔·할당·캐시 없이 작은 constexpr 조회표를 사용하고, 기존 중반/종반 차와 합한 뒤 한 번 혼합한다.
- `UsePawnStructure` 기본 true, 콘솔 `--no-pawn-structure`, C++ `SearchOptions::pawn_structure`로 독립 설정한다. 구조 OFF는 v0.5.5, 방패까지 OFF는 이전 위치 평가를 재현한다. 위치 평가 전체 OFF에서는 두 옵션을 무시한다.

생략1개는 Windows 계정의 파일 심볼릭 링크 생성 권한 부족이다. 실제 새 실행 파일을 인자로 전달하는 선택적 연동 검사도 실행했다. 핵심 규칙·폰 평가 검사는 생략하지 않았다. Windows 최초 전체 로그의 평가21그룹은 이후 특별수 결정 검사1그룹을 보강한 최종 평가22그룹 로그로 대체해 합산했다. Linux도 평가만 변경됐음을 해시로 확인하고 해당 엄격 경고·sanitizer 검사를 다시 실행했다.

새 참조는 비트 마스크 구현을 재사용하지 않는 폰 쌍 비교와 기존 scalar 위치 수식으로 계산한다. 파일 경계·양색·앞/같은 랭크/뒤의 적 폰·최전방만 보상·겹침/고립 합산·봉쇄·국면 반올림·승격 초과 국면·반복 이력 및 되돌리기를 포함한다. 앙파상, 백/흑 승격, 잡으며 승격은 명시적으로 실행하고 구조 ON/OFF와 전체 상태 복원을 확인한다. 일반·전술 탐색의 완전 탐색 참조, 중단 대체 결과, 메이트/무승부 우선, 전이표 재사용·중단·옵션 토글도 검증했다. 별도 읽기 검토에서 차단 결함은 발견하지 못했다.

## 계산 비용과 한계

Ryzen AI 7 350, 8코어/16논리CPU, Windows11, MSVC C++20 `/O2 /W4 /WX`, 단일 탐색 스레드에서 측정했다. Python3.13.16, chess1.11.2다. 비교 순서는 균형 배치했지만 다른 프로그램을 통제한 전용 측정은 아니다.

평가 함수만의 측정은 미리 고정한 자체 58위치(기존42 + 폰 구조 경계8개와 색 반전8개), 별도 번역 단위·LTO OFF, 균등 호출 수, 9블록×4균형 순서를 사용했다. 보드 생성·입출력은 시간에서 제외한다. 방패 ON 상태에서 구조 OFF/ON의 블록 중앙값은 약 **72.03ns → 88.85ns**, 쌍별 비율 **1.23659**로 약23.7%의 추가 비용이다. 방패 OFF에서는 약52.32ns →77.00ns, 쌍별 비율1.45278이다. 각 변형 체크섬은 반복 안정적이며 구조 OFF는 동결 참조와 같다. ON/OFF 점수가 다른 것은 의도한 동작이다.

고정 깊이는 기존 전체10 시작 위치, Hash16MiB, Move Overhead20ms, seed20261018, 각3반복·warmup1이다. 각 표본은 새 게임으로 전이표 기록을 초기화하며 메모리는 재사용한다. 아래 시간 비율은 **후보/기준**이며, 표의 비율은 개별 쌍 비율의 중앙값을 직접 재계산한다.

구조 OFF 60쌍은 수·점수·깊이·노드·최장 깊이·주요 수순·전이표 통계가 모두 일치했다. ON/OFF는 평가 변경으로 읽는 수와 가지가 달라질 수 있어 함수 비용의 순수 비교가 아니다. 전체 탐색 시간은 이 짧은 표본에서 비슷했고, 기능 추가가 모든 위치에서 시간을 줄이거나 같은 시간 안에 더 강해졌다는 뜻은 아니다. 밀리초 단위와 통신 비용·동시 부하의 영향이 있다.

500ms 목표 간격의 프로세스 CPU 표본에서 프로파일22.53초 동안 브라우저2.75 CPU초, 전체 탐색7.40초 동안 브라우저1.109 CPU초가 관측됐다. 측정 중 열려 있던 실제 대국의 엔진은 초기 위치·추천 OFF였으나 전체 부하를 독점 통제하지 않았다. 신규/종료/접근 불가 프로세스와 온도·클럭을 완전히 포착하지 못한다. CPU가0인 프로그램만 존재했다거나 전용 측정이었다고 주장하지 않는다. Godot 검사가 갱신한 아이콘 import 기록이 측정 메타데이터의 dirty 상태에 남았으며, 실행·검사 소스는 고정 커밋과 동일했다.

## 로컬 반영

설치본 v0.5.5·바로가기와 개인 기보132파일을 로컬 백업했다. 대국 창의 정상 종료 전후 사본을 모두 남긴 뒤 `desktop/pawn-structure`에 v0.5.6을 반영했다. 종료 후 기준132파일의 해시와 바로가기를 보존했으며, 백업 경로와 개인 기보는 공개 저장소에 포함하지 않는다.

검증한 새 실행 파일과 설치 파일의 SHA256은 `7663c84b9aa21c6e56374985e8419426e44afb42cfac75503ef1ee2635cd0747`로 일치한다. 실제 바탕화면 바로가기로 실행해 화면 버전·backend 소스/바이너리 식별자, 기본 설정을 확인했다. 추천 ON의 Nf3 화살표와 OFF를 직접 확인했고 착수0·추천 OFF로 두었다. [공개 배포 확인](../checks/2026-10-18-pawn-structure/installation-public.json)과 해시 목록을 남긴다. 로컬 검증을 원격 CI 성공으로 대체 표현하지 않는다.
