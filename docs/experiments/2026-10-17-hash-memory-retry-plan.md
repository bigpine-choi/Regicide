# 100ms 비교의 환경 중단과 재측정 계획

기존 사전 계획의 100ms 묶음은 15판 종료 후 16번 대국 99반수에서 응답 시간 초과로 중단됐다. 결과는 6승 2무 7패와 미완료 1판이며 그대로 보존한다. 실패 판을 무승부·패배·완료로 바꾸지 않는다. 첫 40ms 묶음은 5승 6무 5패로 정상 완료했다.

Windows System 로그에서 2026-10-17 22:28:38.181(+09:00) Kernel-Power 506, 이유 Idle Timeout으로 Modern Standby 진입과 22:40:57.226의 507 재개가 확인됐다. 실패 대국의 비정상적으로 긴 대기와 이 기간이 겹친다. 정확한 99반수 수순·FEN·새/재사용 프로세스·이전/개선 버전의 별도 재현 110회는 모두 정상 응답했다. 최대 응답은 약 82.24ms였다. 이 사실들이 절전으로 인한 외부 중단이라는 해석을 지지하며 엔진 멈춤은 재현되지 않았다.

재측정 결과를 보기 전에 다음 원칙을 기록한다.

1. 원래 `time100.json/.pgn`과 오류·시스템 절전 이벤트·110회 재현 증거를 보존한다.
2. 엔진·도구·옵션·시작 수순·선후공·시간·기본 Hash·안전 한도를 바꾸지 않는다. 소스는 여전히 기준 `ef52f14569222acbfaa512245bab81558795180f`, 개선 `4a0f95a035b1cc0eff8e8d56a14ea898621eab64`다.
3. 한 판만 골라 채우지 않고 **100ms 전체 16판을 한 번** 새 프로세스로 다시 실행해 `time100-retry.json/.pgn`으로 저장한다. 원래 15판과 합쳐 31판짜리 득점 표본을 만들지 않는다. 주 비교는 완료한 재측정 묶음으로 보고하되 원래 실패 결과도 공개한다.
4. Windows `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`를 대국을 실행하는 동안만 적용하고 종료 시 이전 실행 상태로 복원한다. 영구 전원 정책은 바꾸지 않으며 화면 켜짐 요구를 추가하지 않는다. [Microsoft API 문서](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate)를 따른다.
5. 재측정의 성공·실패·경기 결과를 모두 보존한다. 또 실패하면 추가 재측정을 이어 하지 않고 원인을 다시 조사한다. 재측정 중 다른 부하 실험을 실행하지 않는다.

대국 전후 시각과 절전 억제 API 반환값, 시스템 이벤트를 기록한다. 이후 문서는 비용 감소와 경기력 결과를 분리하고, 원래 중단을 숨기거나 유리한 실행만 고르지 않는다.
