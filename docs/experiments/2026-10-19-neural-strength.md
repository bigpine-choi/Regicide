# 1/32 학습 모델의 첫 동일 시간 대국 — 2026-10-19

**이번 표본에서는 기존 평가기를 대체할 기력 향상을 확인하지 못했다.** 새 8개 시작 위치에서 선후공을 바꾼 신경망 모델의 성적은 **100ms/수 2승 2무 12패(18.75%)**, **1초/수 5승 4무 7패(43.75%)**였다. 두 조건 모두 득점률이 50% 미만이며, 1초 조건은 작은 표본의 기술적 구간에 50%가 포함된다. 현재 기본 평가기는 기존 것을 유지하고 신경망 모델은 후속 연구용으로 보존한다.

정적 점수 모방 오차와 입력 정밀도·전체/증분 정확성을 확인한 [이전 단계](../NEURAL_PRECISION.md)의 성과는 실제 승률 증거와 구분한다. 이번에는 모델과 엔진을 고정하고 실제 같은 시간 대국을 별도로 실행했다. Elo를 추정하거나 안정 대국용 버전을 교체하지 않았다.

## 결과

득점률은 신경망의 `(승 + 무승부/2) / 판수`다.

|---|---|---:|---:|---:|

모든 32판이 규칙에 따라 끝났고 미완료·엔진 오류·무효 묶음·재시도는 **0**이다. 시간 조건별 첫 시도 전체를 채택했다. 불리한 결과를 다시 골라 실행하지 않았다.

100ms에서는 신경망 백·흑 각각 **1승 1무 6패**다. 1초에서는 백 **3승 2무 3패**, 흑 **2승 2무 4패**다. 특정 위치에서는 시간 조건에 따라 승패가 바뀌었으며, 이 차이를 시간 증가가 일반적으로 신경망의 상대 기력을 높인다는 증거로 확대하지 않는다.

100ms의 종료는 체크메이트 14판·3회 반복 청구 2판, 1초는 체크메이트 12판·3회 반복 청구 2판·50수 청구 2판이다.

1초의 50수 청구 두 판은 최종 FEN의 halfmove 값이 99다. 다음 합법적인 비폰·비잡기 수로 100이 되는 경우 미리 청구할 수 있으므로, 사전에 정한 예정 수 포함 `claim` 정책에 따른 정상 종료다. 이미 100에 도달한 자동 종료로 처리한 것은 아니다.

## 무엇을 같은 조건으로 비교했는가

[사전 계획](2026-10-19-neural-strength-plan.md)과 `freeze.json`을 첫 대국 전에 고정했다.

- 엔진 소스 커밋은 `bb3100c460618e888c42066ba9c54618c0127c9d`다. 양쪽 실행 파일은 바이트가 같은 두 복사본이며 SHA256은 `598ebec433334b2ce053d0ed6b143fbfd34f9dd3a76557adb62764dcd940c705`다.
- 기준은 기존 위치 평가기, 후보는 `UseNeuralEvaluation=true`와 `UseIncrementalNeuralEvaluation=true`로 선택한 1/32 모델이다. 모델 SHA256은 `c9ca5f35bb0ef0f61fca9b7eba10cd01d4320cf6c2a1dd4863630b7f87baaa92`, 체크섬은 `12850805878070247189`다. 실제 UCI 불러오기 성공 응답을 기록했다.
- 양측 단일 탐색 스레드·Hash 16MiB·Move Overhead 20ms·PVS·SEE·안정화·수 정렬 등은 같다. 신경망 선택과 모델 파일 외의 유효 옵션은 동일하다.
- 요청 시간 100/1,000ms에서 공통 여유 20ms를 빼 내부 예산은 80/980ms다. 같은 PC에서 차례로 생각하며 한 시간 묶음 동안 두 프로세스를 유지한다. 매 판은 새 game token으로 전이표를 초기화한다.
- AMD Ryzen AI 7 350, 8코어/16 논리 프로세서, Windows 11, MSVC 최적화 C++20 `/O2 /DNDEBUG /W4 /WX`, Python 3.13.16·chess 1.11.2다. 기존 빌드의 소스·명령·해시와 복사본 연결을 기록했고 엔진이나 모델을 수정·재학습하지 않았다.

새 실행기와 감사 코드는 당시 작업 트리의 SHA256으로 식별한다. 원시 JSON의 `harness_source_commit`과 checkout HEAD가 엔진 커밋과 같은 것은 실행 시작 HEAD를 뜻하며, 새 도구가 이미 그 커밋에 포함됐다는 뜻은 아니다. `freeze.files`의 실제 바이트 해시가 실행한 도구를 별도로 식별한다.

## 새 시작 위치와 선택의 경계

[고정 수순 8개](../../tests/data/neural_strength_openings_2026-10-19.json)는 엔진 점수·검색·추천 수·경기 결과 없이 손으로 작성했다. 백 차례 4개·흑 차례 4개이며 각 위치에서 후보 백 → 후보 흑 순으로 대국했다. 같은 전체 8개를 100ms와 1초에서 사용했다.

과거 338개 대국 궤적·563개 오프닝 선·학습/검증/보류 5,686행 등의 고유 기물 입력 **26,735개**와 색·랭크 반전까지 대조해 중복 0을 확인했다. 출처 154개 파일의 해시와 범위를 `openings-audit.json`에 보존했다. 원래 무작위 학습 원자료 중 미채집 위치까지 전부 조사한 것은 아니다.

순수 무작위 수순 예비안은 엔진 평가 전에 SAN·배치만 살핀 뒤 정상 오프닝 비교와 거리가 있어 폐기했다. 수작업 KID 선 하나가 과거 대국 위치와 겹쳐, 경기 전에 `c6e7 f3e1` 두 수를 추가했다. 이러한 결과 관측 전 설계 변경도 감사 기록에 남겼다. 최종 수순·모델·판수는 경기 도중과 결과 확인 후에 바꾸지 않았다.

현재 또는 합법적 예정 수로 가능한 3회 반복·50수 무승부는 양측 모두 항상 청구한다. 최대 500ply는 무승부가 아닌 미완료로 처리하도록 했지만 이번에는 한도 도달이 없었다. 별도 평가 점수 기반 승패 판정이나 자의적인 중간 종료는 하지 않았다.

## 부하·정확성·독립 감사

실행 전 규칙 8,325개·실제 학습 모델 26,566개 검사, 규칙 차등 2,997사례, 엔진 통합 19그룹, 기존 대국 실행기 10사례·CPU guard 18검사, 새 driver 6검사와 감사기의 변조 거부 21종을 확인했다. 새 시작 위치는 이 사전 검증의 엔진 탐색 입력으로 쓰지 않았다.

각 시간 묶음 전 10초 연속 유휴를 확인했다. native Windows 감시는 약 0.5초마다 엔진 PID·생성시각·부모 관계와 실제 UCI transport를 대조했다. 100ms **286행**, 1초 **3,765행**, 합계 **4,051개 스냅샷**을 남겼다. 비교 엔진 두 개 외 알려진 외부 엔진은 0개였고 관측 외부 CPU 증가는 **0 tick**이다. 최대 스냅샷 간격은 100ms 0.527초·1초 0.545초로 사전 2초 상한 안이었다. 임시 절전 억제 상태는 두 묶음 모두 복원했다.

독립 감사는 실제 수 **3,833ply**, 탐색 주요 수순(PV) **21,398ply**를 재생해 합법성·FEN·종료·무승부 청구·색상·득점·PGN·시간과 고정 입력 **49개**의 전후 해시를 대조했다. 모든 native CPU 행, PID 계보, 옵션·모델 체크섬, 시작 쌍별 점수와 bootstrap을 다시 계산했고 두 조건 모두 PASS였다.

## 한계와 다음 판단

1. 시간 조건마다 **8개 시작 쌍**뿐인 수작업 시범 표본이다. 두 시간 조건은 같은 위치를 재사용하므로 독립적인 32게임 집단으로 합산하지 않는다. 기술적 bootstrap 구간을 일반적인 신뢰구간이나 Elo로 바꾸지 않는다.
2. 100ms의 관측 열세가 컸다. 1초도 관측 득점률은 낮지만 기술 구간이 50%를 포함해 그 차이의 일반화에는 불확실성이 크다. 작은 표본의 패배를 NNUE 방식 전체의 한계로 확대하지 않는다.
3. CPU 고정·호스트 독점·전력·열·모든 앱 부하를 통제하지 않았다. 경기 중 가벼운 PC 사용이 가능하다고 안내했으며 실제 모든 비엔진 작업의 유무·CPU를 계측한 것은 아니다. 관측된 알려진 외부 엔진 CPU 0은 호스트 전체 부하 0의 증명이 아니다. 샘플 사이 생겼다 사라진 미관측 엔진도 배제하지 못한다.
4. 정적 점수 오차가 줄어도 탐색 중 만나는 위치의 오차 분포와 수 순서·가지치기와의 상호작용은 다를 수 있다. 이번 대국만으로 학습 자료·망 용량·큰 평가 오차 중 무엇이 주된 원인인지 분리하지 않았다.

따라서 **기본 평가기는 기존 것을 유지**한다. 다음 연구에서는 이번 기보를 개발 자료로 분류하고, 실전 및 탐색 중 평가하는 위치에서 큰 오차를 먼저 조사하는 것을 권한다. 모델을 조정한다면 다른 새 시작 위치를 고정해 다시 대국해야 한다. 이번 위치를 재사용해 학습한 뒤 이를 새 검증으로 부르지 않는다. 이 단계에서 추가 학습이나 모델 변경은 수행하지 않았다.

## 기록과 재현
