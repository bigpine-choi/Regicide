# 프로파일링·전이표 사전 비교 계획

엔진·평가 계수와 이 계획을 고정한 뒤 벤치마크와 대국 결과를 수집한다. 기준은 위치 평가·안정화 탐색을 모두 사용하는 v0.3, 커밋 `3869db0fc2a575c25ad8026cf022733708f76b08`이다. 개선 버전은 v0.4이며 이 문서를 포함한 코드 커밋으로 고정한다. 결과를 보고 계수·시작 위치·대국 수를 조정하지 않는다.

## 가설과 측정 분리

- gprof로 확인한 중복 합법 수 생성과 반복 상태 문자열 비용을 줄이면 같은 깊이까지 탐색하는 시간이 감소한다.
- 전이표가 완료한 탐색 결과와 최선 수를 재사용하면 일부 위치의 노드 수와 시간이 추가로 감소한다. 이력 구분·할당 비용 때문에 모든 위치에서 빨라진다고 가정하지 않는다.
- 더 빨리 탐색하는 버전이 같은 시간 대국에서 더 좋은 성적을 내는지는 별도로 확인한다. 속도와 경기력은 서로 대체할 수 있는 지표가 아니다.

## 프로파일링

`scripts/profile_search.cpp`의 초기 배치·전체 이력이 있는 오프닝·Kiwipete·룩 엔드게임 4개를 각각 30회, 수당 5,000노드로 탐색한다. 총 600,000노드다. 양쪽 같은 WSL Ubuntu 24.04 GCC 13.3, `-std=c++20 -O2 -DNDEBUG -pg`를 사용한다. 원시 flat/callgraph와 드라이버 출력을 보존한다. 표본 프로파일의 함수별 비중은 병목을 찾는 자료이며 실제 비계측 속도 배수로 해석하지 않는다.

## 비계측 고정 깊이 비용

Windows, 동일 MSVC C++20 `/O2` Release 빌드를 사용한다. 기준은 별도 `git archive` 소스에서 빌드한다. 단일 탐색 스레드, 위치 평가·안정화 켜짐, 개선 버전 Hash 16 MiB가 기본이다. 테이블은 매 탐색에서 새로 만든다. 할당 비용도 실제 요청 시간에 포함한다.

1. 이전 버전 대 개선 버전: `tests/data/profile_positions.json` 전체 10개 위치, 깊이 3, 각 5회.
2. 전이표 단독 비용 비교: 같은 개선 실행 파일에서 TT 끔 대 켬, 전체 10개 위치, 깊이 4, 각 5회. 그 외 설정은 같다.

`scripts/benchmark_search.py`로 위치 순서를 시드 20261017로 섞고 각 쌍의 실행 순서를 교대한다. 매 표본 `ucinewgame`, 프로세스 시작 시간 제외, UCI 요청/응답 벽시계 시간 포함. 점수 일치·합법 최선 수/PV를 검사한다. 중앙 시간 배수와 노드 비율, 실제 전이표 차단 횟수를 기록한다. 캐시 때문에 동점 최선 수나 PV 길이는 달라질 수 있다.

## 같은 시간 대국

- 주 비교: 양쪽 UCI `go movetime 40`, 전체 8개 기존 시작 수순, 선후공 교대 **16판**.
- 보조 비교: 양쪽 `go movetime 100`, 같은 8개·선후공 교대 **16판**.
- 기존 `Move Overhead` 20ms를 양쪽 유지한다. 따라서 엔진 내부 탐색 할당은 각각 약 20/80ms다. 테이블 초기화도 이 예산에 포함한다.
- `tests/data/comparison_openings.json`은 바꾸지 않는다. 시작 수순을 포함한 전체 이력을 엔진에 전달한다.
- 대국은 한 번에 하나씩 실행하며 프로파일링·벤치마크와 겹치지 않는다. 총 32판을 실행하고 나쁜 결과도 보존한다. 오류·미완료 판을 완료 무승부로 바꾸지 않는다.
- 기본 정책은 가능한 현재/예정 수 3회 반복·50수 무승부를 청구한다. 자동 종료는 별도로 확인한다. 안전 한도 500반수.
- Python `chess==1.11.2`는 UCI 전달·합법성·판정만 담당하며 수는 두 자체 엔진이 선택한다.

소스 커밋, 실행 파일 SHA256, 하드웨어·OS·컴파일러·Python, 옵션, 대국별 수순과 시간·노드·완료 깊이를 저장한다. PGN과 JSON을 독립 재생해 검증한다. 8개 시작 위치의 작은 개발 표본이므로 결과를 Elo·외부 강한 엔진·인간 상대 성능으로 일반화하지 않는다. 같은 위치의 두 판을 묶은 참고 부트스트랩 범위도 이 제한을 유지한다.
