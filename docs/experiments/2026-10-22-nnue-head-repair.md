# 출력 전용 학습에서 드러난 수 선택 악화의 원인과 보정

2026-10-22. 직전 출력 전용 후보는 점수 MSE를 줄였지만, 미학습16위치 중 한 곳에서
`Ng4` 대신 `Bf5`를 골라 제한된 교사 평가상171cp 악화됐다. 이번에는 그 위치를
이미 노출된 개발 사례로 분석하고, 실제 기본 탐색과 같은 설정·완료 깊이에서 얻은
비교 자료를 추가한다. 입력·은닉·차례 표현12,320개를 고정하고 출력 가중치16개만
MSE로 학습하며 기존 과적합 방지를 유지했다. 실제 학습1회로 기존 보호 위치와
tuning의 MSE를 줄였지만, 이미 노출된3위치의 실제 선택은 바뀌지 않았다. 새
미학습16위치에서도 선택이 모두 같았고 교사 추천수 일치는11→11개였다. **실제 수
선택 개선은 달성하지 못했다.** 검사 실패에 따라 대국은0판이며 기본 모델을 유지한다.

## 171cp 악화의 원인

문제 위치는 이전 검사의 `choice-gate-opening-30`이며 흑 차례다. 흑의 `Ng4`와
`Bf5`를 각각 강제해 탐색하자 다음 값을 얻었다. 표의 점수는 **흑 관점**이며 클수록
흑에게 유리하다는 뜻이다. 교사 추천수 `Ne4`도 함께 확인했다.

| 완료 깊이2의 강제 첫 수 | 이전 보존 모델85e | 직전 출력 전용 후보4e100 |
| --- | ---: | ---: |
| Ng4 (`f6g4`) | +51cp | +43cp |
| Bf5 (`c8f5`) | +51cp | +44cp |
| Ne4 (`f6e4`, 교사 추천) | +5cp | −1cp |

이전 모델에서 동점이던 두 수가 출력 보정 후1cp 차이가 됐다. 기존 탐색은 동점에서
앞서 확인한 주수순을 유지하고, 더 높은 점수가 나올 때만 교체한다. 이전 모델은
`Ng4`를 유지했고 새 후보는1cp 높게 본 `Bf5`로 바꿨다. 같은 두 끝 위치에서 출력
가중치가 만든 상대 점수 차이의 원래 분수값 변화는2.2265625cp다. **171cp는
신경망 점수가171cp 변했다는 뜻이 아니라, 작은 순위 변화로 다른 수를 골랐을 때의
교사 평가 차이**다. 기존 영수증의 두 수 직후 백 관점 교사 점수는 각각+126cp와
+297cp였으므로 흑의 선택 품질 차이는−171cp다.

두 모델 모두 `Ng4`와 `Bf5` 이후 백의 대응으로 `Bg5`를 골랐다. 반면 저장돼 있던
Stockfish의 `Bf5` 이후 수순은 `exf6 → Bxb1 → Ng5 → Qxf6 → Nxf7 …`로 이어진다.
여기서 백의 `Ng5`는 잡기나 체크가 아닌 조용한 수다. 완료 깊이2 밖에 있고,
잡기·일부 체크를 이어 보는 quiescence 탐색에도 포함되지 않는다. 따라서 이번
위치에는 **상대의 전술적 대응을 평가하는 데 필요한 얕은 탐색·평가의 사각지대**가
있다. `Ne4` 역시 이전 모델부터 낮게 봤으므로 옛 동점만 복원해서는 교사 추천수까지
개선되지 않는다.

진단에서는 동일하게 노출된 위치만32회 탐색했고 총0.4888864초가 걸렸다. 기본
10,000노드 탐색으로 이전 두 선택과 점수를 정확히 재현했으며, 둘 다 깊이3을
끝내지 못하고 완료 깊이2 결과를 반환했다. TT·PVS·LMR을 끈 강제 탐색도 여섯 개의
완료 깊이2 점수와 수순이 같았다. 실제 static 평가 관찰자는 같은 끝 위치가 해당
수순과 점수를 뒷받침한 것을 확인했다. 이 재현된 순위 변화는 TT·PVS·LMR의 차이로
설명되지 않는다. 진단 중 새 교사 질의·학습·새 검사 위치 탐색은 모두0회다.

다만 기존 교사 점수는 깊이10·최대100,000노드의 제한된 탐색 결과다. 이번 진단에서
더 깊은 독립 교사 분석을 추가하지 않았으므로171cp를 완전한 체스 정답이나 전체
경기력 손실로 해석하지 않는다. 위 전술 수순은 확인한 실패 양상이며, 모든 오판의
원인을 이 한 수순으로 확정하지 않는다.

## 실제 기본 탐색에 맞춘 자료 수집

새 연구용 collector는 핵심 엔진 소스와 기존 collector를 바꾸지 않는다. 기본 게임
탐색과 같이 TT·PVS·LMR·SEE·수 정렬·quiescence·증분 NNUE를 켜고 Hash16MB를
사용한다. 먼저 root 전체를 최대10,000노드로 탐색해 마지막으로 완료한 깊이D를
확인하고, 두 경쟁 수를 같은 설정·같은 깊이D로 각각 강제 탐색한다. 자식 위치의
대응 비교는 남은 깊이D−1에 맞춘다.

각 반복 탐색의 완료 callback에서 점수·주수순·노드 수와 그때까지의 관찰 개수를
저장한다. 이후 노드 제한으로 더 깊은 반복이 중단되더라도, 완료 callback 이전의
관찰만 끝 위치 후보로 사용할 수 있다. 같은 완료 깊이·전체 경로·FEN·기보 이력·반복
상태가 맞고 실제 NNUE 원점수의 백 관점 값이 root 점수와 같아야 한다. TT 때문에
짧아진 수순, 완료 회차가 없는 초기 대체 수, mate·무승부 보정·체크 끝 위치·점수
clamp는 제외한다.

이 검증은 실제 평가 호출과 완료 주수순 점수의 일치를 확인한다. 모든 TT·scout·
재탐색을 추적한 완전한 인과 증명이라는 뜻은 아니다. 기록에는 이를
`observed_completed_pv_support`로 명시한다. 학습 입력은 이때 관찰한 끝 위치이며,
정답은 두 root 첫 수 직후 교사 점수의 차이다. **root 자식 가치의 대리 목표**이므로
교사가 그 끝 위치 자체에 부여한 정답이라고 부르지 않는다.

이미 노출된 QGA 실패는 TRAIN에만 다음3쌍으로 추가한다.

| 개발 사례 | 비교할 두 수 | 목적 |
| --- | --- | --- |
| 원래 흑 차례 root | Ne4 / Bf5 | 현재 선택과 교사 추천수의 순위 |
| Bf5 이후 백 차례 | exf6 / Bg5 | 놓친 상대 대응의 순위 |
| Ng4 이후 백 차례 | h3 / Bg5 | 기존 선택에서도 놓친 상대 대응 |

이3위치의 사후 회복 검사는 학습한 위치를 다시 보는 개발 점검이다. 새로운 위치로
일반화했다고 부르지 않으며 검사 결과로 추가 학습·체크포인트 재선택을 하지 않는다.

`teacher_queries` 등은 이전 자료 수집 수치이며, 이번 실행은 `live_teacher_queries`
74회와 `live_native_searches`77회로 구분한다.

## 출력 전용 학습과 과적합 방지

이번 시작점은 이전 보존 모델85e가 아니라 **직전 출력 전용 후보4e100**이다.
`nnue-output-only/attempt-001/model.nnue`와 그 float 가중치를 이어서 사용한다.
모델 SHA256은
`4e100302474cc3861ee5ef2ec69a641dad0e08cc94c1b685f80c3bb2e8883700`이다.

NNUE v3·기물768입력·차례1입력·은닉16개·입력 배율32를 유지한다. 입력 가중치·은닉
bias·차례 가중치12,320개는 float 바이트와 배포 정수값을 고정하고, 기존 출력
가중치16개만 학습한다. 출력 bias나 새로운 표현은 추가하지 않는다. 공유 표현이
고정돼 있으므로16개 조합만으로 고칠 수 있는 판단의 범위에는 한계가 있다.

```text
기존 교사 point MSE
+ 합친 TRAIN70쌍의 점수차 MSE
+ 4 × 기존 TRAIN1,426위치에서 현재 시작 모델 출력과의 보존 MSE
```

MSE·출력 전용 미분·Adam·정수 TRAIN 목적값 보호 구현은 그대로 사용한다. 새 래퍼는
추가 비교를 인증해 기존 학습기에 연결하고, 고정 표현과 파일 해시를 별도로
검사한다. 비교 쌍 수가 늘어 전체 비교 평균에서 각 옛 쌍이 차지하는 비중은 달라지며,
각 기존 비교의 상대 가중치가 전과 완전히 같다고 해석하지 않는다.

| 조건 | 고정값 |
| --- | --- |
| 실행 수 | 시드 하나, 실제 학습 최대1회 |
| 학습 | MSE, Adam, 시드20261020, 배치128, 최대500회 |
| 학습률 | 출력0.005; 고정 입력·bias 학습률0.0002는 적용하지 않음 |
| 미분 제한 | 학습하는 출력16개만 크기10으로 clipping |
| 정수 TRAIN 보호 | 전체 point+gap+보존 목적값이 늘지 않는 첫 축소 제안만 허용 |
| 축소 순서 | 1, 0.5, 0.25, 0.125, 0.0625, 0.03125; 전부 실패하면 수정 생략 |
| 선택용 검증 | 5회마다 tuning point+gap MSE 확인 |
| 기존263위치 보호 | MSE가 현재 시작값61,507.89733840304 이하인 후보만 허용 |
| 조기 종료 | 1cp²를 넘는 개선이5번의 검증 동안 없으면 종료 |
| 최종 선택 | epoch0 보호와 최적 가중치 복원 유지 |

tuning·보호263위치·새 미학습 위치는 미분에 넣지 않고 TRAIN 제안의 축소 비율을
고르는 데도 쓰지 않는다. 기존69개 사후 점검은 최종 파일 저장 후 한 번만 계산하고
선택·중단·재학습에 사용하지 않는다. 이69위치는 이미 노출된 개발 자료다.

## 새 미학습16위치와 조건부16판

이전16위치는 결과가 노출됐으므로 사용하지 않는다. 이번에는 사전에 정한 홀수
M2 source index1·3·…·31의 계열16개를 각각 조용한 합법 수4ply로 연장해 예약했다.
새 root와 모든 합법 자식의564개 정규화 입력은 이전 기록과의 겹침이0개이며, 새
point·비교·경로 자료에서도 제외한다. 원래 개시 계열 자체가 전혀 새로운 외부
자료라는 뜻은 아니다. 예약 파일은 자료 수집과 학습 전에 봉인했다.

최종 후보와 native 계산 검증 결과를 봉인한 뒤 한 번만 검사한다. 비교 가능한 확정
교사 점수 위치가12개 이상, 시작 모델4e100보다 추천수 일치가2개 이상 증가,
선택수의 교사 평가상 평균 이득20cp 이상,200cp 이상 악화0개, native 불일치0개가
통과 조건이다. 모델이 시작값 그대로 복원되면 검사를 사용하지 않고 보존한다.
검사 결과로 추가 학습·체크포인트 선택·시드·한도·통과 기준 변경을 하지 않는다.

통과할 때만 기본 classical Regicide와 같은 native 엔진에서 후보를16판 비교한다.
8개 고정 시작 위치의 선후공 교대, 수당100ms, Hash16MB, 최대500ply, claim 무승부
정책을 사용한다. 실패하면0판이고 기본 게임 모델을 바꾸지 않는다.16판은 빠른 방향
확인용이며 안정적인 기력 향상이나 Elo의 증거로 해석하지 않는다.

## 구현 검증과 현재 실행 상태

새 native collector 회귀 검사는6개 그룹·68개 단언으로 통과했다. 백/흑 부호·전체
기보·캐슬링·앙파상·승격, 완료 callback 이전 관찰만 사용, 중단 꼬리 배제, TT로
짧아진 수순·잘못된 이력·mate·draw·clamp 거부를 확인한다. 기본 탐색과 관찰자·
callback을 켠 탐색은3위치×전체/증분 계산에서600노드 traversal과 결과·통계가
같았다. 최초 실패1개는 같은 경로의 다른 유효 관찰이 남아 있던 테스트 fixture를
고쳤으며, 코드 동작을 우회해 통과시키지 않았다. 두 실행 로그를 모두 보존한다.

새 검사 회귀9개와 새 LIVE 자료 검증9개도 통과했다. 엔진 핵심·기존 collector·
출력 전용 최적화 구현은 바꾸지 않았다. 연구용 새 collector 실행 파일 SHA256은
`f725c5bf45ddd25432c55223beccfd6a350340b057c2e4346dc337af09c26077`이다.
