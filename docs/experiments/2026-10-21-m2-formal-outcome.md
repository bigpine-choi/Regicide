## 재개 조건

사용자가 “재시작 해.”라고 명시해 [동일 조건 재시작001](2026-10-21-m2-formal-restart-001.md)을 실제 실행했다. `attempt-005`는98.231초에 사전12/24판을 완료 보고한 뒤 중단했다. 최초 위반은09:44:29 UTC의2초 비소유 CPU23.1156%, 종료 표본 최댓값23.6769%였다. [독립 자원 재계산](../checks/2026-10-21-m2-formal/restart-005-resource-diagnosis.md)은378표본 계산 일치와 이전 생성 작업 미차감·타이머 손실·클리핑으로 이번 초과를 설명할 근거가 없음을 확인했다. 새 본 대국은 시작하지 않았다.

[005 중단 전용 독립 감사](../checks/2026-10-21-m2-formal/peer-preflight-stopped-005.json)는 완료12판의 수순1301반수·PV7147반수·실제 탐색 요청1157반수 검증을 통과했다. 예정12쌍 중 완료6·활성2·미착수4쌍을 대조했다. 결과 상태는 `INTEGRITY_PASS_STOPPED_INVALID`이며 전 성적을 비교에서 제외한다.

기존 비소유 CPU 지표는 전체 busy CPU에서 관측한 worker 계열 CPU를 뺀 추정 잔여량이다. Windows·서비스·감시 자체뿐 아니라 관측하지 못한 짧은 실험 자식도 섞일 수 있다. 사용자가 다른 앱을 열었다는 증거는 아니다. 전체 논리 CPU 시간을100%로 정규화하며,20%는 이번 계획의 환경 문턱으로 보편적인 엔진 기준이 아니다.

두 번의 잔여 CPU 문턱 초과를 보존한다. 사용자 앱을 닫는 조치만으로 해결된다고 판단할 근거는 부족하다. 후속 재개에는 실험 자체의 CPU·관측 누락·시스템 서비스의 부하를 분리하는 계측 보완과 새 사전 계획이 필요하다. 아래 재현·보존 조건은 유지한다.

1. 기존 실패 원시 기록과 감사 결과를 모두 보존한다.
2. 같은 출력에 이어 쓰지 않고 새 실행 폴더에 코드·입력·환경을 새로 동결한다.
3. 모델·시작 계열·순서·시간·부하 상한은 바꾸지 않고 사전24판과 감사를 다시 통과한다.
4. 본768판 전체를 새로 실행한다. 중단된176판을 더해 표본 수를 채우지 않는다.
5. 이미 관측한 M2 은행은 고정 기준 자료이며 새 보류 표본으로 표현하지 않는다. 후속 M3 확인 자료에서는 이번에 노출된 자료를 제외한다.

이 기록의 미완료 상태를 유지하며, 표본이 완성되기 전에는 시간별64판 성적표·기력 순위·승격 판단을 제시하지 않는다.

[보존 검사](../checks/2026-10-21-m2-formal/preservation-after.json)에서 native17파일·실행 파일, 원래 두 개발 폴더의 HEAD·미커밋 상태·각 파일 내용이 전후 일치했다. 기존 게임의 GUI 검증을 이번에 다시 수행했다는 뜻은 아니다.
