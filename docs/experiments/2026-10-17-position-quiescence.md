# 위치 평가·안정화 탐색: 이전 버전 대비 64판

## 결론과 주장 범위

**이번 고정 표본에서 두 기능을 합친 버전은 v0.2보다 높은 득점과 낮은 즉시 왕복률을 보였다.** 같은 수당 1,000노드에서는 13승 3무 0패, 같은 수당 40ms에서는 10승 5무 1패였다. 기존 규칙 검증은 유지했다.

위치 평가만 켠 8판은 4승 4무였지만 안정화 탐색만 켠 8판은 전부 무승부였다. 안정화만의 왕복 지표는 오히려 높았다. 따라서 전술 회귀 검사에서 재캡처 실수를 피한 사실과 안정화 탐색 하나의 일반적인 경기력 향상을 구분한다. 비교 상대는 자체 첫 버전이며, 이 결과로 외부 강한 엔진·인간 상대 성능이나 Elo를 추정하지 않는다.

## 사전 계획과 버전 고정

결과를 보기 전에 [계획](2026-10-17-position-quiescence-plan.md), 8개 시작 수순, 예산과 선후공 교대, 기능별 비교 범위를 코드와 함께 커밋했다. 대국 결과를 본 뒤 코드·계수를 조정하지 않았다.

| 항목 | 기준 버전 | 개선 버전 |
| --- | --- | --- |
| 엔진 | Regicide 0.2.0 | Regicide 0.3.0 |
| 소스 커밋 | `6dc69292baa5da0aeb61a66bd25ab016ef3c6272` | `7f23bf161b3312aeb582a819b9aab00f8b94b7d9` |
| SHA256 | `dd70e44bee2cea29bd7c97573ad281c0335ab9844d01613ea643e16bc02fadc4` | `270a24f97863a7a37590fdb695a441f5473f9f29b8902e679f04b7b2741ad6ac` |

기준 커밋을 `git archive`로 별도 `build-baseline/source/`에 추출해 빌드했다. 개선 버전도 소스를 고정한 뒤 변경 없는 체크아웃에서 재빌드했다. 모든 대국은 무시되는 `build/comparison-evidence/`에 먼저 저장했으며, 5개 JSON 모두 대국 시작 시 체크아웃 상태가 깨끗함을 확인했다. 이후 결과를 `docs/matches/2026-10-17/`로 복사했다. 이 문서를 포함한 후속 커밋은 엔진·도구·검사 코드를 바꾸지 않는다.

개선 버전에서 두 기능을 모두 끈 경우에는 기준 실행 파일과 12개 깊이/노드 검사를 비교했다. 선택 수·점수·주요 수순·완료 깊이·노드 수가 모두 같아 이전 동작의 제어 조건을 확인했다.

## 실행 조건

- 날짜: 2026-10-17, Asia/Seoul. 결과 JSON 시각은 UTC다.
- PC: AMD Ryzen AI 7 350 w/ Radeon 860M, 논리 CPU 16개, 메모리 약 31.3 GiB; Windows 11 x64.
- 양쪽 같은 MSVC 19.51.36260.0, C++20 `/O2 /W4 /WX /permissive-`, 같은 빌드 스크립트 계열.
- 탐색 작업 스레드는 각 엔진 1개. 각 수를 번갈아 계산하며 다른 대국을 동시에 실행하지 않았다. 오프닝 북·GPU·학습 데이터·모델은 없다.
- Python 3.13.16, `chess==1.11.2`. Python은 수 선택을 하지 않고 UCI 전달·합법성·종료·기보를 처리한다.
- 시작 수순: `tests/data/comparison_openings.json`의 초기 배치, Open Game, Queen Pawn, Sicilian, French, Caro-Kann, QGD, Reti-English 계열 8개. 직접 작성한 짧은 합법 수순이며 외부 엔진으로 유불리를 골라내지 않았다.
- 같은 시작 수순을 유지하고 선후공을 바꿔 2판씩 진행. 기능별 비교는 계획대로 앞 4개를 사용했다. 엔진에 시작 수순을 포함한 전체 이력을 전달했다.
- 무승부는 가능한 3회 반복·50수 청구를 항상 처리한다. 예정 수를 선언하면 성립하는 청구도 포함한다. 자동 종료는 별도 확인한다.
- 안전 한도는 전체 500반수. 한도·오류·미실행은 완료 무승부로 바꾸지 않는다. 실제로는 64판 모두 정상 종료했고 오류·한도·미실행은 0건이었다.

## 전체 두 기능 대 이전 버전

| 같은 조건, 각 16판 | 개선 승/무/패 | 득점률 | 기보와 상세 JSON |
| --- | ---: | ---: | --- |
| 1,000노드/수 | **13 / 3 / 0** | **90.6%** | [PGN](../matches/2026-10-17/2026-10-17-nodes1000.pgn), [JSON](../matches/2026-10-17/2026-10-17-nodes1000.json) |
| UCI 40ms/수 | **10 / 5 / 1** | **78.1%** | [PGN](../matches/2026-10-17/2026-10-17-time40.pgn), [JSON](../matches/2026-10-17/2026-10-17-time40.json) |
| 명목 깊이 2 | **16 / 0 / 0** | **100.0%** | [PGN](../matches/2026-10-17/2026-10-17-depth2.pgn), [JSON](../matches/2026-10-17/2026-10-17-depth2.json) |

득점률은 `(승 + 0.5 × 무) / 완료 판수`다. 1,000노드에는 안정화 노드도 포함되며 모든 해당 수가 정확히 1,000노드를 보고했다. 40ms는 양쪽 같은 요청 시간이고 기본 Move Overhead 20ms를 남겨 약 20ms를 탐색에 할당한다.

같은 깊이는 같은 계산량을 뜻하지 않는다. 깊이 2에서 기준/개선의 수당 평균 보고 노드는 각각 125.0/970.4였다. 그 조건의 전승을 같은 연산 자원에서의 전승으로 해석하지 않는다. 주 결론은 노드·시간 제한을 맞춘 두 비교에 둔다.

8개 시작 포지션은 고정된 작은 표본이다. 같은 시작의 선후공 두 판을 묶어 재표집한 20,000회 참고 범위는 노드 조건 81.3..96.9%, 시간 조건 68.8..87.5%였다(시드 20261017). 이는 선택한 포지션 쌍에 대한 기술적 부트스트랩이며 임의의 체스 위치 전체에 대한 신뢰구간이 아니다. 깊이 2 전승 표본의 범위가 100..100%로 퇴화하는 것도 확실성 100%를 의미하지 않는다. JSON의 Wilson 참고값 역시 무승부와 짝지은 표본의 독립 베르누이 가정을 만족하지 않으므로 강도 판단에 사용하지 않았다.

## 왕복 지표와 기능별 관찰

기회는 같은 쪽의 연속된 엔진 선택 수가 모두 폰 이외의 비캡처 수이고 체크 회피가 아닌 경우다. 같은 기물이 A→B 다음 자기 차례에 B→A로 되돌아오면 1회다. 시작 수순은 제외한다. 이 지표가 정당한 전략적 왕복까지 나쁜 수로 판정하는 것은 아니다. 양쪽 수순이 달라져 기회 분모도 다르므로 전체 수의 오류율로 해석하지 않는다.

| 전체 두 기능 조건 | 기준 왕복/기회 | 개선 왕복/기회 |
| --- | ---: | ---: |
| 1,000노드 | 89/170 = **52.4%** | 6/70 = **8.6%** |
| 40ms | 165/269 = **61.3%** | 17/106 = **16.0%** |
| 깊이 2 | 58/129 = **45.0%** | 0/55 = **0.0%** |

다음 표는 모두 **같은 앞 4개 시작 포지션·선후공 교대 8판·1,000노드/수**다. 전체 버전도 해당 8판만 추려 비교했다.

| 기능 | 승/무/패 | 득점률 | 개선 쪽 왕복/기회 | 기록 |
| --- | ---: | ---: | ---: | --- |
| 위치 평가만 | 4 / 4 / 0 | 75.0% | 14/91 = 15.4% | [PGN](../matches/2026-10-17/2026-10-17-position-only.pgn), [JSON](../matches/2026-10-17/2026-10-17-position-only.json) |
| 안정화만 | 0 / 8 / 0 | 50.0% | 31/41 = 75.6% | [PGN](../matches/2026-10-17/2026-10-17-quiescence-only.pgn), [JSON](../matches/2026-10-17/2026-10-17-quiescence-only.json) |
| 둘 다 | 7 / 1 / 0 | 93.8% | 4/32 = 12.5% | 주 비교의 앞 8판 |

위치 점수가 전개와 왕복 감소에 기여했다는 가설을 지지하는 관찰이다. 안정화만으로는 이번 대국의 득점 개선이 없었고 기준의 왕복 50/78=64.1%보다 높은 비율이었다. 표본이 각 8판이므로 두 기능의 기여도를 확정적으로 분해하지 않는다. 재캡처 함정을 피하는 전술 검사와 전체 대국의 점수는 각각 보고한다.

## 비용과 남은 한계

아래 시간은 UCI 호출부터 응답까지 실측한 수당 평균이며 고정 위치의 NPS 벤치마크가 아니다.

| 조건 | 기준 평균 ms/수 | 개선 평균 ms/수 | 관찰 |
| --- | ---: | ---: | --- |
| 1,000노드 | 47.32 | 86.18 | 같은 노드에서도 처리 비용 증가 |
| 40ms 요청 | 21.55 | 21.57 | 시간은 비슷하고 평균 보고 노드는 571.7 → 397.1 |
| 깊이 2 | 11.15 | 78.27 | 연장 탐색 때문에 계산량도 증가 |

위치 평가는 아직 손으로 정한 작은 휴리스틱이며 이동성·폰 방패·패스폰의 완전 판정은 없다. 안정화는 잡기·승격·체크 회피를 읽지만 조용한 전술 위협·추크츠방을 해결하지 않는다. 연장 32반수 한계와 복잡한 죽은 포지션의 일반 판정 미구현도 남아 있다. 다음 단계는 이 기준을 보존하며 프로파일링으로 실제 병목을 확인하고, 조정에 사용하지 않은 포지션과 더 강한 상대에서 다시 검증하는 것이다.

규칙 구현·규칙 테스트·기존 외부 기준 비교 소스는 변경하지 않았다. 별도 읽기 전용 검증으로 5개 세트의 **64판·4,152반수(엔진 선택 3,812수)와 주요 예상 수순 8,369수**를 재생했다. 모든 수의 합법성, 시작 이력·선후공 쌍, 최종 FEN·청구 포함 종료·결과, PGN/JSON 일치, 버전·해시·노드 한도·왕복 집계를 재계산해 일치했다. 오류·한도 중단은 0건이다.

원격 Windows/Linux CI도 같은 규칙·평가·탐색·UCI·대국·비교 도구 검사를 실행하도록 구성했다. 원격 결과는 PR/커밋의 Actions 상태에서 확인한다. 원리와 재현 명령은 [개선 설명](../SEARCH_IMPROVEMENTS.md)을 따른다.
