# 정적 평가와 자체 탐색 점수의 신경망 학습 비교

작성일: 2026-10-21 · 실행일: 2026-10-20~21(KST)  
상태: 자료 생성·여섯 모델 학습·공통 참조·100ms 96판 완료, 독립 감사 통과.

이번 조건에서는 **정적 점수를 배운 A가 대국에서 앞섰다.** 탐색 점수를 배운 B의 A 상대 성적은 **27승 20무 49패, 37/96점(38.54%)**였다. 두 조건 모두 자기 정답의 학습 오차는 줄었지만, 100k 공통 참조에서 B의 작은 계열 평균 이점은 불확실했고 실제 득점 개선으로 이어지지 않았다. B의 사전 확대 기준을 통과하지 못했다.

## 목적과 비교 조건

같은 위치·같은 초기값·같은 학습 절차에서 정답만 바꾼다. A는 기존 정적 평가 점수를, B는 신경망을 끈 자체 엔진의 10,000노드 탐색 점수를 배운다. 두 정답은 같은 행에 백 관점 cp로 저장한다. 100cp는 폰 하나에 해당한다.

이 실험은 탐색 점수를 학습시키는 것이 미관측 위치의 평가와 짧은 시간의 수 선택에 도움이 되는지 확인한다. 자기 정답을 잘 배우는지, 같은 공통 참조에 얼마나 가까운지, 실제 대국에서 얼마나 득점하는지는 별도로 평가한다.

| 항목 | 공통 설정 |
|---|---|
| 신경망 | 768입력·16은닉, 두 관점 공유, v2 정수 모델 |
| 정밀도 | 입력·편향 S=32, 활성 상한 4064, 출력 분모 256 |
| 초기값 | 자체 `bootstrap_float()`의 같은 미학습 배열. 자체 기물 가치·특징이 포함되며 완전 무작위 초기화는 아님 |
| 반복 | 배치 순서 시드 20261020·20261021·20261022, 대응하는 A/B의 순서 동일 |
| 학습 | 고정 120epoch, batch 128, 마지막 epoch 사용 |
| 학습률 | 입력·편향 0.00002, 출력 0.005 |
| 최적화 | 기존 QAT와 Adam, β1=0.9·β2=0.999·ε=1e-8 |
| 손실·수치 | 폰 단위 MSE, float64 shadow/moments, 기울기 norm 상한 10 |
| 실행 | NumPy/BLAS 1스레드, 조건별 조기 종료·최고 epoch/시드 선택 없음 |

원래 설계는 [최초 계획](2026-10-20-neural-target-ab-plan.md), 자료량 변경의 근거와 사전 조건은 [후속 계획](2026-10-20-neural-target-ab-followup-plan.md)에 보존한다. 실행 파일·소스·은행·초기 배열·환경·Git 상태는 [attempt-002 동결 파일](../checks/2026-10-20-neural-target-ab/attempt-002/freeze.json)에 기록한다. 현재 HEAD만으로 실행 파일의 빌드 커밋을 증명하지 않는다.

## 공통 참조 평가

보류 687개를 같은 자체 기존 평가기로 100,000노드씩 모두 검색했다. 68,700,000노드·평가 전체 127.814초이며 미시도·검색 중단은 0이다. 그중 670개(97.53%)·16계열이 유효 cp 참조였다. 17개는 mate 등 사전 cp 필터로 제외했다. 전체 이력과 빈 TT를 사용하며 잡기 bestmove라는 이유로 제외하지 않았다. 여섯 모델·미학습 M0·직전 S=32 모델을 같은 참조에서 비교했다.

주 요약은 계열에 같은 가중치를 준 MAE이며 위치별 평균도 함께 제시한다. 시드별 `Δ=A의 MAE−B의 MAE`가 양수이면 이 참조에서 B가 가깝다는 뜻이다. 같은 계열의 세 시드 델타를 평균한 뒤 정상/합성 안에서 계열을 재표집하는 10,000회 bootstrap, seed 20261029의 95% 기술 구간을 사용한다.

아래 세 참조 열은 **계열 평균 MAE(cp)**다. 정적·10k는 보류 687개, 100k는 유효 670개를 사용한다. 마지막 열은 위치 수가 많은 계열에 가중치가 더 붙는 위치별 100k MAE다.

| 모델 | 정적 참조 | 10k 참조 | 100k 참조(주 지표) | 100k 위치별 MAE |
|---|---:|---:|---:|---:|
| A-20261020 | 17.57 | 155.47 | 191.01 | 139.41 |
| A-20261021 | 18.88 | 155.77 | 191.39 | 139.34 |
| A-20261022 | 17.70 | 154.81 | 190.48 | 138.84 |
| B-20261020 | 34.95 | 152.99 | 188.40 | 140.18 |
| B-20261021 | 34.71 | 153.18 | 188.64 | 140.30 |
| B-20261022 | 36.16 | 154.31 | 189.71 | 140.57 |
| 미학습 M0 | 45.37 | 177.31 | 212.12 | 158.25 |
| 직전 S=32 모델 | 28.29 | 161.82 | 197.61 | 143.20 |

세 시드를 평균한 주 델타는 **A−B=+2.043cp**, 계열 bootstrap 95% 구간은 **−2.036~+6.372cp**다. B가 계열 평균에서 조금 가깝지만 구간이 0을 포함하므로 우위를 확정하지 않는다. 위치별 평균에서는 A가 조금 가깝다. 이 가중 방식 차이도 함께 남기며 유리한 지표만 선택하지 않는다. 정적 참조에서는 A가 더 가깝다는 예상된 차이도 보인다.

100k 참조의 종류별 계열 MAE를 세 시드에 걸쳐 평균하면 정상 시작은 A **107.13cp**·B **111.01cp**, 합성 종반은 A **274.79cp**·B **266.82cp**다. 이번 전체 계열 평균의 작은 B 우세는 합성 종반 쪽에서 나온다. 100ms 대국의 시작은 정상 시작 16계열이므로 두 평가의 위치 분포도 다르다.

평가 실행기의 보류 687개×8모델 Python 정수 예측과 C++ 전체/증분 평가는 불일치 0이다. 원시 검색·모든 예측·종류/손번/기물 수/검색 깊이별 세부 오차는 [공통 평가 결과](../checks/2026-10-20-neural-target-ab/attempt-002/evaluation/comparison.json)와 같은 폴더의 `reference_queries.jsonl`·`reference_uci.jsonl`·`predictions.jsonl`에 보존했다. [대국 전 독립 감사](../checks/2026-10-20-neural-target-ab/attempt-002/pre-match-independent-audit.json)는 원시 UCI·8개 모델의 오차 표·모델마다 23개 층별 지표·계열 bootstrap을 재계산해 통과했다. [전체 분할 평가 일치 감사](../checks/2026-10-20-neural-target-ab/attempt-002/all-partitions-runtime-parity.json)도 3,619개 위치×6모델에서 통과했다. 소스 126파일과 모델 동결 43파일은 그대로였다.

## 100ms 대국 결과

새 정상 시작 16계열에서 같은 시드의 A/B를 양색으로 붙여 **96판을 모두 정상 완료**했다. 양쪽 100ms/수·Move Overhead 20ms·Hash 16MiB·단일 탐색 스레드·증분 신경망을 사용했다. 실행 파일과 나머지 옵션은 같고 모델 파일만 다르다. 시작별 시드 순서를 순환하고 첫 색을 교대했다.

현재/예정 수의 청구 무승부를 적용하고 최대 500ply·블록 45분 상한을 유지했다. 중단·미종료·재시도·추가 대국은 0이다. 종료는 체크메이트 76판·3회 반복 19판·50수 규칙 1판이었다. 블록 경과 시간은 **746.473초(약 12분 26초)**다.

| 배치 순서 시드 | B 승 | 무 | B 패 | B 점수 | B 득점률 |
|---|---:|---:|---:|---:|---:|
| 20261020 | 10 | 6 | 16 | 13/32 | 40.625% |
| 20261021 | 7 | 7 | 18 | 10.5/32 | 32.8125% |
| 20261022 | 10 | 7 | 15 | 13.5/32 | 42.1875% |
| 전체 | **27** | **20** | **49** | **37/96** | **38.5417%** |

두 색과 세 시드를 하나의 시작 묶음으로 유지한 16계열 bootstrap 10,000회(seed 20261030)의 B 득점률 95% 기술 구간은 **30.2083~46.8750%**다. 96판을 독립 표본 96개로 다루지 않았다. 시작 16계열 중 B가 50%를 넘은 묶음은 3개였다. 전체와 세 시드 모두 이번 조건에서 A가 앞섰으며, 다른 위치 분포·시간 조건의 보편적 기력이나 Elo로 환산하지 않는다.

사전 확대 기준은 96판 정상 완료·B 53점 이상·세 시드 중 최소 둘이 50% 초과·정확성 실패 0이었다. **B 37점·세 시드 모두 50% 미만으로 미통과**다. 후속 1초 대국은 실행하지 않았다.

실제 탐색 8,844수에서 **요청 100ms를 넘긴 벽시계 시간은 양측 0회**다. A/B의 최대 실제 시간은 91.786/90.702ms였다. 내부 시간 배정은 20ms overhead를 뺀 80ms이며, A에서 한 수가 81ms로 보고됐고 B는 모두 80ms 이하였다. 이 내부 1ms 초과를 요청 100ms 초과와 구분해 남긴다. 서로 다른 대국 위치에서 나온 합계 노드·깊이로 속도 개선을 주장하지 않는다.

CPU 감시는 1,648개 표본, 최대 간격 0.536초로 두 전송 프로세스의 PID·생성 시각·소유 관계를 확인했다. 지정된 이름의 외부 엔진은 관측되지 않았고 CPU 증가·부하 오염 판정도 0이었다. 감시 사이의 짧은 미확인 프로세스와 호스트 전체 부하까지 배제한 결과는 아니다. 임시 절전 방지는 종료 시 복원했다.

증거: [96판 결과·수별 시간·모델 응답](../checks/2026-10-20-neural-target-ab/attempt-002/matches-100ms/match.json), [기보](../checks/2026-10-20-neural-target-ab/attempt-002/matches-100ms/match.pgn), [CPU 요약](../checks/2026-10-20-neural-target-ab/attempt-002/matches-100ms/monitor.json), [실행기 재생 검사](../checks/2026-10-20-neural-target-ab/attempt-002/matches-100ms/audit.json). 원시 `uci.jsonl`·`monitor.jsonl`과 종료 영수증 `driver-state.json`도 같은 폴더에 있다. 실행기 재생 검사는 시작 수순을 포함한 9,996반수·PV 45,249반수를 검사했다.

## 해석의 한계와 판단

- 100,000노드 참조는 B와 같은 자체 교사 계열이며 체스의 객관 정답이나 독립 알고리즘이 아니다. 참조 오차 감소만으로 기력 개선을 선언하지 않는다.
- 자료는 조용한 위치를 선별한 표집이다. 최소량 충족과 정확 입력 중복 0이 모든 체스적 유사성의 누출 방지나 충분한 일반화 표본을 뜻하지 않는다.
- 현재 입력은 손번·캐슬링·앙파상·반복 이력을 읽지 않는다. 상태 충돌 관측 여부만으로 이 한계를 없다고 판단하지 않는다.
- 실제 대국 중 서로 다른 위치에서 얻은 평균 노드·깊이는 같은 위치의 실행 속도 비교가 아니다. 감시된 외부 엔진 CPU 증가 0은 호스트 전체 부하 0을 뜻하지 않는다.
- B가 A보다 앞서도 기존 평가기나 기존 학습 모델보다 강해졌다는 결론은 별도 검증이 필요하다.

현재 작은 망·같은 자료·고정 학습 조건에서는 **정적 정답 A를 다음 신경망 연구의 비교 기준으로 유지**한다. B의 탐색 정답 학습을 실사용에 채택하거나 확대할 근거를 얻지 못했다. 기본 기존 평가기·설치본은 유지한다. A 자체가 기존 평가기나 직전 모델보다 강해졌는지는 이번 A/B 대국으로 확인하지 않았다.

다음에 검증할 가설은 B의 큰 잔차가 자료 종류·탐색 깊이 변동·현재 입력 표현·망 용량·학습 조건 중 어디에서 비롯되는가이다. 이미 저장한 종류별 잔차와 패배 수순을 먼저 분석하고, 변경 요인을 하나씩 새 자료·새 사전 계획으로 시험하는 것이 순서다. 이번 결과만으로 원인을 확정하지 않는다.

## 실행과 재확인

저장소 루트에서 `.venv-tests/Scripts/python.exe`와 `requirements-training.txt`의 환경을 사용했다. 아래는 이번 후속 실행의 단계다. 기존 결과를 덮어쓰지 않으므로 자료를 다시 생성할 때는 새 `--root`와 새 대국 `--output`을 지정해야 한다. 같은 보류를 재사용한 재실행은 새 일반화 실험으로 세지 않는다. 100ms 결과는 실행 시점의 시간 변동도 받는다.

```powershell
$abRoot = 'docs/checks/2026-10-20-neural-target-ab/attempt-002'
$abEngine = 'build-neural-target-ab/regicide.exe'
& .venv-tests/Scripts/python.exe scripts/neural_target_ab.py prepare --root $abRoot --engine $abEngine --followup-from docs/checks/2026-10-20-neural-target-ab/attempt-001
& .venv-tests/Scripts/python.exe scripts/neural_target_ab.py smoke --root $abRoot
& .venv-tests/Scripts/python.exe scripts/neural_target_ab.py generate --root $abRoot
& .venv-tests/Scripts/python.exe scripts/neural_target_ab.py train --root $abRoot
& .venv-tests/Scripts/python.exe scripts/neural_target_ab.py heldout --root $abRoot
& .venv-tests/Scripts/python.exe scripts/neural_target_ab.py evaluate --root $abRoot
```

각 단계 사이의 실제 독립 감사는 위 영수증에 보존했다. 현재 실행 소스와 자료의 동결 일치는 `scripts/neural_target_ab.py verify --root <보존 경로>`로 확인한다. 두 시도의 소스 사본은 `code-snapshot/index.json`의 경로·SHA256과 번호별 `.bin`으로 연결된다. 첫 시도는 해당 사본을 기준으로 재현하며, 현재 개발 파일이 첫 동결과 같다고 주장하지 않는다.
