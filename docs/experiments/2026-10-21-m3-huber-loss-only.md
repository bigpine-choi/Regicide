# M3: 같은 학습 조건의 MSE 대 H100, 16판

2026-10-21 KST. 사용자 요청에 따라 이미 준비된 **B-MSE20261020 대 B-H10020261020**을
같은 조건에서16판만 비교했다. **재학습은 하지 않았다.** 실제 대국125.798793초(약2분6초),
Huber 기준 **4승7무5패·7.5/16점·46.875%**다. 오류·미완료·미시작0, 독립 검증PASS다.

이번 표본에서는 Huber의 기력 우위를 확인하지 못했다. 한 점 차이와16판으로 Huber의
열세를 확정하지 않는다. 두 모델·기존 NNUE·기본 수식 평가를 그대로 보존하며 자동 승격,
다른 시드 시험이나 추가 대국을 하지 않았다. 앞선 실용 비교3승7무6패와 합산하지 않는다.

## 고정한 학습 조건

| 항목 | 두 모델의 공통 조건 |
| --- | --- |
| 정답 | B: 자체10,000노드 탐색의 백 관점 점수 |
| 자료 | 학습2,209행·검증723행, 같은 위치·특징·정답 |
| 구조·정밀도 | 768입력×16은닉, S32 정수 QAT |
| 초기값 | 동일한 실수 초기 배열, SHA256 `5ce9ca28e3436b125db9b307944d28c1fe7e58bbd7415048ec986aa570d4bd05` |
| 시드·배치 순서 | 20261020, 동일120epoch 배치 순서 |
| 학습 | 120epoch·batch128·입력/편향 학습률0.00002·출력0.005·동일 optimizer |
| 바뀐 것 | MSE 대 H100 손실 함수 |

H100은 폰 단위 오차r에 대해 작은 오차에는r², 절대 오차1폰(100cp)을 넘으면
2|r|−1을 쓰는 방식이다. 큰 오차 몇 개의 기울기가 학습을 과도하게 좌우하는 것을 줄인다.
작은 오차의 손실과 기울기는 기존 MSE와 같다.

- MSE SHA256: `267f65646c24292efa28f11a5f5990311ed7da4f6c134d7c4a6b6c1e0f7be1eb`
- H100 SHA256: `9610be208a160ca60d593a4b35d3bd92d201b146311b65e2e68e8e6b79897210`

두 모델은 기존 준비 실행의 고정 첫 시드다. 이번 성적으로 모델·시드·epoch를 고르지 않았다.
대국 전 원래 준비 동결·현재 모델·학습/검증 자료·정답·초기 배열·특징·배치 순서와 설정을
읽기 전용으로 확인했다. 당시 저장된 검증 MAE89.4550→85.1452cp의 개선과 이번 대국 성적은
구분한다. 교사 점수 모방 오차 감소가 기력 향상을 보장하지 않는다.

## 대국과 검증

기존 `compare_engines.py`와 같은 M1 실행 파일을 사용했다. 양쪽 UCI 옵션은 모델 파일만
다르고 나머지는 동일하다. 수당100ms·단일 검색 스레드·Hash16·Move Overhead20·증분NNUE,
같은 탐색 옵션, 작성된 개시8개·각 양색, claim 무승부·500ply 상한을 고정했다.
모든 판이 체크메이트9판·반복무승부7판으로 끝났으며 ply 상한 종료는 없다.

소스 HEAD는 `48954164c3c58f28bf197c460fa5d8f6be39823d`이고 실제 시작 시 작업 트리는
깨끗했다. 실행 파일 SHA256은 `edd950fb673cfca4134968b64cc5ef0f3d77eda698e9f40d2965170f143d6e6a`다.
실제 최대 응답은0.083804초다. 프로세스 CPU·배경 부하·코어/열 격리는 별도로 측정하지 않았다.

독립 검증1회(약0.38초)에서 고정 입력16개와 학습 조건 증빙 입력의 현재 바이트,
양색8쌍, 동일 옵션·실행 파일, 기보1,621ply·검색1,529회·PV8,050ply의 합법성,
최종 FEN·규칙 종료·4승7무5패를 확인했다. 엔진·학습·전체 회귀를 다시 실행하지 않았다.

고정된 노출 개발 은행·한 시드·16판의 짧은 비교다. 손실 차이만 통제했지만 반복 실행이나
새 보류 개시에서의 재현, 보편적인 Elo·일반적인 우위/열세를 증명한 것은 아니다.
