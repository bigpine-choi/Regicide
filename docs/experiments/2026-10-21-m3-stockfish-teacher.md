# M3: Stockfish 교사·소규모 MSE 학습·기본 Regicide 상대16판

2026-10-21 KST. Stockfish 교사 연결과 현재 NNUE 추가 학습을 구현하고 실행했다.
**새 후보는 기본 수식 Regicide에0승1무15패·0.5/16점(3.125%)**였다.
대국111.058384초(1분51초), 오류·미완료·미시작0, 독립 감사PASS다.
이번 조건에서 뚜렷한 열세여서 **후보를 채택하지 않고 기본 엔진을 유지한다.**
학습·대국은 각1회이고 추가 시드·재학습·판수 확대를 하지 않았다.

## 구현과 고정 조건

새 `stockfish_teacher.py`는 기존에 확보한 공식 Stockfish18을 별도 프로세스로 사용해
학습용 평가 점수만 생성한다. 원본 시작 위치와 전체 수순을 재생하고 최종 FEN을 확인한다.
각 위치에서 해시를 비우고 별도 game 문맥으로 분석한다. 마지막 점수 패킷의 백 관점
cp, 실제 탐색량, 원시 패킷, 합법 PV와 제외 사유를 저장한다.

`train_stockfish_teacher.py`는 자료 선정부터 단일 후보 학습·검증까지 연결한다.
현재 v3 NNUE의 기물768+손번1·공유 은닉16·S32와 **MSE를 유지**했다.
새 신경망 구조나 외부 엔진의 수 선택 코드를 도입하지 않았다.

| 항목 | 실제 조건 |
| --- | --- |
| 교사 | Stockfish18 generic, Threads1·Hash16·Skill20·강도 제한 꺼짐·MultiPV1·테이블베이스 없음 |
| 교사 예산 | 위치당10,000노드 요청, 실제 노드는 원시 기록에 보존 |
| 선정 | 기존 분할에서 seed20261021로 학습512·검증128개를 점수 생성 전에 선정 |
| 제외 | 메이트24개·bound185개, 대체 자료 추가 없음 |
| 실제 자료 | 학습350개·검증81개, 기보 계열·기물 특징의 분할 중복 없음 |
| 초기값 | 직전 손번 NNUE의 실수 가중치에서 fine-tune |
| 학습 | seed20261020·batch128·고정500epoch·마지막 epoch 하나 |

메이트 점수를 임의의 cp로 치환하거나 점수를 잘라서 라벨로 사용하지 않았다.
±1500cp 초과도 사전 제외 조건이었으나 실제 제외 사유는 메이트와 bound뿐이었다.
기존 보류 자료와 대국 결과를 학습·epoch 선택에 사용하지 않았다.
작은 자료의 학습량·학습률도 변경했으므로 교사 차이만 분리한 인과 실험은 아니다.

## 학습과 정확성

교사 생성 **10.206205초**, 학습 **2.657233초**였다.

| Stockfish 정답과의 오차 | 추가 학습 전 MAE | 학습 후 MAE |
| --- | ---: | ---: |
| 학습350개 | 205.4771cp | 78.2200cp |
| 별도 검증81개 | 158.0617cp | 221.7284cp |

학습 오차는 줄었지만 보지 않은 자료에서는 악화됐다. **과적합 징후**이며,
이 현상이 실전 열세의 유일한 원인이라고 확정하지 않는다. Stockfish 정답을 사용했다는
사실만으로 자료량·분포·학습 조건·표현 능력 문제가 해결되는 것은 아니다.

교사 모듈 집중 단위5개를 통과했다. 새 가중치에서431자료+46특수수 위치,
총477위치의 Python/전체/증분 점수가 정확히 일치했다. 실제 후보를 읽은 native 모델
회귀13그룹25,521단언도0실패였다. 이전 native·기존 모델 호환성 검사는 같은 바이너리
해시로 연결해 재사용했고 전체 과거 회귀를 다시 실행하지 않았다.

## 기본 엔진과16판

두 쪽 모두 기존 연구 빌드 `build-m3-stm/regicide.exe`를 사용했다.
기준 쪽은 `config/engine-profiles/classical.json`의 전체 옵션과 동일하고
`UseNNUEEvaluation=false`, `UseNeuralEvaluation=false`다.
후보 쪽은 `UseNNUEEvaluation=true`와 새 모델 파일만 바꿨다.
따라서 이번 상대는 이전 MSE NNUE가 아니라 **기본 수식 평가 Regicide**다.

AMD Ryzen AI7 350, 8코어16논리CPU, Windows 공유PC, 검색1스레드·Hash16,
Move Overhead20·수당100ms, 같은8개시에서 양색16판·claim 무승부·500ply 상한이다.
15판 체크메이트·1판 반복무승부로 완료했다. 새 감시·CPU 부하 중단 체계는 만들지 않았다.

독립 감사1회4.44초에서 고정 입력16개,640교사 질의·431라벨의 원본 이력·백 기준 점수·
PV·제외 이유·선정 재현·분할, 모델 형식과 학습 조건, 대국의 양색8쌍·기보1,441ply·
검색1,349회·PV6,955ply·최종FEN·규칙 종료·0승1무15패를 확인했다.

학습 코드 커밋 `602c1ddb5331c4d85064aca33f1d115d30deaa96`, 실행 계획 커밋
`372d22de7c141d855e321c1e9a4768ac98dc47b2`. 대국 시작 시 작업 트리는 깨끗했다.
native 소스는 기존 `e246d8102c58b4c8680b26ac3886095ab25e79f0`와 동일하며 새 빌드는 하지 않았다.
