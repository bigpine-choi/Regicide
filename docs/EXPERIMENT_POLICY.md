# 빠른 엔진 변경 비교 원칙

2026-10-21 사용자 지시: 새 코드가 기존 코드보다 강한지 비교할 때는 시간을
최대한 적게 쓴다. 엔진 개선 작업을 과도한 실험 규모와 감시 구현으로 지연시키지 않는다.
개발 시간은 엔진 코드 개선과 학습에 우선 쓰며, 대국은 그 효과를 짧게 확인하는 수단으로 쓴다.

- 기본 비교는 변경 하나와 기존 기준 버전 사이에서만 한다. 외부 상대·여러 평가기·여러
  생각 시간을 한꺼번에 비교하는 행렬은 별도 목적이 있을 때 사용한다.
- 먼저 변경에 필요한 정확성 검사만 수행한다. 통과한 검사를 이유 없이 반복하지 않는다.
- 첫 대국은 같은 개시에서 선후공을 바꾸는 8쌍·16판, 생각 시간 100ms를 기본으로 한다.
  예상 총 소요 시간을 먼저 알리고, 보통 10분 이내에 첫 판단 자료를 얻도록 한다.
- 첫 비교는 큰 퇴보와 개선 가능성을 찾는 선별 검사다. 소표본 승률을 Elo나 확정적인
  기력 향상으로 해석하지 않는다. 판수 확대는 목적·예상 시간·필요한 근거를 먼저 설명한다.
- 가능한 한 기존 실행·검증 도구를 재사용한다. 동일 원시 자료의 검증은 해시로 연결해
  재사용하고, 실제 실패나 새로운 우려가 없으면 새 감시 체계나 반복 진단을 만들지 않는다.
- 실험 기반 수정, 실행 비용 개선, 실제 경기력 개선을 별도로 보고한다.

현재 사용자가 선택한 M2 축소 범위는 본 96판이다. 위 16판 기본값을 이유로 이미 승인한
96판의 조건을 조용히 바꾸지 않는다. 기존 중단 성적과 사전 대국을 본 성적에 합치지 않는다.
