# 왕 앞 폰 방패 평가

v0.5.4는 왕보다 앞에 가까운 자기 폰이 남아 있는지를 평가한다. 예를 들어 백 왕이 g1에 있을 때 f2·g2·h2의 폰은 가까운 방패다. g폰을 g3으로 전진시키면 공격이나 전개에 도움이 될 수 있지만, 방패의 거리 비용도 조금 생긴다. 폰을 움직이는 수를 금지하거나 항상 나쁜 수로 판정하는 기능은 아니다.

## 계산

왕과 같은 파일 및 양옆 파일을 본다. a/h 파일의 왕은 보드 안의 두 파일만 본다. 각 파일에서 왕 앞의 가장 가까운 자기 폰을 찾는다.

| 앞 폰까지 거리 | 중반 기본 감점 |
| --- | ---: |
| 1칸 | 0cp |
| 2칸 | 4cp |
| 3칸 | 8cp |
| 4칸 이상 또는 앞 폰 없음 | 12cp |

100cp는 폰 한 개의 기본 가치다. 최대 기본 감점은 세 파일 합계 36cp이며, 상대의 나이트·비숍=1, 룩=2, 퀸=4의 합을 최대 12로 제한한 비율로 줄인다. 상대의 공격 기물이 없으면 감점도 0이다. 이 감점은 중반 항목에만 들어가고 기존 중반/종반 혼합을 거치므로 종반에는 영향이 더 작아진다. 정수 나눗셈 때문에 실제 총점 차이는 1cp 정도의 반올림 경계 영향을 받을 수 있다.

왕 뒤나 왕과 같은 랭크의 폰은 앞 방패로 세지 않는다. 같은 파일에 폰이 여러 개 있으면 가장 가까운 앞 폰을 사용한다. 왕의 특정 위치에서 갑자기 평가를 끄지 않으며, 퀸이 없더라도 상대 룩·경량기물이 있으면 작은 비용이 남을 수 있다. 폰만 남은 종반의 평가는 이전 버전과 같다.

## 비교용 설정

기본값은 켬이다. UCI에서 `setoption name UsePawnShield value false`, 콘솔에서 `search 3 --no-pawn-shield`로 이전 평가를 선택할 수 있다. C++에서는 `evaluate_position(board, false)` 또는 `SearchOptions::king_pawn_shield=false`를 사용한다. 위치 평가 전체를 끄는 `UsePositionalEvaluation=false`에서도 새 항목은 사용하지 않는다. GUI의 실제 상대 수와 추천 수는 기본적으로 새 평가를 사용한다.

계수와 코드는 자체 구현한 초기 가정이다. 상대의 공격 경로·상대 폰 폭풍·피앙케토 비숍의 방어·기물 활동성까지 판단하는 완전한 왕 안전 모델은 아니다. 규칙 정확성·평가 의도·검색 비용의 확인과 전체 기력 향상은 구분한다. [계획](experiments/2026-10-18-pawn-shield-plan.md)과 [검증 결과](experiments/2026-10-18-pawn-shield.md)에 범위를 남긴다.
