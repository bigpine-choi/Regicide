# 적극적인 구상을 선택하는 Regicide

일반 대국의 초반에는 기존의 폭넓은 오프닝 선택을 유지하고, 중반에는 자체 엔진이 비슷하게 좋다고 검토한 수들 사이에서 더 활동적인 구상을 선호한다. 먼저 수읽기로 후보를 검증한 뒤 별도의 스타일 선호를 적용하며 기본 평가 cp를 바꾸지 않는다. Stockfish나 외부 모델은 실제 수 선택에 사용하지 않는다.

## 어떤 수를 선호하는가

후보의 예상 수순에서 **상대가 한 번 응수한 뒤**에도 남는 특징을 본다.

- 나이트·비숍·룩·퀸이 활용하는 칸이 늘어나는가.
- 전개된 나이트·비숍과 폰에 막히지 않은 룩의 파일이 늘어나는가.
- 두 개 이상의 기물이 상대 왕 주변을 함께 압박하는가.
- c~f파일의 폰 전진으로 비숍·룩·퀸의 길이 실제로 열리고 상대 응수 후에도 유지되는가.

예를 들어 조용한 d폰 전진이 비숍과 룩의 길을 동시에 열어 주면 선호할 수 있다. 체크·잡기·기물 희생이라는 사실 자체에는 점수를 주지 않는다. 단독 퀸의 왕 주변 공격도 협동 공격 점수를 받지 않는다. 활동 칸 계산은 자기 기물과 상대 폰 공격을 제외한 기하적 추정이며, 핀이나 모든 상대 기물의 공격을 완전히 판정하는 안전성 검사는 아니다.

스타일 점수는 cp(체스 평가 점수)와 단위가 다르다. 상대 응수 이후의 스타일 점수가 기본 수보다 낮은 후보는 최종 선택에서 제외한다. 남은 후보는 품질 차이와 스타일 개선량에 따라 가중치를 주고 대국별 시드로 선택한다. 기본 수는 항상 후보에 남고, 새 대국마다 시드를 바꾸므로 같은 국면에서도 다른 구상을 볼 수 있다. 모든 대국의 수가 달라지거나 특정 오프닝이 균등하게 나오는 것은 아니다.

## 먼저 지키는 수읽기 조건

설정한 생각 시간 전체로 원래 Regicide 탐색을 끝낸 뒤 추가 후보를 검사한다. 후보는 기본 탐색의 마지막 완료 깊이와 같은 깊이까지 읽어야 하고 그 깊이는 최소 4다. 정확한 점수와 합법적인 예상 수순이 함께 있어야 한다.

처음 16착수에는 기존 [오프닝 v3](OPENING_VARIETY.md)의 후보·순서·시간·25cp 검증·최종 선택을 그대로 유지한다. 조용한 피앙케토처럼 준비에 시간이 걸리는 오프닝을 단기 활동성만으로 배제하지 않기 위해서다. 그 뒤에는 80착수까지, 충분한 기물이 남아 있을 때 활동적인 후보를 최대 4개 검토하며 허용 차이를 15cp로 줄인다. 스타일이 아무리 높아도 이 제한을 넘은 수는 선택할 수 없다. 더 깊은 불리한 결과, 범위 점수, 후보 탐색 오류, 시간 초과, 기본 탐색과 크게 모순되는 점수는 기본 수로 돌아가는 근거다.

중반에 메이트 점수, 끝나는 예상 수순, 충분한 상대 응수 정보가 없는 경우, 자체 평가가 이미 300cp 이상 우세인 경우에는 추가 검토부터 생략한다. 체크 중·반복된 국면·사용자 강제 착수·표준 시작이 아닌 대국·단순한 종반·80착수 이후에도 일반 탐색을 사용한다. 이 기준은 제한된 자체 탐색 안의 보호 장치이며 실제 기력 무손실을 증명하지 않는다.

## 생각 시간

| 설정 | 기본 탐색 | 초반 추가 상한 | 중반 추가 상한 |
| --- | ---: | ---: | ---: |
| 0.1초 | 0.1초 | 없음 | 없음 |
| 1초 | 1초 | 1초 | 0.5초 |
| 3초 | 3초 | 2초 | 0.75초 |
| 5초 | 5초 | 2초 | 0.75초 |

추가 시간은 모든 후보가 함께 쓰는 예산이며 항상 전부 쓰지는 않는다. 화면에는 이를 “구상 검토”로 안내한다. 진행 중인 수는 시작할 때의 시간 설정을 지키고, 새 설정은 다음 수에 적용한다. 추가 후보의 제한 탐색 점수는 형세 게이지에 보내지 않는다.

추천수·분석 모드·코칭에는 이 취향 선택을 섞지 않는다. 해당 기능들은 평가상 좋은 수를 찾는 기존 방식을 유지한다. 기물 활동성 자체를 보는 수식 평가는 각 기능에 공통으로 적용되지만, 여기서 설명하는 스타일 정책은 일반 대국의 최종 수 선택에만 적용한다.

## 기록과 개발 비교

실행기에서 자동 적용하며 새 체크 상자를 만들지 않았다. 내부 `HumanGame` API의 `dynamic_play_enabled=False`는 기존 정책과의 비교를 위해 유지하고 실제 앱 진입점은 `True`를 명시한다.

JSON 기보의 `dynamic_play`에는 정책 `regicide-dynamic-play-v1`, 시드, 전체 이력, 기본 수, 검토한 후보, 같은 깊이의 점수, 상대 응수 뒤의 스타일 근거와 최종 선택을 남긴다. PGN의 `DynamicPlayPolicy`·`DynamicPlaySeed`는 보관함 내보내기에도 유지한다. 첫 16착수의 `opening_receipt`는 원본 v3 결정이고 최상단 `selected_uci`도 그 선택과 일치한다. 중반의 스타일 선택은 이와 구분해 기록한다.

무르기 후 같은 국면·이력·시드·시간·평가 버전에는 저장한 결정을 다시 사용한다. 강제 착수와 취소도 별도 기록을 보존한다. 기존 대국 파일은 다시 쓰지 않는다.

[실제 선택 비교·검증·한계](checks/2026-11-02-dynamic-play/README.md)를 참고한다. 개발 국면의 스타일 변화와 자체 평가 제한 준수는 기력이나 Elo 향상과 별도로 보고한다.
