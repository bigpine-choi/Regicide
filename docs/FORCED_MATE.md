# 강제 체크메이트 탐색 프로토타입

일반 대국·갬빗 정책과 분리된 연구용 첫 구현이다.
기준 main: `059f7f70ba25ff3c616b081c99a310e1adf9e583` (한국 시간 2026-11-04).
이 경로의 수 선택과 메이트 증명에는 외부 엔진을 사용하지 않는다.

## 실행

기존 방식으로 빌드한 실행 파일을 `regicide uci`로 시작한다.

```text
uci
position fen 7k/8/5KQ1/8/8/8/8/8 w - - 0 1
go mate 1 nodes 100000
```

`bestmove`를 받은 후 `quit`를 보낸다. 바로 EOF나 quit를 보내면 진행 중인 탐색이 중단된다.

`go mate N`은 현재 차례인 진영이 자신의 N번째 착수 이내에,
상대의 모든 합법적 방어에 대해 체크메이트를 강제할 수 있는지 묻는다.
최대 깊이는 `2*N-1`플라이이며, N은 1..64를 받는다.
플라이는 한쪽의 착수 한 번이다. M16은 최대 31플라이에 해당한다.

기본 총예산은 반복 탐색을 포함한 1,000,000노드다.
`nodes`로 총노드를 바꾸고, `movetime`이나 일반 UCI 양측 시계로 시간도 제한할 수 있다.
Move Overhead 설정은 기존 시간 처리와 동일하게 적용한다.
`stop`은 작업을 중단하며 탐색 중에도 `isready`에 응답한다.

```text
position startpos
go mate 16 nodes 1000
```

이는 M16의 제한된 탐색 요청이며 M16 해결 능력의 증거가 아니다.

`searchmoves`는 루트의 공격 후보만 제한한다. 이후 상대 방어는 모두 유지한다.
출력의 `scope searchmoves`는 이 제한을 뜻하며, 최단 거리와 부정 결과도 해당 후보 안에서만 유효하다.
불법·중복·빈 루트 후보는 거부한다.
`mate`와 `depth` 또는 `infinite`의 조합도 거부한다.
`ponder`는 기존과 같이 지원하지 않는다.

## 결과 구분

| 상태 | 의미 |
| --- | --- |
| `proven` | 지정 범위 안에 모든 합법적 방어를 이기는 메이트 전략이 증명됨 |
| `no_mate_within_bound` | 지정 범위의 모든 허용 공격을 완전 탐색했지만 강제메이트가 없음. 더 긴 메이트는 있을 수 있음 |
| `unknown` | 노드·시간·stop으로 탐색이 끝나 메이트 존재 여부를 판정하지 못함 |

`proven`일 때만 `score mate`, 검증된 주요 수순 `pv`,
반수 거리 `mate_distance plies`를 출력한다.
PV는 증명된 전략에서 가장 오래 버티는 방어를 따른 대표 수순이다.
모든 방어의 증명 트리를 파일로 내보내는 인증서는 이번 구현에 없다.

`completed`는 완전히 판정한 최대 반복 범위를 뜻한다.
미증명 결과에서도 프로토콜상 합법적인 `bestmove`를 반환할 수 있으나
`mate_fallback unproven`으로 표시한다. 이 수는 증명된 공격이나 추천수가 아니다.
이미 종국인 위치는 `bestmove 0000`이다. 입력 오류도 설명과 함께 0000을 반환한다.

## 증명 원리와 규칙

공격 진영은 루트의 차례로 고정한다.
공격자 노드는 한 가지 증명된 공격이 있으면 성공하는 OR 노드다.
수비자 노드는 모든 합법적 응수가 메이트로 이어져야 성공하는 AND 노드다.
단 하나의 탈출 방어만 있어도 해당 공격은 실패한다.

조용한 수, 모든 승격, 앙파상, 캐슬링도 합법 후보에 포함한다.
체크를 먼저 검사하는 정렬은 가능하지만 후보를 제외하는 가지치기는 사용하지 않는다.
1, 3, 5…플라이를 순서대로 검사해 짧은 메이트의 부재를 판정한 뒤
최초 성공 범위의 최장 방어 PV로 최단 강제메이트 거리를 보고한다.
자원 부족은 범위 내 메이트 부재로 바꾸지 않는다.

기존 Board의 정확한 수 이력과 규칙 처리를 복사해서 사용한다.
체크메이트는 수 카운터 무승부보다 먼저 판정한다.
스테일메이트, 확인 가능한 데드 포지션 기물 조합, 5회 반복,
75수 자동 무승부는 메이트가 아니다.
수비자의 현재 또는 예정수에 의한 3회 반복·50수 청구권도 탈출로 처리한다.
공격자는 자신의 선택적 청구권을 포기할 수 있다.
기존 Board의 데드 포지션 판정은 알려진 확실한 기물 조합만 인식하며,
임의의 모든 데드 포지션을 인식하는 별도 판정기는 아니다.

FEN에는 50수 카운터가 있지만 이전 반복 이력은 없다.
이력이 있으면 `position startpos moves ...` 또는
`position fen ... moves ...`로 제공해야 한다.
UCI에서 실제 무승부 청구를 제출하는 기능은 없으며,
여기서는 최선 수비의 청구 가능성을 증명 조건에 반영한다.

별도 `regicide_mate` 라이브러리는 `regicide_core`에만 의존한다.
기존 대국의 alpha-beta 탐색·평가기·TT·갬빗 정책 코드는 변경하지 않는다.
메이트 증명에는 NNUE·형세 점수·선택적 LMR·정지 탐색을 쓰지 않고,
일반 탐색 캐시에 결과를 남기지 않는다.
현재 MSVC에서 기존 SEE 상수 테이블 생성이 실패해, 같은 테이블을 만드는
범위 기반 반복을 인덱스 반복으로 바꾼 컴파일 호환 수정만 함께 포함한다.

## M16 확장 한계

첫 구현은 반복 범위를 사용하는 깊이 우선 AND/OR 탐색이다.
전치 재사용, 증명수 탐색, 테이블베이스, 병렬 탐색, 영속 증명 인증서는 구현하지 않았다.
분기 비용이 기하급수적으로 늘어 일반적인 M16 국면은 예산을 소진할 수 있다.
이번 기능은 주어진 국면을 탐색한다. 새 국면·갬빗·독창적인 M16 문제의
자동 발굴 시스템까지 구현한 것은 아니다.

다음 단계는 재현 가능한 메이트 문제 모음과 무승부 이력을 보존하는
증명수 탐색(Proof-Number Search) 또는 DFPN의 도입이다.
캐시는 남은 깊이, 50수 카운터, 정확한 반복 문맥까지 보존해야 한다.
기물 배치만 해시하면 잘못된 증명이 생길 수 있다.
별도 검증기가 재생할 수 있는 증명 트리도 후속 과제다.
추후 Stockfish·테이블베이스와 비교한다면 Regicide 자체 증명과 별도로 기록해야 한다.
