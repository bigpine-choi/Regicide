대국용 안정 엔진: 기존 v0.5.0. 이 작업은 설치본이나 핵심 수 선택 코드를 교체하지 않는다.

## 목표와 판정

목표는 자체 Regicide가 세계 정상급 인간과 표준 체스에서 경쟁하고 반복 대국으로 우위를 입증하는 것이다. 실제 상대, 대국 전체의 시간제한, 하드웨어와 외부 자료 허용 조건을 정해 기록한다. 한 판 승리, 반복 대국 우위, 특정 엔진 집단의 Elo는 서로 다른 결과다. 엔진 Elo나 외부 엔진의 약화 옵션 수치를 인간 FIDE Elo로 환산하지 않는다.

현재는 자체 엔진과 대국 환경, 회귀 검증, 자체 버전 간 비교를 확보한 단계다. 세계 정상급 인간이나 강한 외부 엔진에 대한 우위는 아직 검증하지 않았다. 현재의 성적에서 목표 달성 시점이나 승률을 추정하지 않는다.

## 첫 개발: 외부 UCI 엔진 기준평가

기존 `compare_engines.py`는 양측 소스 커밋을 Regicide 저장소 안에서만 검증하고 양측 실행에 `uci` 인자를 고정했다. 외부 엔진에는 독립적인 출처와 실행 인자를 기록해야 하며 상대의 Hash/Threads 설정도 제어해야 한다.

이번 변경은 다음을 지원한다.

- 기존 내부 기준 엔진은 `--baseline-commit`을 그대로 사용한다.
- 외부 기준 엔진은 `--baseline-source` JSON으로 이름, 버전, 출처 URL, revision, 실행 파일 SHA256과 실행 인자를 선언한다. 두 출처 모드는 상호 배타적이다.
- 외부 실행 파일의 실제 SHA256이 선언과 다른 경우 실행 전 거절한다. URL/revision은 사용자의 선언이며, 원격 커밋 검증이나 소스와 바이너리의 빌드 관계 증명을 의미하지 않는다.
- `--baseline-options`와 기존 `--candidate-options`로 양측 설정을 분리한다. 광고된 옵션 타입/범위를 검사한 뒤 설정을 전송하고 기록한다. UCI에는 일반적인 설정 읽기 확인 기능이 없으므로 실제 내부 상태를 읽었다고 주장하지 않는다.
- 기존 선후공 교대, 전체 시작 수순, 독립 합법 수 검사, PGN/JSON, 실행 파일 해시, 수별 탐색 정보와 미완료 기록을 유지한다.

[실행과 출처 기록 방법](EXTERNAL_BASELINE.md)을 따른다. 이번 작업 자체는 외부 엔진 대국 성적이나 경기력 상승을 제공하지 않는다.

## 실행 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 외부 기준평가 도구 연결 | 내부 모드 회귀 검증과 외부 UCI 테스트 프로세스의 선후공 연결·설정·기보 재생 확인 |
| 2 | 외부 기준 실력 측정 | 상대의 정확한 버전·바이너리·설정, Regicide 버전, 하드웨어, 시작 위치·시간·선후공·예정 대국 수를 결과 확인 전에 고정하고 전체 결과 보관 |
| 3 | 패배 유형 분류 | 전술 누락·형세 평가·종반 처리·시간 배분을 구분하고 대표 위치를 독립 검토. 자체 점수 급변만으로 악수라고 단정하지 않음 |
| 4 | 개선 가설 하나씩 구현 | 변경 전/후의 규칙 정확성, 계산 비용과 같은 시간 대국을 각각 비교 |
| 5 | 강한 상대와 보류 표본 확대 | 개발에 쓰지 않은 시작 위치와 여러 독립 상대에서 개선 재현 여부 확인 |
| 6 | 목표 인간 대국 조건 검증 | 전체 대국 시계 지원·충분한 외부 평가를 갖춘 뒤 실제 목표 상대와의 조건 및 평가 절차 확정 |

초기 외부 기준 측정은 기존 도구가 지원하는 수당 100ms/1초의 별도 블록으로 준비한다. 전체 대국 시계 방식의 인간 대국을 대체하지 않는다. 같은 노드/깊이 비교는 계산 분석용이며 같은 시간의 경기력과 구분한다. 32개 시작 위치를 선후공 교대하는 64판씩은 초기 계획안이며, 상대·하드웨어·목록을 고정하기 전에는 사전 등록된 실험으로 부르지 않는다. 표본 수만으로 정상급 인간 상대 실력을 입증하지 않는다.

동시 엔진 부하와 절전, 오류, 불법 수, 시간 초과, 미완료 판, 중단/재시도 이유를 보존한다. 현재 비교 도구는 엄격한 전체 대국 시계 심판이나 실행 환경 격리를 제공하지 않는다. 최신 실험의 별도 CPU 감시 절차도 조건에 맞게 재사용·검증해야 한다. 결과를 본 뒤 유리한 판만 고르거나 중단 판을 무승부로 바꾸지 않는다.

## 다음 개선 가설

1. **조용한 전술 위협**: 현재 안정화 탐색은 캡처·승격·제한된 체크를 연장하지만 체크가 아닌 포크 준비 등은 놓칠 수 있다. 대표 패배 위치에서 누락을 재현한 뒤 연장/선택 정책의 이득과 비용을 평가한다.
2. **폰 구조와 기물 관계 평가**: 현재 폰 평가는 주로 전진과 파일 위치다. 고립폰·겹친폰·패스폰을 작은 독립 실험으로 검토하고 대칭성, 중복 보상과 탐색 비용을 검증한다. 계수를 추가하면 강해진다는 가정으로 안정판에 반영하지 않는다.
3. **종반 처리**: 패스폰 경쟁, 킹 활동과 승리 전환 실패를 분류한다. 외부 테이블베이스 사용 여부는 자체 구현 원칙·비용·이용 조건을 확인해 별도 결정한다.
4. **학습 평가 연구**: 기준 엔진과 측정 체계를 확보한 뒤 자체 신경망 평가의 데이터 출처, 검증 분리, 연산 예산을 설계한다. 신경망 도입 자체를 성공 기준으로 삼지 않는다.

실제 수 선택은 계속 Regicide의 자체 엔진이 담당한다. 외부 엔진은 상대와 별도 분석 도구로 사용한다. 사용자가 원리를 이해하고, 자체 엔진을 개선하며, 결과를 재현할 수 있는 변경을 우선한다.
