# Regicide의 다양한 오프닝 선택

일반 대국에서 자체 Regicide가 충분히 좋다고 검토한 초반 후보를 다양하게 선택한다. 기본으로 적용하며 분석 모드·코칭·추천 수와 일반 UCI 엔진에는 이 선택 정책을 섞지 않는다.

## 첫 1~3수의 탐색 범위

처음 **6번 착수, 양쪽이 세 수씩 두는 구간**은 오프닝 자료의 등록 여부와 관계없이 모든 합법 수를 검토 후보로 삼는다. 예를 들어 `1.Nc3 Nf6` 뒤 기존 자료는 `g4` 하나만 제안했지만, 이제 `Nf3`, `e4`, `d4` 등 22개 합법 수를 후보로 삼는다. `1.Nc3 Nf6 2.Nf3 d6`처럼 자료에 다음 수가 없는 국면에서도 세 번째 수를 다양하게 검토한다.

한정된 검토 시간을 유용하게 쓰기 위해 중앙의 c·d·e폰 전진, 처음 나오는 나이트·비숍, b·g폰 한 칸 전진, 잡기와 캐슬링에 검토 순서 가중치 3을 주고, 나머지 합법 수에는 1을 준다. 대국별 시드로 순서를 섞으므로 다른 합법 수도 첫 후보가 될 기회가 있다. 이 가중치는 수읽기 순서일 뿐이며 평가 점수를 올리거나 채택 기준을 면제하지 않는다.

네 번째 수부터는 기존처럼 **16번 착수, 양쪽이 여덟 수씩 두는 구간**까지 현재 국면의 로컬 오프닝 자료에 있는 바로 다음 합법 수를 모은다. 서로 다른 수순으로 같은 국면에 도달해도 후보를 찾는다. 후보 범위에 들어간 모든 수가 실제 선택된다는 뜻은 아니다.

같은 수가 자료의 여러 행에 나와도 후보는 한 번만 센다. 오프닝 이름·자료의 빈도·화면 정렬 순서로 확률을 정하지 않는다. 자료에는 좋지 않은 수순도 있으므로 카탈로그 포함 여부를 실력 근거로 취급하지 않는다.

## 기본 탐색을 지킨 뒤 추가 검토

먼저 설정한 **한 수 생각 시간 전체**로 원래 Regicide 탐색을 실행한다. 이렇게 찾은 수를 보관한 뒤, 기존과 같은 추가 시간 안에서 첫 세 수는 최대 열 후보, 이후에는 최대 여섯 후보를 검토한다. 시간 안에 완료할 수 있는 후보만 검토하므로 항상 열 후보를 평가하는 것은 아니다. 비교가 실패하거나 근거가 불확실하면 보관한 기본 수를 둔다.

| 한 수 생각 시간 | 기본 탐색 | 오프닝 추가 검토 상한 |
| --- | --- | --- |
| 0.1초 | 0.1초 | 없음 |
| 1초 | 1초 | 최대 1초 |
| 3초 | 3초 | 최대 2초 |
| 5초 | 5초 | 최대 2초 |

추가 시간은 후보들이 함께 쓰는 예산이다. 각 후보는 기본 탐색의 마지막 완료 깊이까지 읽고, 먼저 끝나면 남은 시간을 다음 후보에 쓴다. 대국 화면의 시간 안내에도 추가 검토 상한을 표시한다. 중간에 설정 시간을 바꾸면 진행 중인 수는 시작할 때의 예산을 유지하고 다음 수부터 새 시간을 적용한다.

## 채택 기준

후보를 채택하려면 다음 조건을 모두 만족해야 한다.

- 기본 탐색의 **마지막 완료 깊이**와 같은 깊이에서 비교할 수 있고, 그 깊이가 최소 4다.
- 해당 메시지에 정확한 CP 점수와 전체가 합법인 예상 수순이 함께 있어야 한다. 메이트·상한/하한·깊이 부족·서로 다른 메시지를 합친 값은 근거로 쓰지 않는다.
- 수를 둘 쪽 기준으로 기본 수보다 **25cp 이내**여야 한다. 이전 35cp보다 엄격하며, 25cp는 폰 0.25개에 해당하는 자체 평가 단위다.
- 후보 제한 탐색이 기본 탐색보다 지나치게 좋은 점수를 내는 등 비교가 크게 모순되면 기본 수를 유지한다. 더 깊은 불리한 결과가 있는 경우에도 채택하지 않는다.

통과한 후보와 기본 수 사이에서 대국별 시드로 선택한다. 첫 세 수에서는 기본 수의 가중치를 1, 검증을 통과한 각 대안의 가중치를 2로 두어 다른 전개를 더 자주 시도한다. 이는 다양성을 위한 명시적인 선호이며 표본 확률 보정이나 더 강하다는 판단이 아니다. 이후 구간은 기존처럼 기본 수가 항상 포함되는 차이를 고려해 검사한 후보 수와 전체 제안 후보 수로 가중치를 정한다. 실제 가중치와 선택 근거를 기보에 남긴다. 같은 오프닝이 연속해서 나올 수는 있으며 완전한 균등 분포를 보장하지 않는다.

체크 중·종국·사용자 강제 착수·표준 시작이 아닌 대국에서는 일반 탐색을 사용한다. 이미 같은 국면이 반복된 대국은 다양화를 적용하지 않는다. 첫 세 수 이후 자료에 후보가 없거나 전체 범위를 벗어나면 추가 검토도 하지 않는다. 0.1초 설정도 기존대로 일반 탐색을 유지한다.

## 표시·무르기·기록

후보 한 수만 허용한 점수는 전체 국면의 형세 막대에 보내지 않는다. 기본 탐색 점수를 표시한 뒤, 실제 착수 후에는 기존 실시간 평가가 새 국면을 계산한다. 기존 세 후보 추천 기능과도 별개다.

새 대국에는 새 시드를 만들고, 같은 대국에서 같은 수순으로 무르면 저장한 결정을 재사용한다. 생각 시간을 바꾸면 같은 제안 순서를 새 예산으로 검토한다. 검증과 메모에는 실제 전체 수순·반복 이력·캐슬링·앙파상 상태를 유지하며, 화면상 같은 국면이라도 다른 이력의 평가를 섞지 않는다.

JSON 기보의 `opening_variety`에는 정책 버전·시드·후보 출처·각 검토 결과·예산·선택 가중치·이유가 남는다. 현재 정책은 v3이며 `early_plies=6`, `max_early_probes=10`을 기록한다. 각 결정의 `candidate_source`는 초반 합법 수 탐색인지 이후 카탈로그 탐색인지 구분한다. PGN의 `OpeningVarietySeed`와 `OpeningVarietyPolicy`는 보관함 내보내기에서도 보존한다. 이전 v1·v2 기보도 계속 읽으며 다시 쓰지 않는다. 시간 제한 검색은 실행 부하에 따라 달라질 수 있으므로 시드만으로 결과 전체를 재현할 수는 없다.

## 데이터와 검증의 한계

첫 세 수는 로컬 게임 관리기가 합법 수를 제안하고, 이후 후보 자료는 기존 [오프닝 안내](OPENING_GUIDE.md)의 고정된 Lichess chess-openings(CC0-1.0)를 사용한다. 수읽기와 평가는 자체 C++ 엔진이 담당하며 Stockfish의 수·점수·모델은 사용하지 않는다.

기본 탐색 예산 보존과 같은 자체 평가 기준으로 실력을 보호한다. 다만 제한된 자체 평가가 실제 무손실을 증명하지는 않는다. 다양성·자체 점수 비교·추가 지연을 각각 측정하며 경기력이나 Elo 향상으로 바꿔 말하지 않는다.
