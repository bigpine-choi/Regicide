# Regicide의 다양한 오프닝 선택

일반 대국에서 자체 Regicide가 충분히 좋다고 검토한 초반 후보를 다양하게 선택한다. 기본으로 적용하며 분석 모드·코칭·추천 수와 일반 UCI 엔진에는 이 선택 정책을 섞지 않는다.

## 넓어진 후보

처음 **16번 착수, 양쪽이 여덟 수씩 두는 구간**까지 검토한다. 첫 수의 네 후보 제한을 없애고, 현재 국면에서 로컬 오프닝 자료에 있는 바로 다음 합법 수를 모은다. 서로 다른 수순으로 같은 국면에 도달해도 후보를 찾는다. 백의 시작 국면은 제안 후보가 4개에서 20개로, `1.e4` 뒤 흑은 4개에서 19개로 늘어난다. 이는 제안 범위이며 모든 수가 실제 선택된다는 뜻은 아니다.

같은 수가 자료의 여러 행에 나와도 후보는 한 번만 센다. 오프닝 이름·자료의 빈도·화면 정렬 순서로 확률을 정하지 않는다. 자료에는 좋지 않은 수순도 있으므로 카탈로그 포함 여부를 실력 근거로 취급하지 않는다.

## 기본 탐색을 지킨 뒤 추가 검토

먼저 설정한 **한 수 생각 시간 전체**로 원래 Regicide 탐색을 실행한다. 이전처럼 기본 탐색 시간을 절반으로 나누지 않는다. 이렇게 찾은 수를 보관한 뒤, 초반에만 별도의 추가 시간 안에서 최대 여섯 후보를 검토한다. 비교가 실패하거나 근거가 불확실하면 보관한 기본 수를 둔다.

| 한 수 생각 시간 | 기본 탐색 | 오프닝 추가 검토 상한 |
| --- | --- | --- |
| 0.1초 | 0.1초 | 없음 |
| 1초 | 1초 | 최대 1초 |
| 3초 | 3초 | 최대 2초 |
| 5초 | 5초 | 최대 2초 |

추가 시간은 후보들이 함께 쓰는 예산이다. 각 후보는 기본 탐색의 마지막 완료 깊이까지 읽고, 먼저 끝나면 남은 시간을 다음 후보에 쓴다. 대국 화면의 시간 안내에도 추가 검토 상한을 표시한다. 중간에 설정 시간을 바꾸면 진행 중인 수는 시작할 때의 예산을 유지하고 다음 수부터 새 시간을 적용한다.

## 채택 기준

후보를 채택하려면 다음 조건을 모두 만족해야 한다.

- 기본 탐색의 **마지막 완료 깊이**와 같은 깊이에서 비교할 수 있고, 그 깊이가 최소 4다.
- 해당 메시지에 정확한 CP 점수와 전체가 합법인 예상 수순이 함께 있어야 한다. 메이트·상한/하한·깊이 부족·서로 다른 메시지를 합친 값은 근거로 쓰지 않는다.
- 수를 둘 쪽 기준으로 기본 수보다 **25cp 이내**여야 한다. 이전 35cp보다 엄격하며, 25cp는 폰 0.25개에 해당하는 자체 평가 단위다.
- 후보 제한 탐색이 기본 탐색보다 지나치게 좋은 점수를 내는 등 비교가 크게 모순되면 기본 수를 유지한다. 더 깊은 불리한 결과가 있는 경우에도 채택하지 않는다.

통과한 후보와 기본 수 사이에서 대국별 시드로 선택한다. 기본 수는 항상 선택 집합에 들어가지만 다른 수는 일부만 검토되므로, 그 차이 때문에 기본 수가 과도하게 자주 뽑히지 않도록 선택 가중치를 조정한다. 검사한 후보 수와 전체 제안 후보 수, 실제 가중치와 선택 근거를 기보에 남긴다. 같은 오프닝이 연속해서 나올 수는 있으며 완전한 균등 분포를 보장하지 않는다.

체크 중·종국·사용자 강제 착수·표준 시작이 아닌 대국에서는 일반 탐색을 사용한다. 이미 같은 국면이 반복된 대국은 오프닝 자료로 다시 유도하지 않는다. 범위를 벗어나거나 자료에 후보가 없으면 추가 검토도 하지 않는다.

## 표시·무르기·기록

후보 한 수만 허용한 점수는 전체 국면의 형세 막대에 보내지 않는다. 기본 탐색 점수를 표시한 뒤, 실제 착수 후에는 기존 실시간 평가가 새 국면을 계산한다. 기존 세 후보 추천 기능과도 별개다.

새 대국에는 새 시드를 만들고, 같은 대국에서 같은 수순으로 무르면 저장한 결정을 재사용한다. 생각 시간을 바꾸면 같은 제안 순서를 새 예산으로 검토한다. 검증과 메모에는 실제 전체 수순·반복 이력·캐슬링·앙파상 상태를 유지하며, 화면상 같은 국면이라도 다른 이력의 평가를 섞지 않는다.

JSON 기보의 `opening_variety`에는 정책 버전·시드·후보·각 검토 결과·예산·선택 가중치·이유가 남는다. PGN의 `OpeningVarietySeed`와 `OpeningVarietyPolicy`는 보관함 내보내기에서도 보존한다. 이전 v1 기보도 계속 읽으며 다시 쓰지 않는다. 시간 제한 검색은 실행 부하에 따라 달라질 수 있으므로 시드만으로 결과 전체를 재현할 수는 없다.

## 데이터와 검증의 한계

후보 자료는 기존 [오프닝 안내](OPENING_GUIDE.md)의 고정된 Lichess chess-openings(CC0-1.0)를 사용한다. 수읽기와 평가는 자체 C++ 엔진이 담당하며 Stockfish의 수·점수·모델은 사용하지 않는다.

기본 탐색 예산 보존과 더 엄격한 자체 평가 기준으로 실력을 보호한다. 다만 제한된 자체 평가가 실제 무손실을 증명하지는 않는다. 다양성·자체 점수 비교·추가 지연을 각각 측정하며 경기력이나 Elo 향상으로 바꿔 말하지 않는다. [v2 검증 기록](checks/2026-11-02-opening-variety-v2/README.md), [이전 v1 기록](checks/2026-11-02-opening-variety/README.md)을 참고한다.
