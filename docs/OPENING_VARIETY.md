# Regicide의 다양한 오프닝 선택

일반 대국에서 Regicide가 초반의 비슷하게 평가하는 수들 사이에서 다른 선택을 한다. 기본으로 적용되며, 분석 모드·코칭·추천 수와 일반 UCI 엔진의 수 선택에는 섞지 않는다.

## 선택 방식

첫 세 수씩(처음 6번의 착수)만 다양성을 검토한다. 백의 첫 수는 `e4`, `d4`, `c4`, `Nf3` 중에서 후보를 고른다. 주요 첫 수에 대한 흑의 후보는 다음과 같다.

| 백의 첫 수 | 흑의 응수 후보 |
|---|---|
| e4 | e5, c5, e6, c6 |
| d4 | d5, Nf6, e6, f5 |
| c4 | e5, c5, Nf6, e6 |
| Nf3 | d5, Nf6, c5, g6 |

이 목록은 프로젝트에서 정한 연습용 오프닝 후보다. 인기 순위나 강도 순위는 아니다. 이후 초반 국면은 실제 수순과 정확히 일치하는 로컬 오프닝 자료에서 바로 다음 합법 수를 모은다. 오프닝 이름이나 화면의 정렬 순서로 수를 고르지 않는다. 자료에 많이 등장하는 수에도 더 큰 선택 확률을 주지 않는다.

대국마다 새로 만든 난수 기준으로 후보 하나를 고른 다음 **자체 Regicide 엔진**으로 확인한다. 설정 시간이 1초라면 일반 최선수 검색에 0.5초, 후보만 허용한 검색에 최대 0.5초를 쓴다. 후보가 이미 일반 검색의 최선수라면 두 번째 검색을 생략할 수 있다.

다른 후보를 채택하려면 다음을 모두 만족해야 한다.

- 양쪽 검색의 동일한 완료 깊이에서 비교할 수 있고, 그 깊이가 최소 3이다.
- 점수가 정확한 CP 값이며 예상 수순 전체가 합법이다. 메이트·상한/하한·미완료 값은 채택 근거로 쓰지 않는다.
- 수를 둘 쪽 기준으로 후보가 일반 검색 결과보다 35cp(폰 0.35개에 해당하는 자체 평가 단위)를 넘게 나쁘지 않다.
- 후보를 더 깊게 읽은 마지막 결과도 그 허용 범위보다 나빠지지 않는다.

검증이 실패하면 원래 검색에서 찾은 합법 수를 둔다. 초반 범위를 벗어나거나, 체크 중이거나, 표준 시작이 아니거나, 사용자가 Regicide의 수를 강제로 바꾼 대국에서는 일반 탐색을 사용한다. **0.1초 설정은 검증 시간 부족으로 다양화를 건너뛴다.** 현재 화면의 1·3·5초 설정에서는 적용된다.

이 방식은 제한된 시간의 자체 평가에 따른 허용 기준이다. 최선수·무손실·기존의 한 번짜리 전체 시간 검색과 같은 경기력을 보장하지 않는다. 다른 오프닝 경험을 제공하기 위한 대국 기능이며 경기력 향상을 주장하지 않는다.

## 평가 표시와 기보

후보 한 수만 허용한 평가를 전체 국면의 최선 평가처럼 막대에 표시하지 않는다. 일반 검색의 점수를 표시한 뒤, 실제 착수 후에는 기존 실시간 평가가 새 국면을 다시 계산한다.

새 대국에는 새로운 기준을 만들되, 같은 대국에서 같은 수순으로 무르면 기존 선택을 재사용한다. 생각 시간을 바꾸면 후보 자체는 다시 뽑지 않고 바뀐 시간으로 재검토한다. 진행 중인 수의 시간은 바뀌지 않는다. 다른 갈래를 두고 원래 수순으로 돌아와도 같은 예산·엔진·모델·자료 조건이면 저장한 결정을 사용한다.

JSON 기보의 `opening_variety`에는 기준값(seed), 정책 버전, 후보, 비교 점수·깊이·예산, 선택 이유와 실제 진행 결정이 남는다. 무르기 뒤에 없어진 수는 실제 진행 기록에서 제거하고, 재방문용 결정은 따로 둔다. PGN의 `OpeningVarietySeed`와 `OpeningVarietyPolicy`는 보관함에서 다시 내보내도 보존된다. 기준값만으로 시간 제한 탐색을 완전히 재현할 수는 없으므로 실제 결정 근거도 함께 저장한다. 기존 기보는 다시 쓰지 않는다.

## 데이터와 검증

후보 자료는 기존 [오프닝 안내](OPENING_GUIDE.md)의 고정된 Lichess chess-openings(CC0-1.0)를 사용한다. 이 자료는 평가값이나 승률을 제공하지 않는다. 첫 수 후보 구성·난수 선택·검증 기준은 프로젝트 구현이며, 수읽기와 평가는 자체 C++ 엔진을 사용한다. Stockfish의 수·점수·학습 결과는 이 선택 기능에 들어가지 않는다.
