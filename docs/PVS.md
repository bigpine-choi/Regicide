# PVS: 좋은 첫 후보를 활용해 탐색 비용 줄이기

PVS(Principal Variation Search)는 첫 후보를 정상 범위로 읽은 다음, 후속 후보가 현재 최선보다 좋은지 좁은 점수 범위로 먼저 확인하는 방식이다. 더 좋은 후보일 가능성이 있으면 정상 범위로 다시 읽는다. 수를 영구히 버리거나 평가 공식을 바꾸는 방법은 아니다.

## 작은 예

같은 깊이에서 첫 후보 `Nf3`의 점수가 +30이라고 하자. 다음 후보 `Bc4`는 정확히 몇 점인지 먼저 구하기보다 +30을 넘는지를 검사한다. 넘지 못하면 기존 후보를 유지한다. 넘고 현재 탐색의 상한에도 못 미친다면 넓은 범위로 다시 읽어 점수와 주요 수순을 확정한다. 재탐색이 잦으면 절감한 비용보다 추가 비용이 커질 수도 있다.

## Regicide의 구현

- 정상 negamax의 첫 합법 후보는 기존 alpha-beta 범위로 탐색한다.
- 뒤의 후보는 자식 기준 `[-alpha-1, -alpha]`로 검사한다. 부모 점수가 `alpha < score < beta`이면 기존 `[-beta, -alpha]`로 다시 탐색한다. 이미 beta 이상이면 가지치기에 충분한 하한이므로 다시 읽지 않는다.
- 예정 수를 통해 반복 또는 50수 무승부를 청구할 수 있으면 그 선택의 점수를 0 이상으로 처리한 뒤 재탐색 여부를 판단한다. 무승부 청구의 선택권은 기존 동작을 유지한다.
- 안정화 탐색의 범위, 체크 예산, 평가, 수 정렬, 시간 할당, 전이표 키와 검색별 세대 정책은 유지한다. aspiration window나 선택적 깊이 축소는 도입하지 않는다.
- 중단된 탐색은 수 적용을 되돌리고 마지막으로 완료한 반복의 수·점수·PV를 반환한다. 부분 탐색의 점수를 정확한 값으로 전이표에 저장하지 않는다.

UCI 옵션 `PVS`는 기본 `true`이며 `setoption name PVS value false`로 기존 탐색 경로를 선택할 수 있다. 실행 중 옵션 변경은 기존 세션의 중단·대기 처리를 거친다. C++에서는 `SearchOptions::pvs`를 사용한다.

`SearchResult::pvs_probes`는 후속 수의 좁은 범위 검사 시작 횟수, `pvs_researches`는 정상 범위 재탐색 시작 횟수다. 중단된 작업도 포함한다. UCI는 `info string pvs probes N researches N`으로 전달하며 기존 전이표 계측 줄을 마지막에 유지한다.

## 검증과 해석

작은 독립 완전 탐색과 PVS 켬/끔의 고정 깊이 점수를 비교하고 전이표·무승부·메이트·중단·상태 복원을 검사한다. 동점인 최선 수와 PV의 차이는 허용하되 선택 수와 PV의 합법성을 확인한다. 기존 노드 수까지 정확히 고정한 회귀 검사는 PVS를 명시적으로 꺼서 유지한다.

계산 비용과 같은 시간의 대국 성적은 별도로 측정한다. [사전 고정 계획](experiments/2026-10-18-pvs-plan.md)은 깊이 3·4 비용 비교 및 PVS 끔 대조, 100ms·1초 각각 선후공 교대 16판을 규정한다. 성적을 보고 시작 위치나 판수를 바꾸지 않는다.

PVS는 공개된 탐색 원리를 참고해 자체 구현했다. [Stockfish 공식 탐색 구현](https://github.com/official-stockfish/Stockfish/blob/master/src/search.cpp)은 연구 참고이며 GPLv3다(확인일 2026-10-18). 외부 엔진 코드·평가 표·신경망 가중치를 Regicide에 가져오지 않았다. 실제 수 선택은 계속 자체 C++ 엔진이 수행한다.
