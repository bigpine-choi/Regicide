# 신경망 증분 갱신 — 2026-10-19

이 문서는 증분 갱신 단계의 기록이다. 후속 [첫 학습 파이프라인·가중치 저장·불러오기 검증](NEURAL_TRAINING.md)을 완료했으며 아래의 미학습 설명은 당시 상태를 뜻한다.

자체 `bootstrap-v1` 모델을 바꾸지 않고 **전체 재계산과 정확히 같은 점수를 내는 증분 갱신**을 탐색에 연결했다. 신경망을 선택하면 기본으로 증분 경로를 사용한다. 기존 위치 평가기가 엔진 기본값인 점은 유지했다. 학습과 기력 검증은 수행하지 않았다.

## 원리 → 체스 예 → 구현

이 신경망의 첫 층은 활성 기물·칸 특징의 가중치 행을 더한 값이다. 매 수마다 전체 기물을 다시 읽는 대신, 사라진 특징 행을 빼고 새 특징 행을 더한다. 예를 들어 `e2e4`는 e2의 백 폰 행을 빼고 e4의 백 폰 행을 더한다. 백·흑 두 관점을 함께 갱신한다.

`NeuralAccumulator`는 관점별 16개 정수, 합계 32개의 **클리핑 전 누적값**을 보관한다. 음수를 0으로 만드는 ReLU와 127 상한은 점수를 읽을 때만 적용한다. 누적값 자체를 잘라 저장하면 이후 기물이 움직여도 원래 계산으로 돌아갈 수 없다. 테스트는 음수·0·양수 경계를 반복 통과하는 실제 수순을 포함한다. 현재 모델의 유효 기물 수·가중치 범위에서는 127 상한을 넘는 합이 나오지 않아 상한 통과 검증을 했다고 주장하지 않는다.

`update_generated(before, after, move)`는 보드의 전후 상태 중 바뀌는 칸만 읽는다. 일반 이동·캡처·승격은 출발/도착 2칸, 앙파상은 제거된 폰을 더한 3칸, 캐슬링은 왕·룩의 출발/도착 4칸이다. 이 함수는 생성된 합법 수와 그 정확한 전후 상태를 요구한다. 전체 64칸 스캔은 초기화와 기준 재계산에만 남겼다. 왕 위치를 기준으로 입력 전체가 달라지는 구조가 아니므로 왕 이동에도 같은 갱신을 쓸 수 있다.

규칙 보드 코드는 바꾸지 않았다. 탐색기의 `AppliedMove`가 보드 이동과 누적값 갱신을 함께 수행한다. 수를 두기 전의 누적값을 저장했다가 undo에 복원하므로 분기·재탐색·중단 예외에서도 같은 부모 상태로 돌아온다. 저장하는 누적값은 이 환경에서 128바이트이며 별도 동적 할당은 없다. 수 적용이 실패하면 누적값은 바뀌지 않는다. 무승부 주장 가능성을 조사하는 가상 수에도 같은 경로를 적용했다.

`evaluate_neural(board)`는 이전의 전체 재계산 코드 그대로 유지했다. 새 증분 코드가 자기 자신을 정답으로 삼지 않도록, 최종 점수와 별도로 누적값 32개 전체도 보드에서 새로 만든 값과 비교한다.

## 설정과 재현

```powershell
./scripts/build.ps1 -BuildDirectory build-neural-incremental -Test
./build-neural-incremental/regicide.exe search 4 --neural
./build-neural-incremental/regicide.exe search 4 --neural --neural-full-refresh
./.venv-tests/Scripts/python.exe tests/neural_integration_tests.py build-neural-incremental/regicide.exe
./build-neural-incremental/regicide_neural_incremental_benchmark.exe 500000 6
python scripts/benchmark_neural_incremental.py build-neural-incremental/regicide.exe --output build-neural-incremental/search-cost.json --depth 4 --repeats 5
```

UCI의 `UseNeuralEvaluation=true`로 신경망을 켠다. 새 `UseIncrementalNeuralEvaluation`의 기본은 true이며 false로 바꾸면 같은 모델을 전체 재계산한다. 콘솔의 `--neural-full-refresh`는 증분만 끄며, 신경망 선택에는 `--neural`도 필요하다. 신경망이 꺼져 있으면 증분 옵션은 평가 방식을 바꾸지 않는다. 옵션 변경은 진행 중 탐색을 종료하고 적용하며, 각 탐색은 자신의 루트에서 새 누적값을 만든다.

## 검증 결과

- Windows 표준 빌드: MSVC toolset 14.51.36231, C++20, `/O2 /DNDEBUG /W4 /WX`. 기존 규칙·탐색·위치 평가·보드 상태·전이표·SEE 검사를 모두 통과했다. 신경망 8그룹 **51,153 assertions, 실패 0**.
- Linux: GCC 13.3.0, ASan+UBSan, debug 합법 수 사전조건 검사 활성화. 같은 신경망 **51,153 assertions, 실패 0**. 실제 명령과 sanitizer 링크 라이브러리도 보존했다.
- 특수 수: 양색·양쪽 캐슬링 4종, 양색 앙파상, q/r/b/n의 양색 일반·캡처 승격 16종, 더블 폰 이동과 룩 잡기로 캐슬링 권리 소실을 포함한다. 이동 직후·형제 분기·undo마다 원시 누적값, 양쪽 점수 관점, 보드와 히스토리를 비교했다.
- 결정적 수순 6개(3루트 × 2시드)를 최대 160ply 진행하고 형제 수를 검사한 뒤 끝까지 undo했다. ReLU 하단 경계 수순도 별도로 확인했다.
- 탐색: 4위치 × 정지 탐색 on/off × PVS on/off × 빠른 수 적용 on/off의 32조합에서 매 반복 깊이의 수·점수·PV·노드·TT/SEE/PVS 통계가 일치했다. 노드 제한, stop 플래그, 콜백 중단, 반복 무승부 이력, 전이표 저장공간 재사용도 검사했다.
- 실제 UCI 신경망 전환 **40쌍**, 콘솔 **8쌍(신경망 증분/전체 4, 신경망이 꺼진 기존 평가의 옵션 비활성 확인 4)**, 이전 버전 기본/기물 가치 **8쌍**을 통과했다. 기존 UCI 통합 19그룹과 벤치마크 도구 회귀 9검사도 통과했다.
- 비용 측정의 동일 실행 파일 깊이 4 **50쌍(10위치 × 5회)**에서 시간 외 출력 17개 필드가 모두 같았다. 소스·실행 파일·위치 데이터의 측정 전후 SHA256과 현재 파일도 일치했다.
- 보존한 기준 커밋 `b007323` 실행 파일과 추가 **50쌍**(기존 평가 30, 기물 가치 10, 신경망 10)을 깊이 4로 비교해 시간 외 출력이 모두 같았다. 기존 평가의 새/이전 엔진 시간 중앙비율은 1.000, 프로세스 포함 경과시간 중앙비율은 1.012였다. 이 작은 표본에서 기존 경로의 비용 개선은 주장하지 않는다.

코드와 원자료를 별도 에이전트가 읽기 전용으로 점검하고 비용·해시·탐색 일치를 독립 재계산했다. [검증 폴더](checks/2026-10-19-neural-incremental/)에 전체 기록을 남겼다. 이번에 CI와 Godot 화면 검증, 대국은 실행하지 않았다.

## 평가 함수 비용과 전체 탐색 비용

AMD Ryzen AI 7 350, Windows 11, 단일 프로세스 순차 실행. 평가 단위 측정은 자체 작성한 9개 FEN의 모든 합법 수 **163개 전이**를 같은 고정 순서 생성기로 순환했다. 준비·합법 수 생성은 측정에서 제외하고, 각 항목은 1,000회 워밍업 뒤 500,000회씩 6회 측정했다. 항목 순서는 매 회 반전했고 결과 checksum을 출력했다. 모든 신경망 항목의 checksum이 정확히 같았다.

| 측정 범위 | 중앙값 ns/회 | 해석 |
|---|---:|---|
| 신경망 전체 재계산 | 617.75 | 이동 후 보드에서 매번 특징 합 계산 |
| 저장된 누적값에서 점수 출력만 | 17.93 | 갱신 비용 제외, 전체 이득으로 해석하지 않음 |
| 증분 갱신 + 점수 + 저장·복원 | 60.03 | 전체 재계산 대비 **10.29배**, 보드 이동 비용 제외 |
| 수 적용 + 전체 재계산 + undo | 671.04 | 보드 히스토리 갱신 포함 |
| 수 적용 + 증분 평가 + undo·누적값 복원 | 107.67 | 위의 같은 수 처리 대비 **6.23배** |

원자료: [evaluation-cost.csv](checks/2026-10-19-neural-incremental/evaluation-cost.csv). 초기 누적값 생성은 각 루트 준비 단계이며 수당 비용에서는 제외했다. 수 적용 항목은 히스토리 용량을 미리 확보한 상태에서 측정했다. 실제 탐색에서는 루트 생성·전이표·수 생성·SEE·분기 등 비용도 포함된다.

전체 탐색은 기존 10위치 세트를 모두 사용해 깊이 4, Hash 16MiB, 단일 탐색, 나머지 기본 옵션으로 각 5회 비교했다. 역할 순서는 번갈고 위치 순서는 시드 `20261019`로 섞었다. 엔진 보고 탐색시간의 full/incremental 쌍별 중앙비율은 **1.182배(약 15.42% 시간 단축)**, 프로세스 시작을 포함한 실제 경과시간은 **1.130배(약 11.50% 단축)**였다. [search-depth4.json](checks/2026-10-19-neural-incremental/search-depth4.json)에 원시 출력·각 시간·조건·해시를 보존했다.

CPU 고정·외부 부하 감시·신뢰구간은 적용하지 않았다. 보고된 탐색시간은 정수 ms이며 위치별 중앙값이 2~98ms로 짧아 오차가 있다. 실행 중 다른 빌드·검사·벤치마크를 병행하지 않았지만 시스템 전체가 격리된 것은 아니다. 따라서 **이번 조건에서 계산 비용이 줄었고 점수가 보존됨**을 확인한 결과다. 기력 향상이나 Elo 변화는 판단하지 않는다.
