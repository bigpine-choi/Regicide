# 보수적인 LMR

LMR(Late Move Reductions, 뒤쪽 수의 탐색 깊이 감축)은 정렬상 뒤에 있는 평범한 수를 조금 얕게 먼저 읽어 계산을 절약하는 방법이다. 절약한 시간으로 더 깊은 탐색을 끝낼 수 있다는 가설이며, 뒤에 숨어 있는 좋은 수를 놓칠 위험도 있다.

예를 들어 나이트를 안전하게 옮기는 여러 후보가 있고 앞의 후보들이 이미 유망하다면, 다섯 번째 이후의 평범한 기물 수는 한 반수 얕게 먼저 읽는다. 그 수가 현재 최선보다 좋아 보이면 반드시 원래 깊이로 다시 읽는다. 얕게 읽었을 때 평범해 보였던 수는 정상 깊이에서 좋아질 수도 있으므로 이 절차가 모든 수의 정확성을 보장하지는 않는다.

## v0.5.8의 좁은 적용 범위

- PVS와 일반 수 정렬이 모두 켜져 있어야 한다.
- 루트와 주요 수순(PV)을 보호한다. 남은 깊이 4 이상인 비PV 노드의 좁은 창 검사에서 정렬상 다섯 번째 이후만 대상이다.
- 나이트·비숍·룩·퀸의 일반 이동만 감축한다. 체크 중의 회피, 체크를 주는 수, 포획·앙파상·승격, 폰·킹 이동(캐슬링 포함)은 보호한다.
- 직전 주요 수순·전이표 우선수와 두 killer 수(앞서 컷오프를 만든 일반 수)를 보호한다.
- 현재 또는 이 수로 생기는 무승부 청구와 메이트 점수 근처 창을 보호한다.
- 감축량은 한 반수다. 얕은 검사에서 alpha(현재 후보를 개선하기 위한 문턱)를 넘으면 원래 깊이로 재검사하고, 필요하면 기존 PVS의 전체 창 검색도 수행한다.

감축 후 개선하지 못한 점수는 최선 수나 주요 수순으로 직접 채택하지 않는다. 이런 가지가 섞인 노드의 실패 상한은 전이표(TT, 이미 읽은 결과의 캐시)에 저장하지 않는다. 서로 다른 깊이가 섞여 있으므로 저장 깊이만 낮추는 것으로 안전한 상한이 되지는 않기 때문이다. 각 검색은 기존처럼 새 TT 세대를 사용해 옵션 변경과 과거 결과를 격리한다.

## 설정과 관찰

기본은 켬이다. UCI GUI에서는 `UseLMR=false`, 콘솔에서는 다음처럼 비교한다.

```powershell
.\build\regicide.exe search 6
.\build\regicide.exe search 6 --no-lmr
```

C++에서는 `SearchOptions::lmr`를 사용한다. `PVS=false` 또는 `UseQuietMoveOrdering=false`이면 LMR도 감축하지 않는다. Godot의 대국과 추천 수는 동일한 자체 엔진의 기본 설정을 사용하므로 LMR을 함께 사용한다. 별도의 화면 버튼은 추가하지 않는다.

UCI `info string lmr reductions X researches Y`와 콘솔의 `lmr_reductions`, `lmr_researches`는 감축 시도와 정상 깊이 재검사 시도 횟수다. 중단된 탐색의 작업도 포함하며 완료 깊이와 구분한다. 얕은 검색이나 보호 위치에서 0이어도 정상이다. 기존 TT 정보는 호환성을 위해 마지막 `info string`으로 유지한다.

`scripts/lmr_experiment.py`는 기존 고정 깊이·대국 실행기를 그대로 호출하면서 이 두 통계를 별도 JSON에 수집한다. `benchmark|match --telemetry <새 파일> -- <기존 실행기 인수>` 형식이다. 원래 PGN/JSON 및 종료 코드는 바꾸지 않는다. 구버전의 없는 카운터는 0 대신 `null`로 기록한다.

## 검증 경계

기존 검색 오라클은 LMR OFF로 유지한다. OFF의 수·점수·노드·PV·TT가 v0.5.7과 같은지 확인하고, ON은 보호 조건·실제 감축/재검색·결정성·중단 복원·메이트/무승부·프로토콜/추천 연결을 별도로 검사한다. 규칙 코어와 평가식은 바꾸지 않는다. 같은 명목 깊이에서 ON의 수·점수가 달라도 자동으로 오류인 것은 아니다.

[고정한 계획](experiments/2026-10-18-lmr-plan.md)에 따라 비용과 같은 시간 대국을 구분한다. 노드 감소나 완료 깊이 증가를 기력이나 Elo로 환산하지 않는다. 외부 엔진 코드를 가져오지 않았으며 공개 탐색 구현은 개념 참고에만 사용했다.
