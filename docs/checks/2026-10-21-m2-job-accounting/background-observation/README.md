기존 기록만 짧게 조회했다. 추가 재시작, CPU 부하 실험, 설정 변경, 프로세스 조작은 하지 않았다.

최초 실패 UTC의 간격은 600.133083초다. 반면 phase 시작 간격은 738.119976초이고, 실행 후 실패까지 걸린 시간도 서로 다르다. 따라서 같은 실행 경과 시간에 발생하는 조건으로는 설명되지 않는다. 두 번의 벽시계 관측만으로 10분 주기나 특정 프로그램·서비스를 원인으로 확정할 수 없다.

각 최초 실패 시점 ±5초의 기존 `Microsoft-Windows-TaskScheduler/Operational`, `Application`, `System` 로그를 조회했다. 여섯 쿼리 모두 일치 이벤트가 없었다. TaskScheduler/Operational은 비활성 상태이므로 예약 작업의 실행 여부는 **확인 불가**다. Application/System은 활성 상태이나 해당 창의 일치 이벤트가 없었다. 로그에 남지 않는 CPU 활동은 배제할 수 없다. McAfee 등 특정 프로그램을 지목할 근거를 얻지 못했다.

`timing-analysis.json`에는 원문 최초 실패 행 번호, FILETIME 원시값과 100ns 시간, phase/guard 경과 시간, 원본 해시·크기를 기록했다. `windows-events.json`에는 쿼리 창과 원래 오류를, `log-metadata.json`에는 로그 활성 여부를 보존했다. 보고서의 `elapsed_seconds`는 별도로 남겼으며 최초 실패 UTC에서 계산한 경과 시간과 혼용하지 않았다. 잔여 CPU는 비동기·양자화 계측의 추정치이며, 이벤트 부재나 시간 패턴은 실제 CPU 원인에 대한 증명이 아니다.
