# 갬빗 연속 체크 탐색: 구현과 두 후보 비교

2026-11-05, 한국 시간. **기존에 생략됐던 `g4+` 후속 경로를 실제로 읽는 실험 옵션을 구현했다. 그러나 최종 후보는 11국면·두 예산의 22개 비교에서 기존과 같은 수를 선택했고, 시작 위치의 `...a3` 오판도 남았다. 기력 향상이나 문제 해결을 선언하지 않고 실전 활성화를 보류한다.** 기본값은 비활성이다.

## 구현과 적용 범위

`SearchOptions.quiescence_forcing` / UCI `UseQuiescenceForcing`를 추가했다. 정지 탐색은 정상 탐색의 끝에서 포획·체크 등을 더 읽는 과정이다. 이번 옵션은 이미 시작한 같은 진영의 체크 공격에 제한된 추가 기회를 준다.

- 최종 후보는 경로당 추가 조용한 체크를 최대 두 번 허용한다. 체크를 받는 위치에서 합법 회피가 세 개 이상이면 추가 연속 공격의 소유 문맥을 끊는다. **회피 수 자체는 전부 유지한다.**
- 공격 측의 비체크 착수는 연속 공격을 끝낸다. 강제 회피·반격 체크, 포획·승격과 합법적인 무승부 권리는 기존 규칙을 유지한다.
- 정지 탐색 시작점이 이미 체크 중이면 공격 진영을 초기 문맥에 반영한다. 별도 정지 탐색 깊이 제한 옵션과 함께 사용해도 추가 체크의 소비 조건을 일치시켰다.
- 정지 탐색 캐시 키에 공격 진영과 남은 연장 예산을 넣는다. 반복 문맥·50수 카운터와 기존 잔여 깊이도 유지한다. 체크가 해결되지 않은 절대 깊이 한계에서는 해당 반복을 버리고 이전 완료 결과를 보존한다.
- 실제 수는 자체 Regicide가 선택한다. Stockfish는 자체 선택을 모두 끝낸 뒤 사후 감사에만 사용했다. 갬빗 제안·희생 빈도·운영 기억·평가 가중치를 이번 변경으로 교체하지 않았다.

이 정책도 선택적이다. 회피가 넓은 공격, 새로운 조용한 준비, 두 번을 넘는 추가 체크를 모두 해결하지 않는다. 추가 수를 읽는 기능과 최종 수 선택 개선을 구분한다.

## 비교 조건

비교 전 기준 코드 HEAD는 `60853b3`이며 실험 변경은 미커밋 상태였다. 이전 기준 바이너리는 `f893c6f`에서 만든 `build-gambit-horizon/baseline/regicide.exe`다. 두 후보의 당시 소스와 입력·실행 파일 해시는 별도로 보존했다.

| 항목 | 조건 |
| --- | --- |
| 자체 평가 | classical + `UsePieceActivity=true`, positional 활성, 신경망·NNUE 비활성 |
| 자원 | Hash 16MiB, 단일 자체 검색, 질의마다 새 프로세스, 순차 실행 |
| 노드 조건 | 각 검색 최대 850,000노드. 실제 소비량도 기록 |
| 시간 조건 | 각 검색 2085ms 요청, 기본 Move Overhead 20ms |
| 실행 순서 | 국면마다 기준/후보 순서를 교대 |
| 감사 | Stockfish 18, Threads 1, Hash 32MiB, 강도 제한 해제, 질의별 Clear Hash, 최대 깊이14·0.5초 |
| 감사 비교 | 같은 루트의 자유 탐색과 실제 선택 수를 공통 정확 완료 깊이에서 비교. 이번 비교는 모두 깊이14 |
| 환경 | Windows 11, AMD Ryzen AI 7 350, 8코어/16논리CPU, MSVC x64 C++20 `/O2 /DNDEBUG /W4 /WX` |

한 실행은 기존 실패 네 위치·반복 체크·Nxe5 희생의 여섯 개발 위치, 기존 시작판 대조, 별도 작성한 네 대조로 구성했다. 네 대조는 첫 실행 전 합법성만 확인해 고정했다. **두 번째 후보에서는 이미 관측한 회귀 대조**이며 새로운 미사용 자료가 아니다. 원시 입력의 `new_control` 표기는 최초 작성 구분이지 두 번째 실행의 독립 최종 평가를 뜻하지 않는다. 새 갬빗 계열 일반화나 실제 대국 성적을 측정한 표본도 아니다.

각 실행은 옵션 off 동등성 두 국면의 네 검색과 11국면×노드/시간×기준/후보의 44검색, 합계 48개 자체 검색이다. 첫 실행 약95.4초, 두 번째 약97.3초였으며 이는 해당 실행의 경과시간이다. 같은 요청 시간·노드 상한이 동일 실제 CPU 사용량이나 동일 탐색 트리를 뜻하지 않는다.

## 첫 후보: 넓은 연장의 비용과 악화

첫 후보는 추가 체크 네 번을 허용하고 회피 폭으로 연속 공격을 끊지 않았다. 기능은 동작했지만 비용이 커서 채택하지 않았다. 아래는 외부 최선 대비 손실 cp이며 폰100 기준이다. 승률이 아니다.

| 기존 개발 위치 | 85만 노드 기준→첫 후보 | 2085ms 기준→첫 후보 |
| --- | ---: | ---: |
| King's:9 | 281→164 | 281→281 |
| King's:11 | 42→245 | 42→245 |
| Morra:25 | 271→270 | 271→270 |
| Budapest:16 | 277→0 | 277→0 |
| 반복 체크 | 195→195 | 195→195 |
| Nxe5 희생 | 8→8 | 8→8 |

King's:11의 두 예산 모두 **203cp 추가 악화**로 사전 경고 조건을 충족했다. 이 조건은 후보 손실>150cp이고 기존보다≥100cp 악화한 경우다. 두 경고는 같은 위치를 두 예산에서 본 결과이며 독립적인 두 국면이 아니다.

반복 체크의 완료 깊이는7→3, Morra는5→1, Nxe5는6→3으로 낮아졌다. 반복 체크의 노드 조건에서는 추가 체크203,159회를 수행했지만 `...a3`와195cp 손실을 유지했다. King's:11은515,281노드, Budapest는323,504노드에서 반환했으며, 완료 PV·합법 수·정상 종료와 요청 상한 준수는 확인했다. 실제 소비량이 같았다고 표현하지 않는다. 연장한 경로가 체크 상태의 절대 정지 탐색 한계에 도달하면 반복 전체를 중단하는 안전 경계가 비용 문제와 맞물릴 수 있어, 최종 후보에서는 연장 폭을 줄였다.

첫 후보 실행 파일 SHA256: `5f38cb5abea51d4d3439985254f4f5624286b94fedaa456ec1fd9c8d13bd0f01`.

## 최종 후보: 비용 축소 후의 결과

추가 체크 두 번과 회피 폭 조건으로 줄인 두 번째 후보는 모든 노드 조건에서 정확히850,000노드를 사용했다. **11국면의 두 예산 모두 선택 수가 기준과 같았고 외부 손실도 같았다.** 큰 추가 악화 경고와 새 피메이트는 관측하지 않았다. 제한된 표본의 결과이며 일반 안전성이나 기력 향상 증명이 아니다.

| 기존 개발 위치 | 두 예산의 공통 선택 | 두 예산의 공통 외부 손실 | 노드 완료 깊이 기준→후보 | 시간 완료 깊이 기준→후보 |
| --- | --- | ---: | ---: | ---: |
| King's:9 | Nc3 | 281cp | 6→6 | 6→6 |
| King's:11 | Nd4 | 42cp | 6→6 | 6→6 |
| Morra:25 | Kh1 | 271cp | 5→5 | 5→5 |
| Budapest:16 | Kh8 | 277cp | 5→5 | 5→5 |
| 반복 체크 | ...a3 | 195cp | 7→7 | 7→7 |
| Nxe5 희생 | Nxe5 | 8cp | 6→6 | 6→5 |

시작판은Nc3를 유지했다. 별도 네 대조에서도Qd8#·Qxd4·Re1·Kd3를 각각 유지했다. 그중 왕 압박 대조의 노드 완료 깊이는5→4, 퀸 위협은8→7, 나이트 대조는7→6이었다. 조용한 폰 엔드게임 대조는13→13을 유지했다. 탐색 구조가 달라 명목 깊이만으로 강도를 판정할 수 없지만, 개선 수 없이 추가 계산 비용이 남았다는 점을 함께 기록한다.

최종 비교 실행 파일 SHA256: `ae0a960c45ab68ba676971b748c45d3531d5b47ddcb11129d4ae0978281b64a9`.

## 국소 경로 진단

기존에 공개한 최소 FEN에서 `...a3 Rh8+ Kf7 Rh7+ Kg6`를 재생하고 백의 루트만Rg7+로 제한했다. 이후 상대 응수는 모두 유지했다. 같은 명목 깊이1의 별도 진단이다.

| 설정 | 자체 백 기준 점수 | 실제 노드 | 선택 |
| --- | ---: | ---: | --- |
| 연장 off | −450cp | 238 | Rg7+ |
| 최종 후보 on | +47cp | 732 | Rg7+ |

검사 observer는 `Rg7+ Kh6 Re6+ Kh5 g4+` 뒤 실제 평가 호출에 도달함을 확인했다. 별도 동일 루트 Stockfish 감사는 자유+419cp, Rg7+ 한정+371cp, 공통 깊이14·정상 종료0이었다. 자체 평가가 외부 감사와 같은 방향으로 바뀐 **국소 진단**이다. 자체 점수+47을 정확한 보상이나 외부 점수의 재현으로 보지 않는다. 노드를 약3.08배 썼으며 동일 계산량 비교가 아니다. 최초 전체 루트의 `...a3` 오판은 해결하지 못했다.

## 검증·채택 판단

두 비교 모두 옵션 off 동등성2/2, 48개 자체 검색의 합법 완료·판/이력 보존·정상 종료·해시 불변, 외부 감사의 공통 정확 깊이·정상 종료를 통과했다. 기능 회귀와 선택 품질 결과를 구분한다.

최종 전체 C++ 검사는 **227개 그룹**, 별도 UCI 통합 검사는 **31개 그룹**을 통과했다. C++ 검사는 기존215개와 신규 연속 체크12개 그룹의 합계다. 실제 `g4+` 경로의 평가 호출, 정지 탐색 캐시, 체크 포획 뒤 제한 예산 소비, 넓은 회피에서 모든 수 보존, 강제 반격 체크, 중단·노드 한도·판 복원, 실제 반복 이력·50수·메이트 우선순위를 확인했고 원시 출력을 증거에 보존했다.

최종 검사 재빌드의 실행 파일 SHA256은 `418397dd66e1a3e88b00d6d280da2f84a8215694f983b6cbd54db46d954bc8c2`다. 비교 당시 `ae0a960c...`와 최종 재빌드의 모든 `src/*.cpp`·`include/regicide/*.hpp`가 바이트 단위로 같음을 확인했다. 비교 뒤 신규 검사 소스만10개에서12개로 확장됐다. 실행 파일 자체는 해시가 다르므로 비트 동등성을 주장하지 않으며, 최종 재빌드로11국면 비교를 다시 수행한 것으로 보고하지 않는다.

전체 루트 개선이 없고 일부 위치의 추가 비용이 남아, 현재 국면 선별 단계를 통과한 후보로 보지 않는다. 현 단계에서 같은 후보의 대국 수를 늘려 승격 근거를 만들지 않았다. 실제 갬빗 정책 전체의 완주 대국·Elo·Chess.com `!`/`!!` 변화·GUI 수동 검사는 수행하지 않았다. 기존 활성 대국 바이너리와 정책의 실전 설정은 유지한다.

다음 연구는 전체 루트에서 왜 국소 반박의 값이 전달되지 않는지를 실제 평가 경로와 상대의 최선 회피까지 추적하고, 같은 시간의 수 선택 개선을 확인하는 것이다. 이번에 사용한 대조는 후속 실험에서 회귀 자료로 취급한다.

## 재현과 증거

새 출력 경로로 실행한다. 최종 소스에서 별도로 빌드한 후보에 옵션을 명시한다.

```powershell
.\.venv-tests\Scripts\python.exe tests/forcing_validation.py --baseline build-gambit-horizon/baseline/regicide.exe --candidate build-gambit-forcing/regicide.exe --output-dir build-gambit-forcing/replay-new --stockfish build-m2-opponents/stockfish18/package/stockfish/stockfish-windows-x86-64.exe
```

기본값은850,000노드와2085ms다. `--development-only`는 최초 여섯 개발 위치와 시작판 대조만 사용한다. `--prepare-only`는 엔진 검색 없이 입력과 해시를 저장한다. 두 후보는 이름이 같은 옵션의 서로 다른 구현이므로, 최종 후보를 재빌드해 첫 결과와 같다고 간주하지 않는다. 시간제 재실행은 같은 수와 완료 깊이를 보장하지 않는다.
