# 착수 대기 목표 추가 1초 단축

시간제 대국의 계산 후 대기 목표를 추가로 1,000ms 줄였다. 정책은
`regicide-engine-pacing-v10`이다. 일반·보스·스파링에 공통 적용하며,
시간제 없는 대국의 수동 생각 시간은 그대로다. 실행 중인 앱에는 재실행 후 적용된다.

## 변경 이유와 범위

기존 `TURN_REDUCTION_MS`를 늘리면 초반의 짧은 기본 탐색까지 줄고,
별도 오프닝 상한에 걸린 대기는 그대로 남을 수 있었다. 따라서 검색용
`target_total_ms`와 실제 대기용 `wait_target_total_ms`를 구분했다.
대기 목표는 초반 상한과 수 선택 후 조정을 모두 반영한 목표에서 1초를
뺀 값이다. 이미 쓴 계산 시간을 포함하며 0 아래로 내려가지 않는다.

같은 위치·시계·시드에서 기본 탐색, 후보 검토, 접전 회복, 기물 안전검사
예산은 유지한다. 회복·안전검사 후에는 기존대로 추가 대기를 하지 않는다.
후속 실제 대국에서는 절약된 잔여시간 때문에 이후 계산 예산이 달라질 수 있다.
폴링·시계 조정에서 중복 차감하지 않고, 실제로 완료한 장고의 재발 억제도
단축된 목표를 반영한다. 기보 내보내기에도 새 정책 번호를 보존한다.

## 실제로 실행한 검증

- 자동 테스트 **163개 통과**: 시간 배분·초반 상한·리듬·호스트 중단·시계 조정·
  회복·기물 안전검사·기보 호환. `validation.json`, `tests.txt`, `archive-tests.txt` 참고.
- 새 집중 테스트 10개는 같은 계산 예산·같은 수를 유지한 상태에서 대기와
  시계 차감이 1초 감소하는지 확인한다. 계산이 단축된 목표를 넘겼다면
  계산을 끝내고 추가 대기 없이 둔다. 엔진과 시계는 통제된 테스트 대역이다.
- `git diff --check` 통과.

기존 실제 4판의 206회 착수 기록에서 계산·선택·후속 시계를 고정하고,
기록된 대기만 최대 1초 줄이는 가상 비교도 수행했다.

| 범위 | 착수 수 | 기존 평균 | 가상 적용 평균 | 감소 |
| --- | ---: | ---: | ---: | ---: |
| 전체 | 206 | 7.889초 | 7.165초 | 0.723초 |
| 첫 12수 | 48 | 3.989초 | 3.613초 | 0.376초 |
| 첫 20수 | 80 | 7.456초 | 6.868초 | 0.588초 |

`recorded-comparison.json`에 원자료 해시와 착수별 계산을 남겼다.
이번 변경 후 새로 대국을 돌려 측정한 평균은 아니다. 이미 대기가 짧거나
회복·안전검사로 대기가 없는 수는 1초를 모두 줄일 수 없으므로,
전체 평균이 정확히 1초 감소한다고 주장하지 않는다. 경기력 검증도 아니다.

집중 테스트 재현:

```powershell
./.venv-tests/Scripts/python.exe -m unittest discover -s tests -p faster_pacing_tests.py
```

나머지 검사 목록과 검증 당시 소스 해시는 `validation.json`에 기록했다.
