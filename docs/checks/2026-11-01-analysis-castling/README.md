# 분석 모드 캐슬링 검증 · 2026-11-01

후속 사용자 확인에서 **분석 대국 중 왕 두 칸 드래그** 문제를 다시 조사했다. 관련 없는 편집의 권리 보존 정책과 실제 마우스 검증을 포함한 [후속 수정 기록](../2026-11-01-analysis-castling-workflow/README.md)이 최신이다. 아래의 이전 권리 초기화 설명은 최초 구현 당시의 기록이다.

기존 엔진과 분석 API는 캐슬링 권리가 포함된 FEN 및 캐슬링 수를 처리했다. Godot 자유 배치 화면에서는 편집 후 초기화된 권리를 FEN 문자열로만 지정할 수 있었다. 편집 화면에 백·흑 킹사이드/퀸사이드의 네 권리 체크 항목을 추가하고, 분석 중에는 합법 수 목록에 있는 캐슬링을 직접 실행하는 두 버튼을 추가한다.

원래 칸의 왕·룩은 권리 설정의 조건이며 현재 캐슬링의 합법성을 보장하지 않는다. 실제 버튼은 현재 차례의 합법 수 `e1g1`, `e1c1`, `e8g8`, `e8c8`만 따른다. 체크·막힌 경로·공격받는 통과 칸·도착 칸을 화면이 임의로 허용하지 않는다. 퀸사이드의 b열 공격은 왕의 통과 칸과 구분한다.

가져온 FEN의 권리는 표시하지만 잘못된 권리를 렌더링 과정에서 조용히 고치지 않는다. 자유 배치 변경 후에는 권리를 다시 선택해야 한다. 캐슬링 착수와 무르기는 기존 분석 서비스로 처리해 왕·룩·권리와 수순을 함께 갱신한다. 추천과 실시간 형세도 새 위치에서 계산한다.

최종 검증 결과:

- 백엔드 7그룹 통과: 양쪽의 두 캐슬링, 정확한 되돌리기, 권리 없음/상실, 막힘·체크·통과/도착 칸 공격, b열 공격과 퀸사이드의 구분, 실제 UCI 엔진 처리와 기존 대국·기보 보존. `backend-castling.txt`.
- 브라우저 분석 34개와 기존 추천 10개·오프닝 8개·시간 설정 검사 통과. 이전 드래그·복구·형세 검사도 포함한다. `final-web-*.txt`.
- Godot 합성 82개·실제 Viewport 입력 디스패처 44개·실제 엔진 연동 71개 통과. 네 권리 선택, 양쪽 캐슬링 버튼과 왕 두 칸 끌기, 정확한 무르기, 금지 조건, 형세 갱신, 드래그 취소와 이동량0 입력을 포함한다. `godot/`의 실행 명령과 기록을 참고한다. 이는 대화 도구를 통한 실제 OS 포인터 조작과 구분한다.
- 별도 HTTP 검수에서 네 캐슬링 후 왕·룩 위치, 새 합법 추천과 현재 위치의 평가, FEN·권리·카운터의 정확한 무르기를 확인했다. 기존 대국 상태와 저장 파일 바이트 지문도 같았다. `http-castling.json`.
- 실제 브라우저 화면에서 열린 경로의 FEN을 불러와 두 버튼이 켜지는 것, O-O 버튼으로 백 왕 g1·룩 f1 이동과 흑 차례 전환, 백 권리 해제, 새 형세 갱신을 확인했다. 되돌리기로 왕 e1·룩 h1과 권리를 복원하고 대국 화면으로 돌아가 0수 상태가 유지되는 것도 확인했다. `browser-castling-evaluation.png`는 캐슬링 후의 화면이다.

형세 스트리밍 신규 16개·기존 분석 22개·추천 15개·대국 평가 16개 회귀 검사도 통과했다. 정상 종료를 우선하는 취소 처리로 실제 엔진 반복 취소 시 미처리 Future 경고가 없는지 검사했다. 기록은 인접한 `../2026-11-01-analysis-evaluation/`에 있다.

검수에는 `build/regicide.exe`의 Regicide 0.7.0-dev를 사용했다. 엔진 SHA-256은 `edd950fb673cfca4134968b64cc5ef0f3d77eda698e9f40d2965170f143d6e6a`이며 C++ 규칙·탐색·평가 코드는 수정하지 않았다. 최종 소스 파일과 기준 커밋은 `source-manifest.json`에 기록한다. 사용자 개인 기보는 검수에 사용하지 않았으며 엔진 경기력에 대한 주장은 포함하지 않는다.

최종 검수용 관리기는 종료했고 stderr는 비어 있었다. 검수용 드래그·형세 관리기와 Godot 프로세스가 남지 않은 것도 확인했다. 사용자의 기존 대국 프로세스는 정리 대상으로 삼지 않았다.
