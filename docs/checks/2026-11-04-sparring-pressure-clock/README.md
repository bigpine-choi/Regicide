# 21~49수 압박과 5분 시간 제어

## 변경

20수까지의 접전 목표와 양쪽 50번째 착수부터 의도적 양보를 중단하는 경계는 유지한다. 21~49수는 선형 전환 대신 `1−(1−진행률)²`로 기준수의 힘을 더 빨리 보존한다. 양보 상한은 `min(120cp, 현재 양의 우세×0.35)×(1−진행률)²`이며, 열세에서는 의도적으로 더 양보하지 않는다. native/referee/final-quality가 같은 가드를 사용한다.

같은 루트 평가가 5cp 안으로 비슷한 검증 후보들 사이에서 상대 비폰 기물의 활동과 왕 탈출로 제한을 우선한다. 이는 실제 손실이 5cp 이하라는 보장이 아니라 후보의 루트 평가 동점 규칙이다. 착수 후 재검사와 최종 품질 검사는 별도로 수행한다. 기하학적 점수는 장기 전략이나 기력 향상의 증명이 아니다.

우세할 때는 안전한 다른 후보가 있으면 반복·스테일메이트·50수 규칙에 따른 무승부를 허용하는 선택을 피하고, 두 번째 반복에도 동점 감점을 준다. 열세에서 기존 기준수가 제공하는 무승부 방어는 보존한다. 모든 후보가 무승부인 경우 합법 기준수를 버리지 않는다.

스파링만 남은 시간 **300000ms부터** 연속적인 시간 압박을 적용한다. 일반 착수 목표 배율은 5분 1.0, 4분 0.9, 3분 0.8, 1분 0.6이다. 장고·회복·품질·전술 검사 예산도 줄인다. 실제 잔여 시간과 10초 예비 시간이 우선하며 검증을 마치지 못하면 `unverified`로 남긴다. 일반 시간제 모드의 기존 3분 기준과 앞선 착수 시간 단축은 유지한다. 상세 조건은 `clock-policy.json`.

## 실제 대국에서 발견한 실패와 수리

중간 수정본의 양색 계속 대국 2판에서 21~50수 120반수를 새로 뒀다. 흑 22...Bxf3는 별도 3초 평가에서 흑 +69→−142cp, 211cp 손실이었다. 실행 중에도 위험을 감지했지만 보조 탐색이 f6·g6의 두 나이트에 편중되어 더 좋은 비숍 후보를 찾지 못했다. 이 실패는 `independent-audit/audit-game-002.json`과 `bxf3-diagnostic.json`에 보존한다.

비숍 전체 수만 400ms 읽는 첫 가설도 Bc5를 반환했고 독립 평가 −157cp여서 실패했다. 최종 품질 정책 `regicide-sparring-quality-v5`는 21~49수의 위험 수리에서 기존 두 보조 슬롯을 기물 종류별로 나누고, 보드에서 상대 minor 이상 기물을 공격하는 합법수 그룹을 자체 엔진으로 읽는다. 외부 엔진의 추천 수를 주입하지 않으며 기존 슬롯 수·400ms 예산·전체 8초 상한을 늘리지 않는다.

기록된 Bxf3 입력을 실제 자체 엔진과 심판으로 두 번 재현하자 둘 다 Bb4로 교체됐다. 별도 3초 평가는 root +67/+69cp, 원래 수 −142cp, 새 수 +74cp였다. 한 번의 실행 중 판정은 `mitigated`, 재실행은 `replaced`다. 짧은 분석의 변동을 숨기거나 첫 판정을 엄격 통과로 바꾸지 않는다. 원시 UCI·기보·해시·완료 깊이·독립 평가를 `bxf3-native-quality-replay-v5.json`, `bxf3-replay-cli-v5.json`에 보존한다. 재실행은 저장소 루트에서 다음과 같이 수행한다.

```powershell
.venv-tests\Scripts\python.exe docs/checks/2026-11-04-sparring-pressure-clock/replay-bxf3.py --output <새로운-출력.json>
```

## 자동 검증과 재현 조건

- 최종 압박·품질·헌납·호스트·시계·회복 회귀 469개 통과. `ramp-tests-v5.json`, `ramp-tests-v5.log`.
- 5분 경계·3분·1분·30초·10초·시계 편집·취소 등 시간 제어 검사 211개 통과. `clock-tests.log`. 위 검사와 중복되므로 합산하지 않는다.
- 독립 감사 도구의 관점·점수·완료 패킷·구/신 가드 검사 8개 통과. `audit-tests.log`.
- 코칭 기호·핵심 장면·기보 확장은 [별도 화면 검증](../coaching-navigation/README.md)을 참조한다.

최종 계속 대국은 `docs/matches/2026-11-04-pressure-clock-v3/{white,black}`에 보존한다. 이전 실제 대국의 처음 40반수를 그대로 재생하여 전체 반복·50수 규칙 이력을 유지한 뒤 21수부터 새로 두며, 시작 시계는 양쪽 각각 300000ms로 명시 초기화한다. 상대는 Stockfish 18 제한 설정 1700, 상대 시간 300ms, Regicide 설정 3000ms·생각 시간 자동 배분, 각 엔진 Threads 1이다. 자체 Hash 16MB, 심판 Hash 32MB이며 별도 감사는 Threads 1·Hash 32MB·100000노드, 의심 국면마다 전후 각각 3초다. 버전·운영 환경·정책 및 실행 파일 해시·모든 착수 기록은 각 `metadata.json`, `native-searches.jsonl`, `moves.jsonl`, `game.json`, `game.pgn`에 있다. 두 색은 병렬로 실행했으며 Elo나 동등 시간의 경기력 비교가 아니다.

첫 `pressure-clock-v1` 시도는 재현용 시계 이력에 `mover`가 없어 새 수를 두기 전에 중단됐다. 하네스를 수정한 뒤 재실행했으며 해당 실패를 정상 대국에 포함하지 않는다. `v2`는 Bxf3 실패를 발견한 중간 실험, `v3`는 품질 v5 수정 후 실험이다.

동결한 호스트·정책·UI·계속 대국 하네스 소스 225개는 `source-snapshot.zip`과 `source-snapshot-manifest.json`에 보존한다. 사용자 설정·인증 정보·실행 중 게임은 포함하거나 수정하지 않았다. 수 제한은 미완료 `*`로 남기며 정상 승리·무승부로 환산하지 않는다. 기존 20수 기록은 새로 둔 수로 집계하지 않고, 새 계속 대국의 안전성과 승리 보장을 일반화하지 않는다.

최종 수정본에서 새로 둔 수는 총 91반수이며 기존 20수 기록은 제외했다. 두 판 모두 무승부·시간패·수 제한 없이 종료됐다. 양보 가드 위반·근거 미확인·독립적인 과도 양보 신호는 0건이다. 5분 시간 정책 인자가 두 판의 모든 자체 착수에 적용됐고, 실행 전후 소스·실행 파일 해시 및 보존한 소스 스냅샷과 현재 파일이 일치했다. `continuation-runtime-v3.json`, `independent-audit-v3-summary.json`, `independent-audit-v3/{white,black}`에 원시 결과를 보존한다.

실행 중 흑 한 수의 품질 검사는 `unverified`로 남았다. 이를 안전 확정으로 바꾸지 않았으며 별도 사후 분석과 구분한다. 백의 사후 원시 검사에는 39.a5에서 `M15→+10.97`과 교환 중 최저 −300cp가 겹친 경고 1건이 있다. 실제 `39.a5 Rxd5 40.Rxd5 Kg8`은 백 비숍 −300cp 뒤 흑 룩 +500cp를 회수해 순수 기물 차이가 +200cp다. 보상 없는 헌납으로 확인되지 않는다. 제한된 분석에서 메이트 점수가 유한 평가로 바뀌었다는 사실만으로 해당 수 이후 강제 메이트가 없다고 결론 내리지 않는다. 원래 경고는 삭제하지 않고 별도 검토 근거와 함께 보존한다.

이 두 판은 동일한 시작 국면의 선후공 교환 매치나 Elo 실험이 아닌 기능 재현이다. 소표본 승리를 보편적 승률·세계 정상급 기력·항상 질식시키는 스타일의 근거로 사용하지 않는다. 49수·50수 경계와 강제/열세 무승부 처리의 경계 조건은 자동 회귀 검사에서 별도로 검증했다.

39.a5 이후를 별도 Stockfish 18 프로세스(Threads 1, Hash 64MB, 15초)로 재검사한 결과 백 +13.12점, 완료 깊이 27이었다. 메이트는 여전히 탐색에서 확인되지 않아 강제 메이트 유지나 부재를 단정하지 않는다. 실제 정상 교환과 우세 유지를 확인한 근거는 `independent-audit-v3/white/ply77-independent-interpretation.json`이다. 원본 기보와 감사 경고는 변경하지 않았다.
