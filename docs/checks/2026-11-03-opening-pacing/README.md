# 오프닝의 불필요한 대기 단축

2026-11-03. `regicide-engine-pacing-v6`는 등록된 오프닝 수순 밖의 평범한 초반 전개에도 짧은 전체 착수 상한을 적용한다.

기존에는8개 대표 수순의 정확한 배치만 빠르게 인식했다. 실제로 `Nc3`를 선택하거나 흔한 다른 수순으로 진행하면 일반 판단 시간을 복원했고, 후보 변경·예상 밖 응수에 추가 대기까지 붙었다. 새 상한은 최초 탐색 배정과 최종 대기 보정에 모두 적용하므로 이 경로가 긴 대기를 되살리지 못한다.

- 첫12수 이내, 킹·폰 이외 기물10개 이상과 폰12개 이상인 전개를 대상으로 한다. 조용한 전개는0.35–1.2초, 가벼운 기물 접촉·체크 후보·핀 하나가 있는 전개는0.9–2초의 시드별 상한을 둔다. 기존 목표가 더 짧으면 늘리지 않는다.
- 체크를 받거나, 공격받는 무방비 기물·과부하 수비·심한 킹 주변 공격·승격/전진 통과폰·여러 강제 후보가 있으면 이 할인을 적용하지 않는다. 모든 긴 전술을 검출한다는 의미는 아니다.
- 초반 상한이 적용된 국면에는 별도의 장고 이벤트를 붙이지 않는다.13수 이후와 위험 신호가 있는 국면은 기존 배분을 사용한다.4분 시간 압박,0.1초 즉답, 기존1초 단축,10초 이하 추가 대기 생략을 유지한다.
- 사람에게 표시하는 권장시간·암기 판정과 수 선택 정책은 바꾸지 않았다. 짧은 예산에서는 분석과 레이팅 관측이 줄 수 있지만, 부족한 근거로 새 관측을 만들지 않는다. v6 저장·복원 식별자도 추가했다.

## 실제 엔진 확인

[임시 게임의 HTTP 검사](native/native-result.json)에서 자체 엔진 선택, 실제 대기와 시계 차감, 합법 수, 복원 PGN의 정책 식별자를 확인했다. 합법적인 초반 수순과 시계 이력은 검사용으로 주입했고, 측정한 현재 착수는 실제 시간을 사용했다.

| 시험 국면 | v5 목표 계산 | v6 실제 착수 |
|---|---:|---:|
| 시작 배치에서 Nc3 선택 | 5.678초 | 0.786초 |
| Nc3 이후 | 4.986초 | 0.643초 |
| 레티 | 6.804초 | 0.933초 |
| 이탈리안 | 11.450초 | 1.643초 |
| 닫힌 시실리안 | 7.938초 | 0.752초 |
| 런던 | 6.278초 | 1.158초 |

v5 열은 고정 커밋 `895cf07894574665f5f536d4633660cacb374643`에 v6에서 실제 얻은 동일 탐색 자료를 넣은 목표시간 계산이다. v5의 실제 검색·대기 측정이 아니며, 같은 기력·실전 평균 단축을 입증하지 않는다. 같은 자료를 재사용한 잔여4/3/1분 계산과 위험한 초반·이후 국면의 상한 제외도 별도로 검사했다.

[관련 단위·호스트 검사172개](unit/validation.json), [Godot77개 및 브라우저 검사](ui/validation.json)가 통과했다. 초반 상한, 목록 밖 실제 선택, 탐색 후보 변경, 위험 예외, 중반 장고 유지, 시간 압박, 저장과 레이팅 근거 처리를 포함한다. 수동 GUI 대국·전체 기력 검사는 수행하지 않았다.

[소스 일치 확인](source-verification.json)과 [산출물 해시](artifact-manifest.json)를 보존했다. 실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`로 유지했다. 사용자 게임·라벨·실행 중 세션을 변경하지 않았다. 앱을 재실행하고 새 대국을 시작하면 적용된다.

재현: 테스트용 Python으로 `tests/opening_pacing_tests.py` 또는 `tests/opening_pacing_integration.py --output <새 경로>`를 실행한다. 후자는 기존 산출물을 덮어쓰지 않으며 실제 엔진 실행 파일이 필요하다.
