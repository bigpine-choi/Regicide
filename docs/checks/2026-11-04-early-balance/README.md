# 20수 접전 실패 재현과 안전한 접전 복구

이전 실제 3판 중 20수 접전 기준을 벗어난 국면부터 조사했다. [실패 13개 추출과 원인별 진단](diagnostics/README.md)에 원본 기보·해시·별도 3초 평가를 보관한다. 100cp는 표시 관례상 1점이며, 서로 다른 엔진의 점수를 빼서 손실을 계산하지 않는다.

## 확인한 원인

1. 최종 품질 검사가 불리해지는 수만 거르고 큰 우세·승리 메이트를 접전 목표와 비교하지 않았다. 앞선 자체 엔진이 안전한 유한 평가 대안을 찾았어도 마지막 단계가 강제 승리를 유지하도록 되돌릴 수 있었다.
2. 추가 백 13.Qd5에서는 실제 자체 탐색이 찾은 Nd5가 외부 안전 검사를 통과했는데도 자체 재확인의 최소 깊이에 못 미쳐 폐기됐다. 400→1200ms로 늘린 [첫 수정 실험](replay-smoke-qd5.json)도 실패했다. 별도 400/1200/3000ms 원시 UCI 기록은 반복해서 약 0.17초에 완료 깊이 2로 종료됐다. 코드의 긴 전술 수순 확장 보호 장치가 진행 중 반복을 중단하고 이전 완료 결과를 보존하는 구조와 일치한다. [원시 기록](diagnostics/nd5-uci.log).
3. 흑 4~6수는 이미 약 −1.2점인 위치에서 작은 열세가 누적된 사례였다. 새 대안을 찾아도 같은 수가 최선인 경우가 있었으므로 이 고정 국면들을 접전 복구 성공으로 세지 않는다.

## 변경

최종 정책은 `regicide-sparring-quality-v4`다. 표준 시작의 20수 전 우세가 +80cp를 넘거나 승리 메이트면 자체 엔진이 합법 후보를 넓게 읽는다. +30cp 목표에 가까워진 후보만 비교하며, 직접적인 기물 헌납·즉시 메이트 허용 검사를 물질 반환 예외 없이 적용한다. 중앙 ±80cp 복귀는 `balanced`, 안전한 격차 축소는 `balance_improved`로 구분한다. 이미 불리할 때는 양보 없이 저항을 보강한다. 21~49수의 양보 축소, 50수 이후 전력, 전체 8초·시계 부족·취소·다른 국면 차단을 유지한다.

보호 장치 때문에 자체 깊이가 낮게 남는 위험 수리에는 별도 검증 경로를 추가했다. 표준 시작·20수 전·처음부터 외부 검사로 위험하다고 확인된 원래 수에만 적용한다. 복수 후보의 자체 탐색에서 발견한 수와 정확한 재탐색 결과 두 개(깊이 2 이상·점수 차이 40cp 이내), 헌납 검사, 새 외부 현재/착수 후 분석 두 번을 요구한다. 외부 분석은 각각 완료 깊이 10 이상, 착수 후 각각 ±80cp, 점수 변동·최초 하한을 확인해야 한다. 실제 깊이는 그대로 보존하고 `reference_confirmed_native_candidate`로 기록한다. 이를 자체 깊이 4 통과로 세거나 반복 자체 결과 자체를 전술 안전의 강화 근거로 표현하지 않는다. 우세 반환이나 21수 이후에는 이 경로를 사용하지 않는다.

## 실제 고정 국면 재현

[수정 후 핵심 재현](replay-smoke-v2.json)은 실제 자체 엔진·전체 기보를 사용하고, 선택 후 별도 Stockfish 프로세스로 각 위치를 3초씩 평가했다. 기록된 원래 수를 고정해서 재현했으며 시간제 탐색이 원래 수를 매번 다시 고른다는 주장은 아니다.

| 원래 수 | 새 자체 수 | 새 수 이후 독립 평가 | 해석 |
| --- | --- | ---: | --- |
| 13.Qd5 | Nd5 | −26cp | 접전 복귀; native depth2와 두 외부 확인을 별도 보존 |
| 16.Qd7+ | Rxa2 | +257cp | 기물 헌납 없이 조기 메이트 유예; 접전 미충족 |

[흑 3국면 재현](replay-black.json)은 원래 수를 유지했고 독립 평가는 각각 −122/−131/−151cp였다. 이미 불리한 고정 위치에서 더 나은 검증 후보를 찾지 못한 것이며, 접전 성공으로 집계하지 않는다. 모든 재현의 전후 소스·실행 파일 해시가 같다.

## 추가 실제 대국에서 찾은 결함과 2차 보완

중간 수정본으로 4판·280ply를 끝까지 실행했다. 첫 시드의 백·흑은 자체 착수 직후 20/20이 접전이었지만, 새 시드는 양쪽 16/20이었다. 모든 원본과 별도 감사를 보존한다. 새 백에서는 첫 안전 후보가 −100cp 경계에 닿자 더 좋은 후보를 찾기 전에 멈췄고, 중앙 룩의 Re1을 놓쳤다. 새 흑에서는 한 번의 재포획만 계산해 `...h5 Rxd4 Qxd4 Qxd4`에서 퀸까지 잡히는 잘못된 보호를 인정했다. 동시에 직전 동가 교환의 상대 재포획이 한 차례 지연된 경우까지 새 헌납으로 막는 한계도 있었다.

최종 보완은 다음과 같다.

- 첫 경계 안전 후보를 버리지 않고 보관하면서 중앙 후보를 더 찾는다. 중앙 파일의 룩을 별도로 자체 탐색하되 전체 후보 슬롯 수·8초 상한은 늘리지 않는다.
- 같은 칸의 모든 합법 재포획을 이어 읽어 순수한 기물 이득을 계산한다. 기본 128노드·25ms, 절대 1024노드·100ms 상한이고 하위에서 한 번이라도 한도가 끝나면 전체 이득을 0·미완료로 반환한다.
- 버틸 수 있는 20수 이전 위치에서 명백한 헌납이면 외부 점수가 접전 범위여도 수리 대상으로 분류한다. 손실 축소 경로로 다시 허용하지 않는다.
- 바로 직전 동가 이상 기물 교환과 상대의 한 번 미룬 응수만 재생해, 같은 기물·칸·원래 합법 재포획이 그대로 남은 정상 교환을 별도 `pending_equal_exchange`로 기록한다. 현재의 다른 희생·옛 기물 반환에는 크레딧을 주지 않는다. 원래 엄격 검사와 교환 근거를 함께 보존한다.

[최종 고정 재현](replay-final-v3.json)과 [요약](replay-final-summary.json)은 소스·바이너리 불변 상태에서 4개 모두 자체 생성·별도 3초 평가 ±100cp·엄격 검사 또는 입증된 직전 동가 교환 조건을 충족했다.

| 실패 과정 | 최종 자체 대안 | 별도 평가 | 안전 근거 |
| --- | --- | ---: | --- |
| 원래 13.Qd5 | Nd5 | −26cp | 자체 깊이 2·외부 확인 2회 별도 보존 |
| 새 백 31ply 품질 검사 입력 g4, 이후 Qb5 경계 선택 | Re1 | −66cp | 실제 중앙 룩 탐색·자체 완료 깊이 확보 |
| 새 흑 28ply Bxe3 후 큰 우세 잔존 | Kf8 | +25cp | 직전 Bxd4 동가 교환의 동일 재포획만 유지 |
| 새 흑 36ply h5의 가짜 재포획 보호 | c5 | +54cp | 연속 재포획 계산·엄격 기물 보호 통과 |

## 남은 백 이탈의 3차 보완

앞선 보완 뒤 추가 2판·179ply를 끝까지 실행한 결과, 흑은 자체 착수 직후 20/20 접전, 백은 16/20이었다. 남은 백 4개는 +139/+150/+317/+283cp의 우세가 남은 사례였으며 열세 붕괴는 아니었다. 원본 Bxb5의 국지 기물 노출 신호는 `...Qxa5 Bxd7+` 뒤 모든 합법 왕 응수에서 Bxc8로 회수하는 보상이 있어 공짜 헌납으로 판단하지 않았다. [사후 기물 검토](diagnostics/bxb5-material-review.md).

동시에 더 자연스러운 접전 대안이 있었다. 직전 `Nxa5`의 동가 나이트 교환 뒤 상대가 `...Qc7`로 퀸 위치를 바꿔 재포획 수 표기가 달라졌는데, 원래 UCI와 정확히 같아야 한다는 조건이 정상 교환을 막았다. 최종 v4는 원래 재포획 가능성, 상대 응수 후 후보를 두기 전의 실제 재포획 가능성, 같은 기물·칸·최근 2ply를 모두 요구하면서 상대가 바꾼 재포획은 `opponent_changed_recapture`로 구분한다. 현재 후보가 새로 공격을 열거나 다른 기물을 내주는 경우는 계속 거부한다.

외부 평가상 우세가 남지만 원래 수가 기물 보호 검사에서 거부된 경우에도, 먼저 엄격한 보호·교환 근거를 충족하는 접전 후보를 찾도록 했다. 실패하면 남은 예산으로 기존 안전 수리를 시도하고 미검증을 검증 성공으로 바꾸지 않는다.

[최종 v4 실제 고정 5국면](replay-final-v4.json)과 [요약](replay-final-v4-summary.json)은 전후 소스·실행 파일이 같으며 5개 모두 자체 후보 출처·별도 3초 ±100cp·기물 보호/입증된 동가 교환을 확인했다. 추가 백 29ply는 Bxb5 대신 자체 Kf1을 골랐고 독립 평가 −23cp였다. 기존 Nd5(−26), Re1(−66), Kf8(+25), c5(+54)도 그대로 통과했다. SF 진단 PV를 실제 후보로 주입하지 않았다.

## 자동 검사와 독립 검토

[최종 통합 475개 검사](python-tests.json)가 모두 통과했다. 실패·오류·생략 0, 69.188초이며 검사 중 Python 소스·테스트 해시가 불변이다. 새 접전 29·지연 교환 11·연속 재포획 10개를 포함하고, 기존 시간·단계 전환·취소·기물 안전·코칭·오프닝을 함께 확인했다. [최종 Python 471개 파일](verified-python-sources.zip)과 [해시 목록](verified-python-sources.json)을 보존하고 압축 안의 바이트도 다시 검증했다. 커밋·배포를 뜻하지 않는다. [중간 수정본의 445개 검사](python-tests-v2.json)와 이전 소스 스냅샷도 남겼다.

독립 읽기 검토에서 임의 시작 위치의 메이트 양보 범위와 +90→−95cp처럼 목표에서 멀어지는 선택을 찾아 수정했다. [검토 기록](diagnostics/independent-code-review.json)을 보존한다. 실제 자체 후보만 사용하며 외부 평가의 최선수를 후보에 주입하지 않는다. 이 변경은 Stockfish 보조 스파링의 기능 개선이며 C++ 자체 엔진의 기력 향상 근거가 아니다.

## 새 실제 대국 최종 결과

[조건·8판 전체 결과·원본](../../matches/2026-11-04-early-balance-v3/README.md)을 보존한다. 표준 시작, Stockfish18 1700 설정, 10+0, 자체 요청 3000ms/상대 300ms를 사용했다. 실제 계산 시간과 연출 대기를 모두 게임 시계에 부과하고, 초기·모든 착수 후 위치를 별도 200000노드, 의심 장면을 전후 각 3초로 평가했다.

이번 요청에서 **8판·640ply**를 끝까지 실행했다. 중간 수정본 6판·459ply에서 발견한 실패를 보존하고, 최종 v4 선후공 2판·181ply를 별도로 검증했다. 모든 판이 정상 체크메이트로 끝났고 오류·감사 미완료는 없었다. 서로 다른 코드의 8판을 하나의 동일 버전 표본이나 승률 향상 증거로 합치지 않는다.

| 최종 v4 | 실제 종료 | 20수까지 자체 착수 직후 접전 | 양측 착수 후 모든 위치 |
| --- | --- | ---: | ---: |
| 백 | 89ply | 20/20 | 38/41 |
| 흑 | 92ply | 20/20 | 37/41 |

**최종 두 판의 스파링 착수 직후 40/40이 ±100cp**였다. 상대가 둔 직후에는 7개 위치가 범위를 벗어났으므로 초기부터 41개 위치 모두가 연속 접전인 엄격 기준은 0/2다. 이를 감추거나 모든 상대와 모든 순간의 접전 보장으로 바꾸지 않는다. 20수 이후의 독립 과도 양보 신호는 0건이었다.

흑 12...Ra7(ply24)에서 원시 기물 감소 의심 1건이 있었다. 실제 수순은 13.e5 Nxe5 14.Nxe5 Bxe6이며, 상대가 나이트를 잡은 순간의 재료 감소와 다음 착수의 폰 회수·합법적인 d6xe5 교환 가능성을 따로 검토했다. 별도 평가도 교환 구간에서 흑 +108→+66→+45→+31cp를 유지했다. Ra7의 별도 3초 평가는 +250→−31cp였고, 룩을 공짜로 내주는 수순은 아니었다. 원시 신호는 보존하며 이를 보상 없는 헌납으로 확정하지 않았다. 실제 수순·회수·후속 점수 근거는 대국 결과 폴더의 검토 문서를 따른다.

최종 두 판의 적용 대체 10건(백2·흑8)은 원본 자체 탐색·완료 패킷·현재 위치·전체 기보와 일치했다. 미확인·생략·검사 누락은 0건이었다. 이 두 판에서 얕은 후보의 두 외부 확인과 pending 교환 예외가 실제 적용된 횟수는 0이므로, 해당 경로는 고정 재현 증거와 구분한다.

실행 전후 운영 소스와 양 엔진 해시가 일치한다. 검사 엔진은 정리했고 기존 사용자 앱과 그 앱이 교체한 엔진 프로세스는 종료하지 않았다. 소규모 기능 검증이며 Elo·독립 엔진의 기력 향상·모든 기물 희생의 수학적 안전 증명이 아니다.
