# 갬빗 공격 후보와 전술 검증 분리

2026-11-04. 기준 소스 `02b513c323898fe3507d678cb5d0db859e823ee0`, 기준 전술 정책 v3, 후보 v4, 호스트 정책 v9. 연구 분기에서 구현과 기능 검증을 완료했다. **실제 선택 개선·Elo 상승·Chess.com 등급 증가는 확인하지 못했다.**

## 문제와 구현

기존 정책은 공격 후보를 깊이 D에서 기준수와 비교한 뒤, 후보만 D+1로 읽어 0cp 이상인지 확인했다. 다른 수들은 다시 D에서 검색했다. 따라서 후보가 D+1에서도 양수라는 사실만으로는 같은 깊이의 기준수보다 뒤처지지 않는다고 판단할 수 없었다.

새 정책은 다음 두 번의 자체 검색을 사용한다.

1. 기존과 동일하게 희생 후보를 우선 생성하고 D에서 비교한다. 후보가 0cp 이상이며 기존 기준수 대비 손실이 25cp 이내여야 한다.
2. 후보와 기존 기준수를 함께 `searchmoves`에 넣어 D+1까지 검색한다. 완전히 완료한 정확한 점수·합법 PV·최종 수·깊이별 저장 패킷이 일치하고, 자체 엔진이 후보를 선택했으며 그 점수가 0cp 이상일 때만 교체한다. 두 수가 같으면 중복을 제거한다.

상대의 응수와 이후 내 수는 제한하지 않는다. 기준수가 이기거나 완료 자료가 불충분하면 원래 기준수를 보존한다. D+1의 낮은 점수를 D의 높은 점수와 직접 빼서 서로 다른 깊이를 혼합하지 않는다. 후보가 두 최종 후보 중 선택됐다는 사실은 전체 합법 수의 전역 최선이나 희생 보상의 증명이 아니다.

이 변경과 함께 기존 세 번째 검색의 `already_winning`·`critical_opportunity` 분류 조건을 착수 자격에서 분리했다. 해당 분류를 입증할 전수 비교는 더 이상 하지 않으며, 비희생 후보는 `verified_forcing_candidate`로 기록한다. `quality_qualified`, `classification_scope`, `paired_verification.global_best_proven=false`를 기록해 국소 품질 검사와 사이트 등급을 구분한다. 이미 우세한 위치의 건전한 공격도 품질 조건을 만족하면 선택할 수 있다. 따라서 이번 A/B는 **더 깊은 두 후보 비교와 분류용 세 번째 검색 제거를 함께 평가**한 것이다.

전체 추가 시간 상한은 1000ms다. 첫 후보 탐색의 비율을 유지하고 남은 시간을 두 후보 비교에 사용한다. 모양 분석·검증·검색 시간을 하나의 실제 경과시간 마감으로 계산하며, 미완료·오류·시간 초과 결과로 수를 교체하지 않는다. 기존 `candidate_compared`는 D, `candidate_final`은 D+1로 유지해 호스트 기록과 호환한다. v9 정책 식별자는 이전 캐시와 구분하고 v8 기보 및 갬빗 후속 운영의 호환성을 유지한다.

## 연구와의 관계

- [Oracle-Guided Soft Shielding, 2026](https://arxiv.org/html/2603.08506v1): 후보 생성과 실수 검증을 분리한다는 설계 원칙을 참고했다. 논문은 학습한 실수 확률 모델을 사용하지만, 이번 구현은 **자체 엔진 검색을 이용하는 결정 규칙**이다. 논문의 학습 모델이나 성과를 재현했다고 주장하지 않는다.
- [Diversifying AI, 2023–2024](https://arxiv.org/abs/2308.09175): 다양한 공격 후보를 찾는 과정과 최종 선택의 품질을 구분하는 방향을 참고했다. 새 신경망·리그 학습·다양성 보상은 구현하지 않았다.
- [CHSM8, 2026](https://arxiv.org/html/2610.25356v1): 스타일 지표와 기력을 구분해야 한다는 한계를 반영했다. 희생 횟수나 `!`·`!!` 기대를 객관적 수질 점수에 가산하지 않는다.

외부 코드·모델·가중치는 가져오지 않았다. 실제 수는 자체 Regicide만 선택한다. Maia 상대 모델, 보정된 WDL, 장기 학습 평가기는 후속 연구이며 이번 완료 범위에 포함하지 않는다.

## 수행한 검증

자동 검사 **134개**를 통과했다. 전술 선택 25개, 호스트 연결 11개, initiative 16개, repertoire 11개, boss play 19개, 상태 저장 14개, 오프닝 12개, 희생 후 운영 15개, 희생 기하 판정 11개다. 모의 검색을 이용한 검사는 실제 기력 근거로 계산하지 않는다.

- D에서는 허용됐지만 D+1에서 기준수가 선택되면 공격 후보를 거절한다.
- 후보가 이긴 양수 희생, 기준수와 후보의 중복 제거, 강제 수 후보를 처리한다.
- 메이트·상하한 점수·잘못된 시점/관점·불법 PV·누락/충돌한 깊이 패킷·다른 반환 수를 보호한다.
- 시간 초과·예외·기보 이력·판 복원·캐시 재생·되돌리기·오래된 게임 응답·짧은 시계 경계를 확인한다.
- 실제 선택 함수를 호스트에 연결하고 모의 UCI 응답을 전달해 두 후보 `searchmoves` 전송, D+1 완료, 저장 기록의 등급 분리를 확인했다.

별도 읽기 전용 코드 검토에서 적용을 막는 새 결함은 발견하지 못했다. 핵심 C++ 검색과 퀸 방어 실험 옵션은 변경하지 않았으며, 그에 대한 전체 C++ 검사나 GUI 수동 조작 검사를 새로 수행했다고 주장하지 않는다.

## 실제 엔진 A/B

동일 바이너리(`15872d934b736d52c0e5d173c4023fbf27a1be3a17fa6d027e694b3be9947e57`)의 고전 활동성 평가, Hash 16MiB, LMR 활성 조건이다. 각 위치의 기본 검색을 한 번만 실행하고 그 수·점수·깊이별 패킷을 양 정책에 그대로 전달했다. 정책별 추가 시간 상한은 1000ms이며, 실행 순서를 위치마다 교대했다. 각 추가 검색은 새로운 게임 식별자를 사용한다. 하드웨어와 검사 명세는 [verification.json](verification.json)에 기록했다.

| 구분 | 기본 검색 | 위치 수 | 실제 선택 변경 | 추가 자격 충족 | 기능 검사 |
| --- | --- | ---: | ---: | ---: | --- |
| [정규 시간 진단](native-summary.json) | 최대 1000ms | 8 | 0 | 0 | 전부 통과 |
| [최소 깊이 진단](depth4-summary.json) | 깊이 4, 최대 1000ms | 같은 8개 | 0 | 0 | 전부 통과 |

깊이 4 진단은 첫 실행에서 서로 다른 두 후보 비교가 발동하지 않아 그 경로를 확인하려고 추가했다. 여기서도 후보와 기준수가 다른 상태의 두 루트 비교는 발동하지 않았다. **이 분기는 모의 검색 및 호스트 통합 검사로 검증됐으며, 이번 자연 발생 네이티브 사례로는 검증되지 않았다.** 이 사실을 숨기기 위해 품질 하한을 완화하거나 수를 주입하지 않았다.

정규 시간 진단의 Legal `Nxe5`는 양 정책에서 그대로 선택·확인됐다. 이 한 사례의 추가 검증은 **3회·522.970ms에서 2회·234.852ms**로 줄었다. 반복 평균이나 일반적인 속도 향상으로 해석하지 않는다. 다른 7개 위치를 포함한 중앙 시간은 오히려 약 163.6ms에서 170.6ms였으며, 동일 시간 상한은 동일 CPU 사용량을 뜻하지 않는다.

두 실행 모두 합법 선택·공통 기본 결과·원시 패킷·판/기보 보존·프로세스 종료 코드 0을 확인했다. 사용한 8개 위치는 기존 개발 자료이므로 미사용 평가 자료가 아니다. 선택 변경/신규 자격 충족 위치만 사후 외부 감사 대상으로 미리 정했고, 해당 위치가 없어 Stockfish 검색은 수행하지 않았다. 완주 대국과 Elo 측정도 수행하지 않았다.

다음 판단에는 실제로 다른 두 후보가 경쟁하는 개발 외 국면과 전체 갬빗 정책의 같은 총시간 대국이 필요하다. 기존 반복 체크 지평선 문제, 기본 엔진의 과대평가, 전역 후보 누락은 이번 변경으로 해결됐다고 보지 않는다. 최종 확인에서 새 양의 메이트가 발견돼도 CP 전용 정책은 기준수를 보존하며, 기준수 단독 검증 성공은 기존처럼 후속 initiative 선택보다 우선한다.
