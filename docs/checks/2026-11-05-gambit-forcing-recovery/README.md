# 반복 체크 오판의 부분 수정과 실제 선택 개선

2026-11-05, 한국 시간. **공개 국면 두 곳은 개선됐지만, 핵심 엔진16판 선별에서1승7무8패(28.125%)로 퇴보 경고가 나타나 실전 활성화를 보류했다.** 국면 개선을 전체 기력 향상으로 보고하지 않는다. 기준 코드는 `7a3ca1cb474dc5f806a8cdd09a2a7079bda36125`, 실험 코어 변경은 `6aa8319f51919cd12ae336c3dd5747c67f540d2d`다. `...a3`의 허상 우세를0cp로 낮추고 자유 선택을Qd5로 바꾼 부분 개선과, 남은 과대평가·탐색 비용을 함께 보존한다. 기본 옵션은 비활성이고 현재 실전 런타임5011은 유지한다.

## 바뀐 탐색

이전 `UseQuiescenceForcing` 실험 옵션을 확장했다. 기본값은 계속 비활성이다.

1. **실제 반복 이력에 따른 한 번의 추가 탐색:** 체크 중인 동일 위치가 실제 이력에서 두 번 나타나면 경로당 한 번만 추가 체크 예산 두 개를 준다. 두 번 반복 자체를 무승부 점수로 만들지 않는다. 실제 청구 가능한3회 반복·50수와 자동 종국·메이트 우선순위는 기존 판정을 따른다.
2. **세 회피까지 연속 공격 문맥 유지:** 체크 회피가 세 개 이하인 경우에도 연속 체크를 이어 읽는다. 네 개 이상이면 추가 공격 문맥을 끊되 모든 합법 회피 자체는 남긴다.
3. **조용한 룩 준비수 한 번:** 노출된 왕 주변의 새 공격 칸을 두 개 이상 만드는 합법적인 비체크 룩 이동을 후보로 만든다. 기하학은 후보 생성에만 사용하며 평가 점수를 더하지 않는다. 해당 후보 뒤에는 상대의 모든 합법 수를 탐색한다. 추가 준비수는 경로당 한 번으로 제한한다.

반복 보충 여부·공격 진영·남은 예산을 정지 탐색 캐시 키에 포함한다. 포획·승격·강제 반격 체크·판/이력 복원·중단 처리를 유지한다. 특정 FEN·착수 번호·Stockfish 수를 실제 선택 규칙에 넣지 않았다. 이번 구현은 일반적인 선택적 탐색이며, 유한 예산으로 모든 공격을 해결하는 증명기는 아니다.

## `...a3` 한정 검색의 직접 비교

개인 기보가 아닌 기존 공개 최소 FEN에서 시작했다.

```text
r4k2/2p5/1pqp4/5r2/p3R2R/2B3P1/PP3P1P/6K1 b - - 3 31
```

두 검색 모두 같은 루트에서 `a4a3`만 허용하고850,000노드를 사용했다. 상대 응수와 이후 수는 제한하지 않았다.

| 검색 | 흑 자체 점수 | 완료 깊이 | 실제 총 노드 |
| --- | ---: | ---: | ---: |
| 기준 옵션 off | +441cp | 8 | 850,000 |
| 중간 비교 후보946 on | 0cp | 7 | 850,000 |

기준 자유 탐색의 완료 깊이7과 이 한정 대조의 깊이8은 서로 다른 검색이다. 후보의 반복 PV는 다음과 같다.

```text
...a3 Rh8+ Kf7 Rh7+ Kf8 Rh8+ Kf7 Rh7+ Kf8
```

정확한 전체 이력으로 재생한 끝 위치는 현재2회 반복이며, 백이 다음Rh8+를 선언해3회 반복을 청구할 수 있다. 현재 이미3회 반복이 완료됐다고 표시하지 않는다. 즉 이번0점은2회 반복을 임의의 무승부로 바꾼 결과가 아니다.

이 결과는 **이 위치에서 `...a3`의 허상 우세를 바로잡았다는 제한된 의미**다. 모든 반복 체크·왕 탈출·강제 수순을 해결했다는 뜻은 아니다.

## 자유 선택과 두 외부 감사의 구분

중간 비교 후보946은 자유 탐색에서 두 조건 모두 `...Qd5`를 선택했다. 아래 최종 상한 후보에서도 같은 선택을 확인했다. 자체 점수는 흑 +424cp였다. 선택 뒤에만 실행한 외부 감사를 별도로 읽는다.

| 비교 자료 | 공통 외부 완료 깊이 | 기준 `...a3` 손실 | 후보 `...Qd5` 손실 | 개선량 |
| --- | ---: | ---: | ---: | ---: |
| 11국면 선별의 동일 루트 감사 | 14 | 195cp | 101cp | 94cp |
| 앞선 동일 루트5후보+자유 탐색 감사 | 18 | 233cp | 114cp | 119cp |

깊이14와18의 수치를 섞어 평균이나 추가 향상으로 계산하지 않는다. 깊이18 감사는 중간 빌드가 이미 선택한 동일 `...Qd5`를 검사한 자료다. 최종 빌드도 같은 위치에서 같은 수를 선택했으므로 그 수의 별도 감사로 재사용한다. 해당 외부 답을 최종 자체 탐색 입력으로 전달하거나 실제 선택 수를 강제하지 않았다.

깊이18의 흑 평가에서 `...a3`·`...d5`는0cp, `...Qd5`는+119cp, `...Re5`는+221cp, `...Qxe4`는+214cp였다. 자유 탐색은+233cp였다. 서로 다른 제한 탐색의 유한 깊이 추정값이며 수학적 승리 증명이 아니다.

**Qd5의 자체 +424cp와 외부 +119cp 사이에는 여전히 큰 차이가 남는다.** 후보의 `...d5` 한정85만 노드 점수도+306cp로, 외부0cp와 다르다. 따라서 `...a3` 오판의 수정과 이 위치 전체의 정확한 순위·평가 완성은 구분한다.

## 최종 코어의 추가 계산 상한

최종6aa 코어는 각 정상 탐색 말단에서 시작하는 추가 정지 탐색에65,536노드 상한을 둔다. 이 상한이나 해결되지 않은 체크 깊이 한계에 도달하면 불완전한 추가 결과를 버리고 같은 위치를 기존 정지 탐색 정책으로 다시 계산한다. 옵션 전체를 켠 상태의 탐색 상한·취소 요청은 계속 지킨다. 캐시는 두 정책의 문맥을 구분한다.

노드 상한이 있는 선택적 정책이므로, 캐시의 계산 절약으로 추가 탐색 완료와 기본 경로 재검색 여부가 달라지면 캐시 on/off의 선택·값이 항상 같다고 보장하지 않는다. 이 동등성 예외는 실제 재검색이 발생한 경우에만 적용하며, 재검색 없는 캐시 동등성 검사는 유지하고 재검색 횟수도 기록한다.

최종 비교 실행 파일은 `d7df9ce92c57c5a98dad2b68145f8fc384f5f3c930335ae17b4a54d50fa028e8`다. 별도 `screen-bounded64k`에서 같은11국면·85만 노드/2085ms 조건을 다시 확인했다. 반복 체크195→101cp·Morra271→196cp 개선, 다른9위치의 선택·손실 유지, 큰 추가 악화·새 피메이트0이라는 결과를 유지했다. 중간946의Nxe5 조기 반환과 달리 최종 노드 조건은11위치 모두850,000노드를 소진했다. Nxe5의 완료 깊이6→5 등 추가 계산 비용은 여전히 남았다.

최종 실행 파일 자체의 별도 `...a3` 한정85만 노드 확인도 완료 깊이7·0cp와 같은 합법 반복 PV를 반환했다. 중간 후보946에서만 관측한 결과를 최종 코어의 결과로 대체하지 않았다.

최종 전체 C++231개 그룹(신규 연속 체크16개 포함), UCI 통합31개 그룹, observer 도구4개 검사가 통과했다. 이 검사는 규칙·상태 복원·상한·기능 회귀의 근거이며 전체 기력을 증명하지 않는다.

별도 [블랙마–디머 실전 분석](../2026-11-05-blackmar-diemer-review/README.md)에서는 더 넓은 문제가 확인됐다. 실제37.Rc8 위치를 최종 코어로 재검색해 얻은Re5도 외부 감사에서 피메이트를 허용했다.11개 개발·회귀 위치에서 새 피메이트가 없었다는 사실을 모든 실전 위치의 안전성으로 일반화하지 않는다. UI·대기 재배분·실전 확인 정책은 이 코어 기록과 별도 작업이다.
