# 37수 직전 국면: 최종 코어의 별도 회귀 진단

이 검사는 [호스트 대기 시간 재사용](idle-recheck.md)과 독립적이다. 호스트 정책이나 추가 검증 없이 최종 연구 실행 파일에 정확850,000노드만 주었다. 개인72플라이 이력은 메모리에서만 재생하고 최소 FEN·짧은 수순·해시만 [기록](finalcore-regression.json)했다.

- 실행 파일: `build-gambit-forcing-next-final/regicide.exe`, SHA256 `d7df9ce92c57c5a98dad2b68145f8fc384f5f3c930335ae17b4a54d50fa028e8`.
- 설정: `UseQuiescenceForcing=true`, `UsePieceActivity=true`, 신경망 평가 off, Hash16MiB, 단일 자체 검색.
- 한 번의 고정 노드 검색:850,000노드, 완료 깊이4, 자체 -323cp, `Re5`(`c5e5`) 선택. 경과1813.906ms는 CPU 비격리 환경의 참고값이다.
- 자체 수 선택이 끝난 뒤 별도 Stockfish18 감사: Threads1, Hash32MiB, Clear Hash, 같은 원래 국면에서 `Re5`만 허용, 최대 깊이18·3초. 완료 깊이18에서 정확 **-M12**(266,529노드)를 얻었다. 이 감사는 수 선택에 입력하지 않았다.

이전 동일 국면 감사에서 실제 `Rc8`은-M12, 기존 실행 파일의850,000노드 `Bf4`는-M10, 계산 제한 이전 연구 후보의 `a4`는-M7였다. 최종 코어가 수를 바꾸었지만 이 국면의 기물 헌납과 피메이트 문제를 해결했다는 근거는 없다. 이미 크게 불리한 위치이고, 짧은 외부 검색의 메이트 거리 차이를 안정적인 기력 순위로 해석하지 않는다. 기존 실행 파일에 새 호스트 검증을 연결해 `Rc3`를 얻은 결과와 합쳐서 코어의 개선으로 주장하지 않는다.
