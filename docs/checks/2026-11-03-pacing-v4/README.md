# 착수 목표시간 단축과 잔여4분 시간 관리

2026-11-03. 시간제 대국의 Regicide 목표 착수 시간을 최대1초 줄이고, 시간 절약 시작점을 잔여3분에서4분으로 앞당겼다. 사람에게 표시하는 권장시간 계산은 그대로이며, 스파링 자동 탐색 예산은 짧아진 착수 목표에 맞춰 배정된다.

일반적인 수는 기존 목표보다1초 빠르다. 빠른 강제수·명백한 포획은0.25초를 하한으로 사용하되, 원래 목표가 그보다 짧으면 늘리지 않는다. 실제 잔여시간과 안전 여유 제한이 이 하한보다 우선한다.45초 상한을 먼저 적용한 뒤1초를 줄인다. 잔여10초 이하에서는 추가 대기를 하지 않으며, 긴급 탐색 예산에서 다시1초를 빼서1ms로 붕괴시키지 않는다.

잔여4분부터 기본 시간과 장고의 추가 시간을 연속적으로 줄인다.4분/3분/2분/1분에서 기본 압박 계수는 각각1/0.875/0.75/0.625다. 이 계수는 남은 시간에 따라 변하는 사람 권장시간에 추가 적용된다. 처음 계획과 선택 후 보정은 각각 원래 권장시간에서 계산하므로1초를 두 번 빼지 않는다. 선택 후 보정은 이미 배정한 탐색 예산을 늘리지 않는다. 탐색이 목표시간을 넘겼다면 완료 후 바로 두므로 모든 실제 착수가 정확히1초 빨라진다는 보장은 아니다.

새 식별자는 `regicide-engine-pacing-v4`다. 시드별 기본 템포와 변동은 v3와 같은 해시 입력을 사용하여 보존하고, 과거 리듬 이력은 정책별로 구분한다. 화면의 자동 생각시간 안내를4분·약1초 단축에 맞췄다. 시간제 대국 저장에 활성 여부를 명시하여 복원 PGN에도 실제 v4 정책이 남게 했으며, 과거 기록을 v4로 다시 이름 붙이지 않는다.

## 검증

- [기존 관련 단위·호스트118개](unit/validation.json)와 [새 정책13개](comparison/unit.log), 총131개 통과.4분 경계, 빠른 수의 하한, 한 번만 차감, 시계 안전 제한, 탐색·관측 예산, 종료·저장·레이팅 상태를 검사했다.
- [Godot77개](ui/godot.log)와 [브라우저 검사](ui/browser.log) 통과. 자동 UI 검사이며 수동 대국 검사는 아니다.
- [실제 시간제 HTTP 연결](http/native-result.json) 통과.10+0·10+5·15+10에서 대기 중 시계·증가시간·착수·v4 PGN을 확인했다. 잔여4/3/2/1분의 자동 스파링, 사용자0초 이후 계속 진행, 엔진 시간 초과도 확인했다. 짧은 시계 설정에는 가상 경과시간을 주입하고 이후 착수는 실제 엔진으로 실행했다. 완전한 시간제 대국이나 시간패율 검사는 아니다.
- [실제 레이팅 연결](rating-http/validation.json)도 통과. 관측 예산이 남는 고정 시드에서 기준수 유지·사용자 수 분석·보정 저장과 다음 대국 반영을 확인했다. 이 검사의 표시 대기는 즉시 착수 기능으로 생략했다.0.25초 목표처럼 예산이 매우 짧으면 관측을 생략할 수 있으며, 부족한 자료로 새 레이팅을 만들지 않는다.

## 같은 입력의 목표시간 비교

[비교 결과](comparison/comparison.json)는 v3 커밋 `79d0587863c099f810ec91c3226991020da9adab`와 같은5국면·32시드·5개 잔여시간의800개 계산이다. 이전에 실제 엔진으로 얻은 원시 분석 자료를 두 정책에 똑같이 제공했다. 새 엔진 검색이나 실제 대기를 실행한 평균이 아니다.

| 잔여시간 | 평균 목표시간 감소 |
|---|---:|
| 10분 | 0.878초 |
| 4분 | 0.878초 |
| 3분 | 1.147초 |
| 2분 | 0.879초 |

일반 전개·전술 국면과 실제 오프닝 목록 밖 선택의 목표는 잔여10분에서 정확히1초 줄었다. 유일한 합법 응수는 평균0.654초에서0.25초로 줄어 평균 단축량이1초보다 작다. 짧은 수가 많이 포함된 제한된 사례 집합이며 실전 착수 분포의 대표 표본이 아니다. 잔여10초의 추가 대기0도 유지했다.

[소스 일치 확인](source-verification.json)과 [근거 파일 해시](artifact-manifest.json)를 보존했다. C++ 실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`로 동일하다. 개인 대국·레이팅 라벨과 실행 중 게임은 변경하지 않았다. 재실행 후 새 대국부터 적용된다.

재현은 `tests/pacing_v4_tests.py`와 `tests/rapid_clock_live_tests.py`를 사용한다. 같은 입력 비교는 이 폴더의 `compare_pacing.py --output <새 경로>`를 테스트용 Python으로 실행한다. 원격 CI 완료나 기력·레이팅 정확도 개선을 의미하지 않는다.
