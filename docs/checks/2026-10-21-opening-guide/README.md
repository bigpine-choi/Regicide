# 실시간 오프닝 안내 검증

검증일: 2026-10-21, Windows 11. 기준 코드: M1 통합 `b2419957e20e280f63c1ff720b161c2ed38864a3` 위의 오프닝 기능 변경. 테스트 당시 작업 중인 소스의 최종 파일 해시는 `source-freeze.json`에 기록한다.

## 구현 범위

- Godot·브라우저에서 현재 이름/ECO, 다른 순서로 같은 위치에 도달한 경우, 다음 수별 이름과 실제 남은 수순을 표시한다.
- 즉시 도달하는 이름과 여러 번 더 착수해야 도달하는 이름을 구분한다. 실제 착수 이력과 자동 무승부 종료를 반영한다.
- 무르기·핸디캡·기보 재생 위치에 맞춰 다시 계산한다. 안내를 펼치는 동작은 착수·기보 수정·추가 엔진 탐색을 하지 않는다.
- 이름 목록은 고정 버전 Lichess CC0 자료 3,865행, 색인 7,983위치다. TSV5개와 LICENSE 원본은 총 402,112바이트이며 `data/openings/manifest.json`에서 개별 SHA256을 검증한다.
- 안내는 외부의 유한한 분류 자료이며 자체 엔진의 수 선택·학습·모델을 바꾸지 않는다. 이름은 영어 원문을 사용한다.

Godot의 최종 결과는 다음 기록을 기준으로 한다. 중간 시도도 별도 폴더에 보존한다.

- `godot-final-schema/report.json`: 독립 headless import 성공, 신규 합성 38개와 실제 HTTP 연결 17개, 총 55검사 PASS. 임시 대국에 실제 엔진을 하나만 연결했고 추가 탐색 0회, HTTP는 GET만 사용했다.
- `godot-regression-final/report.json`: 기존 보드·입력 637개, 평가 막대 43개, 실제 대국 장면 82개와 생각 시간 33개·힌트 41개 검사 PASS. 별도 실제 엔진 종료 사례도 PASS.
- `godot-extra-regression-final/report.json`: 핸디캡 실제 장면 53개와 기보 재생 실제 장면 78개 PASS. 기존 화면 내 클릭·무르기·새 대국·PGN 검사를 유지했다.
- `godot-rendered-final/`: 실제 등록 자료를 넣은 최종 접힌 화면·펼친 화면 PNG와 `capture-result.json`. 보드와 착수 이력 불변 확인.

검사 순서는 승격 선택 위치 수정 → 기존 화면 회귀 → 생략 여부·표시 순서 문구 수정 → 신규 55검사·최종 렌더다. 마지막 실행 도구의 독립 import 추가 후에도 신규 55검사를 다시 통과했다. 마지막 문구 수정 이후 입력 처리나 컨트롤 배치는 변경하지 않았다.

실제 등록 자료를 넣은 게임 화면의 자동 렌더 결과도 포함한다. 이는 실제 게임 컨트롤을 그린 자동 장면이며 사람이 직접 한 판을 둔 수동 검증은 아니다. 브라우저는 DOM 검사 범위이며 실제 브라우저 렌더링·소화면 시각 검증은 수행하지 않았다. 원격 CI 실행 결과도 주장하지 않는다.

## 발견해 수정한 문제

1. JSON 목록·null 등 잘못된 자료 형식이 대국 상태 응답까지 막을 수 있었다. 자료 형식을 명시적으로 검증하고 안내 불가 상태로 처리한다.
2. 75수·5회 반복으로 자동 종료되는 위치를 지나가는 후보 수순이 표시될 수 있었다. 실제 이력을 반영해 종료 뒤 착수가 필요한 수순을 제외한다. 종료 위치 자체의 이름은 유지한다.
3. 새 안내가 기존 승격 선택을 화면 밖으로 밀어내는 문제가 기존 장면 검사에서 드러났다. 필수 승격 선택을 안내 위에 배치하고 회귀 검사의 기존 기준을 유지했다.
4. Godot의 생략 표시가 실제 응답 필드와 달랐다. 다음 수·즉시 이름·후속 이름·현재 이름 각각의 실제 생략 필드를 표시하도록 맞췄다.

## 조회 비용과 해석 범위

`core-review-fixes-performance.json`의 공유 데스크톱 측정에서 최초 색인은 1.776초, 이후 100회 중앙값은 초기 배치 27.65ms, Ruy Lopez 3.66ms였다. 대국·기보 화면에는 이력과 위치를 함께 구분하는 최대 128개 캐시를 두어 같은 위치의 반복 조회를 재사용한다. 이는 조회 비용 표본이며 경기력·Elo·엔진 탐색 속도 향상의 증거가 아니다.

기준 엔진 SHA256은 `edd950fb673cfca4134968b64cc5ef0f3d77eda698e9f40d2965170f143d6e6a`로 유지됐다. C++ 엔진 소스와 모델은 변경하지 않았다. 원격 업로드·설치본 덮어쓰기는 수행하지 않았다.
