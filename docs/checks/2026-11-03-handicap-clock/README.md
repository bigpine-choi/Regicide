# 핸디캡 수 변경 뒤 시계 유지

2026-11-03. 스파링 대국에서 Regicide의 수를 바꾸면 `forced_move()`가 `GameClock(None)`을 만들어 시계와 자동 생각시간을 함께 끄고 있었다. [수정 전 재현](before.json)은 임시 대국과 가상 시간으로 이 동작을 확인한다. 실제 사용자 기보를 수정하거나 진행 중인 대국을 재시작하지 않았다.

수 변경을 확정하면 원래 시계의 시간제·증가 시간·시간 초과 규칙·기록을 복제하고, **선택한 원래 수가 완료된 시점**으로 복원해 다음 차례의 시계를 시작한다. 원래 수의 소비 시간과 증가 시간을 그대로 한 번만 보존하며, 편집 시간이나 버린 후속 수순의 시간은 차감하지 않는다. 선택한 수 이후의 시계 조절은 버리고 그 수가 완료되기 전 조절은 보존한다. 시계 변경 번호도 올려 과거 버튼 요청을 거부한다.

미리보기는 일시정지하고 취소하면 편집 직전 잔여시간·누적 생각시간부터 이어 간다. 시간제 스파링의 자동 시간 관리와 클릭 시계 조절은 확정 후에도 유지한다. 원래 시간 제한이 없었던 대국은 그대로 무제한이다. 결과가 종료인 대체 수는 시계도 종료하며, 사람의 0초 계속 진행·Regicide 시간 초과 패배 규칙을 유지한다.

[수정 후 재현](after.json)에서는 10+5 스파링에서 `...e5`를 `...c5`로 바꾼 뒤 원래 완료 잔액을 유지하고, 사용자 시계가 2초 차감되며, 자동 시간 관리와 저장 기보 재구성이 유지되는 것을 확인했다. 추가 회귀 검사와 실제 엔진·HTTP 연결 결과는 이 폴더의 로그 및 JSON에 기록한다. UI 검사는 합성 상태이며 실제 수동 대국과 구분한다.

검증 결과:

- [시계 관련 67개 검사](clock-regression-summary.json) 통과. 양 색·3종 시간제, 증가 시간 중복 방지, 과거 수 교체·클릭 조절 이력, 취소·무르기·시간 초과·복기를 확인했다.
- [기존 핸디캡·보관함·시간 초과 검사](regression.json)는 41개 중 40개 통과, 별도 바이너리 인수를 요구하는 기존 실제 엔진 검사 1개는 생략했다. 실제 엔진 확인은 아래 전용 통합 검사에서 수행했다. 앞 항목과 일부 검사가 중복된다.
- [실제 엔진 HTTP 검사](native-integration.json)는 10분·10+5·15+10 × 사용자 백·흑의 6개 경우 모두 통과했다. 미리보기 정지·취소·수 교체 뒤 사람 시계 진행과 다음 Regicide 합법 응수·자동 시간 배분·PGN 시계를 확인했다. 임시 보관함을 썼고 테스트 서버와 엔진 종료도 확인했다.
- Godot 시계 검사 119개와 브라우저의 시계·클릭 조절 검사 2개 파일을 통과했다. 실제 UI 생산 코드는 변경하지 않았으며, 고친 서버 상태가 화면에서 올바르게 유지되는지 검증했다.

기존 저장 기보와 과거 검증 문서는 보존한다. 이미 실행 중인 프로그램의 코드를 강제로 바꾸지 않았으며, Regicide를 다시 실행한 뒤 새로 수를 변경할 때 수정 동작이 적용된다. 이 수정은 시계 기능의 정확성 검증이며 기력이나 균형 회복 정책 변경이 아니다.
