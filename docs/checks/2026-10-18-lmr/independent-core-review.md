# 보수적 LMR 코어 독립 검토

검토 범위는 현재 `src/search.cpp`, 검색 옵션과 결과 구조, TT의 깊이·세대 정책이다. 이 문서의 판단은 소스 읽기에 근거하며, 같은 깊이의 점수 동일성이나 기력 상승을 확인했다는 뜻이 아니다.

## 확인한 문제와 수정

첫 구현은 미검증 감축 실패가 남은 노드의 상한을 `depth - 1`의 TT 점수로 저장했다. 앞쪽 수는 원래 깊이, 뒤쪽 수는 감축 깊이로 읽으므로 전체가 같은 얕은 깊이의 탐색은 아니다. 따라서 깊이를 낮춰 기록하는 것만으로 고정 깊이 상한을 증명할 수 없다. 예를 들어 [100,101] 창에서 원래 깊이의 첫 수가 80이어도 그 수의 얕은 값은 200일 수 있다.

수정 후 `if (table_ && !selective_upper)` 조건으로 이 혼합 결과의 TT 저장을 완전히 생략한다. 감축 실패 결과는 best/PV 갱신 전에 건너뛰며, 노드는 alpha 경계만 반환한다. 기존처럼 원래 깊이로 재확인한 수가 컷오프를 일으킨 경우와 일반 완료 노드는 원래 깊이의 저장 경로를 유지한다. 지적한 직접 TT 재사용 위험은 해소됐다.

## 나머지 경계 검토

- 루트는 PV 노드로 시작한다. 첫 수는 기존 PV 성격을 전달하고, 후순위 scout는 비PV, 정식 PVS 재탐색은 원래 PV 성격을 전달한다.
- LMR은 PVS와 조용한 수 정렬이 모두 켜진 비PV 노드에서만 가능하다. 루트, 깊이 4 미만, 처음 네 수, 넓은 창, 체크 회피, 현재 무승부 청구, 메이트 점수 영역은 보호한다.
- 폰·킹 이동, 포획·앙파상·승격, 전달된 우선 수·TT 우선 수, killer 수는 제외한다. 실제 착수 후 체크를 주는 수와 의도된 무승부 청구도 제외한다.
- 감축 결과가 alpha를 넘으면 원래 깊이의 scout로 다시 읽는다. 필요한 경우 기존 PVS의 전체 창 재탐색을 거친다. 미검증 감축 실패는 직접 best/PV로 승격하지 않는다.
- 합법 수 없음과 자동 무승부 판정은 감축 전에 처리한다. TT 키는 반복 문맥과 반수 시계를 계속 포함하고, 매 검색마다 새 논리 세대를 사용한다.
- `AppliedMove`의 복원은 취소 예외에서도 유지된다. 중단된 재귀는 완료된 TT 저장 지점에 도달하지 않는다.
- 감소와 재탐색 카운터는 실제 호출 직전에 증가한다. 미완료 작업 포함이라는 공개 정의와 일치하며, 재탐색 수가 감소 수보다 많아지지 않는다.
- LMR OFF는 기존 분기와 원래 깊이의 검색을 유지하도록 작성됐다. 실제 이전 버전과의 탐색 그래프 동등성은 별도 회귀 실행 결과로 판단해야 한다.

이 수정 외에 소스 검토에서 추가로 확인된 결함은 없다. LMR ON은 선택적 탐색이므로 같은 깊이의 정확한 minimax 동값을 보장하지 않으며, 실제 기력은 같은 시간 조건의 별도 대국 검증이 필요하다.
