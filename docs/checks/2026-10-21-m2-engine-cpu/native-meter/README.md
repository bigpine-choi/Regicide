# 엔진 CPU 계수 검증

15개 테스트가 통과했다. 12개는 계측 실패·식별 오류·누적 계수 감소·시계 오류·예외 보존·핸들 정리 등을 확인하는 독립 fixture이며, 3개는 실제 Windows API를 사용했다.

- 실제 자체 프로세스의 계수를 별도로 선언한 GetProcessTimes 조회 전후와 대조했다.
- 새로 만든 짧은 단일 스레드 Python 작업과 긴 두 스레드 작업을 측정했다. 종료 후 유지한 프로세스 핸들의 최종 계수가 독립 GetProcessTimes 조회와 정확히 일치했다.
- 계측 핸들을 닫아도 살아 있는 자식 프로세스가 계속 동작하고, 그 뒤 정상 요청으로 종료하는 것을 확인했다.

자식 프로세스는 모두 실제 기본 Python을 직접 실행했다. 가상환경의 실행 중계 프로세스를 엔진으로 잘못 측정하지 않도록 자체 보고 PID·실행 파일도 확인했다. 자식 3개의 정상 종료와 생성 식별자별 최종 조회를 보존했으며, 남은 자체 자식·상태 미확인 자식은 각각 0개다. 사용자 앱·서비스와 실제 체스 엔진은 실행하거나 종료하지 않았다.

계측은 선택한 실제 UCI 엔드포인트 프로세스의 모든 스레드를 합산하며 자손 프로세스는 제외한다. 응답 시간은 엔진 호출만 감싸고, CPU 계수 조회·영수증 작성 시간은 응답 구간 밖에 둔다. CPU 조회 두 번은 호출보다 조금 넓은 구간이므로 원시 조회 시각을 함께 보존한다. 계수의 시간 분해능 때문에 즉시 응답의 CPU 증가가 0일 수 있다. CPU/응답 시간 비율은 진단값이며 최솟값을 합격 기준으로 사용하지 않는다.

실행 명령·원시 영수증 및 소스 SHA는 [execution.json](execution.json)에 기록했다. 실제 대국과 Sunfish 엔드포인트 판별 검증은 별도 단계다.
