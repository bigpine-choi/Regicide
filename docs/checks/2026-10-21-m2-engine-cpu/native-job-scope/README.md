# 현재 Job을 이용한 엔진 식별 검증

새 식별기 `m2_engine_identity_v2.py`의 오프라인 검증 33개가 통과했다. 전역 부모 PID가 일치해도 현재 실험 Job 밖의 프로세스는 열지 않으며, 같은 Job 안에서도 생성 시각이 부모보다 이른 프로세스는 생성 식별 증명으로 제외한다. 실제 자식·손자, 접근 오류, 불완전 Job 목록, breakaway 허용, 로컬 식별 변화는 계속 실패로 처리한다.

`attempt-001`은 새 자체 Job 안의 게이트로 제어한 단일 Python 작업에서 실제 Regicide·Stockfish·Sunfish를 차례로 실행했다. 정식 실행과 동일한 기본 엔진 실행 옵션으로 각각 100ms 요청의 합법 수 한 개를 확인했다. 세 경우 모두 현재 Job 조회, breakaway 금지 플래그 8192, 완전한 PID 목록 및 worker·transport·endpoint 식별을 검증했다. Sunfish는 실행 중계 프로세스의 실제 Python 자식을 측정했다.

Regicide에 대해서는 전역 목록에서 관측한 Job 밖 PID 1396의 부모 PID 필드만 합성으로 바꿨다. 실제 Job·프로세스 생성 식별 증거는 유지했다. 이 조건에서도 해당 PID에 `OpenProcess`를 요청하지 않고 원시 제외 근거를 보존했다. 이는 새 식별 경계의 시험이며, 이전 중단의 원인 프로세스를 재현하거나 확정한 결과가 아니다.

대국은 실행하지 않았다. 자체 작업은 모두 정리했고 최종 Job의 활성 프로세스 0개·상태 미확인 0개와 Job 핸들 닫힘을 기록했다. 사용자 앱·서비스·보안 설정은 변경하지 않았다. 명령·소스 SHA·Job 원시 값·각 엔진 식별과 CPU 영수증은 `attempt-001/receipt.json`과 `worker-receipt.json`에 보존했다.

같은 Job에 남은 오래된 무관 프로세스에도 보수적으로 두 차례 생존·멤버십 증명을 요구한다. 이 프로세스가 조회 사이에 종료하면 안전하게 중단될 수 있다. 다른 lane의 무관한 Job PID 집합 변화는 허용하며, 실제 로컬 엔진 계통의 변화는 허용하지 않는다.
