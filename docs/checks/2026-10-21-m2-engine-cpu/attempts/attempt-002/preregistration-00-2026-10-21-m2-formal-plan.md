# 정식 M2 사전 계획

2026-10-21 KST. 수치와 정책을 첫 사전 대국 결과 전에 JSON과 실행 폴더에 동결한다. 목적은 **현재 통합 엔진의 세 평가 경로를 고정 외부 상대에서 측정하는 로컬 기준선**이다. 기본 평가기의 교체나 Huber 승격 실험이 아니다.

## 대상과 표본

- M1 통합의 수식 평가·보정망 V2·정수 NNUE S32를 같은 native 실행 파일과 기존 모델로 유지한다. M2 파일럿과 같은 세 프로필·두 공식 외부 상대(Stockfish18, Sunfish 고정 커밋)를 쓴다.
- 본 대국은 자체 작성 새32개 부모 수순의 시작 위치, 각 양색, 두 상대, 세 평가, 한 수당100ms/1000ms로 **768판**이다. 인벤토리에서 명시한 과거 관측 자료의 유의미한 부모/위치와 중복을 검사한다.
- 8반수 부모 수순/전치 위치와 이후 입력, 색·랭크 반전의 충돌을 검사한다. 1~3수의 공통 도입부를 전부 배제하지 않는다. 상위7개 오프닝 묶음도 같이 기록하며32개가 통계적으로 완전히 독립이라고 가정하지 않는다. 정확한 조사 범위·해시·제외 이력은 은행 준비 영수증을 따른다.
- 사전 실행은 본 대국과 별개인 사전 은행의 **첫1개 계열**에서 동일한12조건×양색, **24판**이다. 사전 은행의 두 번째 계열로 유리한 결과를 골라 바꾸지 않는다. 사전 실행은 연결·자원·오류 검증이며 본 성적에 합치지 않는다.

## 자원과 순서

CPU는 Ryzen AI7 350,8물리·16논리 코어다. Windows native API로 물리 코어의 논리 CPU 마스크를 조사한다. 서로 겹치지 않는2물리 코어씩 네 lane에 배정하고 worker와 자식 엔진의 실제 affinity를 검사한다. Regicide 검색과 Stockfish는1스레드이며 Hash16이다. Sunfish는 고정 Python 환경/소스의 단일 검색이다. Hash가 같아도 프로세스 전체 메모리가 같다는 뜻은 아니다.

동일 계열·상대·시간의 세 평가 경로는 같은 lane에서 순서대로 실행한다. lane은 `(계열번호+2×시간번호+상대번호)%4`, 세 후보의 순서는 같은 번호들의 합을3으로 나눈 나머지로 회전한다. 본 대국에서 각 후보·상대·시간 조건은 lane마다8쌍을 배정받는다. lane 간 작업 훔치기와 실행 중 재배분은 하지 않는다.

최대500반수, 청구 가능한3회 반복·50수 무승부는 항상 청구한다. 500반수 도달은 미완료 `*`이며 무승부로 세지 않는다. UCI 요청시간은 대국 전체 시계 심판이 아니다. 응답 외부 상한은 요청시간×2+0.25초이며 초과는 실험 오류로 중단하고 패배/무승부로 바꾸지 않는다. 한 양색 쌍의 wall 상한은1500초, 사전 단계는1800초, 본 단계는14400초다. 준비·검사 시간은 별도다.

## 부하와 중단

샘플 간격0.5초, 최대 간격·샘플 소요시간2초다. 단계 시작마다5초 idle 검사를 요구한다. 알려진 비소유 엔진은 PID와 생성시각의 집합이 같고 관측 CPU 증가가0이어야 한다. 새/사라진 외부 엔진, 접근 실패, 시간·카운터 오류는 허용하지 않는다. worker는 직접 만든 프로세스의 실제 생성 객체를 등록하며 검증된 자식만 소유 cohort로 제외한다.

호스트 전체 CPU시간에서 유휴와 소유 cohort의 CPU시간을 뺀 비소유 부하를2초 창으로 계산해 전체 논리 CPU 대비20%를 넘으면 중단한다. monitor·OS·기타 프로그램도 이 수치에 포함한다. 알려지지 않은 엔진, 샘플 사이의 짧은 프로세스, 열·전력·OS 배치를 완전히 격리했다는 보장은 아니다. Huber 학습과 native 검증은 사전 대국 전에 끝낸다.

**첫 오류·미완료·부하 위반에서 네 lane의 새 대국을 모두 중단한다.** 실행 전에 고정한 판수와 순서를 성적에 따라 바꾸거나 추가하지 않는다. 실패 시도는 남기고 같은 출력 경로로 재시도하지 않는다. 제품 결함을 고친 사전 재실행은 새 실행 식별자·새 동결·원래 실패 기록과 함께 구분한다. 본 대국의 인프라 실패를 좋은 성적만 남기는 재시도로 지우지 않는다.

자체 worker만 새 Windows job에 넣고 startup gate 이후에 엔진을 실행한다. job 종료 시 소유 자식과 고아 자식까지 정리한다. 기존 사용자 게임이나 다른 프로세스를 종료하지 않는다. 관련 Windows 동작은 [공식 job 구조 문서](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information), [kill-on-close 정책](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)을 따른다.

Windows venv 실행기는 별도 interpreter 자식을 만들 수 있으므로 worker는 고정한 기본 CPython 실행 파일을 직접 시작한다. 실제 Popen PID와 worker PID를 동일하게 유지하며, chess 패키지 경로를 명시하고 기본 interpreter·chess 원문2파일 해시를 검사한다. Python 전체 표준 라이브러리와 OS를 봉인하는 것은 아니다.

## 완료와 해석

사전24판이 전부 정상 종료하고 부하·코어 배분·입력/기보/PV/설정 감사가 통과해야 본 대국을 시작한다. 완료 조건은 본768판, 예정384쌍, 오류·미완료·미실행0과 부하 정책 충족, 원시 PGN/JSON·모델/파일·프로세스/자원 기록 및 독립 감사의 일치다. 실패·미완료는 실제 남은 수와 중단 이유로 보고한다.

각 후보×상대×시간의64판 승/무/패·점수·탐색 자원·응답시간 초과를 따로 공개한다. 조건이 다른 점수를 합쳐 일반 모델 순위나 Elo로 만들지 않는다. 상위7개 묶음을 재표집하고 그 안의 부모 수순·양색을 같이 유지하는 percentile cluster bootstrap을20000회, seed2026102101로 계산한다. 불균형한7묶음과 고정 자체 작성 자료에서의 서술적 구간이며 보편적 기력의95% 신뢰구간이나 다중 비교 승격 규칙이 아니다.

M3의 H10012후보는 이미 준비했어도 이 기준선의 프로필에 넣지 않는다. 후보 선택·확인자료·확인 대국은 별도 사전 계획으로 진행한다. 이 정식 M2 결과의 범위는 고정된 외부2상대·짧은 두 시간·단일 로컬 병렬 환경이며, 세계 순위나 인간 Elo로 환산하지 않는다.
