# 래피드 시계·사람 기준 복잡도·생각시간 안내

2026-11-03. Godot와 브라우저 대국 화면에 세 기능을 연결했다. 실제 착수는 기존 자체 Regicide 엔진이 결정하며, 복잡도와 생각시간 안내는 새 엔진 탐색 없이 보드 구조와 시계를 읽는 별도 계산이다. 사람 대상 난이도 보정이나 경기력 향상을 입증한 기능은 아니다.

## 사용 방법

Regicide를 다시 실행한 뒤 오른쪽 **새 대국 시간**에서 선택하고 **새 대국 시작**을 누른다. 기본·보스·스파링 모드 모두 사용한다.

| 선택 | 각자 시작 시간 | 합법 착수 완료 후 추가 |
| --- | --- | --- |
| 10분 래피드 | 10분 | 없음 |
| 10+5 래피드 | 10분 | 5초 |
| 15+10 래피드 | 15분 | 10초 |

선택 변경은 다음 새 대국에 적용하며 현재 시계를 재설정하지 않는다. 초기 화면과 과거 API의 시간 제한 없는 대국에는 **새 대국에서 시간 선택**이 표시된다. 기존 **Regicide가 한 수를 생각할 시간**은 AI의 기준 탐색시간 설정으로 별개다. 보조 검토가 추가될 수 있어 AI 전체 착수의 경과 시간과 같지는 않다.

양쪽 남은 시간은 보드 위·아래에 표시한다. 사용자의 차례에는 **사람 기준 복잡도 · 높음 57/100 · 실험**과 **이번 수 총 30초 권장 · 앞으로 18초** 같은 안내를 보여준다. 숫자는 예시이며 해당 국면과 시계에 따라 달라진다. 이미 사용한 시간을 계속 빼며, 권장량을 쓰면 착수를 권한다. 상대 차례와 종료 후에는 추천을 중지한다.

분석·코칭·기보를 열어도 진행 중인 대국 시계는 계속 흐른다. 무르기는 남겨진 국면의 저장 잔여 시간을 복원하므로 훈련용 무르기이며 경쟁 대국의 무르기 규칙은 아니다. 핸디캡 미리보기에서는 잠시 정지하고 취소 시 이어 간다. 실제로 상대 수를 바꾸는 핸디캡 분기는 시간 제한 없는 연습으로 전환한다.

## 사람 기준 복잡도의 의미

점수는 AI 탐색 깊이·노드 수나 단순 유불리 점수를 난이도로 바꾼 값이 아니다. 사람에게 확인할 관계가 얼마나 많은지 다음 특징으로 추정하는 자체 휴리스틱이다.

- 합법적 선택의 수, 체크·잡기 갈래, 공격받는 느슨한 기물과 핀, 여러 기물을 동시에 지키는 수비 관계.
- 킹 주변 공격, 전진한 통과폰과 양쪽 승격 경쟁, 적은 기물이라도 템포가 중요한 폰 종반.
- 합법 응수가 한 개면 현재 선택 부담을 낮게 표시한다. 넓고 조용한 초반을 무조건 어렵다고 판정하지 않도록 선택 개수의 비중은 작다.

0~24 낮음,25~49 보통,50~74 높음,75~100 매우 높음이다. 이유를 최대 세 문장으로 설명하고 특정 추천 수를 노출하지 않는다. 공격 관계는 정적 근사이므로 숨은 장기 전술·전략, 개인별 오프닝 친숙도와 계산 능력은 충분히 포착하지 못한다. 점수는 실수 확률이나 인간에게 실측한 난이도 백분율이 아니다.

## 생각시간 배분

현재 잔여 시간에 이번 수에서 이미 사용한 시간을 더해 착수 시작 시점의 예산을 복원한다. 국면별 예상 잔여 수(24/28/36수)와 증분의 일부를 참고해 기본 배분을 잡고, 복잡한 수에 더 배분한다. 향후 수에 쓸 예비 시간을 남기며, 한 수 상한은 시작 예산의18%와 증분 일부, 최대90초 중 보수적인 범위를 적용한다. 예상 잔여 수는 실제 대국 길이 예측이 아니다.

상대보다 시간이 크게 적으면 배분을 줄이고, 30초·10초 이하에서는 시간을 아끼는 안내를 우선한다. 아직 얻지 않은 다음 증분을 현재 남은 시간처럼 사용할 수는 없다. 현재 위치와 일치하는 안정된 엔진 평가가 접전이면 시간 배분만8% 소폭 늘릴 수 있다. 복잡도 자체는 바꾸지 않는다. 검증되지 않은 추정 레이팅을 사용자의 확정 실력으로 취급하지 않으므로 이번 버전은 레이팅에 따른 개인화 배분을 하지 않는다.

권장 시간은 확정 최적값이 아니다. 같은 국면을 계속 조회한다고 예산이 매번 새로 시작되지 않으며, 새 평가 근거로 소폭 조정될 수 있다. 네트워크·화면 응답이 늦을 때도 오래된 표본이 남은 시계와 권장 잔여 시간을 되돌려 늘리지 않도록 보정한다.

## 시계와 기록의 정확성

서버의 단조 증가 시각으로 실제 경과를 계산하며 시스템 날짜 변경과 분리했다. 흰색 시계는 새 대국 시작부터 작동하고, 실제로 합법 수가 완료된 뒤 한 번만 증분을 더한다. 불법·오래된 요청은 증분을 받지 못한다. 양쪽 시간 모두 AI 보조 분석과 통신 대기를 포함한 차례의 경과를 계산한다. AI 잔여 시간이 부족하면 보조 분석을 생략하고 기본 탐색 예산도 줄인다. 시간 이후 도착한 엔진 수는 적용하지 않는다.

시간이 끝나면 서버가 결과를 확정한다. 상대가 메이트할 기물이 없다고 확인되는 경우에는 무승부 처리한다. [FIDE6.9](https://handbook.fide.com/chapter/E012023)는 어떤 합법 수순으로도 메이트할 수 없는 경우를 예외로 두며, 구현은 기존 [python-chess의 has_insufficient_material](https://python-chess.readthedocs.io/en/latest/core.html#chess.Board.has_insufficient_material)을 사용한다. 이 함수는 기물 기반의 보수적 판정이므로 모든 배치 의존 죽은 국면을 완전히 증명하는 구현은 아니다. 단순히 '마이너 기물 하나라 무조건 무승부'로 처리하지 않는다.

JSON에는 처음과 착수 완료 뒤의 잔여 시간 및 현재 표본을, PGN에는 TimeControl과 각 수의 [%clk]를 저장한다. 보관함은 합법 수순, 번갈아 가는 차례, 증분·경과·상대 시간 불변 관계를 독립 확인한 뒤 시간을 재생한다. 시간패도0초·패배 색·기물 조건과 결과가 일치해야 읽는다. 과거 프레임의 시계는 정지하며, 최종 시계나 미래의 생각시간 안내를 이전 수에 끼워 넣지 않는다. 예전 시계 없는 기록은 계속 읽힌다.

## 검증 범위

- 새 시계11개, 실제 호스트 경로19개, 저장·복기11개, 사람 기준 안내16개 검사를 통과했다. 정확한0초, 합법 수 증분, 잘못된 요청, 지연된 엔진 응답과 동시 조회, 기권·종료·무르기·편집, 훼손된 시간 기록을 포함한다.
- 기존 호스트/평가30+26개(선택적 native1개 제외), 생각시간27개, 스파링 상태8개, 레이팅 상태12개가 통과했다. 기존 보관함24개 중22개 통과, 계정의 파일 심볼릭 링크 권한과 선택적 기존 native 테스트2개는 제외됐다. 새 native 검증은 별도 실행했다.
- 실제 Regicide 실행 파일을 사용하는 HTTP 검증에서 세 시간 설정, 백·흑, 시계 감소·증분·PGN·복기·기권 후 정지를 확인했다. 마지막 시간패 검사는 주입된 시각에601초를 더한 경계 검사다. 실제10분을 기다린 완주 대국이나 기력 비교가 아니다. 실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`로 유지했다.
- 독립 검토에서 정지 순간0초를 넘는 문제, 늦은 표본으로 시계가 늘어나는 문제, Godot의 비활성/상대 차례 null 값을 발견해 수정하고 회귀 검사에 포함했다.
- 실제 엔진과 HTTP를 연결한 Godot 통합 검사는 보드 방향·입력637개, 평가 게이지56개, 실제 장면87개와 준비·탐색·응답 대기 중 종료3가지가 모두 통과했다. 새 체크아웃 실행과 에디터 가져오기도 확인했다. 자동 입력 검사이며 사람의 수동 플레이를 주장하지 않는다.
- 추가 통합 검사의 첫 콘솔 실행은 에디터 가져오기 프로세스가 종료 코드3221225477로 끝났으며, 일반 실행 파일로 재실행해 통과했다. 다음 실행은 이미 변경된 현재 위치 평가 대신 과거 방식의 평가를 기다리던 오래된 검사1개가 실패했다. 검사 기대값·스크롤 입력·시계 변화 비교를 현재 동작에 맞추고 마지막 전체 통합 검사를 통과했다. [최종 결과와 앞선 시도](godot-live/validation.json)에 구분해 기록했다.
- 새 검사를 GitHub의 기존 자동 검사에도 연결했다. 이 기록의 로컬 검사 통과를 원격 CI 완료로 표현하지 않는다.

기능 변경은 Python 호스트와 Godot/웹 UI이며 C++ 엔진은 수정·재빌드하지 않았다. 모든 테스트는 임시 대국 폴더를 사용하며 사용자의 기존 기보·레이팅 라벨을 수정하지 않는다. 실측 사람 난이도, 권장 시간의 학습 효과, 완주율·Elo에 대한 검증은 수행하지 않았다.

검증 시점은 기능 소스의 커밋 직전 작업본이다. 원본의 당시 Git 표기·경로는 보존했으며, 기록된 소스 SHA256과 최종 파일이 일치함을 확인했다. 보고서에 원격 CI 성공이나 인간 대상 검증 결과를 추가하지 않았다.
