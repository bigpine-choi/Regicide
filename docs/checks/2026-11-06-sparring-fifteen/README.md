# 스파링15수 접전·16수 강화 전환 검증

현재 사용 정책은 양쪽의15번째 착수까지 ±1점 접전을 목표로 하고,16~49수에는 강도를 점진적으로 높이며 우세 보존을 우선한다. 양쪽의50번째 착수부터 의도적 양보를 중단한다. 이 기록의 실제 경계 검사는 기능 확인이며 기력·Elo·승률·역전 확률의 증거가 아니다.

## 실행 전 고정 입력

[고정 입력](fixed-inputs.json)은 실제 엔진 검색 전에 작성했다. 기존 `tests/sparring_state_tests.py`의 생성된 합법 이력에서28·29·30·31·96·97·98·99반수 접두부를 그대로 사용한다. 각 위치에서 새로 계산하는 것은 다음 한 수뿐이다. 따라서15·16·49·50수 각각 백과 흑의 실제 선택8회를 확인하며,50수짜리 대국8판으로 세지 않는다. 현재 사용자의 저장 대국은 읽지 않는다. 특정 정답 수나 가짜 과거 실력 관측은 넣지 않는다.

점진 강도는 의도적 양보 허용폭과 후보 선호의 곡선이다. 연산량을16수에5.6%만 사용한다는 뜻이나 Elo 비율이 아니며, 기본 자체 검색은 기존 전체 예산을 유지한다. 전환이 줄이는 것은 의도적 양보와 접전 회복 동작이다.

모든 위치는 같은 Regicide5011 바이너리·Hash16MiB·요청1000ms로 실행한다. 고정 시드는 각 접두부 번호에서 정한다. 현재 자체 스파링·심판·안전·최종 품질 검사의 추가 예산을 유지하며 요청 시간과 실제 경과 시간을 별도로 기록한다. 시계는 비활성이고 CPU 격리는 하지 않는다.

실제 `HumanGame.engine_move`와 로컬 Stockfish18 심판을 사용한다. 이 SF는 스파링의 원래 선택 보조·최종 품질 검사를 수행하므로, 자체 Regicide만의 독립 기력 시험으로 해석하지 않는다. 화면용 힌트·자체 표시 평가는 기존 검색 없는 도우미로 대체하며 실제 선택 자료로 쓰지 않는다.

## 판정 범위

위치·수순·단계·최종 합법 착수·자체 엔진의 실제 반환/수순 증거·기본 요청 시간·최종 품질 영수증의 수 일치·소스/바이너리 해시·소유 프로세스 정상 종료를 검사한다. 모든 자체/SF 요청과 완료 패킷은 원시 로그에 남긴다. 품질 검사가 미확인 또는 손해 완화로 끝나면 그 상태를 그대로 보고하며, 기능 정상과 품질 확인을 구분한다.

50수의 의도적 양보 경로가 자체 기본 수를 보존하는지와, 그 뒤의 별도 안전 검사가 최종 수를 바꾸었는지를 분리한다. 안전 교체가 있었다고 의도적 양보 재개로 표시하지 않으며, 변경된 최종 수를 원래 기본 수라고 표시하지도 않는다.

## 현재 확인한 사항

실제8턴 검색은 **실행하지 않았다**. 사용자 요청으로 추가 실행을 취소했으며, 아래 도구와 입력은 준비된 상태로만 보존한다. 하네스 구문 검사와8개 입력의 합법성·단계 검사는 완료했지만 실제 native/SF 선택·품질·실행 시간·프로세스 종료 결과는 없다. 이를 실제 경계8턴 검증 통과로 보고하지 않는다.

UI는 웹 모드 회귀검사를 통과했고, 실제 Godot4.7.2 headless 모드 검사101개가 모두 통과했다. 백과 흑이 각각15번 둔 뒤 양쪽16번째 수부터 전환하는 안내와, 점진 강화·우세 보존·50수 전력 문구를 확인했다. 이는 화면·제어 흐름 검사이며 실제 엔진의 기력 증거가 아니다.

통합 정책 회귀930개에서는 이전49수 진행률 기대값이 남은4개가 실패했다. 기대값을 현재34/35로 정정한 관련49개 재검사는 모두 통과했다. 전체930개를 정정 뒤 다시 실행한 결과는 없으며, 두 실행을 하나의 완전 통과 실행으로 합쳐 표시하지 않는다.

고정 입력의 출처 테스트파일 SHA만 실행 전에 갱신했고,8개 위치·시드·조건·판정은 동일하다. 이전 입력과 변경 영수증을 함께 보존했다. 실제 엔진 쿼리는 갱신 전후 모두0회다.
