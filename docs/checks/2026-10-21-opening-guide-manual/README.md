# 실제 게임 화면 검증

검증일: 2026-10-21, 한국 시간. 기준 개발본 `431163fe3fd9ad916d40f3c02db3c83279556007`에서 시작해 아래 표시 오류를 수정했다.

## 결론

실제 Godot 게임 창에서 클릭·드래그·키보드·스크롤로 조작했다. 현재 오프닝, 다음 분기와 남은 수순, 기존 대국 조작이 검증 범위에서 정상 동작했다. 이름 없는 등록 중간 위치를 자료 밖으로 표시하는 오류 1건은 수정 후 같은 위치에서 다시 확인했다.

PGN 파일 내보내기는 운영체제 저장 창의 포커스를 자동 조작 도구가 유지하지 못해 저장 완료를 확인하지 못했다. 자동 저장과 기보 재생은 직접 확인했고, 자동 저장된 6개 PGN의 수순·마지막 배치를 JSON 기록과 별도로 대조했다. 내보내기 성공으로 간주하지 않는다.

## 검증 방식과 범위

- 실제 `Godot_v4.7.2-stable_win64.exe`와 `build/regicide.exe`를 실행했다. 스크린샷은 실행 중인 창에서 얻었으며, 이전 검증의 SubViewport 렌더나 장면 신호 호출로 대체하지 않았다.
- 일반 시작 위치에서 백·흑 대국 2개를 조작했다. 첫 대국의 AI 수 하나를 게임의 정식 핸디캡 기능으로 바꿨다. 흑 대국은 기권 종료까지 확인했다.
- 오류 위치 재현·승격·앙파상·체크메이트의 진단 위치 4개는 프로그램으로 **준비만** 했다. 그 뒤 검증한 이동·승격 선택은 실제 창에서 조작했다. 초기 배치와 준비 수순은 `fixture-*.json`에 기록한다.
- 백엔드 HTTP는 관찰 시 GET만 사용했다. `01-*.json` 등은 화면 조작 전후를 뒷받침하는 읽기 전용 상태 기록이다. UI 미리보기나 검증 착수를 API로 주입하지 않았다.
- 기보는 별도 `build/manual-opening-*/games`에 저장했다. 기존 개인 기보·원본 체크아웃·모델을 변경하지 않았다. 검증용 앱과 엔진은 종료했다.

## 발견한 오류와 수정

`1. Nf3 d5 2. e3`에서 안내 데이터는 `status=in_catalog`이고 이어지는 분기가 2개였다. 현재 위치에 별도 이름이 없다는 이유로 Godot가 “현재 위치는 등록 수순 밖입니다.”라고 잘못 표시했다.

이제 이름 없는 등록 위치에는 **“등록된 오프닝으로 이어지는 중간 위치입니다.”**를 표시하고, `beyond_catalog`일 때 자료 밖이라는 설명을 사용한다. 마지막 확인 이름과 다음 분기는 유지한다.

- 수정 전: `21-bug-unnamed-prefix-mislabeled.png`, `21-black-move-response.json`.
- 수정 후 동일 FEN: `23-fixed-prefix-status.png`, `23-fixed-prefix.json`.
- 수정 후 실제 미리보기: `24-fixed-prefix-eleven-ply-preview.png`와 `24-fixed-prefix-after-preview.json`.
- 수정 전후 오프닝 데이터는 동일하고, 미리보기 전후 대국 상태·저장 파일도 동일하다.
- 수정 후 자동 검사: `fix-automated/live/report.json`의 합성 42개+실제 HTTP 17개, 총 **59/59 통과**. 독립 검토는 `fix-automated/peer-review.txt`.

## 증빙과 재검증

- `manual-actions.json`: 실제 네이티브 입력 기록. 초기 창 탐색·최대화·첫 분기 선택 후부터 구조화한 기록이다.
- `*.png`: 실제 실행 중인 게임 창 캡처. 네이티브 파일 대화상자의 개인 폴더 목록은 증빙 이미지로 저장하지 않았다.
- `saved-*.pgn`, `saved-*.json`: 검증용 대국 6개의 최종 자동 저장본.
- `session-audit.json`: 미리보기/불법 수/기보 재생의 상태 불변성, 특수 규칙 결과와 PGN/JSON 일치 대조.
- `runtime/`: 실제 앱과 진단 호스트 실행 로그. Godot 스크립트 오류 없음.
- `provenance.json`, `artifact-integrity.json`: 검증한 소스·엔진과 결과 파일 해시.

보존한 기록을 다시 대조하려면 저장소의 테스트 Python 환경에서 다음을 실행한다.

```powershell
.\.venv-tests\Scripts\python.exe docs/checks/2026-10-21-opening-guide-manual/audit_records.py
```

다시 실행하면 기록 대조를 재수행한다. 실제 창 조작을 다시 수행하는 명령은 아니다. 엔진의 경기력·Elo 향상은 이번 검증 범위에 포함하지 않는다.
