# 교환 도중의 갬빗 운영 점수 측정 수정

`gambit_operations.continuation_evidence()`는 후보 수와 상대 응수의 두 반수만 적용한 뒤 계획의 기하적 진전을 측정했다. `6.h3 Bxf3 Qxf3`처럼 곧바로 되잡는 예상 수순도 `...Bxf3` 직후에 끊어, 나이트의 일시적인 부재와 상대 비숍의 일시적인 압박을 확정된 결과처럼 계산했다.

이번 변경은 **실제 자체 엔진 예상 수순의 교환·체크 구간만 최대8반수까지 정산**한다. 더 긴 예상 수순의 조용한 전개를 무조건 더하지 않는다. 수 선택이나 엔진 평가를 대신하는 검색도 하지 않는다.

- 첫 두 반수의 기존 기준을 유지한다.
- 아직 남은 교환칸을 실제 다음 수가 재포획하면 연장한다. 체크가 끼면 실제 체크 해소와 이어지는 재포획까지 추적한다. 체크한 기물을 다른 칸에서 잡아 해소하더라도 원래 교환칸을 잊지 않는다.
- 재포획이 합법적으로 가능한데 예상 수순이 끊겼거나, 체크 해소 수가 없거나, 필요한 수가 잘못됐거나,8반수 안에 마치지 못하면 `None`을 반환한다. 중간 점수는 제공하지 않는다.
- 다음 실제 수가 재포획도 체크도 아닌 합법 수라면, 재포획을 하지 않는 선택으로 보고 그 추가 수를 측정에 넣지 않는다. 합법 수 검사에 핀·앙파상·승격이 포함된다.
- 종결 국면에는 기존처럼 운영 점수를 주지 않는다. 측정한 수순과 반수 수, 확장 이유, 측정 정책을 반환 자료에 추가했다. 기존 반환 필드는 유지했다.

여기서 “정산”은 이 제한된 실제 예상 수순 안의 교환·체크 경계라는 뜻이다. 모든 전술이나 다음 수의 안전성이 검증됐다는 뜻이 아니다. 예상 수순의 질 자체는 여전히 자체 엔진의 검색에 달려 있다.

## 전개된 기물의 정상 교환

교환을 마친 뒤에도 살아 있는 전개 기물 수를 그대로 비교하면, 전개된 나이트를 상대 비숍과 같은 값으로 교환한 것에 전개 퇴보 감점이 남았다. 이제 재료 변화가0 이상인 경우에는 기존 피처에서 전개로 집계되지 않은 마이너 기물(나이트·비숍)이 얼마나 줄었는지를 전개 진전으로 쓴다. 정상 전개는+1, 후퇴는-1이고 이미 전개된 기물의 같은 값 교환은0이다.

재료 변화가 음수라면 기존의 전개 기물 수 변화만 쓴다. 미전개 기물을 그냥 잃어서 남은 미전개 기물 수가 줄었다고 전개 보너스를 얻을 수 없다. 원래 `developed_minors_change`는 관측 자료로 남기며, 별도 `development_progress`와 사용 근거를 기록한다. 재료 이득으로 보상된 교환을 포함하는 설명용 규칙이며, 실제 센티폰 평가나 기력 증거가 아니다.

## BDG 최소 재현

```text
rn1qkb1r/ppp1pppp/5n2/8/3P2b1/2N2N2/PPP3PP/R1BQKB1R w KQkq - 1 6
PV: h2h3 g4f3 d1f3
```

| 측정 방식 | 측정 반수 | 재료 변화 | 전개 기물 수 변화 | 전개 점수에 쓰는 변화 | 운영 점수 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 고정 두 반수 | 2 | -300cp | -1 | -1 | -11.00 |
| 교환만 정산, 기존 전개 척도 | 3 | 0cp | -1 | -1 | -4.25 |
| 교환 정산과 전개 부담 척도 | 3 | 0cp | -1 | 0 | +0.75 |

운영 점수의 단위는 기하적 계획 점수이며 cp가 아니다. 새+0.75는 활동성 변화에서 왔다. 미전개 마이너 기물 수는2→2이며, 나이트·비숍 교환 자체에는 전개 보너스가 없다. [실행한 최소 비교 자료](continuation-measurement.json)에 이전 커밋·소스 해시와 새 소스 해시를 기록했다. 개인 전체 기보와 외부 엔진 점수는 사용하지 않았다.

현재 기본 정책 v7은 이+0.75만으로 `h3`를 선택하지 않는다. 후보는 기존 추가 시간 안에서 기본 검색과 같은 완료 깊이의 검증을 거친다. 새 연구로만 제안되는 독립 후보는0cp 손실 상한을 적용하며, 같은 수를 독립적으로 유효한 기존 운영 기억도 제안하면 그 출처의 종전 검증·허용치를 보존한다. 기존 기억의 현재 이력·원본 행·엔진 식별자 검증을 생략하지 않는다. 운영 근거가 필요한 위치에서 이 함수는 교환·체크 정산의 완료 여부를 확인한다. 운영 점수가 개선되거나, 운영 점수가 같은 상태에서 자체 평가가 개선돼야 하며, 최소10cp의 자체 개선이 확인되면 기하적 운영 점수의 악화만으로 막지 않는다.

v5의 D+1 공동 검색은 실제 비교에서 악화가 관측돼 기본 적용에서 제외했다. v6의 중복 출처 덮어쓰기도 기존 운영 기억의 선택을 막는 회귀가 드러나 v7에서 수정했다. 두 실패와 현재 출처 보존 규칙은 [자체 연구 수순 문서](../../../data/gambits/NATIVE_CONTINUATIONS.md)에 구분해 기록했다. 이러한 채택 정책 변경은 위 운영 측정 수치를 바꾸지 않는다.

## 확인한 범위

운영 측정 변경 당시 로컬 `.venv-tests`에서 다음72개 검사가 통과했다. 아래 수는 해당 측정 변경의 검사 기록이며, 이후 v5·v6·v7 선택 정책의 전체 검사 수나 실전 비교 결과를 뜻하지 않는다.

- 새 `gambit_continuation_tests.py`20개: BDG 정산, 끊긴 수순, 조용한 뒷수순 제외, 연속 재포획, 체크 중간수와 해소·체크 기물 포획 후 원래 교환의 재개, 실제8반수 제한, 핀, 잘못된 입력, 종결, 앙파상, 승격, 정상 전개·후퇴·무상 기물 손실, 백/흑 대칭, 원본 보드·입력 보존.
- 기존 `gambit_operations_tests.py`15개, `gambit_initiative_tests.py`16개, `gambit_repertoire_play_tests.py`11개, `gambit_practice_memory_tests.py`10개.

기존 CI의 `gambit_*tests.py` 발견 검사에 새 파일이 포함된다. `git diff --check`도 통과했다. 이 변경은 운영 점수 측정에 한정된다. 오프닝 채택 정책, 코어 탐색 실험 활성화, 실전 실행 파일 변경, 전체 경기력 향상은 이 기록의 완료 주장에 포함하지 않는다.
