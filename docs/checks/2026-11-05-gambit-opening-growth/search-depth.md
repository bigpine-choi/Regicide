# Regicide와 Stockfish의 표시 깊이

2026-11-05. 이번 오프닝 연구의 Regicide 요청은 최대 깊이7·100만 노드였다. 완료 깊이5~7은 이 제한 아래의 결과이며 엔진의 최대 가능한 깊이가 아니다. 별도 Stockfish 사후 감사에 적용한 깊이18 상한과 직접 비교하면 조건이 다르다.

사용자 질문에 답하기 위해 같은 머신에서 각1초·단일 스레드·Hash16MiB·Move Overhead20ms·새 프로세스·깊이/노드 요청 상한 없음으로 두 위치를 순차 비교했다. Regicide는 실전5011 고전 활동성 평가, Stockfish는18·강도 제한 해제였다. 위치마다 실행 순서를 교대했다. CPU를 격리하지 않은 단일 관측이며 속도 보장이나 기력 평가가 아니다. [환경 기록](environment.json)은 Ryzen AI 7 350·Windows 11과 OS가 보고한 메모리를 보존하며, WMI의 최대 클록 속성을 실제 검색 순간 주파수로 해석하지 않는다.

| 국면 | Regicide 완료 깊이 | Stockfish18 완료 깊이 | Regicide 최대 도달 반수 | Stockfish 최대 도달 반수 |
| --- | ---: | ---: | ---: | ---: |
| 시작 위치 | 7 | 19 | 23 | 34 |
| BDG `d4 d5 e4 dxe4 Nc3 Nf6 f3 exf3 Nxf3 Bg4` 뒤 | 5 | 18 | 26 | 37 |

[실행 조건과 반환 기록](depth-comparison.json)은 완료된 정확 점수/PV 보고를 기준으로 한다. 아직 끝나지 않은 다음 반복의 보고는 제외했으므로 이를 총 처리 노드·초당 처리 속도의 정밀 비교로 사용하지 않는다. Regicide의 추가 체크·포획 계산과 선택적 감소 때문에 표시 깊이가 모든 경로의 길이를 뜻하지 않는다. 깊이1은 한쪽의 한 착수(반수)이며 양쪽이 각각 한 수 두는 단위가 아니다.

현재 Regicide는 알파베타, 수 정렬, 전이표, PVS와 제한적인 LMR을 사용한다. 늦은 조용한 마이너/룩/퀸 수에 한 단계 감소를 적용하고, 개선 가능성이 있으면 정상 깊이로 다시 읽는다. Stockfish18은 여러 종류의 생략·감소·검증을 함께 사용한다. [공식 검색 소스](https://github.com/official-stockfish/Stockfish/blob/sf_18/src/search.cpp)의 razoring, futility pruning, 검증을 동반한 null-move search, ProbCut 등이 근거다. 이번 수치만으로 실행 속도·정렬·평가·가지치기 각각의 기여율을 분리하지 않는다.

개선 방향은 표시 숫자를 올리는 것이 아니라 같은 시간에서 더 좋은 수를 고르는 것이다. 수 생성·평가·정지 탐색의 비용을 측정하고, 가지치기/감소를 하나씩 검증하면서 메이트·희생·반복·폰 엔드게임 회귀를 확인해야 한다. 오프닝 수순 연구는 후보 제공을 개선하지만 범용 탐색 효율의 차이를 모두 해결하지 않는다. 이번 작업에서는 C++ 탐색이나 실전 실행 파일을 바꾸지 않았다.
