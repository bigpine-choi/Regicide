# 모든 대국 모드의 공통 착수 시간 관리

기본·갬빗·스파링의 시간제 대국에 같은 시간 관리 알고리즘(`regicide-engine-pacing-v13`)을 적용했다. 앱 첫 기본 대국도 10+0으로 시작한다. 시간 제한 없는 연구 API는 기존 고정 탐색 설정을 유지한다.

명백한 수와 강제 응수는 빠르게, 복잡한 갈림길과 뜻밖의 응수는 길게 생각한다. 남은 시간이 5분 이하이면 연속적으로 시간 소비를 줄인다. 후보 검증 시간도 전체 착수 시간에 포함하며, 검증 후 동일한 대기를 다시 부과하지 않는다. 갬빗 후보 검증의 최소 기본 탐색과 추가 검증 시간을 함께 예약해, 공통 자동 시간이 갬빗 기능을 무력화하지 않게 했다.

## 수행한 검증

- 정책 회귀 113개 통과: `policy-regression-result-v2.json` 및 두 최종 로그.
- 모드 회귀 82개, 시간 관리 호스트 회귀 58개 통과. 시작 시계 및 공통 API 추가 검증 6개 통과.
- 웹 5개 테스트 묶음 통과. 격리한 Godot 프로젝트의 255개 검사 통과.
- 실제 Regicide 실행 파일과 HTTP 서버로 11차례 착수 검증 전부 통과. `native-v1/native-result.json`에 조건·결과·소스와 실행 파일 해시를 기록했다.

실제 착수 11회는 세 모드 각각 강제 응수·명백한 퀸 획득·복잡한 선택을 한 번씩 실행한 9회와, 표준 시작 갬빗 수순 2회다. 빠른 6회는 약 0.057~0.088초를 사용했다. 복잡한 3회는 드문 장고 분기를 의도적으로 선택한 시드로 약 29.91초씩 사용했다. 이는 평균 대기 시간 표본이 아니다. 표준 갬빗에서는 `1.d4 e5 2.dxe5 d6`을 실제 선택했으며 약 0.748초·0.694초를 사용했다. 기본 탐색 500ms 및 추가 검증 예약이 살아 있는 것도 확인했다.

5분·3분·1분·10초 경계의 시간 예산 검사는 주입 시계로 수행했다. 위 11회는 실제 엔진 검증이며 직접 GUI에서 사람이 대국한 기록이나 승률·Elo 측정은 아니다. 실행 전후 소스와 실행 파일 해시는 일치했다. 검증 당시 소스는 `source-snapshot.zip`과 manifest에 보존했으며, 이후 공통 UI·무승부·형세 게이지 수정과 구분한다.
