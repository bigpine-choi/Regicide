# 분석 모드 형세 표시 검증 · 2026-11-01

추천 수를 계산하는 같은 Regicide 탐색에서 완료된 깊이별 점수를 읽어 형세 막대와 점수를 갱신한다. 추가 평가 엔진을 병렬로 띄우지 않는다. 설정한 분석 시간 동안 갱신하고, 착수·무르기 후 새 위치를 다시 계산한다.

점수는 항상 백 기준이다. 양수는 백, 음수는 흑, 0은 균형이며 100cp를 화면에서 1.00으로 표시한다. 막대는 `0.5 + 0.5 * cp / (abs(cp) + 400)`의 시각적 척도이며 승률이 아니다. 메이트 거리·승자·평가 상하한과 확정된 체크메이트·무승부 결과도 구분한다.

위치 번호·수정 번호·FEN을 함께 확인해 이전 위치의 점수가 새 위치에 나타나지 않게 한다. 새 위치·편집·연결 오류·중단은 이전 점수를 지운다. 흑 관점의 UCI 점수는 백 관점으로 변환하며 상한·하한의 방향도 함께 바꾼다. 독립적인 점수·깊이 쌍이 있는 패킷만 반영하고, 나중에 온 깊이만 있는 패킷에 이전 점수를 붙이지 않는다.

검증 기록:

- `backend-evaluation.txt`: 16개 검사 통과. 백·흑 부호, 상하한 역전, 메이트0 승자, 완료 전 점수, 중단·시간 초과·이전 응답 거절과 실제 엔진 검사. 실제 엔진의 반복 중단 후 완료 응답을 회수하고 경고 없이 종료되는 것도 포함한다.
- `final-web-*.txt`: 브라우저 형세 표시, 기존 드래그·추천·오프닝·시간 설정 회귀 검사.
- `godot/`: Godot의 합성 입력·실제 엔진 연동·실제 Viewport 입력 전달과 기존 추천/평가 검사. 대화 도구를 통한 직접 Windows 창 조작과 구분한다.
- `http-streaming.json`: 실제 HTTP 연결로 백 퀸 우세·흑 퀸 우세·체크메이트를 검사했다. 첫 두 위치에서 추천 수가 완료되기 전에 점수가 도착했고, 점수의 부호·현재 위치 식별자·합법 추천·종료 시 점수 초기화가 맞았다. 기존 대국 상태와 저장 파일 지문도 같았다.

기존 드래그 검수에서 자동 조작의 이동 이벤트에 상대 이동량이 0으로 들어오면 Godot의 기본 드래그 문턱을 넘지 못하는 문제를 재현했다. 눌렀던 위치와 현재 포인터 위치의 차이로도 드래그를 시작하도록 보완했다. 실제 Viewport에 누르기→이동→놓기 이벤트를 전달하는 검사로 일반·이동량0·취소·판 밖 놓기를 확인했다. 사용자의 실제 대국 창은 이 자동 검사에 사용하지 않았다.

개인 기보 대신 별도 검수용 보관함을 사용했다. C++ 탐색·평가 함수와 실행 파일은 바꾸지 않았으며, 실제 대국 성능이나 Elo 비교를 수행한 기록이 아니다.

후속 캐슬링 UI를 포함한 최종 검사와 실제 브라우저 화면은 [캐슬링 통합 검증](../2026-11-01-analysis-castling/README.md)에 보관했다. 형세·드래그 기능을 포함한 최종 소스 지문도 해당 폴더에 있다.
