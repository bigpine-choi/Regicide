# 스파링 형세 판단 정밀화

2026-11-03. 자체 Regicide 엔진의 분석을 더 깊게 이어가고, 양보 후보의 상대 반격을 별도로 확인한다. 게이지의 흑백 점수는 실제 탐색값이며 접전을 연출하기 위해 ±1점으로 잘라 표시하지 않는다. C++ 실행 파일·평가 함수·신경망은 교체하지 않았다.

## 사람이 생각하는 동안의 정밀 분석

스파링에서는 첫 완료 평가를 즉시 표시한다. 같은 국면의 탐색을 기본3초 진행하고, 최신 깊이8 이상에서 최근3개 연속 깊이의 첫 수가 같고 점수 폭이35cp 이내면 종료한다. 그렇지 않으면 최대10초까지 같은 탐색을 이어간다. 1cp는 표시상 폰0.01개에 해당하는 엔진 평가 단위다. 메이트는 같은 승자·거리의 합법 메이트 수순이 반복되어야 한다. 이 기준은 조정 가능한 수렴 휴리스틱이며 정답 확률이 아니다.

범위 점수, 잘못된 차례 관점, 다른 MultiPV 순위, 누락·불법 수순, 깊이 역행, 메이트 주장과 수순의 모순은 표시하지 않는다. 점수·깊이·수순은 하나의 완료 패킷에서 읽는다. 더 깊은 무효 결과가 오면 이전 유효 점수는 보존하되 안정 표시를 해제한다. 마지막 평가를 평균 내거나 이전 국면 평가와 섞지 않는다. 합법 메이트 수순을 확인하는 것은 그 한 수순의 정합성 검사이며 모든 방어의 패배 증명은 아니다.

3초 이후 분석이 계속되면 Godot·웹에 **정밀 분석 중**을 표시한다. 착수·새 대국·종료 때 취소하며 늦은 응답은 새 국면에 들어가지 않는다. Regicide 차례는 기존 제한 시간의 기준 탐색을 이용하고, 추가 분석기가 경쟁하도록 만들지 않는다. 따라서 시간 압박에서 같은 정밀도를 보장하지 않는다. 종료 직전의 평가가 남는 기존 경로도 수정하고 재검사했다.

## 양보 후보의 착수 후 반격 검증

기존 같은 깊이의 후보 비교 뒤, 최종 양보 후보를 실제로 둔 복사본에서 상대의 모든 합법 응수를 자체 엔진으로 다시 탐색한다. 기존 추가 예산 중 약30%를 확보하며 최종 검증은100~600ms 범위다. 전체 추가 예산을 늘리지 않는다. 깊이는 `max(4, 기준 깊이−1)`로 시작한다. 이는 착수 한 번 뒤의 명목상 깊이 기준이며 선택적 탐색의 동일성을 보장하지 않는다.

정확한 완료 점수·합법 수순·반환 수 일치를 요구한다. 부족한 깊이, 범위·메이트 점수, 시간 부족, 양보 하한 미달, 기존 후보 평가와80cp 초과 불일치가 있으면 원래 기준수를 유지한다. 성공한 착수 후 점수도 접전 달성 여부 계산에 포함하며, 별도 국면 점수를 현재 게이지에 게시하지 않는다. 검증 자체도 유한한 탐색이므로 장기 함정 부재나 반드시 승리함을 보장하지 않는다.

30수까지 조절,31~69수 매 수2.5%포인트 증가,70수부터 완전 해제 정책은 그대로다. 새로운 평가·후검증 식별자는 JSON과 복원한 PGN에 기록하고, 과거 기보에 새 검증을 수행한 것처럼 붙이지 않는다.

## 실행한 검증

- [최종 단위·호스트 검사129개](unit/validation.json): 엄격한 패킷, 안정 종료·취소, 기준 시점 이후 데이터 차단, 양보 후검증, 흑백 관점, 저장·복원, 기존 대국 평가와 모드 분리 모두 통과.
- [UI 검사](ui-validation.json): 웹23개, Godot58개 통과. 자동·헤드리스 검사이며 사람의 수동 대국 검증은 아니다.
- [실제 HTTP 연결](http-live/result.json): 백·흑 사용자 대국에서 자체 엔진 착수, 첫 점수 스트리밍, 최대 약10초 보강 중 응답, 이전 국면 격리, 보드 불변성·PGN 복원을 확인했다. 엔진 차례 평가 조회의 관측 최대 응답은 약27ms였다. 특정 환경의 짧은 기능 검사로 지연 보장은 아니다.
- [실제 정책 사례](native-policy.json) 두 개는 기준수를 유지했다. [초반 메이트 대신 유한 양보 후보 사례](native-fools-mate.json)는 `d7d6` 뒤 상대 전체 응수를 깊이5로 약147ms 재탐색했고, 기존 후보와 같은 흑 기준+27cp를 확인했다. 총 추가 시간 약713ms였다. 과거 실력 관측은 통제 입력이며 사용자 기력·승률 증거가 아니다.

## 22개 고정 국면의 추가 탐색 효과

기존 개발 국면22개 전체를 유지했다. 동일 엔진·Hash16·검색1스레드·기물 활동성 평가에서 국면마다12초 연속 탐색을 한 번 실행하고,3초 시점·적응형 종료 시점·마지막 시점의 완료 결과를 비교했다. [전체 기록과 조건](convergence/manifest.json), [집계](convergence/summary.json), [원본 패킷](convergence/records.jsonl)을 보존했다.

| 동일 엔진12초 결과와의 차이 | 기존3초 시점 | 적응형 시점 |
|---|---:|---:|
| 평균 절대 점수 차이 | 9.23cp | 2.14cp |
| 중앙값 | 5.5cp | 0cp |
| 최대 차이 | 38cp | 19cp |
| 첫 수 일치 | 19/22 | 20/22 |

8국면이 더 가까워졌고14국면은 같았다. 적응형 평균 종료는6.72초였으며12국면은 안정 조건에서,10국면은10초 상한에서 종료했다. ±1점 범위의 흑백 분류 일치는 두 방식 모두22/22였다. 정밀도가 크게 나쁜 국면을 해결했다고 과장하지 않는다.

**이 수치는 추가 자원을 썼을 때 같은 탐색의 나중 결과에 가까워진 정도다.** 별도3초 실행과의 동등 자원 비교도, 외부 정답·Elo 검사도 아니다. 같은 경로를 공유하므로 수렴에 유리한 비교다. 이론적 종료 시점은 실제 보조 분석기의25ms 감시 간격과 약간 다르며 실제 연결은 별도로 검사했다.12초 자체 평가도 틀릴 수 있고, 기존 폰 종반의 장기 판단 약점은 해결됐다고 주장하지 않는다.

별도로 직접 작성된 메이트·회피 국면의 규칙 열거 정답8개를 실제 엔진이 모두 통과했다. 이는 제한된 전술 정확성 검사다. 전체 시스템 CPU286표본은 평균16.76%, 최대44.32%였으며 자체 엔진을 포함한다. 외부 부하를 완전히 분리하거나 독점 환경을 확인한 측정은 아니다.

실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`다. 기존 사용자 대국·레이팅 라벨과 실행 중 프로세스는 변경하지 않았다. 재실행 후 새 스파링 대국부터 적용된다. 원격 CI 완료는 별도 확인 전 주장하지 않는다.
