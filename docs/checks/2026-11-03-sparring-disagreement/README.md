# 스파링 평가 불일치 재현과 최종 검사

2026-11-03 시작, 한국 시간 11월 4일까지 진행한 검증이다. 기존 저장 대국의 전체 수순을 복원하고 실제 게임이 사용하는 Regicide 실행 파일과 `UsePieceActivity=true` 설정을 사용했다. 기존 국면을 FEN만으로 만들지 않아 수순 단계와 반복 맥락을 유지했다.

## 발견한 원인

기존 심판은 자체 기준수 하나만 남거나 50수 이후이면 후보 비교를 생략했다. 후보를 비교하더라도 잘못된 기준수 자체의 평가를 안전 기준으로 사용했고, 기준수가 선택되면 착수 후 검사가 없었다. 직접 기물 노출을 찾는 전술 검사만으로는 조용한 수의 형세 악화를 포착하지 못했다.

시간만 늘려도 해결되지 않는 사례가 있었다. 실제 설정의 6초 탐색에서 50.Ne5는 깊이 8, 자체 +123cp로 남았지만 Stockfish의 착수 후 평가는 −331cp였다. 43...Bxc3도 깊이 7, 자체 +140cp로 남았지만 Stockfish는 −146cp였다. 이 숫자는 [재현 탐색](probes/README.md)의 200000노드 외부 평가다. 아래 수정 후 독립 3초 검증과 구분한다. 21...Nxe4는 원래 완료 깊이 5를 고정하면 재현되지만, 새 시간제 탐색은 더 깊이 읽어 d5를 찾기도 했다.

초기 진단의 UCI 기본 옵션은 게임과 달랐음을 발견해 보존·정정했다. `probes/` 바로 아래 초기 JSON은 대조군이며, 제품 설정의 증거는 `probes/activity-enabled/`만 사용한다. [옵션 정정](probes/CORRECTION.md).

## 수정한 판단 흐름

최종 선택을 전술 검사 다음에 다시 확인한다. Stockfish가 제한 없이 읽은 현재 국면과 실제 선택을 둔 뒤의 국면을 비교한다. 두 분석은 완료 깊이 10 이상의 정확한 점수가 필요하다. 기본 수만 남은 경우와 50수 이후도 검사한다.

- 20수까지: 버틸 수 있는 국면을 자기 쪽 −100cp 미만으로 만드는 선택을 거른다. 이미 불리하면 최선의 저항 대비 추가 손실을 제한한다. 안전한 우세 반환은 허용한다.
- 21~49수: 독립적인 현재 국면 점수를 기준으로 기존 양보 상한을 점차 줄인다. 잘못된 기본 수를 안전 하한으로 삼지 않는다.
- 50수 이후: 의도적 양보는 종료하며 기본 수에도 손실 검사를 적용한다. 최종 검사의 손실 상한 40cp와 탐색 변동 허용치 20cp는 기력·승패 보장이 아니다.
- 문제가 있으면 그 수를 제외하고 Regicide가 대안을 생성한다. 전체 후보 탐색 최대 네 번과 아직 탐색하지 않은 나이트·비숍의 기물별 탐색 최대 두 번을 사용한다. 각 대안도 다시 검사한다. Stockfish의 자유 탐색 PV를 후보로 주입하지 않는다.
- 반복 분석의 작은 점수 변화로 최초 안전 하한이 느슨해지지 않게 한다. 큰 불일치·미완료·오래된 결과·다른 대국/이력·다른 실행 파일은 검증 완료로 취급하지 않는다.

각 국면 분석은 최대 650ms, 첫 기동 여유는 최대 1500ms다. 같은 착수의 재검사에서는 하나의 Stockfish 프로세스를 재사용하고 종료 시 닫는다. 기동·검사·자체 대안 탐색의 총 예산은 8초이며 남은 시간이 3분 미만이면 축소한다. 10초 이하에서는 추가 검사를 생략한다. 대안 탐색 이후 연출용 대기는 없다.

`quality_guard`는 외부 검증 기록이고 자체 점수는 그대로 유지한다. 하한을 통과하지 못해도 원래 150cp 이상의 손실을 100cp 이상 줄이는 검증된 자체 후보는 `mitigated`로 보존할 수 있다. 이 근거도 없으면 기존 합법 수를 유지하며 `unverified` 또는 `skipped`로 기록한다. 손실 축소와 검증 실패를 접전 성공이나 안전 하한 통과로 집계하지 않는다.

앞선 자체 전술 검사에서 시간 초과 등으로 Regicide 프로세스를 폐기했다면 최종 검사는 실행하지 않는다. 이 경우 앞선 실패 기록은 남고 `quality_guard`는 없을 수 있으므로, 후속 대국 요약에서 누락을 검증 성공으로 세지 않는다.

## 실제 엔진 재현

[guard-replay.json](guard-replay.json)은 6개 고정 오류 국면의 최종 실행 결과다. 문제 수는 저장된 실제 수로 고정하고, 대안 생성은 수정된 검사 코드와 실제 Regicide로 수행한다. 원래 수를 새 시간제 탐색이 언제나 다시 고른다는 주장은 하지 않는다. 각 위치의 독립 검증은 별도 전력 Stockfish 프로세스로 현재·원래 착수 후·교체 착수 후를 각각 3초 분석한다. 원시 점수, 완료 깊이, PV, 전체 수순, 옵션, 소스와 실행 파일 해시를 저장한다.

**초기 6국면 결과: 6/6 교체·독립 검증 통과.** 모두 실제 Regicide 재탐색에서 반환한 수이고, 실행 전후 소스·바이너리 해시가 일치한다. 다음은 원래 착수할 쪽 기준 Stockfish cp이며, 100cp를 관례상 1점으로 표시한다. 이 버전의 결과는 `guard-replay-v1.json`에도 보존했다.

| 원래 수 | 자체 생성 대안 | 원래 수를 둔 뒤 | 대안을 둔 뒤 |
| --- | --- | ---: | ---: |
| 50.Ne5 | b4 | −394 | 0 |
| 43...Bxc3 | ...Rh1 | −206 | +49 |
| 15...axb4 | ...e6 | −172 | −24 |
| 21...Nxe4 | ...d5 | −154 | +71 |
| 27.Qxb7 | e6 | 0 | +302 |
| 9.Nxa7 | Qc4 | −451 | −80 |

27수의 사례는 갑작스러운 열세 대신 이미 얻은 우세를 과도하게 돌려주는 문제였다. 50수의 사례는 양보 종료 이후에도 기본 수를 검사해야 함을 보여 준다. 최종 검사 자체는 2.59~7.83초 걸렸으며 원래 기본 탐색 시간과 별개다. 정상 수를 확인할 때도 첫 엔진 기동 비용이 있고, 이 PC의 첫 검사 관측치는 약 1.5초였다. 같은 착수의 후속 검사는 기동을 재사용한다. 소규모 사례의 시간 범위이며 항상 같은 지연을 보장하지 않는다.

첫 실행은 **0/6 교체**였다. 새 Stockfish의 기동에 약 0.85초가 걸려 650ms 총 예산에서는 분석 전에 종료됐다. [첫 실패 원본](guard-replay-startup-timeout.json)을 보존했으며, 위 기동 예산 분리와 같은 착수 내 프로세스 재사용을 추가했다. 실패를 제외하고 통과율을 계산하거나 검사 기준을 낮추지 않았다.

두 번째 실행은 **4/6 교체**였다. [두 번째 원본](guard-replay-cache-incomplete.json)과 [Stockfish 원시 패킷](probes/activity-enabled/referee-incomplete.json)을 보존했다. 27.Qxb7의 자식 국면에서는 깊이 14~21의 정확한 완료 점수가 있었지만, 미완료 깊이 22에서 최종 반환 수가 바뀌자 모든 완료 평가를 버리고 있었다. 외부 형세 판정은 마지막 완료 반복의 점수·깊이·PV를 하나의 증거로 사용하도록 구분했다. 미완료 반복의 다른 수를 그 점수의 근거로 표시하지 않는다. Stockfish의 반환 수를 실제로 두는 기능도 아니다. 실제로 둘 Regicide 대안은 계속 해당 수와 일치하는 완료 패킷을 요구한다.

부족한 완료 깊이 등으로 한 번 검증이 안 된 경우에도 정상 상태의 검사 프로세스는 다음 후보에 재사용한다. 취소·시간 초과·오류·국면 변경·정체성 불일치 프로세스는 재사용하지 않는다. 깊이 10 이상과 정확한 완료 점수 조건은 유지한다.

## 추가 검증과 범위

[선후공 실제 대국 검증](../../matches/2026-11-03-sparring-quality/protocol.md)은 수정된 `HumanGame` 경로를 사용한다. 실제 탐색 시간을 사용하며 연출용 대기만 게임 시계에 동일 시간을 부과하고 수면을 생략한다. 화면을 직접 조작한 수동 대국 테스트는 아니다.

**1차 실제 대국에서는 새 실패를 발견했다.** 백 63ply·흑 122ply, 총 185ply 모두 정상 종료했고 자체 대체 5건의 출처를 확인했지만, 독립 평가에서 백 17.f4는 260cp, 21.axb4는 462cp를 잃었다. 흑 17...Qa5의 297cp 변화는 +273에서 −24로 접전에 들어간 20수 이전 양보로 구분한다. 첫 20수 스파링 직후 접전은 백 6/20, 흑 20/20으로 백은 기준에 미달했다. [1차 결과와 실패 원본](../../matches/2026-11-03-sparring-quality/README.md).

21수에서는 실제 자체 대안 Nxf6가 원래 수보다 약 5점 나았는데도 허용 하한을 2cp 못 맞춰 버리고, 이미 나쁘다고 확인한 원래 수를 다시 뒀다. 이 경우는 안전 기준을 충족했다는 표시 대신, 충분히 검증된 큰 손실 축소를 `mitigated`로 남기며 자체 대안을 사용할 수 있도록 보완했다. 기준 통과와 손실 축소는 분리한다. 얕은 자체 후보도 곧바로 버리지 않고 외부 검사에서 유망하면 같은 수를 자체 엔진으로 다시 읽어 완료 깊이 4 이상을 확인한다.

17수에서는 기존 전체 후보 순위에서 안전한 Nd5를 찾지 못했다. 모든 나이트 수를 제외 없이 따로 읽는 일반적인 기물별 자체 탐색에서는 Nc3의 여러 합법 수 중 Nd5를 완료 깊이 5로 찾았다. 이 탐색은 Stockfish가 제안한 칸을 검색 대상으로 지정하지 않는다. 아직 검토하지 않은 나이트·비숍의 원래 칸을 자기 진영 기준의 고정 순서로 정하고 그 기물의 남은 합법 수를 비교한다. 기물별 후보도 동일한 외부 검사와 전체 시간 상한을 지킨다.

[2차 자동 검사 기록](automated-tests-v2.json): 중복 제외 **355개 통과**, 실패·오류·생략 0개, 검사 중 소스 불변. [실행 당시 Python 소스](verified-python-sources-v2.zip)와 [파일별 해시](verified-python-sources-v2.json)를 보존했고 압축 파일 안의 453개 파일을 해시로 다시 확인했다. 이 스냅샷은 커밋이나 원격 반영을 뜻하지 않으며, 외부 실행 파일은 포함하지 않는다.

[2차 선후공 대국 조건](../../matches/2026-11-04-sparring-quality-v2/protocol.md)은 1차와 동일하되 확률적 상대 때문에 동일한 대국 수순 비교로 취급하지 않는다.

**최종 실제 대국 3판, 총 238ply**를 끝까지 실행했다. 20수 전에 끝난 첫 백 대국(33ply) 외에 흑(86ply)과 추가 백(119ply)을 포함했고, 검증된 대체 수 8건 모두 실제 자체 탐색에서 나온 수임을 확인했다. 종료 후 테스트 프로세스도 모두 정리했다. [최종 대국 결과와 원본](../../matches/2026-11-04-sparring-quality-v2/README.md).

20수까지 스파링 착수 직후 ±100cp인 위치는 첫 백 15/17, 흑 17/20, 추가 백 12/20이었다. 따라서 **20수 동안 계속 접전을 유지하는 목표는 아직 미충족**이다. 추가 백의 13수에서는 독립 재검토상 112cp 손실이 남았고, 53수에서는 강제 메이트를 놓쳤으나 +1023cp의 큰 우세를 유지했다. 미확인 판정 3건을 검증 성공으로 세지 않았다.

첫 백 14.Qh3의 기물 감소 신호는 후속 수순까지 확인했다. 비숍을 되잡을 수 있는 수순이 있었고 실제 상대의 다른 응수 뒤에는 기물 회수 대신 메이트를 택했다. 이 사례는 보상 없는 헌납으로 판단하지 않았으며 [기물 손실 재검토](../../matches/2026-11-04-sparring-quality-v2/material-review.md)에 원본 신호와 분석을 함께 보존했다. 이 작은 표본의 검사 결과를 모든 기물 헌납이나 역전의 완전 차단으로 확대하지 않는다.

자동 검사는 단계별 판정, 흑백 점수 방향, 메이트와 무승부, 잘못된/미완료 증거, 자체 대안 출처, 기록 보존, 일반 모드 격리, 시계 부족·시간 만료·종료·국면 변경·검사 프로세스 정리를 확인한다. 기물 헌납의 징후와 보상 없는 손실은 구분하며, 모든 희생을 차단하지 않는다.

[1차 자동 검사 기록](automated-tests.json): 중복 테스트 ID를 제외한 **329개 통과**, 실패·오류·생략 0개, 59.047초. 당시 코드에서 시간 배분, 단계 전환, 전술 안전, 기존 심판, 새 형세 판정과 호스트 연결을 함께 검사했다. 실제 국면 재현과 자동 검사를 별개로 집계한다.

이 변경은 **Stockfish 보조 스파링의 형세 검증**이다. C++ 자체 평가 함수를 개선했거나 독립 Regicide가 Stockfish 수준에 도달했다는 증거가 아니다. 더 긴 독립 검증도 같은 Stockfish 평가 계열을 사용하므로 모든 전술을 증명하지 못한다. 알려진 오류 국면의 회귀 방지와 작은 대국 표본의 기능 검증을 전체 경기력·Elo·항상 접전 유지로 확대하지 않는다.
