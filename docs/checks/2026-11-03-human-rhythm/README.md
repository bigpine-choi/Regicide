# 사람처럼 이어지는 착수 리듬 v3

2026-11-03. 시간제 대국의 착수 간격을 국면과 실제 선택 수, 직전 예상 수순, 남은 시간에 맞춰 조절한다. 스파링의 자동 생각시간에도 적용된다. 직접 설계한 휴리스틱이며 인간 대국 시간 자료로 학습·보정한 모델은 아니다. C++ 수 선택 엔진과 실행 파일은 바꾸지 않았다.

## 달라진 동작

- **대국의 기본 템포:** 매 대국의 재현 가능한 시드로 기본 속도를 정한다. 인접 착수는 일부 리듬 요소를 공유하고, 각 국면에는 작은 변동을 더한다. 매번 독립적으로 시간을 뽑던 방식에서 연속성을 추가했다.
- **미리 생각한 수순:** 직전 자체 탐색에서 예상한 상대 응수와 다음 자기 수가 모두 실제 진행과 일치하고, 현재 후보도 안정되었을 때 빨리 둔다. 단순히 상대가 예상 수를 두었다는 이유만으로 다른 후보까지 즉시 두지 않는다.
- **안전한 되잡기:** 같은 칸에서의 되잡기이고, 탐색 후보가 안정되었으며 체크·핀·공격받는 기물 등 경고가 없을 때 시간을 줄인다. 안전성의 일반적인 증명은 아니다.
- **뜻밖의 응수·후보 재고:** 실제 이전 예상과 다른 응수, 완료 깊이 사이의 후보 변경·큰 평가 변동은 더 고민하는 근거로 쓴다. 복잡한 일부 국면에는 간헐적인 장고를 넣고, 실제 장고를 마친 뒤에는 연속 장고를 억제한다.
- **선택한 수에 맞는 빠른 결정:** 알려진 오프닝의 실제 후속 수, 강제수, 즉시 메이트, 명백한 퀸 포획은 빠르다. 익숙한 배치에서 다른 수를 선택하거나 메이트·퀸 포획을 포기하면 일반 구조에 따른 시간을 복원한다. 제한된 대표 오프닝 목록이므로 모든 알려진 오프닝을 인식하지는 않는다.

실제 선택 수와 일치하는 합법 PV(엔진이 예상한 후속 수순), 올바른 차례 관점의 정확한 완료 점수, 깊이4 이상을 요구한다. 범위 점수·다른 후보·다른 국면의 후검증 결과를 예상 수순으로 빌리지 않는다. 이후의 무효·불안정 패킷은 빠른 판단의 근거가 되지 않는다. 자료가 부족하면 최초 시간 계획을 유지하며, 실제 선택과 맞지 않는 빠른 판단 표시는 해제한다.

지난 리듬은 같은 대국 시드, 시작 배치, 전체 착수 이력, 이전 자기 수, 현재 분기가 맞아야 사용한다. 무르기·핸디캡·새 대국에서 이력이 섞이지 않는다. 즉시 착수로 취소한 대기는 완료된 장고로 세지 않는다. 이 예상 수순 일치는 상대 행동의 확률 모델이 아니다.

## 시간과 탐색의 경계

처음 계획한 탐색 예산은 고정하고, 이미 수행한 탐색 결과로 **차례 전체의 목표시간**만 한 번 조정한다. 이 조정 때문에 엔진을 다시 검색하지 않는다. 검색·후검증·요청 전 경과시간을 모두 포함하므로 이미 쓴 시간을 기다림으로 중복해서 더하지 않는다. 원래 탐색 한도보다 최종 목표가 짧으면 계산이 끝난 뒤 바로 둔다.

잔여3분 미만부터 기본 시간과 추가 장고를 함께 줄인다. 완료 시점의 최신 시계로 다시 제한하며 10초 이하에서는 추가 대기를 생략한다. 차례 목표 상한45초와 시간 여유분도 유지한다. 미래의 증가시간을 현재 차례에 미리 쓰지 않는다. 이 장치는 시간패 방지 보장이 아니다.

사람에게 표시하는 권장시간의 기존 절반 배율은 유지한다. 안정 평가의 `bound="exact"` 표기를 기존 코드가 거부하던 문제를 고쳐, 이미 있던 균형 국면의 작은8% 시간 조정이 실제 평가에도 적용되게 했다. 스파링30수까지 조절,31~69수 단계 상승,70수부터 완전 해제 및 사용자0초 계속 진행 정책은 유지된다.

JSON에는 v3 시간 정책·실제 선택·예상 수순·조정 이유·대기 완료 기록을 남긴다. PGN 복원에도 실제 저장된 v1/v2/v3 식별자를 보존하고, 과거 기보에 새 정책을 사용한 것처럼 붙이지 않는다.

## 수행한 검증

- [단위·호스트 검사182개](unit/validation.json) 통과. 새 시간정책24개, 호스트 연결14개, 진단 도구5개를 포함한다. 예상/뜻밖 응수, 잘못된 수순, 새 대국·되돌리기, 실제 선택과 기준 후보 분리, 시간 부족, 취소, 기존 수동 생각시간을 검사했다. 제어된 패킷과 가상 시계 검사이며 인간 행동의 정확도 측정은 아니다.
- [독립 재검토](independent-audit.json)에서 취소된200ms 대기의 장고 오인과 목록 밖 실제 수의 오프닝 할인 문제를 재현한 뒤 수정 여부를 확인했다.
- [실제 HTTP 대국 연결](http/native-result.json)에서10+0·10+5·15+10, 양쪽 사용자 색상, 대기 중 상태 조회·시계 차감·증가시간·기보 복원을 확인했다. 네 차례 목표8.411~26.407초에 대해 실제 시계 차감은 목표보다 약1.2~11.3ms 많았다. 한 환경의 짧은 기능 검사이며 모든 착수의 지연 보장이 아니다.
- 같은 연결 검사의 스파링 잔여 약180/120/60초 사례는 실제 응답2.271/0.917/0.345초, 할당 탐색701/265/100ms였다. 잔여시간 설정에 가상 경과시간을 주입했으며 이후 착수는 실제 엔진과 실제 대기다. 서로 다른 새 대국 시드이므로 순수 시간압박 효과의 정량 비교가 아니다. 동일 시드의 단조 감소는 별도 단위·격자 검사로 확인했다.
- 잔여 약1초인 엔진이 합법 수를 두는 경계 사례, 사용자0초 이후 계속 착수, 엔진0초 패배도 확인했다.10분 완주 대국이나 시간패율 측정은 아니다.

## 실제 탐색 자료를 이용한 시간 계산 진단

[조건](diagnostic/manifest.json), [국면](diagnostic/positions.json), [전체 기록](diagnostic/records.jsonl), [집계](diagnostic/summary.json)를 보존했다. 작성된5국면을 자체 실행 파일로 각1초 분석한 뒤, 같은 자료를32개 시드와5개 잔여시간에 재사용한 **800개 시간 계산**이다. 이800개에서 실제 대기를 수행한 것은 아니다. 원시 PV94개와 반환 수5개의 합법성을 별도로 재생 확인했다. 깊이·실행 비용은 컴퓨터 부하에 따라 달라질 수 있다.

이 진단에는 과거 착수 기록이 없으므로 장고·예상 수순·뜻밖 응수의 실전 빈도를 입증하지 않는다. 그 분기들은 제어된 단위·호스트 검사에서 검증했다. 함께 저장된 v2 비교는 커밋 `49ff4ccec87051e0df3417a4ea6980902855a97b`의 시간 코드와 현재 권장시간 함수를 사용한다. 사람과 더 비슷해졌다는 통계, 승률, Elo의 증거가 아니다.

실행 파일 SHA256: `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`. [소스 일치 확인](source-verification.json)과 [근거 파일 해시](artifact-manifest.json)를 함께 보존한다. 사용자 대국·점수 라벨과 실행 중 게임은 변경하지 않았다. 바탕화면 Regicide를 재실행한 새 대국에서 적용된다. GUI를 직접 플레이하며 자연스러움을 평가한 검사는 아직 수행하지 않았다. 원격 CI 완료를 의미하지도 않는다.
