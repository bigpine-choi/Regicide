# 블랙마–디머 실전 패배 정밀 분석

2026-11-05. **이 판의 주된 문제는 오프닝 자료의 부재보다 자체 탐색의 후속 운영·왕 안전 과대평가였다.** 오프닝 지식은 존재했지만 실전의6수에서 책 후보를 거절했고, 이후에는 자체 기본수가 그대로 선택됐다. 35.Qf1에서 큰 추가 손실,37.Rc8에서 피메이트를 허용하는 문제가 확인됐다. 책 수를 강제로 두게 하거나 갬빗을 제거하는 결론으로 일반화하지 않는다.

## 대상과 개인정보

최신 완주 블랙마–디머는 이전Rc8 신고와 같은 판이다. 기록상 Regicide가 백, 사용자가 흑이며 결과는0-1이다. 바로 이전의 사용자 백 패배 판은 다른 개시이므로 분석 대상에서 제외했다.

원본 JSON SHA256은 `9763ce102a6e6659d241da7cf1718b74a4f064ba29db41deed138479bb5472b2`다. 전체 기보·게임 ID·파일 경로·전체 착수 이력과 원시 UCI는 비공개 로컬 분석 폴더에만 보관했다. 이 문서와 [report.json](report.json)은 최소 FEN·짧은 변화·집계·해시만 포함한다.

실전 엔진은 기존 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba` 바이너리, 고전 활동성 평가, 인터페이스 소스`60853b3`·보스 정책v9였다. 새 연속 체크·룩 준비수 후보가 적용된 판으로 해석하면 안 된다. 사용자 시계 수정이 포함된 연습 대국이므로 이 한 판을 Elo 검증으로 환산하지 않는다.

## 무엇이 실제 수를 골랐는가

엔진44착수 중42착수는 자체 기본 탐색의 수와 같았다. 갬빗 정책이 기준수를 바꾼 차례는 첫d4와2.e4뿐이다. 중후반의 `trap_hunt` 표시는 실제 희생 교체가 일어났다는 의미가 아니다.35.Qf1과37.Rc8은 모두 자체 기본수였다.

2.e4의 추가 손실은 자체 실전 검증111cp, 별도 깊이18 감사108cp였다. 이는 기록상 허용한 갬빗의 의도적 비용이며 이후 전술 실수와 구분한다.

## 책은 있었으나6.h3가 거절됐다

같은 카탈로그 해시의 블랙마–디머 자료는32라인, 최대15반수다. Teichmann 계열4라인이 있고6.h3도 포함돼 있다. 실제 수순에서는 그래프 후보가6수까지 있었고, 연습 기억이 정확한 이력으로 조회된 것은5수의Nxf3 위치뿐이었다. 자료가 있다는 사실과 이후44수 운영을 익혔다는 주장은 다르다.

6수 위치에서 실전 자체 점수는Be3−68cp, h3−69cp로 차이가1cp였다. h3는35cp 품질 한도는 만족했지만 `no_reply_supported_operations_gain`으로 거절됐다.

운영 특징 함수는 예상 수순의 첫 두 반수만 측정한다. 따라서 `h3 Bxf3` 직후 기물이300cp 줄고 전개 기물도 하나 줄어든 것으로 세지만, 같은 자체 예상 수순의 다음 수는Qxf3였다.

| 측정 위치 | 재료 변화 | 전개된 마이너 변화 | 왕 위험 감소 | 이동 가능 수 변화 |
| --- | ---: | ---: | ---: | ---: |
| h3 Bxf3 직후 | −300cp | −1 | −2 | −8 |
| 이어서Qxf3 재포획 뒤 | 0cp | −1 | 0 | +3 |

기록된 운영 점수는 h3−11, 기준Be3/Nc6는+6.75였다. 교환 중간에 측정하는 시점 문제가 있지만, 재포획 뒤에도 전개 기물 수 등 다른 특징 차이는 남는다. 측정 시점만 바꾸면 반드시h3를 고른다고 단정하지 않는다.

근거 코드는 [continuation_evidence](../../../scripts/gambit_operations.py#L225)의 `pv[:2]` 재생과 [후보 거절 조건](../../../scripts/gambit_repertoire_play.py#L144)이다. 오프닝 자료가 없었던 사례와, 자료를 알고도 운영 휴리스틱이 배제한 사례를 분리해야 한다.

## 같은 루트의 깊은 비교

실전과 같은5011 엔진을 별도 프로세스에서 깊이6·최대500만 노드로 계산했다. 모든 자체 선택이 끝난 뒤 Stockfish18로 자유 탐색과 실제 수·책 후보를 같은 루트·공통 완료 깊이18에서 감사했다. 아래는 백 기준이며 cp는 승률이 아니다.

| 차례·수 | 자체 깊이6 | 외부 자유 탐색 | 외부 실제 수 | 최선 대비 손실 |
| --- | ---: | ---: | ---: | ---: |
| 2.e4 | −108cp | +33cp | −75cp | 108cp |
| 6.Be3 | −68cp | −22cp | −85cp | 63cp |
| 같은 위치6.h3 | −69cp | −22cp | −26cp | 4cp |
| 24.Qg4 | −86cp | −205cp | −210cp | 5cp |
| 35.Qf1 | −45cp | −505cp | −706cp | 201cp |

6.Be3의 선택 품질은h3보다 낮았지만 그 한 수로 패배 전체를 설명하지 않는다.24.Qg4는 짧은 감사에서67cp 손실로 보였으나 깊은 감사에서는5cp로 줄었다. 짧은 전체 스캔은 정밀 분석할 위치를 찾는 용도였다.

35.Qf1은 실전 깊이4·자체−37cp였고, 깊이6 재계산에서도 같은 수·−45cp를 유지했다. 시간을 조금 더 주는 것만으로 문제가 해결됐다는 근거는 없다. 평가 함수와 선택적 탐색 중 어느 부분이 주된 원인인지는 이 비교만으로 확정하지 못한다.

짧은 반격 비교는 다음과 같다.

- 자체 예상: `Qf1 Bg3 Bf2 f4 Bxg3 Rxg3`.
- 깊은 사후 감사: `Qf1 Qd5 Rc5 Qxe4 Rc2 Rg3`.

실제 사용자의 응수도Qd5였다. 그 자식 위치에서 같은 자체 깊이5 검색은Bg3를 흑+45cp로 선호했고, 실제Qd5는+37cp로 평가하며 `Qd5 Rc5 Qa2`를 예상했다. 따라서Qd5를 전혀 생성하지 못한 사례라고 보지 않는다. 중앙 폰을 잡은 뒤g·h파일로 침입하는 후속의 가치를 충분히 반영하지 못한 증거이며, 예상 수순 끝이 최종 평가의 확정 원인이라는 주장과도 구분한다.

## 실전 시간과37.Rc8

실전35수의 기본 요청은500ms, 실제 기본 검색은485.6ms, 완료 깊이는4였다. 추가 분석 상한431ms 중 약173.2ms를 사용했고, 표시상 기다린 시간은 약242.7ms였다.

37수는 기본 요청1156ms·실제1141.7ms·완료 깊이5였고, 이후 표시 대기 약6031ms가 있었다. 이 대기는 추가 계산 가능성을 검토할 근거지만, 여유 시간을 주기만 하면 좋은 수를 고른다고 보장하지 않는다.

별도Rc8 동일 루트 깊이18 감사에서는 자유Rc2가 백−674cp인 반면, 실제Rc8은12수 피메이트로 평가됐다. 이미 상당히 불리했던 위치에서 더 직접적인 패배를 허용한 문제다. 얕은 전체 스캔은 이 메이트를 발견하지 못했으므로 해당 정밀 감사와 구분한다.

## 검증 조건과 다음 판단

전체88반수를 먼저 짧게 스캔했다. Stockfish18, Threads1·Hash32MiB, 각 자유/실제 수 질의 최대 깊이12·50ms였으며 루트마다 공통 완료 깊이를 따로 기록했다. 핵심 네 위치의 자체 분석은 같은5011·Hash16MiB·고전 활동성·깊이6·최대500만 노드, 새 프로세스 조건이었다. 이후 외부 감사는 Threads1·Hash32MiB·질의별 Clear Hash·최대 깊이18·1.2초였고 모두 공통 깊이18을 얻었다. 엔진 정상 종료와 원본 해시 불변을 확인했다.

비공개 원시는 정확한 전체 이력을 유지했다. 공개된 최소 FEN만으로 재실행한 결과가 반복 문맥을 포함한 원시 결과와 비트 단위로 같다고 보장하지 않는다. [report.json](report.json)은 원시 산출물의 해시와 조건을 기록한다.

우선 검증할 사항은 교환 도중의 운영 특징 측정, 자체 왕 안전·장기 위협 평가, 위험한 기본수의 후속 확인, 실제 대기를 계산으로 재배분할 때의 효과다. 책 수 강제·확정 레이팅 상승·새 후보의 실전 검증 완료로 결론 내리지 않는다.

별도의 [연속 체크 연구 기록](../2026-11-05-gambit-forcing-recovery/README.md)은 공개 개발 위치의 부분 개선을 다룬다. 그 결과가 이 실전 전체의 문제를 해결했다는 뜻은 아니다.
