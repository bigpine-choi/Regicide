# 기존 기억과 새 병합 기억의 갬빗 모드 대국 사전 계획

2026-11-05. 최초 실제 대국 전에 작성했다. 기준 코드 `7821109`의 같은 production `HumanGame` 갬빗 정책을 양쪽에 사용하고 읽는 분석 기억만 다르게 한다. 호출별 기억 선택 문맥과 대국 기록 도구를 추가하며 기존 대국용 기억은 덮어쓰지 않는다.

## 비교할 입력

- 실행 파일: 자체 Regicide, SHA256 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`.
- 평가: `classical_activity_v1`, Hash 16MiB, 단일 검색 스레드. 신경망·외부 착수 엔진 없음.
- 기준 기억 SHA256: `c00cef2484dac5e90ae4eaa851f5f1cb82850d51881a2be5eacfd4ec66babcfa`.
- 병합 기억 SHA256: `e905789fcd243826db670a81fcd062180244519a45e2d3b26c0e286866b92b59`.
- 입력 명세: `build/gambit-memory-match-inputs/memory-delta.json`, 시작 위치·시드: 같은 폴더의 `cases.json`.

검색 전 비교에서 전체 161개 정확한 이력 중 실제 후보 수·순서·저장 근거가 달라지는 위치는 한 곳이다. `e4 e5 f4 exf4 Qg4 Qf6` 뒤 백 차례이며 기존 기억에는 없고 새 기억은 `Nh3`, `Qxd7`을 제안한다. 이는 기존의 자체 기하학 후보보다 먼저 검증될 수 있으므로 개선과 함께 추가 검증 비용·후보 대체의 손해 가능성도 확인한다. 저장 점수는 착수 승인 근거가 아니며 실시간 자체 검증을 유지한다.

## 대국 조건

8쌍·16판을 순차 실행한다. 한 쌍은 같은 시작 수순과 같은 시드에서 후보/기준의 색을 바꾼 두 판이다. 후보가 먼저 백으로 두는 쌍과 흑으로 두는 쌍을 교대한다. 양쪽 기본 시간은 500ms이며 production 갬빗 추가 시간 상한은 동일하게 최대 500ms다. 기본 시간 100ms에서는 갬빗 정책이 비활성화되므로 사용하지 않는다. 같은 시간 상한이 같은 실제 CPU 사용량을 뜻하지는 않는다.

두 호스트 모두 갬빗·동적 수 선택·오프닝 다양성 설정을 동일하게 유지한다. 시간제 시계는 사용하지 않으며 생각 시간과 대기 정책도 같다. 표시·힌트용 엔진은 검색하지 않는 도우미로 대체한다. 기존 사용자 GUI 프로세스는 건드리지 않는다.

| 층 | 쌍 수 | 시작 조건과 목적 |
| --- | ---: | --- |
| 기풍·일반 개시 | 4 | 초기판, King's 제안 직전, Evans 제안 직전, Stafford 제안 직전. 엔진이 실제 갬빗을 제안하는지 관측 |
| 새 기억에 노출되는 조건 | 4 | 유일한 변경 위치에서 사전에 고른 서로 다른 시드 4개. 같은 위치의 반복이며 독립 개시 4개로 해석하지 않음 |

시작 수순은 합법 기보 이력으로 양쪽에 동일하게 설치하며 강제 착수 기능으로 갬빗 정책을 끄지 않는다. 시작 수순의 희생·수락은 엔진이 이번 대국에서 수행한 행동으로 세지 않는다. 제안 직전 위치의 시드는 실제 검색 전에 오프닝 계획만 확인해 지정하며 검색 결과나 승패를 보고 고르지 않는다.

실제로 도달한 종국 조건만 승패·무승부로 인정한다. 앱의 `automatic_outcome`에 맞춰 완료된 세 번째 반복·50수와 체크메이트 등을 처리하며, 다음 수를 두면 무승부를 청구할 수 있다는 이유만으로 미리 끝내지 않는다. 시작 수순 뒤 새로 둔 수가 240반수에 도달하면 `*` 미완주로 기록한다. 한 판의 전체 실행시간 상한은 300초이며 여기에 도달한 경우에도 `*` 미완주로 기록한다. 오류·중단·상한 종료를 무승부나 승점에 합산하지 않는다. 결과가 좋거나 나쁘다는 이유로 중도 중단하거나 위치를 바꾸지 않는다.

## 기록과 판정

- 전체 및 두 층별 후보 기준 승·무·패, 완료·미완주·실패, 색상 및 쌍별 결과
- 실제 갬빗 제안/선택, 실제 희생 수락, 검증된 전술 희생 후보의 선택. 서로 다른 사건을 구분
- 기물 전개·협동 공격·왕 주변 압박 등 같은 정의의 기하학적 지표. 이것만으로 좋은 공격이나 기력을 판정하지 않음
- 새 기억 위치 도달, 후보 노출, 실제 검증 시도, 승인·착수, 원래 기준수와의 관계
- 기본/추가 시간 상한, 실제 경과시간·원시 UCI 검색, 전체 기보 및 정확한 재생, 엔진 종료 코드와 입력 해시 불변

새 기억의 이득이 한 위치에 국한된다는 점을 전제로 층별 결과를 분리한다. 전체 16판 승점을 일반 갬빗 Elo나 광범위한 개선으로 환산하지 않는다. 기풍 관측도 소수 기회에서의 기능 증거이며 Chess.com의 `!`·`!!` 실제 등급을 측정한 것이 아니다. 결과와 노출·채택 기록을 함께 보고 반영·보류를 권고한다.

## 사용자 요청에 따른 실행 속도 변경

최초 실행 도중 사용자가 대결 속도를 높이도록 요청했다. 실행 당시 1~5번 판이 완료되고 6번 판이 진행 중이었다. 1~4번은 완성된 두 선후공 쌍으로 유지한다. 5번은 후보 승리였지만 반대 색 6번이 미완료여서 쌍 전체를 다시 실행한다. 원래 5번 승리와 중단한 6번은 별도로 보존하고 본 성적에 합산하지 않는다. 변경 사유·시각·중단한 자체 프로세스 확인 내역은 원본 결과 폴더의 user-speed-change.json에 남긴다.

남은 3~8번 쌍은 최대 네 개의 독립 runner로 병렬 실행한다: a=쌍3~4, b=쌍5~6, c=쌍7, d=쌍8. 각 runner 내부는 순차 대국이며 색·시드·시작 수순·동일 실행 파일·기억·Hash16·수당500ms와 추가최대500ms·240반수/300초 상한은 유지한다. 소스는 변경하지 않는다. 이 변경은 결과 개선을 위한 재선택이 아니라 사용자 요청에 따른 실행 방식 변경이다. 단독4판/병렬12판을 구분하며 병렬 CPU 경쟁으로 시간제 검색의 실제 노드 수는 달라질 수 있음을 명시한다. 전체 결과는 같은 쌍 안에서 두 색을 교대한 조건부 선별 결과로만 해석한다.
