# 갬빗 병합 기억 비교 결과 — 2026-11-05

갬빗을 제안하는 성향은 관측한 기회에서 유지됐지만, 이번 병합 기억으로 기력이 향상됐다는 근거는 얻지 못했다. 새 버전은 16판에서 **4승 5무 7패, 6.5/16점(40.625%)**이었다. 새 기억이 다른 후보를 제공하는 위치에서 시작한 8판만 보면 **3승 2무 3패, 50%**다. 운영 기억은 기존 파일을 유지한다.

## 승패와 해석

모든 수치는 새 병합 기억을 읽는 후보 기준이다. 승=1점, 무=0.5점. 16판 모두 규칙에 따른 종국이며 본 성적의 오류·미완주·시간/수 상한 종료는 0판이다.

| 비교 범위 | 판수 | 승 | 무 | 패 | 승점 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전체 | 16 | 4 | 5 | 7 | 6.5/16, 40.625% |
| 일반 개시·갬빗 제안 | 8 | 1 | 3 | 4 | 2.5/8, 31.25% |
| 새 기억 위치에 직접 노출 | 8 | 3 | 2 | 3 | 4/8, 50% |
| 단독 실행분 | 4 | 0 | 2 | 2 | 1/4, 25% |
| 사용자 요청 후 병렬 실행분 | 12 | 4 | 3 | 5 | 5.5/12, 45.833% |

일반 개시 8판에서는 같은 실제 이력에 두 기억을 각각 적용해도 사용 가능한 후보의 수·순서·출처가 달라진 차례가 없었다. 이 부분의 낮은 성적을 새 기억의 악영향으로 귀속할 수 없다. 시간제 탐색은 실행 부하에 따라 완료 깊이와 수순이 달라질 수 있다. 16판은 작은 선별 표본이며 Elo·일반적인 기력 향상 또는 퇴보를 확정하지 않는다. 특히 목표 위치 4쌍은 같은 위치를 시드만 바꾼 반복이며 서로 독립인 네 개시가 아니다.

## 새 기억이 실제로 한 일

전체 161개 저장 상태 중 실전 후보가 달라지는 상태는 다음 한 곳이었다.

`1. e4 e5 2. f4 exf4 3. Qg4 Qf6` 뒤 백 차례.

- 기존 기억에는 해당 상태가 없고, 병합 기억은 `Nh3`, `Qxd7`을 추가한다. 기존 기하학 후보보다 먼저 검토될 수 있다.
- 목표 8판의 첫수는 양쪽 모두 `Nh3`였다. 각 버전이 백을 맡은 4번 모두 자체 기본 탐색이 이미 같은 수를 골랐다.
- 새 버전의 4회 노출은 모두 `knowledge_move_is_baseline`으로 처리됐다. 추가된 기억 후보를 별도로 비교 검증하거나, 기억 때문에 기본수를 다른 수로 바꾼 횟수는 **0회**다. `Qxd7`을 채택한 경우도 없다.
- 공통으로 있던 기존 기억은 양쪽 모두 각각 2회 기본수를 바꿨다. 이를 새로 추가한 기억의 성과로 세지 않는다.
- 해당 첫수의 호스트 경과시간은 후보 평균 약 751ms, 기존 약 946ms였다. 기존 쪽은 기하학 후보를 더 검토했고 후보 쪽은 기본수 일치로 일찍 끝났다. 이는 이 위치 4회씩에서 관측한 비용 차이이며 CPU 시간, 일반 검색 속도 개선, 기력 향상의 증명은 아니다.

다음 개발은 판수 확대보다 **기존 탐색이 놓치는 유효한 후속 수를 확보하고, 정확한 이력으로만 찾는 기억의 유효 범위를 넓히는 연구**가 우선이다. 저장 행의 증가와 실제로 달라지는 수 선택을 별도 지표로 유지한다.

## 갬빗 기풍

시작 수순에 이미 들어 있던 희생은 이번 엔진이 만든 사건에서 제외했다. 제공한 말의 포획은 수락이 지연된 경우까지 전체 기보로 추적했다. 이는 순기물 희생의 크기나 희생의 건전성을 판정하는 지표는 아니다.

| 관측 지표 | 기존 | 새 병합 |
| --- | ---: | ---: |
| 지정한 King's/Evans/Stafford 제안 직전 기회에서 실제 제안 | 3/3 | 3/3 |
| 실제 갬빗 제안 착수 | 6 | 6 |
| 제안한 말이 이동하기 전에 실제로 잡힌 사건 | 6 | 6 |
| 제안 종류 | King's 2, Falkbeer 2, Evans 1, Stafford 1 | 동일 |
| 착수 기록으로 확인한 전술 희생 후보 선택 | 5 | 4 |
| 전술 희생 후보가 기본수를 바꾼 횟수 | 2 | 2 |

관측한 갬빗 제안 성향은 유지됐다. 공격의 질까지 같거나 좋아졌다는 뜻은 아니다. 한 수 후의 기하학적 협동 압박 증가 평균은 기존 0.1187, 후보 0.0697로 후보가 낮았고, 왕을 공격하는 기물 수 증가 평균도 0.0614 대 0.0585였다. 서로 다른 이후 국면·종국까지 섞인 설명용 수치여서 그 차이로 기풍 훼손이나 강도를 판정하지 않는다. Chess.com의 `!`·`!!` 등급은 수집하거나 재현하지 않았다.

## 조건과 실행 방식 변경

기준 코드: `7821109d3622bbee2523418ee8f7b988fd23170e` + 이번 기억 문맥 분리·대국 기록 도구. 양쪽 실제 착수는 같은 자체 Regicide 바이너리와 production HumanGame 정책으로 선택했다. 외부 착수 엔진은 사용하지 않았다.

- Regicide 실행 파일 SHA256: `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`.
- 기존 기억 SHA256: `c00cef2484dac5e90ae4eaa851f5f1cb82850d51881a2be5eacfd4ec66babcfa`.
- 병합 기억 SHA256: `e905789fcd243826db670a81fcd062180244519a45e2d3b26c0e286866b92b59`.
- `classical_activity_v1`, Hash 16MiB, 단일 검색 스레드. 갬빗·동적 수 선택·오프닝 다양성 모두 동일 설정.
- 기본 500ms + 선택적 추가 최대 500ms. 게임 시계는 끄고, 새로 둔 수 240반수 및 판당 실행 300초 상한을 양쪽에 동일하게 적용했다. 표시용 도우미는 검색하지 않는다.
- 같은 시작 이력과 시드에서 색을 교대한 8쌍. 기보의 전체 이력을 유지하며 강제 착수 API는 사용하지 않았다.
- Windows 11 Home 10.0.26200, AMD Ryzen AI 7 350, 8코어/16논리 프로세서, 가용 표기 메모리 약 31.3GiB. Python 및 python-chess 버전은 원시 match.json에 기록했다.

처음에는 순차 실행했다. 사용자의 속도 개선 요청 시 원래 1~5번이 완료되고 6번이 진행 중이었다. 1~4번의 완성된 두 쌍을 유지하고, 원래 5번 후보 승리와 6번 중단 판을 모두 별도로 보존·제외한 뒤 해당 쌍 전체를 재실행했다. 남은 쌍은 최대 네 개의 독립 runner에서 병렬 실행했다. 수당 계산 조건과 입력은 유지됐으나 실제 CPU 경쟁은 바뀌므로 단독·병렬 결과를 위 표에서 분리했다. 정확한 변경 기록은 `user-speed-change.json`과 `audit-selection.json`에 있다.

대국 실행은 한국시간 01:14:14~01:34:17, 약 20분이었다. 병렬 전환 후 남은 대국은 약 7분 34초 걸렸다. 준비·검증 시간은 여기에 포함하지 않는다.

## 검증과 보존

- 기억 분리 9개, 기존 기억 10개, 대국 도구 11개, 지표 11개: 합계 41개 자동 검사 통과. 테스트는 가짜 상대와 production 호스트를 사용한 기능 검사이며 자체적으로 기력을 입증하지 않는다.
- 별도 감사기로 본 대국 16판/1,952착수의 합법성, 전체 접두 이력, 실제 종국, 조기 무승부 종료 없음, 색·시드, 기억 선택, 설정, 기보 재생, 원시 검색을 확인했다. 실패 0건.
- 본 대국의 자체 엔진 32개 모두 종료 코드 0을 확인했다. 기존 사용자 프로세스를 중단하지 않았다. 사용자 속도 요청으로 중단한 원래 6번의 자체 엔진 2개는 별도로 구분된다.
- 수당 기본 요청 500ms 및 추가 허용량이 같음을 확인했다. 원시 기록의 실제 추가 검색 시간이 500ms를 넘은 착수는 없었다. 일찍 반환한 검색이 있으므로 여러 추가 검색의 요청 상한 합계는 실제 소요시간과 다르다.
- 실행 전후 바이너리·기억·소스 해시가 유지됐다. 운영 기억 파일을 덮어쓰지 않았다.
