# 갬빗 전술 오판 개선: 첫 말단의 퀸 위협 대응

2026-11-04. 기준 소스 `f893c6f`, 후보 구현 `0058387`. **퀸 위협이 남은 탐색 말단을 한 번 더 비교하는 선택적 탐색을 구현·검증했다.** 알려진 국면의 부분 개선, 기풍 회귀 검사, 핵심 엔진 16판 선별을 완료했다. 후보 6승 5무 5패로 전체 기력·레이팅 상승은 확정하지 않는다. 실험용 옵션으로 보존하며 활성 대국용 실행 파일은 유지한다. 반복 체크는 별도 미해결 문제다.

## 문제와 구현

기존 King's 개발 국면의 `Nc3 d5 Qh5 Nf6 Bb5+ Nc6` 뒤에는 체크가 아니지만 퀸이 공격받고 있었다. 기존 정지 탐색은 그 위치의 정적 평가 −141cp를 그대로 유지할 수 있었다. 앞선 observer 기록은 실제 평가 호출을 확인한 자료이며, 단일 호출이 루트 선택을 결정했다는 완전한 인과 증명은 아니다.

`SearchOptions.quiescence_queen_defense` / UCI `UseQuiescenceQueenDefense`를 추가했다. 기본값은 `false`이다. 활성화 시 첫 정지 탐색 위치(qply 0)에서 자기 퀸이 적 폰·나이트·비숍·룩·킹에게 기하학적으로 공격받고 있으면 현재 평가 유지(stand pat)를 허용하지 않고 모든 합법 응수를 비교한다. 자식은 기존 포획·승격·체크 정책으로 돌아간다.

- 퀸 도피만 강제하지 않는다. 반격, 공격자 제거, 막기, 퀸 희생도 모두 합법 후보다.
- 퀸 위협 자체에 평가 벌점을 더하지 않는다. 핀된 공격자도 확장을 유발할 수 있으므로 이 선택적 지평선이 언제나 더 정확하다고 가정하지 않는다.
- 왕 체크 회피, 선택 가능한 3회 반복·50수 청구, 자동 무승부, 메이트 우선순위와 중단 복원을 유지한다.
- 새 전이표 상태는 필요하지 않다. 옵션은 검색 중 불변이며, 별도 정지 탐색 캐시는 이미 qply에 대응하는 잔여 깊이를 키로 사용한다. 캐시는 검색마다 초기화된다.
- 후속 qply에서 처음 생긴 퀸 위협과 연속 체크의 부족은 해결하지 않는다. 실제 반복 체크 말단 진단은 [별도 기록](perpetual-diagnosis/README.md)에 있다.

갬빗의 개시, 희생 손실 한도, 빈도, 후속 운영 정책과 생각 시간 배분은 변경하지 않았다. 외부 엔진의 수나 점수를 자체 착수 선택에 넣지 않는다.

## 첫 원인 진단

같은 King's:9 이력, 활동성 평가, 깊이 6에서 다음을 관측했다. 같은 깊이는 같은 계산량을 뜻하지 않는다.

| 검색 | 기준 | 퀸 방어 활성 후보 |
| --- | --- | --- |
| 자유 선택 | Nc3, −141cp, 446,299노드 | Qf5, −149cp, 907,594노드 |
| Nc3로 제한 | −141cp, 56,624노드 | −355cp, 201,784노드 |

이는 의심 수의 낙관적 평가가 낮아지고 선택이 달라졌다는 진단이다. 계산 비용 증가도 크므로 시간제와 고정 노드 비교 없이 기력 향상으로 해석하지 않는다.

## 비교 조건과 채택 기준

변경 하나만 비교한다. 평가기는 양쪽 classical + `UsePieceActivity=true`, 단일 탐색, Hash 16MiB다. 기준과 후보는 같은 MSVC x64 C++20 `/O2 /DNDEBUG /W4 /WX` 조건으로 빌드했다. 후보에서 새 옵션을 끈 대조군은 기존 기준과 고정 100,000노드 검색의 선택·점수·PV·노드 수가 같은지 먼저 확인한다.

1. 선언한 개발·전술·규칙 대조군에서 100,000노드와 100ms를 각각 비교한다. 개발 국면과 새 합성 대조군을 구분한다.
2. 자체 선택이 끝난 뒤만 Stockfish를 사후 감사로 사용한다. 공통 완료 깊이의 정확한 점수만 비교하며 메이트는 별도 취급한다. 큰 악화 경고는 최선 대비 손실 >150cp이면서 기존보다 >=100cp 악화한 경우다.
3. 기존 `comparison_openings.json`의 여덟 개시를 모두 사용해 선후공 16판, 수당 100ms, 최대 320ply로 핵심 엔진을 선별한다. 종료되지 않은 판은 `*`이며 무승부로 세지 않는다. 양쪽 기본 Move Overhead 20ms가 적용된다. 이는 갬빗 정책 전체의 대국이나 Elo 검증이 아니다.
4. 갬빗 정책은 별도 실제 Host 검사에서 발동 가능한 시간을 사용해 확인한다. 일반 회귀·기풍 유지·승패를 하나의 점수로 합치지 않는다.

작은 국면 또는 대국 표본만으로 안정판의 기력 상승을 선언하지 않는다. 새 피메이트·큰 악화·기풍 손실은 채택 보류 사유다. 실험용 옵션과 실제 대국용 설치를 구분한다.

### 정확성과 기풍

- 기존 native 회귀 **206개 그룹, 실패 0**. [기존 검사 출력](regression.txt).
- 신규 **9개 그룹, 실패 0**. 축소한 퀸 위협 위치의 모든 응수를 독립 탐색한 값, 색상 반전, 퀸을 무시한 메이트 반격, 기존 Nxe5 전술, 핀된 공격자, 비활성 경로, 무승부 청구, NNUE 전체/증분 일치, 캐시·중단·노드 한도를 확인했다. [신규 출력](queen-defense-tests.stdout.txt), [실행·해시](queen-defense-tests.json).
- 옵션을 끈 후보와 새로 빌드한 기준의 두 국면에서 선택·점수·PV·노드 동등성을 확인했다.
- 18개 국면(기존 개발 14, 결과를 보기 전 선언한 합성 대조 4)에서 고정 100,000노드와 100ms를 따로 비교했다. 고정 노드에서는 17개 비종료 국면의 선택이 모두 같았고, 시간제에서는 Morra 한 위치만 달랐다. 수정판의 외부 감사 손실이 37cp 증가한 이 위치도 함께 기록했다. 개선 사례만 고르지 않았다. [선별 요약](screen-summary.json).
- 두 버전 모두 `Qxg8+` 희생 메이트, `Nxe5` 퀸 제안, 룩 언더프로모션 및 메이트 대조 수를 유지했다. 실제 `HumanGame`에서 King's·Stafford의 개시 선택과 정해진 수락 뒤 운영 계약도 각각 통과했다. 500ms 설정을 사용했으며 후보 옵션은 실제 엔진에 전달했다. 이는 제한된 기풍 회귀 검사이고 장기 공격 빈도·Chess.com 실제 등급 증가의 증명은 아니다.

초기 검증 도구는 종료판의 `bestmove 0000`을 python-chess의 null move 대신 `None`만으로 검사해 네 오류를 기록했다. 엔진 오류와 구분해 원본을 보존했고, 도구를 고친 뒤 해당 네 종료 질의만 재실행해 `0000`, 노드 0, 메이트, 프로세스 종료 0을 확인했다. 전체 선별을 반복해 유리한 결과를 고르지 않았다. 최종 총 노드도 완료 반복 발표 시점의 노드와 분리했다. [후속 실행 요약](followup-summary.json).

### 같은 예산의 알려진 개발 국면

100ms 선별에서 대부분 선택이 같아, 실제 갬빗 사용에 가까운 조건에서 King's:9 한 위치만 명시적으로 추가 확인했다. 미학습 평가 자료가 아니다.

| 조건 | 기준 | 후보 | 최종 총 노드(기준 / 후보) |
| --- | --- | --- | --- |
| 각각 850,000노드 | Nc3, 깊이 6 | Bb5, 깊이 5 | 850,000 / 850,000 |
| 각각 2085ms 요청 | Nc3, 깊이 6 | Bb5, 깊이 5 | 778,530 / 799,481 |

깊이 숫자는 추가 방어를 포함한 서로 다른 탐색의 명목 깊이다. 후보가 더 낮은 깊이에 머문 계산 비용도 결과의 일부다. 외부 엔진은 모든 자체 선택이 끝난 뒤 감사에만 사용했다.

Stockfish 18을 Threads 1, Hash 32MiB, 강도 제한 해제, 질의마다 Clear Hash, 깊이 14·최대 0.5초로 사용한 공통 정확 깊이 14 감사에서 백 기준 자유 선택은 −252cp, Nc3는 −533cp, Bb5는 −416cp였다. 최선 대비 손실은 **281→164cp**로 줄었지만 여전히 더 나은 수가 남았다. 이는 알려진 한 위치의 부분 개선이며 승률 환산치가 아니다.

최초 선별·후속 SF 감사는 정확한 깊이 패킷과 bestmove를 저장한 뒤 context manager의 강제 close로 종료 코드 1을 남겼다. 완료 점수와 정상 종료 검증을 구분해 원본을 보존했다. 핵심 King's 위치의 자유/Nc3/Bb5 세 질의만 명시적 UCI quit로 다시 확인했고, 같은 점수·정상 종료 코드 **0**·판과 소스 불변을 확인했다. [정상 종료 재감사](sf-reaudit-summary.json). 원래 18개 선별이나 자체 선택을 다시 실행한 것이 아니다. 새 검증 도구는 외부 감사의 완료와 정상 종료를 별도로 검사한다.

## 채택 판단과 재현

**첫 퀸 위협 말단의 낙관적 평가를 고치는 구현과 1차 비교를 완료했다. 안정판 교체는 보류한다.** 같은 깊이 비용 증가, 짧은 예산에서 대부분 같은 선택, 작은 대국 표본을 함께 고려한 결정이다. 기존 활성 실행 파일 SHA256 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`와 갬빗 정책 v8은 유지한다. 다음 연구에서는 불필요한 방어 확장의 비용과 후속 체크 지평선을 각각 독립 변경으로 검증한다.

빌드·소스·실행 파일 해시는 [빌드 기록](build-provenance.json), 실제 native 소스 바이트는 [소스 보관본](native-source.zip)에 있다. [검증 증거 ZIP](validation-artifacts.zip)에는 원본 선별·후속·재감사 보고서, 원시 UCI, Host 기록, 실제 실행 소스와 재현 설명을 보존했다. [48개 보관 항목의 검증 기록](validation-artifacts.json)은 원본 보고서 불변·개별 해시와 압축 무결성 확인을 기록한다. 실행 파일은 별도 `build-gambit-horizon/baseline`, `candidate` 폴더에 보존했다. Windows 11, Ryzen AI 7 350(8코어/16논리CPU), MSVC 14.51.36231 x64, Python 3.13.16 / python-chess 1.11.2 환경이다. CPU 격리를 하지 않았으며 시간제 수치는 해당 실행의 관측값이다.
