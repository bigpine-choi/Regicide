# 리체스 연결 한 번 저장 후 자동 복원

2026-11-03, 한국 시간. 저장된 연결키가 있으면 앱을 다시 실행할 때
로컬 연결 상태를 읽고 오프닝 탐색기를 자동으로 켠다. 연결 설정에는
빈 입력란 대신 저장 상태와 **연결키 변경** 버튼을 표시한다.
실제 리체스 통계 조회는 오프닝 화면이 보일 때에만 한다.

## 확인한 원인과 변경

이 PC의 암호화된 연결키는 이미 저장돼 있었고 새 프로세스에서도
불러올 수 있었다. 기존 UI는 이 상태를 사용하지 않고 매번 꺼짐으로
시작했으며, 연결 설정은 빈 입력란과 발급 안내를 그대로 보여줬다.
연결키 없음과 서버의 키 승인 거부도 같은 문구로 표시했다.

Godot·브라우저 화면이 시작할 때 localhost에서 연결 상태를 확인하고
저장된 연결을 자동으로 사용하도록 수정했다. 늦게 도착한 시작 응답이
사용자의 끄기나 새 연결 저장을 덮지 않는다. 키가 거절되면 서버의
실제 이유를 표시하고 교체 입력란을 연다. 설정 여부는 인증 성공과
구분하며 연결키 자체는 화면 응답·진단·기보에 넣지 않는다.

이미 실행 중인 다른 창도 저장 파일의 교체·삭제를 다시 읽는다.
일시적으로 파일을 못 읽었을 때에는 다음 확인에서 재시도한다.
새 키 저장에 실패하더라도 이전에 저장한 키를 먼저 지우지 않도록
원자적 교체를 적용했다. Windows 사용자 계정의 암호화 저장은 유지한다.

## 수행한 검증

- Python **36개 통과**: 새 프로세스에서 복원, 열린 창에서 저장·교체·삭제 인식,
  일시적 읽기 실패 후 회복, 저장 실패 시 기존 키 보존, 비밀값 미노출,
  기존 통계·HTTP 검증. `backend-validation.json`, `backend-tests.txt` 참고.
- 실제 PC에 저장된 키를 다시 입력하지 않고 새 프로세스에서 읽어,
  표준 시작 위치를 공식 리체스 탐색기에 조회했다. 캐시를 쓰지 않은
  응답이 `ready`이고 통계가 있는 것을 확인했다. 키를 바꾸거나 기록하지 않았다.
- 웹 테스트 17개, Godot 화면 검사 40개, 실제 localhost 통합 화면 검사 17개가
  모두 통과했다. 명령과 소스 해시는 `ui-validation.json`, 통합 요약은 `integration.json` 참고.
  통합 검증의 통계는 합성 자료이며, 별도 분석에서 사용하는 Regicide는
  실제 엔진이다. 이 UI 검사와 위의 실제 리체스 조회를 구분한다.

실행 중인 앱에는 다시 실행한 뒤 적용된다. 이미 저장된 이 PC의 키를
다시 발급하거나 입력할 필요는 없다. 사용자가 리체스에서 키를 취소한
경우처럼 실제 인증이 불가능해진 경우에만 새 연결이 필요하다.

## 실제 창을 재실행한 후속 확인

게임 창을 실제로 실행하고 정상 종료한 뒤 다시 실행했다. 연결키 입력이나
탐색기 켜기 조작 없이 오프닝 탭에 저장된 연결 안내와 마스터 통계가 표시됐다.
연결 설정에서도 입력란 없이 **연결키 변경** 버튼만 보이는 것을 확인했다.

이 과정에서 일반 대국의 레이팅 필터가 JSON 숫자의 실수형·정수형 차이로
거부되던 별도 표시 오류를 발견했다. JSON 왕복 테스트로 수정 전 실패를
재현하고, 정확한 숫자값을 비교하도록 수정한 다음 다시 실행했다.
일반 대국 통계도 정상 표시됐으며, 1600 미만·래피드/클래시컬 필터의
실제 새 요청은 `ready`, `cached=false`, 저장된 키 사용으로 확인됐다.
`manual-restart.json`에 비밀값을 제외한 관측 결과를 기록했다.
수를 두지 않았고 마지막 확인용 게임 창은 통계 화면을 열어 둔 상태다.
