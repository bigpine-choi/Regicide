## 1. 일반 대국: 보존 확인, 개선 미관찰

src/uci.cpp는 go.mate가 있을 때만 solve_mate()를 호출하고 반환한다. 나머지는 기존 search()를 사용한다. 기준본과 프로토타입의 search.cpp, 보드, 평가, 신경망, TT, main CLI 소스는 바이트 단위로 같다. 새 증명기를 일반 대국 수 선택에 통합한 실험이 아니다.

시드 0x20261105로 합법 수를 균일 선택한 10개 무작위 진행에서 10/20/30/40플라이를 뽑았다. 40국면 각각 10,000노드, 3회, 교대 순서로 실행했다. 엔진별 워밍업 1회는 제외했다.

| 항목 | 결과 |
| --- | --- |
| 비교 횟수 | 40국면 × 3회 = 120쌍 |
| bestmove·점수·깊이·노드·PV 전체 일치 | 120/120 |
| 국면별 3회 중앙값의 프로토타입/기준본 비율 중앙값 | 1.000739, 약 **0.07% 느림** |
| 게임 단위 군집 bootstrap 95% 구간 | 0.973834–1.018666, 약 **−2.62%~+1.87%** |

시간 차이를 개선이나 저하로 단정할 수 없다. 5,000회 재표집은 원자료를 늘리지 않으며 독립 진행은 10개뿐이다. OS 부하·CPU 온도·코어 배치를 통제하지 않았고 구간이 체계적 오차까지 보장하지 않는다. 무작위 진행은 실전 분포의 대표 표본이 아니다. 이 결과는 검사한 기본 옵션의 회귀 부재를 뒷받침하며 Elo 증가를 입증하지 않는다.

원자료: normal-search.json. 요약: normal-summary.json.

## 2. 동일 예산 메이트: 해결률 동일, 명시적 증명 기능 추가

기존 독립 오라클 회귀 27국면에 새 시드 0x20261104의 KQK/KRK 12국면을 추가했다. 새 국면은 엔진 실행 전 독립 오라클 결과만으로 M1/M2/2수 이내 없음 각 4개를 선정했다. JSON의 new_seed_case로 기존 개발 표본과 구분한다.

전체 39국면은 M1~M3 정답 23개와 목표 수 이내 메이트가 없는 16개다. 조용한 수, 특수 수, 무승부 경계와 루트 제한을 포함한다. 수비자가 청구 가능한 무승부는 방어로, 공격자의 선택적 청구는 포기 가능으로 처리한다.

- 고정 노드: 기존 go nodes 50000 / 신규 go mate N nodes 50000.
- 고정 시간: 기존 go movetime 100 / 신규 go mate N movetime 100 nodes 1000000000.
- 동일 searchmoves 범위, 순서 교대. 시간 실험은 큰 노드 한도를 명시하여 기본 100만 노드 제한의 영향을 피했다.

| 항목 | 기존 일반 탐색 | 신규 메이트 탐색 |
| --- | --- | --- |
| 5만 노드: 강제메이트 첫 수 선택 | 23/23 | 23/23 |
| 100ms: 강제메이트 첫 수 선택 | 23/23 | 23/23 |
| 새 시드 표본만의 메이트 첫 수 | 두 예산 모두 8/8 | 두 예산 모두 8/8 |
| 목표 이내 양수 mate 보고의 오판 | 두 예산 모두 0 | 두 예산 모두 0 |
| 명시적 상태 | 일반 점수·PV | 두 예산 모두 proven 23, no_mate_within_bound 16, unknown 0 |
| 새 시드 12국면 상태 | 증명 상태 인터페이스 없음 | proven 8, no_mate_within_bound 4 |

독립 Python AND/OR 탐색으로 국면의 정답과 반환한 첫 수의 강제성을 확인했다. 신규 증명의 거리, PV 합법성·최종 체크메이트도 확인했다. 단일 PV 재생을 전체 방어의 검증으로 간주하지 않는다. 기존 mate 보고가 이 표본에서 맞았다는 사실과 엔진이 증명 상태를 제공하는 것은 다른 결과다.

no_mate_within_bound는 해당 목표 이내 부재다. 더 긴 메이트 불가능 판정이 아니다. 기존 탐색이 목표 밖 mate 점수를 출력한 경우도 거짓 양성으로 세지 않았다. 기존 탐색의 최단 거리 정확성을 전 범위에서 보증하는 실험은 아니다.

### 응답 시간 해석

메이트가 있는 23국면의 중앙값:

| 예산 | 기존 최초 올바른 mate 보고 | 신규 증명 보고 | 기존 bestmove 종료 | 신규 bestmove 종료 |
| --- | ---: | ---: | ---: | ---: |
| 5만 노드 | 0.976ms | 0.817ms | 142.872ms | 0.871ms |
| 100ms | 0.994ms | 0.793ms | 100.879ms | 0.857ms |

기존 탐색은 mate 점수를 출력하고도 예산까지 계속 탐색하고, 신규 경로는 증명 후 종료한다. 마지막 두 열만으로 “100배 빨라졌다”고 해석하면 잘못이다. 최초 보고는 reader의 monotonic clock으로 측정했고, 보고 PV 첫 수도 독립 검증했다.

대부분 1ms 부근의 쉬운 표본이며 시간 실험 반복도 적다. 작은 최초 보고 시간 차이를 보편적인 속도 향상으로 주장하지 않는다. 노드당 작업도 서로 다르므로 NPS로 직접 우열을 판정하지 않는다.

원자료: capabilities.json. 요약: capabilities-summary.json. 저장 JSON은 운송용 중간 출력 중복을 제거하고 명령·최종 결과·시간·최초 보고를 보존한다.

## 3. 깊이 증가: M4 독립 확인, M16 달성 근거 없음

별도 확장 실험은 백 Qa2, 흑 Kh7에서 백 왕 위치만 바꾸고 첫 수를 searchmoves a2g2로 고정했다. **지정 첫 수 아래의 증명이며 루트 전체의 최단 거리 주장이 아니다.** 각 국면에 go mate 16을 요청했다.

| 백 왕 | 독립 오라클 | 신규 5만 노드 | 신규 100ms |
| --- | --- | --- | --- |
| f5 | 지정 첫 수의 M3 | proven, 813노드 | proven, 813노드 |
| f4 | 지정 첫 수의 M4 | proven, 31,135노드 | proven, 31,135노드 |
| f3 | 장거리 정답 미산정 | unknown, 50,000노드 | unknown, time_limit |
| f1 | 장거리 정답 미산정 | unknown, 50,000노드 | unknown, time_limit |

이 구성에서 M3→M4의 노드는 약 38.3배 증가했다. 일반적인 증가율로 외삽하지 않지만 현재 완전 탐색의 비용을 보여준다. f3/f1을 M5/M6 문제라고 단정하지 않는다.

M4의 100ms 실행에서 기존 최초 M4 보고는 46.892ms, 신규 증명 보고는 83.717ms였다. 첫 수를 제한했고 독립 오라클로 M4가 확인됐다. **정답 보고보다 모든 방어 증명이 더 비싼 사례**이며, 신규 엔진이 항상 빠르다는 결론은 지지되지 않는다.

현재 전치 저장, proof-number/DFPN 탐색, 외부로 내보낸 증명 자료의 재검증, 테이블베이스가 없다. 다음 개선은 반복·50수 이력을 반영하는 안전한 캐시와 증명 탐색 순서를 도입하고 같은 국면·예산으로 검증하는 것이다. 일반 대국 통합은 별도 정책과 시간 배분 실험이 필요하다.

실제 M16 정답 국면 해결이나 자동 발굴은 실증하지 않았다. go mate 16 입력 처리와 M16 해결 성능은 구분한다. 원자료는 scaling.json이며 M3/M4는 독립 오라클로 거리까지 확인했다.

## 4. 원격 CI: 신규 검사 통과, 전체는 기존 오류로 미통과

- [프로토타입 Engine and rules #169](https://github.com/bigpine-choi/Regicide/actions/runs/41762182798): Ubuntu/Windows 빌드와 CTest 통과. 독립 메이트 오라클은 Ubuntu 통과, Windows는 이후 취소되어 미실행.
- Ubuntu는 기존 nnue_qsearch_cost_gate_tests.py의 Frozen NNUE differs에서 실패했다.
- [변경 전 main 실행](https://github.com/bigpine-choi/Regicide/actions/runs/41703766543)도 동일 테스트·스택·오류로 실패했다.
- 저장된 reservation의 원래 Windows 절대 경로를 현재 checkout의 모델 절대 경로와 비교하는 것이 해당 실패 원인이다. reservation의 모델 SHA와 코드의 기대 SHA는 같다. 이 실험에서는 불변 연구 기록이나 CI 검사를 수정·완화하지 않았다.
- 다른 두 워크플로(Own search training data, Paired neural target experiment tools)는 성공했다.
- **전체 CI 통과로 표시하지 않는다.** 기존 CLI 교차검사 3개의 로컬 미완료 기록도 앞선 보고서에 남아 있다.

실행 링크와 오류 발췌: ci-audit.json.

## 재현

동일 컴파일러·Release 설정으로 두 버전을 빌드한다. MSVC 기준본에도 같은 SEE 컴파일 호환 수정을 적용한다. requirements-test.txt 의존성을 설치한 뒤:

~~~text
python tests/mate_performance.py BASELINE_BINARY PROTOTYPE_BINARY --output OUT
python tests/mate_scaling_probe.py BASELINE_BINARY PROTOTYPE_BINARY OUT
~~~

첫 명령은 독립 오라클과 정상 탐색 비교를 실행한다. --part capabilities / normal / summarize로 분리할 수 있다. summarize는 기존 측정값의 통계만 다시 계산한다.

실제 실행은 전체 비교 후 최초 보고 시각을 추가하여 메이트 부분만 다시 실행했다. 일반 탐색은 같은 원자료를 사용하고 bootstrap 단위를 게임으로 보정했다. initial-run.txt는 초기 기록이고, first-report-run.txt와 normal-summary.json이 본문의 최종 수치다. 후속 검증 중 엔진 바이너리는 변경되지 않았다.
