# 오프닝 구상·대응·초반 판세 코칭 — 2026-11-02

기준 커밋은 `6d8584e29658f19cbba7f99aa2c11a3882201eed`다. 오프닝 복기에 **백의 구상 / 흑의 대응 / 초반 판세** 설명을 추가했다. 자체 엔진의 수 선택과 탐색 예산은 그대로이며, 새 해설은 이미 저장된 실제 수순과 평가를 사용한다.

## 사용과 판단 범위

표준 시작부터 기록된 첫 24착수에서 백의 체계와 흑의 대응을 보여준다. 한 항목을 선택하면 해당 실제 착수 뒤의 보드를 유지하고 영어로 읽는다. 기본 국면 대사는 짧게 유지하며, 자세한 설명은 선택한 항목에만 표시한다. **오프닝 복기** 버튼은 중반·종반에서도 분석된 초반의 마지막 확인 지점을 열어 기능을 찾기 쉽게 한다. 다른 수·기보·색·총평·연습·추천 수순으로 이동하면 이전 설명과 음성을 취소한다.

한 대국의 공동 오프닝 위치를 두 진영의 관점에서 설명한다. 백이 레티로 시작했어도 이후 퀸스 갬빗이나 시실리안의 위치에 도달하면 전환을 알려준다. 현재 위치와 마지막으로 확인된 이름을 구분한다. 사용자 지정 FEN이나 이력이 부족한 시작 위치에서 과거 오프닝 선택을 추측하지 않는다.

이름은 기존 고정 CC0 목록과 Chess.com 기준 표시 보정을 사용한다. 구상 설명은 [공식 출처 확인](source-verification.json)을 바탕으로 직접 작성했다. 포지션별 조언은 대표 계획과 실제로 일어난 사건을 구분한다. [연구·감사 메모](notes.md)에 명칭, 수순 전환과 자료의 한계를 남겼다.

판세는 오프닝 이름의 고정 상성이나 공개 승률표로 결정하지 않는다. 12착수 이후에 실제 수의 일치하는 합법 PV, 경계가 아닌 평가값, 완료된 깊이 4 이상을 확인하면 현재 탐색의 잠정 평가를 설명한다. 절댓값 0.50 미만은 큰 차이 없음, 0.50~0.99는 약간 선호, 1.00 이상은 해당 측의 국면을 더 선호하는 표시 정책이다. 백 기준 점수의 부호를 흑 착수 뒤에도 그대로 해석한다. 더 깊은 탐색도 확정된 상성 승리로 승격하지 않는다.

깊이와 점수 구간은 검증된 정확도 기준이 아니다. 실제 짧은 분석의 깊이 5~6을 전부 숨기게 되는 임의의 깊이 8 경계를 검토한 뒤, 잠정적이라는 설명을 유지하며 표시용 최소 깊이를 4로 정했다. 12착수 이전·불확실한 비교·누락 또는 한계 점수·잘못된 PV·얕은 분석은 우열 판정을 보류한다. 실제 메이트·자동 무승부는 숫자 평가보다 우선한다. 이후 중반 실수로 생긴 점수를 오프닝 선택의 결과로 소급하지 않는다.

## 구현과 회귀 수정

- `coach.opening`에는 양쪽 이름, 확인된 오프닝과 시점, 세 설명, 실제 착수 뒤 FEN, 근거 출처와 잠정 평가를 담는다. 인칭을 바꾸어도 양쪽 구상과 점수 방향은 같다.
- 기존 이름 색인의 끝 위치만 조회하며, 모든 후속 오프닝 수순을 열거하지 않는다. 별도 엔진 검색이나 실행 중 외부 요청이 없다. 자료 누락·손상은 오프닝 설명만 생략한다.
- 캐시의 해설을 신뢰하지 않고 보존된 합법 수순으로 v7 문구를 재구성한다. 원본 기보와 진행 중인 대국은 변경하지 않는다.
- 실제 시실리안 통합 검사에서, 기물을 공격하지 않고 중앙만 지키는 `Nc3`를 기존 전략 해설이 처리하다 멈추는 오류도 발견했다. 없는 공격 대상의 접근을 고쳤으며 양색 회귀를 추가했다.

## 실제 엔진 연결

`scripts/check_coach_openings.py`로 아래 합성 기보 두 개를 각각 탐색당 0.5초에 분석했다. 사용자 기보와 별도의 임시 저장소를 사용했다.

```text
1. e4 c5 2. Nf3 d6 3. d4 cxd4 4. Nxd4 Nf6 5. Nc3 a6 6. Be3 e5 *
1. Nf3 d5 2. d4 Nf6 3. c4 e6 4. Nc3 Be7 5. Bg5 O-O 6. e3 h6 *
```

두 보고서의 실제 위치 24개, 오프닝 이름과 설명, 실전 점수의 방향을 확인했다. 캐시의 문구를 의도적으로 바꾼 뒤 다시 열었을 때 추가 엔진 실행 없이 복원됐으며, 원본 PGN 바이트는 같았다. 조건과 결과는 `real-engine-integration.json` 및 두 `*-report.json`에 기록한다. 이는 기능 연결 검사이며 오프닝의 객관적 우열·승률·경기력 증명이 아니다.

## 자동 검사와 화면 확인

최종 검사 수와 결과는 `validation-summary.json` 및 개별 로그에 기록한다. Python에서는 실제 이력·오프닝 전환·양쪽 점수 방향·불충분한 근거 거절·원본 보존·캐시 재구성을 검증한다. 웹에서는 새 설명 선택, 자동 음성, 실제 보드와의 일치, 다른 모드로 이동할 때 취소, 연습 정답 가림을 확인한다. 실제 Python 보고서 두 개를 두 사용자 관점에서 각각 1·6·12착수의 세 설명에 연결하는 별도 VM 검사도 수행한다.

Godot은 임시 프로젝트 복사본에서 기본·백의 구상·흑의 대응·초반 판세를 1240×860와 900×680로 렌더링한다. 긴 이름과 설명의 줄바꿈, 보드 크기 유지와 내용을 검사한다. 사용자 게임·서버를 종료하지 않는다. 화면은 독립 테스트 장면이며, 실제 대국을 사람이 수동 조작하거나 스피커 음성을 청취한 검증은 아니다. 웹 검증은 DOM·음성 모의 환경으로 실제 브라우저 렌더링은 포함하지 않는다.
