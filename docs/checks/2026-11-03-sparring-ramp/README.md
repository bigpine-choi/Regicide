# 20수 이후 봐주기 해제와 과도한 양보 제한

## 확인한 문제

사용자가 지적한 동일 대국의 저장된 결정 기록을 읽었다. 22수에는 심판 기준 +4.66인 기본 수 대신 응수 후 +3.13인 수를, 30수에는 +1.55인 기본 수 대신 응수 후 +0.15인 수를 선택했다. 이는 새로운 분석 결과가 아니라 당시의 저장된 평가다.

자체 정책은 목표 점수를 점차 올려도 하한을 -100cp로 유지했고, 접전 범위의 후보가 있으면 범위 밖의 기본 수를 비교에서 제외했다. 이 때문에 해제가 거의 완료되어도 큰 양보가 허용될 수 있었다. 심판 쪽은 별도 half-move 수식으로 해제 비율을 계산해 백·흑의 같은 수 번호에서 비율도 달랐다.

## 변경

20수까지의 접전 정책과 50수부터의 전력 모드는 유지한다. 21~49수에는 자체 선택과 심판 선택이 같은 full-move 해제 비율을 사용한다.

| 수 번호 | 한 수의 최대 의도적 평가 손실 |
|---|---:|
| 21 | 1.16점 |
| 30 | 0.80점 |
| 40 | 0.40점 |
| 49 | 0.04점 |
| 50 | 0점 |

상한은 `120cp × (1 − 해제 비율)`이며 실제 허용 손실은 우세·열세 보호 조건으로 더 작을 수 있다. 기본 수가 우세이면 0 아래로 내려가는 양보를 금지하고, 이미 열세이면 더 나빠지는 양보를 금지한다. 자체 후보의 비교 평가와 최종 평가, 별도 상대 응수 평가 모두 새 하한을 적용한다. 램프 구간에서는 기본 수도 계속 포함해 목표와의 거리를 비교한다. 임시 회복 목표도 손실 하한을 완화하지 못한다.

세부 근거는 결정 기록의 `regicide-sparring-ramp-guard-v1` 메타데이터로 구분한다. 이전에 저장된 평가나 정책 기록은 수정하지 않는다.

## 실제 기록을 이용한 선택 경로 재검증

`recorded-decisions.json`은 원본 대국에서 필요한 위치·수순·평가 패킷만 추출한 읽기 전용 증거 스냅샷이다. `tests/ramp_record_replay_tests.py`는 그 점수들을 현재의 실제 심판 선택 경로에 입력한다.

| 당시 수 | 당시 기본 수 / 최종 선택 | 새 기준 결과 |
|---|---|---|
| 22수 | Ra1 +4.66 / Rg1, 응수 후 +3.13 | 허용 하한 +3.54에 미달하여 Ra1 유지 |
| 25수 | Rd7 -0.03 / Bc7, 응수 후 +0.23 | 개선되는 선택인 Bc7 유지 |
| 30수 | Bd2 +1.55 / Bc7, 응수 후 +0.15 | 허용 하한 +0.75에 미달하여 Bd2 유지 |

이는 기록된 평가가 주어졌을 때 정책이 어떤 수를 선택하는지 재검증한 결과다. 새 엔진 탐색이나 전체 대국 재대결 결과로 해석하면 안 된다. 점진적 해제, 백·흑 일치, 큰 손실 및 부호 역전 차단, 정상적인 작은 양보 허용, 상대 응수에서 하한 이탈 시 거절도 별도 자동 테스트로 검증한다.

최종 실행: `python -m unittest sparring_referee_v3_tests ramp_guard_tests ramp_record_replay_tests sparring_play_tests sparring_referee_tests recovery_policy_tests` (PYTHONPATH=tests). 114개 모두 통과했다. 새 경계 검증은 14개, 실제 기록 재생은 한 테스트에서 3개 위치를 검증한다. 기존 후보 탐색 테스트 한 곳은 후보 탐색용 패킷만 제공하므로 별도 최종 안전 검사를 격리했고, 최종 안전 검사는 전용 호스트 테스트로 유지했다.

## 한계

의도적으로 허용하는 손실을 제한한다. 엔진의 평가 오류, 놓친 전술, 상대의 좋은 수에 의한 역전까지 금지하거나 승리를 보장하지 않는다. 앞서 추가한 전술 안전 검증과 함께 동작한다. 변경 적용에는 실행 중인 앱의 재시작이 필요하다.
