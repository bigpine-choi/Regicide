# 캐릭터 코치 루크와 다시 두기

2026-11-01. 기존 대국 코칭에 한국어 캐릭터 해설, 주요 국면 수업, 독립된 다시 두기를 추가했습니다. C++ 엔진과 평가 모델은 변경하지 않았습니다.

## 판단과 기보 보존

- 자체 Regicide 엔진이 수를 탐색합니다. python-chess는 합법 수·기보·변화 수순의 검증에 사용합니다.
- 한국어 해설은 로컬 문형으로 구성합니다. 체크와 메이트는 실제 보드 판정, 포획·승격·캐슬링은 합법 수 적용 결과로 확인합니다. 공격 관계만 보고 포크·핀·필연적 기물 손실이라고 단정하지 않습니다.
- 기물 점수 변화는 표시한 유한한 예상 수순 안의 단순 기물 합계이며 엔진 평가나 승률이 아닙니다. 원래 대국에서 실제 발생한 결과와 구분합니다.
- 기존 캐시의 문구·법적 착수 목록을 신뢰하지 않고 검증된 수순에서 해설과 연습 가능 수를 다시 구성합니다.
- 다시 두기는 원래 국면의 전체 기보 이력을 재구성하고, 제한 없는 탐색과 사용자가 고른 수로 제한한 탐색에 동일한 시간 예산을 줍니다. 원래 보고서는 수정하지 않습니다.
- 동시에 하나의 연습 분석만 허용합니다. 세션 변경·취소·종료와 오래된 응답을 구분하고, 제한 시간을 넘기면 연습 엔진을 정리합니다.

## 실제 엔진 HTTP 검증

`tests/coaching_http_tests.py`를 별도 임시 저장소와 Fool's Mate 기보로 실행했습니다. 인증, 잘못된 입력, 오래된 국면, 모든 반환 변화 수순의 합법성, 주요 수업 국면과 근거 칸, 원본 보고서 보존을 확인했습니다. `g4`를 다시 두었을 때 메이트 허용을 평가하고, 실제 실행 중인 다시 두기를 취소하면 오래된 결과가 거절되는 것을 확인했습니다. 완료 캐시 재사용과 일반 분석 취소도 통과했습니다.

증거: `http/http-evidence.json`, `http/fools-mate-report.json`, `http/retry-result.json`. 사용자의 개인 대국·저장소는 사용하지 않았습니다.

엔진 실행 파일 SHA-256: `edd950fb673cfca4134968b64cc5ef0f3d77eda698e9f40d2965170f143d6e6a` (Regicide 0.7.0-dev). 기능 정확성 검사이며 엔진 경기력·속도 향상 검증이 아닙니다.

## 실제 화면 검수

Godot의 실제 렌더러로 총평·설명·근거 강조·다시 두기·승격을 1240×860과 900×680에서 렌더링했습니다. 보드 한 변은 각각 597px와 370px로 화면 상태가 바뀌어도 동일했습니다. 루크와 연습 버튼, 승격 네 선택지가 잘리지 않는 것을 이미지로 확인했습니다. 별도 실제 엔진 보고서를 넣은 화면도 확인했습니다.

- `native-real-coach.png`: 실제 엔진이 분석한 메이트 허용 장면의 한국어 설명과 추천 수.
- `native-real-retry.png`: 같은 국면에서 정답·평가를 가린 연습 보드.
- [크기별 네이티브 이미지](../2026-11-01-character-coaching/native-render/): 합성 검수 기보의 10개 화면과 정확한 보드 크기.

브라우저는 임시 저장소를 사용하는 별도 서버를 실제 IAB에서 열어 검수했습니다. 코칭 시작, 주요 국면 사이 실제 기보 재생, 메이트 근거 장면, 정답 가리기, `g4`의 재도전 안내, 흑 `Qh4#`의 정답 피드백, 새 분석 수순 재생을 확인했습니다. 처음에는 HTML 드래그와 포인터 입력이 충돌해 드래그 착수가 전달되지 않았습니다. HTML 드래그를 끄고 포인터·마우스 방식으로 통일한 뒤 실제 `d8 → h4` 드래그 착수와 엔진 응답까지 재검수했습니다.

- `web/drag-retry-verified.png`: 수정 후 실제 드래그로 정답을 둔 화면.
- `web/verified-mate.png`: 설명에 대응하는 왕·퀸 강조 장면.
- `web/final-preservation.json`: 검수 전후 대국 상태·기보 바이트 보존 확인. 검수용 서버와 탭은 종료했습니다.

음성은 명시적 버튼으로만 시작합니다. 로컬 한국어 음성의 존재와 비활성 대안을 검사했으며, 이 컴퓨터의 Godot에서 Microsoft Heami(ko_KR)를 확인했습니다. 실제 소리를 재생해 청취한 검수는 하지 않았습니다. 네이티브는 자동 씬 입력과 렌더링 검수이며 사용자의 실행 중 창을 직접 조작한 검수가 아닙니다. 사용자의 원래 Regicide 창과 개인 기보는 건드리지 않았습니다.
