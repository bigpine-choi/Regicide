# v0.6.5 종반 진단·자료 규모 연구

2026-10-19 KST. 종반 자료와 정답을 늘렸지만, 이번 범위에서는 자료량에 따른 일관된 개선을 확인하지 못했다. 미리 정한 후보도 원격 채택 검증에서 탈락해 **기존 수식 평가를 유지했다.** 연구와 결과 가져오기는 완료했으며, 최종 CI 확인과 로컬 설치는 아직 완료하지 않았다.

[최초 계획](../../experiments/2026-10-19-endgame-learning-scale-plan.md), [학습 전 확정한 원격 검증 수정](../../experiments/2026-10-19-endgame-validation-revision.md), [구조와 실행](../../ENDGAME_LEARNING.md)을 함께 본다. 기준 소스는 `527289e74dbdfb28a98625ef961c7470e9c78ff9`(v0.6.4), 실험에 동결한 연구 구현은 `fee60f4e23155a0c4e2b15f83a922411d9e62b3a`다.

## 종반에서 확인한 것

기존 학습용 자가대국 중 승패가 갈린 완료 대국 72판을 조사했고, 45판에 종반이 있었다. 종반은 퀸이 없고 전체 기물이 12개 이하이거나, 기물별 가중치를 합한 국면 값이 8 이하이면서 전체 기물이 16개 이하인 위치로 정의했다. 패한 쪽의 종반 결정 681개에서 다음 문맥을 확인했다.

| 위치의 문맥 | 결정 수 | 해당 대국 수 |
|---|---:|---:|
| 룩이 남은 종반 | 545 | 42 |
| 통과폰 | 551 | 43 |
| 전진한 통과폰 | 395 | 42 |
| 공격받고 방어되지 않은 비폰 기물 | 112 | 37 |

문맥은 서로 겹치며, 빈도가 패배 원인을 증명하지 않는다. 예약 채택 대국은 진단이나 학습 자료 구성에 사용하지 않았다.

12판의 핵심 위치 24개를 자체 교사 검색으로 144회 재분석했다. 깊이 4의 자유 선택과 실제 수 강제 검색을 비교하고, 50,000·200,000 노드의 두 단계 검색도 비교했다. 합법 주수순(PV), 정확한 유한 점수, 완료 깊이와 안정성을 확인한 결과, **100 cp 이상 손실을 여러 검색이 일관되게 지지한 위치는 2개**였다. cp는 폰 1개의 가치를 100으로 놓는 점수 단위다.

- `g0004-french-r1`, 56반수: 실제 `a2a4`보다 깊이 4의 `f2f3`, 깊은 두 검색의 `h2h4`가 유리했다. 같은 깊이에서 손실은 315 cp, 깊은 두 비교에서는 210·212 cp였다.
- `g0015-french-r1`, 71반수: 실제 `d6c6`보다 나이트의 `e5d7`·`e5g4`가 유리했다. 같은 깊이에서 128 cp, 깊은 두 비교에서 144·143 cp 손실이었다. 최선 점수도 −535 cp로 이미 크게 불리한 위치였다.

이는 좋은 대안을 놓쳤다는 근거다. 순수한 평가 오류인지 탐색 부족인지, 모든 종반 패배의 공통 원인인지는 분리하지 못했다. 두 사례만으로 반복되는 룩 운용 결함을 확정하지 않았고, 메이트를 임의의 cp 값으로 바꾸지 않았다. [진단 원자료](run/diagnosis/endgame-report.json)와 [독립 감사](validation/diagnosis-audit.json)를 보존했다.

## 다양한 실제 자료와 안정된 정답

외부 엔진·데이터·모델을 가져오지 않고 합법 시작 위치(FEN) 48개를 직접 구성했다. 24개 구조 계열을 학습 16개·검증 4개·시험 4개로 먼저 나눴다. 학습에는 룩과 통과폰, 폰 경주와 킹 활동, 경·중기물의 안전과 협력 문맥이 들어간다. 차례가 다른 시작 위치도 직접 구성했으며, 단순 색 반전으로 정답을 복제하지 않았다.

새 보류 대국 16판을 먼저 수집해 전체 수순을 보호한 뒤 학습용 128판을 실제 완료했다. 수당 1,000 노드 상한·최초 교사 10,000 노드·최대 384반수·2반수 간격 표본을 사용했다. 모든 결과는 실제 규칙 판정이며, 미완료 대국을 무승부로 처리하지 않았다.

| 항목 | 실제 수량 |
|---|---:|
| 새 학습 원본 | 128판·1,877위치 |
| 안정성 기준을 통과한 학습 정답 | 1,314위치·127판·16계열 |
| 위 정답의 실제 백·흑 차례 | 652·662위치 |
| 신경망 입력 중복 제거 후 | 1,211위치 |
| 새 독립 보류 정답 | 검증 49위치·시험 81위치 |
| 기존 보류 자료 | 검증 96위치·시험 125위치, 원본 바이트 유지 |

자체 교사의 10,000 → 50,000 → 200,000 노드 답을 비교했다. 모든 단계가 정확한 유한 점수이고, 마지막 두 검색의 추천수가 같으며 점수 차가 30 cp 이내이고 완료 깊이가 3 이상인 답만 썼다. 학습 위치 563개는 추천수 불안정 315개·점수 불안정 164개·메이트 84개로 제외했다. 새 보류 자료도 처음 정의할 때만 같은 기준으로 정제해 221개 중 130개를 동결했다.

총 6,294회 교사 검색의 원시 점수·수순·정책을 독립 재계산했다. 깊은 자체 검색의 합의가 완전한 정답이나 최선 수의 증명은 아니다. [원래 학습 기보](run/endgame-train/games.pgn), [보류 기보](run/endgame-heldout/games.pgn), 정제 전 라벨과 전체 검색 기록을 보존했다.

새 학습 자료는 기존 자료의 전체 입력, 기존 검증·시험의 전체 수순, 새 보류 대국의 전체 수순, 예약 시작 풀과 과거 채택 대국의 모든 수순에 대해 정규화한 보드 및 신경망 입력 중복이 0개였다. 새 보류 자료는 영속 `endgame_holdouts`에 등록해 이후 일반 수집과 자료 합본에서도 보호한다. 완료된 학습 대국은 기존 자료 목록에 한 번만 누적한다. [자료 독립 감사](validation/data-audit.json)를 함께 공개한다.

## 자료량 실험

기존의 정제된 학습 위치 1,071개를 유지하고 새 위치 0·128·512·1,024개를 중첩 추가했다. 같은 V2 신경망 구조(768 → 32 → 16 → 1), 기존 평가에 대한 ±100 cp 보정 한도, Adam 학습률 0.003, L2 0.0001, 배치 크기 64, 100 epoch를 사용했다. 두 시드는 `2026101901`·`2026101902`이며, 같은 시드의 모든 규모는 같은 초기값으로 시작했다. BLAS·OMP·MKL 스레드는 1로 고정했다.

모델을 저장할 학습 시점(epoch)은 기존 검증 위치 96개만으로 골랐다. 새 종반 검증·시험과 기존 시험은 보고용이며, 후보나 설정 선택에 쓰지 않았다. 아래 오차는 `tanh(cp / 600)` 척도의 평균제곱오차(MSE)다. 작을수록 자체 교사의 답에 가깝지만 실제 기력과 같지는 않다.

| 새 학습 추가량 | 전체 학습 위치 | 새 종반 시험 MSE, 시드 1 | 시드 2 | 갱신 횟수 |
|---:|---:|---:|---:|---:|
| 0 | 1,071 | 0.095738 | 0.102173 | 1,700 |
| 128 | 1,199 | 0.099236 | 0.098421 | 1,900 |
| 512 | 1,583 | 0.090284 | 0.103004 | 2,500 |
| 1,024 | 2,095 | 0.102015 | 0.098268 | 3,300 |

새 종반 시험의 기존 수식 평가 오차는 0.093161이다. 1,024개 추가 모델의 새 종반 검증 오차는 두 시드에서 각각 0.058834 → 0.052724, 0.055714 → 0.052445로 줄었다. 그러나 시험에서는 한 시드가 악화하고 다른 시드가 개선했다. 자료량에 따라 일관되게 새로운 위치를 더 잘 판단하는 결과는 확인하지 못했다.

큰 자료는 같은 100 epoch에서도 학습 연산이 늘어난다. 기준 자료만 194 epoch 반복한 보조 모델은 3,298회 갱신으로 가장 큰 자료의 3,300회와 가깝게 맞췄다. 보조 모델의 새 시험 오차는 0.097352·0.102173이었다. 이 통제에서도 자료량만의 개선 근거를 얻지 못했다. 배치 분포가 다르고 epoch 단위로 근사했으므로 완벽한 계산량 통제는 아니다.

후보는 사전 정책대로 **1,024개 추가·첫 시드·선택 epoch 22**로 고정했다. 모델 SHA256은 `f4484072465f1c44dc41c1215704125a9bb61d5cfa3bf76f2496bd4d00af74a7`이다. 시험 성적이 나은 512개 모델로 바꾸지 않았다. [학습 곡선](run/curve/report.json)과 [독립 감사](validation/curve-audit-study6.json)에 상세 결과가 있다.

## 100 cp 보정 한도가 설명하는 범위

학습이나 모델 선택을 추가로 수행하지 않고, 동결된 자료에서 한도의 영향을 사후 계산했다. 각 위치에서 예측이 도달할 수 있는 범위는 `tanh((기존 평가 − 100) / 600)`부터 `tanh((기존 평가 + 100) / 600)`까지다. 교사 정답을 이 범위의 가장 가까운 값으로 옮겨 오차를 구했다.

이 계산은 **위치마다 독립적으로 최적 값을 고를 수 있다는 낙관적 가정의 이론 하한**이다. 실제로 구현하거나 학습한 모델의 성능이 아니며, 하나의 작은 신경망이 이 값까지 도달할 수 있다는 보장도 없다.

| 자료 | 위치 수 | 교사 점수가 보정 범위 밖인 위치 | 기존 평가 MSE | 이론상 최소 MSE | 고정 후보의 실제 MSE |
|---|---:|---:|---:|---:|---:|
| 새 종반 검증 | 49 | 21 | 0.057662 | 0.033436 | 0.052724 |
| 새 종반 시험 | 81 | 36 | 0.093161 | 0.057456 | 0.102015 |
| 고정 후보의 학습 자료 | 2,095 | — | 0.061323 | 0.034266 | 0.036690 |

검증과 시험에서는 이상적인 위치별 보정을 가정해도 기존 오차의 약 58.0%·61.7%가 남는다. 따라서 100 cp 한도가 일부 교사 점수를 정확히 맞추지 못하게 하는 제약인 것은 확인했다. 반면 그 한도 안에서도 시험 오차를 줄일 여지는 남는데 실제 후보는 기존 평가보다 나빴다. 학습 자료에서는 하한에 가깝고 새 위치에서는 멀다는 차이도 있다. **한도만으로 부진의 원인을 설명하거나, 한도를 늘리면 기력이 좋아진다고 결론 내릴 수 없다.** 한도는 변경하지 않았다. [위치별 계산·모델 출력·입력 해시](validation/correction-cap-audit.json)를 보존했다.

## 같은 탐색 노드 상한의 종반 개발 대국

미리 고정한 별도 종반 시작 위치 16개에서 각 규모를 기존 수식 평가와 선후공 교대로 32판씩 비교했다. 같은 실행 파일·Hash 16 MiB·단일 스레드·수당 1,000 노드 상한·동일 옵션·전체 이력과 실제 규칙을 사용했다. 다른 프로그램의 사용을 제한하지 않았고, 벽시계 시간은 비교하지 않았다. 같은 노드 상한이어도 신경망 추론 비용 등이 달라 CPU 작업량이 같다는 뜻은 아니다.

| 새 학습 추가량 | 후보 승·무·패 | 승점률 |
|---:|---:|---:|
| 0 | 4·19·9 | 42.1875% |
| 128 | 4·19·9 | 42.1875% |
| 512 | 3·24·5 | 46.8750% |
| 1,024 | 2·14·16 | 28.1250% |

총 128판이 실제 완결됐다. 이 좁고 작은 표본에서 자료량 증가에 따른 일관된 개선은 없었고, 가장 큰 후보의 성적은 더 낮았다. 이를 같은 시간의 전체 기력이나 Elo로 바꾸지 않는다. 이 결과로 후보를 바꾸거나 모델을 채택하지 않았다. [독립 수순 감사](validation/development-audit-study6.json)를 보존했다.

## 원격 채택 검증: 기존 평가 유지

사용자 PC 사용을 제한하지 않도록 최종 검증은 [GitHub Actions의 Windows 실행 환경](https://github.com/bigpine-choi/Regicide/actions/runs/39152559775)에서 진행했다. 로컬에서 동결한 실행 파일과 후보 모델을 그대로 전달했고, 입력 묶음·실행 파일·모델의 해시가 원격 결과와 같은지 확인했다. 원격 계산에 사용자 PC의 브라우저나 게임 부하는 섞이지 않는다. 다만 원격 환경의 모든 알 수 없는 부하나 열 상태까지 통제했다는 의미는 아니다.

원래 채택 조건은 **수당 100 ms 이상, 최소 32쌍(64판)의 깨끗하게 완료된 선후공 대국, 단측 승점률 하한 0.5 초과**다. 누적 시도 보정도 유지했다. 이번 시도 번호는 6이고, 시도별 오류 예산은 `0.05 / (6 × 7)`이다. 예약 시작 분포와 후보는 결과를 보기 전에 고정했다.

| 항목 | 실제 결과 |
|---|---:|
| 완료한 대국 | 8쌍·16판 |
| 후보 승·무·패 | 2·5·9 |
| 실제 승점 | 4.5 / 16, 승점률 28.125% |
| 남은 예정 대국 | 24쌍·48판 |
| 남은 대국을 모두 이긴다고 가정한 최종 승점률 | 82.03125% |
| 위 낙관적 가정의 원래 기준상 단측 하한 | 0.495953 |
| 판정 | `rejected_early_futile`, 새 모델 채택 안 함 |

남은 48판을 모두 이겨도 하한이 0.5를 넘지 못하므로, 실제 16판 뒤 조기 탈락했다. 이는 원래 최종 기준을 통과할 가능성이 없다는 **탈락 전용 판정**이다. 가상의 승리를 실제 기보에 추가하지 않았고, 32쌍 미만의 결과로 채택을 허용하지 않았다. 실제 16판 성적은 전체 예정 대국의 기력 추정이나 Elo 추정치가 아니다.

독립 감사에서 27,679조건을 확인했고, 실제 1,773수와 주수순 8,698수를 재현했다. 자원 기록은 343개, 최대 표본 간격은 0.532초였다. 감시 대상 외부 엔진·브라우저의 CPU 사용 증가나 오염은 관측되지 않았다. 전체 일정은 완료하지 않았으므로 일반 비교용 완료 표시는 거짓이며, 별도 탈락 증명이 유효함을 확인했다. GitHub 실행 정보, 결과 커밋의 부모·파일 내용, 입력 해시, 원본 기보·모델·자원 기록을 대조한 뒤 로컬로 가져왔다. 경로를 로컬에 맞춘 항목만 별도 기록했으며, 기존 채택 기준과 모델 등록 절차는 유지했다.

[원격 원본 기보](https://github.com/bigpine-choi/Regicide/blob/c2c1a80eaf3f8b8ee0ecf0a4168740681bf485ba/docs/checks/2026-10-19-endgame-learning-scale/remote-result/7a14a7b222f6/arena/games.pgn), [원격 판정 원자료](run/remote-evidence/arena/arena.json), [가져오기 감사](run/remote-import.json), [독립 원격 감사](validation/remote-audit-study6.json), [최종 연구 상태](run/cycle.json)를 보존했다. 새 모델은 채택되지 않았고 기존 수식 평가가 기본값이다.

## 규칙·기능 검증과 로컬 반영

기존 규칙·수식 평가·탐색·신경망 수식 및 보정 한도를 유지했다. 실행한 검사는 다음과 같다.

| 검사 | 결과와 증빙 |
|---|---|
| 네이티브 회귀 | 155그룹·539,633조건, 실패 0 — [로그](validation/native-build.log) |
| Python 검사 | 35개 모음 모두 통과 — [결과](validation/python-checks.json) |
| 외부 규칙 라이브러리와 차등 검증 | 2,997건 통과 — [로그](validation/rules_differential.log) |
| Godot 자동 검사 | 963건, 실패 0 — [클라이언트 검사 요약](validation/client-checks-summary.json) |
| 웹 문법·추천 수 자동 검사 | 모두 통과 — [같은 검사 요약](validation/client-checks-summary.json) |

Godot 검사는 화면 없는 자동 장면 검사와 격리된 실제 백엔드 연결 검사다. 수동 GUI 대국을 수행했다고 주장하지 않는다. 실행 코드 커밋 `43ee0082a1e1fab2538480722dc50438cba8ee2e`의 [Windows·Ubuntu 전체 CI](https://github.com/bigpine-choi/Regicide/actions/runs/39153073785)는 두 환경 모두 성공했다. 이후 커밋은 문서·증빙만 추가하며 실행 코드가 같음을 [별도 대조](validation/final-source-equivalence.json)로 확인했다. [CI API 증빙](validation/ci-study6-fixed-final.json)을 보존했다.

로컬 설치는 완료했다. 실제 설치된 실행 파일의 버전·SHA256, 기본 모델 선택과 격리된 런타임 검사 13건을 확인했다. 후보는 채택되지 않아 실제 기본 모델 선택도 기존 수식 평가였다. 연구 상태 250개 파일을 전부 같은 바이트로 반영했고, 기존 학습 상태 105개 파일과 이전 실행 파일은 `build/v064-before-endgame-learning-scale/`에 별도로 백업했다. 이전 학습 기록 중 불변 102개 파일도 새 상태에 그대로 남아 있다. 설치 전후 개인 기보 172개는 파일명과 내용을 공개하지 않고 합산 해시로 동일함을 확인했다.

설치 당시 로컬·연구·원격 소스는 `92c7d1e11a4bf9493631046339b53425678afe31`로 일치했다. 이후 검사 증빙과 이 보고서를 포함한 후속 커밋도 로컬에 반영한다. [설치 기록](validation/installation.json), [설치 후 검사](validation/post-install-checks.json), [실제 기본 모델 선택](validation/installed-selection.log), [개인 기보 보존](validation/personal-games-after.json)을 참고한다. 설치 전 검사에서 발견한 LF/CRLF 줄바꿈 차이는 실제 코드 변경과 구분했으며, 동일한 Git 원본과 줄바꿈 외 내용의 일치를 확인했다. 규칙과 채택 기준을 완화하지 않았다.

시도 5는 기보 합본 경계의 빈 줄 부족을 발견해 학습 전에 실패했다. 이를 고치고 회귀 검사를 추가했다. [실패 기록](failed-attempt-000005/cycle.json)과 원자료 29개 파일을 보존했으며, 시도 6에서 완료된 자료 파일 22개의 정책·신원·해시를 다시 확인해 재사용했다. 시도 번호를 초기화하거나 같은 자료를 중복 등록하지 않았다. Windows 경로의 8.3 표기와 긴 이름을 문자열로 비교하던 검사도 경로 정규화로 고쳤다.

실행 버전은 0.6.5다. 실행 파일 SHA256은 `e2b218e7b22f3f4f166d999f011ed08cb66120cc6a6f3265448537d72b8254e3`이며, 원격에 전달한 ZIP도 [입력 요청](remote-input-000006/remote-request.json)에 고정했다.

완벽한 종반 정답 제공기는 도입하지 않았다. 자체 교사의 공통 오류, 100 cp 보정 제한, 기존 검증 분포와 새 종반 분포의 차이, 작은 시험 표본과 시드 변동이 남아 있다. 각 요인이 부진에 얼마나 기여했는지는 이번 실험으로 분리하지 못했다. 자료량만 늘리면 자동으로 강해진다는 설명은 이번 결과로 뒷받침되지 않는다.

공개 자료에서는 사용자 절대 경로를 가릴 수 있다. 내부 해시는 원본 바이트를 가리키므로 [공개 해시 대응표](publication-manifest.json)의 원본·공개 SHA256을 구분해야 한다. 모델과 원격 입력 실행 파일 ZIP의 바이트는 유지한다.

공개 대응표에 열거한 모든 파일과 원격 입력 3개의 Git 저장 바이트를 별도로 검사한다. [공개 자료 감사](publication-audit.json)에 결과가 있다. 클라이언트 검사에 포함된 `selected-game.pgn` 등은 자동 검사에서 생성한 격리된 자료이며 실제 학습·기력 검증 판수에 더하지 않는다. 임시 절전 방지 요청도 종료했고 영구 전원 설정은 바꾸지 않았다.
