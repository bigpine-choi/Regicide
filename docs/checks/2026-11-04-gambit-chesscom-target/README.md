# 체스닷컴의 !·!!를 목표로 하는 갬빗 플레이

2026-11-04. 기준 소스 `4e4de2f`. **정책 v8의 실제 착수 경로에 전술·희생 우선 검증을 연결했다.** 좋은 희생 후보를 기존 갬빗 운영보다 먼저 검토하고, 최선 방어에 크게 손해 보는 중반 미끼를 차단한다. 자체 `!`·`!!` 분류기를 새로 만들거나 표시 기준을 바꾸지 않았다. 체스닷컴 실제 등급 증가와 전체 기력 향상은 검증하지 않았다.

## 목표와 공개 기준

사용자가 말한 `!`·`!!`는 **체스닷컴 Game Review 기준**이다. [공식 도움말](https://support.chess.com/en/articles/8572705-how-are-moves-classified-what-is-a-blunder-or-brilliant-etc)(2026-02-09 게시, 2026-11-04 확인)은 `!`를 결과에 중요한 수로, `!!`를 최선 또는 그에 가까운 좋은 기물 희생으로 설명한다. 희생 후 불리하지 않아야 하며, 그 수 없이도 이미 쉽게 이기던 상황은 제외한다. 레이팅에 따라 판정도 달라진다.

공식 설명에는 특수 등급의 세부 구현과 레이팅별 수치가 제공되지 않는다. 아래 자체 cp 기준은 그 개념을 지향하는 **개발용 보수적 조건**이며 체스닷컴 판정식이 아니다. Stockfish 감사도 Chess.com Game Review가 아니다. 상대가 미끼를 잡은 한 수순만으로 좋은 희생이라고 판정하지 않는다.

## 구현과 보호 규칙

- `scripts/sound_sacrifice.py`: 새 비폰 기물 투자를 찾는다. 합법 포획과 그 칸의 전체 합법 되잡기 교환을 확인한다. 순투자 최소 100cp이며 동가 교환, 이미 매달린 기물의 이동, 불법 포획, 계산 미완료는 근거에서 제외한다. 이는 국소 기물 투자 관측이지 보상 증명이 아니다.
- `scripts/gambit_tactics.py` 정책 v3: 희생 후보 최대 8개를 별도로 탐색한다. 희생군이 없으면 체크·포획에서 중요한 전술을 찾는다. 기준 수가 조용한 비희생 수라는 이유로 희생군을 지배하지 않게 했다.
- 동일 완료 깊이 D에서 후보와 재검증 점수가 기준 수보다 25cp 넘게 낮지 않고 0cp 이상이어야 한다. D+1도 완료해 비패배 평가를 확인한다. D+1을 D와 섞어 손실을 계산하지 않는다.
- 후보를 제외한 **나머지 모든 합법 루트 수**를 D에서 탐색한다. 그 대안이 자체 기준 250cp 이상 또는 승리 메이트면 특별한 희생 선호를 적용하지 않는다. 희생이 아닌 중요 전술은 대안이 −200cp 이하 또는 패배 메이트일 때만 검토한다. 이 숫자는 공식 등급 경계가 아니다.
- 최대 3회 자체 탐색, 기존 추가 시간 상한 1초를 상대 관찰과 공유한다. 앞 호출이 깊이를 완료하고 일찍 종료하면 남은 실제 시간을 뒤 호출에 돌려준다. 개별 요청 상한 합계와 실제 경과 시간을 분리한다. 하나의 전체 마감 시간과 watchdog을 유지하며 늦은 결과는 폐기한다.
- `boss_play.py`와 `play_human.py`: 확인된 전술은 중반 미끼 빈도가 낮아도 우선한다. 미확인 상태에서는 남은 시간으로 기존 정책을 실행하거나 기준 수를 보존한다. 시계 부족·강제 대국·체크·반복·불완전 PV·메이트 기준의 보호를 유지한다.
- 중반의 기존 `explore_traps`에도 정확한 거절 기준 **비패배 및 기준 수 대비 최대 35cp 손실**을 적용했다. 등록된 개시의 의도적 희생은 기존 정책을 유지한다.
- 정책 v8, 전술 v3가 캐시 신원에 포함되고 v7 기보를 계속 읽는다. 희생 후 운영 상태도 v8을 인식한다. 기보에는 실제 탐색 근거를 기록하지만 `!`·`!!`나 체스닷컴 등급을 생성하지 않는다.

핵심 C++ 엔진과 설치 실행 파일은 변경하지 않았다. 착수는 자체 Regicide가 선택한다. 외부 엔진은 선택 완료 후 두 사례를 감사하는 데만 사용했다.

## 실제 결과

자체 실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`다. classical activity, Hash 16MiB, LMR on, 단일 탐색을 사용했다. 8개 국면을 [실행 전에 지정](predeclared-fixtures.json)했으며, 기존 개발 사례와 명시된 합성·직접 작성 대조군이다. 미학습 일반화 평가 자료가 아니다. 참고 수를 selector에 주입하지 않았다.

`native-001`은 최초 구현으로 8/8 실행을 완료했지만 확인 후보가 0개였다. 기준 수가 후보군을 다시 지배하는 문제와 서로 다른 깊이를 섞은 품질 비교를 발견했다. 실행 당시 소스와 실패 기록을 보존했다.

수정 후 `native-002`는 **8/8 기능 실행 통과, 희생 확인 1개, 기본 탐색과 다른 실제 착수 0개**였다. 확인된 Nxe5는 기본 엔진도 이미 선택하던 수다. 이 표본에서 희생 횟수나 체스닷컴 배지가 증가했다고 주장하지 않는다. 최종 v3는 품질 조건을 유지하고 조기 완료 시간 재사용만 보완했으며, 전체 8개를 반복하지 않고 문제가 드러난 실제 host 두 사례를 재검사했다.

최종 실제 `HumanGame.engine_move` 경로는 다음 두 사례 모두 통과했다. 기준 탐색 1초, 상대 관찰과 전술·미끼 검증을 합친 추가 상한 1초, 임시 대국 저장소를 사용했다. UI 보조 평가기만 가짜이며 착수 검색과 정책은 실제 자체 엔진이다.

## 수행한 검사와 남은 한계

총 **123개 자동 검사**가 통과했다: 희생 기하 11, 전술 선택 20, 신규 host 연결 10, 기존 갬빗 선택 19, 기존 host 상태 14, 공격·지식·운영·기보 49개다. 가짜 시계를 이용한 조기 완료 재배분과 마감 뒤 결과 거부, 잘못된 깊이·점수·PV, 동가 교환과 기존 매달림, 무르기·재사용·취소·낮은 시계도 포함한다. 가짜 검색을 사용하는 연결 검사는 실제 기력 증거로 집계하지 않는다.

8국면의 같은 시작 위치 비교와 실제 host 두 사례를 수행했다. 완주 대국·승률·Elo·Chess.com Game Review·GUI 시각 검수는 수행하지 않았다. 정확한 체스닷컴 판정에는 해당 복기의 실제 결과와 레이팅 조건이 필요하다. [검토용 PGN](review-selected-moves.pgn)은 선언된 개시 뒤의 마지막 한 수만 새 정책이 선택한 미완료 사례이며, 기보 전체를 자체 대국으로 표시하지 않는다.

원시 실행과 UCI는 `native-001/evidence.zip`, `native-002/evidence.zip`에 있다. 각각의 실행 소스 ZIP과 최초 host 실패를 함께 보존했다. 최종 host 기록은 v3 소스 해시를 포함한다. 압축과 저장 시 실제 실행 바이트의 해시를 검증한다.
