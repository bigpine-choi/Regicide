# 중반의 활동적인 구상 선택 — 2026-11-02

일반 대국에서 자체 탐색으로 검증한 비슷한 후보 사이에 활동성 선호를 적용했다. 처음 16착수의 오프닝 v3 선택은 그대로 유지한다. 이 기록은 동작·시간 제한·표본 선택 검증이며 경기력이나 Elo 향상 실험이 아니다.

중반 허용 상한은 15cp이며 초반에는 기존 25cp를 유지한다. 스타일 점수는 cp와 다른 단위다. 두 수 뒤의 기하적 특징을 나타낼 뿐, 모든 전술적 안전성을 보장하지 않는다.

실제 예로 `open-center`에서는 `a4` 대신 비숍의 길을 여는 `d3`를 두 번 선택했다. 공통 완료 깊이 5에서 자체 차이는 8cp이고, 상대 응수 이후 활동 칸과 열린 선이 늘었다. `closed-center`에서는 `O-O` 대신 `Bd7`, `flank-center`에서는 `Nd2` 대신 `Qc2` 또는 `Kh1`을 선택했다. 적극성 선호가 매번 체크·희생이나 즉각 공격으로 나타나는 것은 아니다.

### 외부 비교와 남은 평가 문제

달라진 선택의 고유 조합 5개를 중복 제거하고, 고유 제한 탐색 9개로 비교했다. Stockfish 기준 새 수−옛 수 차이는 `+19, +45, +28, 0, -111cp`였다. 평균은 `-3.8cp`다. 서로 다른 엔진의 cp를 빼지 않았고, 같은 Stockfish가 각 수를 평가한 차이만 사용했다. 2초 제한 탐색은 정답·최적성 보장이 아니다.

가장 나쁜 `-111cp`는 `queen-pawn-center`에서 `…Nbd7`와 `…f5`의 차이다. 새 정책은 이때 **스타일 대안을 전혀 선택하지 않고 기본 탐색의 `…f5`를 유지했다**. 기존 방식도 나머지 세 시드에서 `…f5`를 선택했다. 따라서 이 값은 스타일 선택 때문에 생긴 손실의 증거가 아니며, 제한 시간 내 자체 기본 탐색의 불안정성과 평가 차이를 보여 주는 후속 조사 사례로 남긴다. 기존 중반에는 receipt가 없으므로 그 한 요청의 완료 깊이까지 사후 복원했다고 주장하지 않는다.

스타일이 실제로 변경한 6회는 고유 4조합이며 외부 차이는 `+19, +45, +28, 0cp`였다. 개발용 소표본의 결과이므로 기력 향상·무손실을 주장하지 않는다. 별도 국면과 계산량을 맞춘 충분한 완결 대국 검증은 아직 수행하지 않았다.

## 첫 시도에서 수정한 부분

`initial-trial/`은 폐기한 첫 정책의 원본이다. 초반에도 단기 활동성 선호를 적용했더니 이 표본의 `1.e4` 응수가 네 시드 모두 `…Nc6`로 몰렸다. 백의 `d3` 선택도 외부 비교에서 나쁜 사례가 있었다. 특정 수를 금지하거나 점수를 맞추지 않고, **처음 16착수에는 이미 검증한 오프닝 v3 후보·검증·추첨을 그대로 유지**하도록 범위를 바꿨다. 변경 전후 원본 소스와 기록을 모두 보존했다.

독립 감사는 제품의 스타일 계산 함수를 호출하지 않고 별도로 특징을 계산했다. 실제 기록 32쌍/64요청, receipt 40개, 합법 PV 358개, cp 차이 130개, 허용 후보 68개, 초반 원본 보존 8개, 중반 특징 계산 36개를 확인했다. 최종 결과는 `final-trial/independent-audit.json`이다.

최초 감사는 개별 후보에 할당한 시간의 합을 전체 시간과 비교하는 잘못된 가정으로 실패했다. 실제 탐색이 목표 깊이에 일찍 도달하면 남은 시간을 다음 후보에 다시 할당하므로 이 합은 실제 누적 시간과 다르다. 개별 요청 상한·실제 누적 시간·전체 경과 시간으로 바로잡고 재감사했다. 최초 실패 기록도 보존했다. 제품 코드는 이 때문에 바뀌지 않았다.

생산 실행 검사의 첫 스크립트는 UTF-8 기보를 Windows 기본 cp949로 읽어 실패했다. 검사 스크립트의 인코딩을 명시한 뒤 다시 통과했다. 제품 저장 동작의 오류는 아니었다. 이 검사와 Godot 검사는 사용자의 게임을 종료하거나 다시 띄우지 않았다. 실제 게임 화면을 직접 조작한 시각 검수로 보고하지 않는다.

## 재현과 증거

저장소 루트에서 아래 명령을 실행한다. 출력 폴더/파일은 새 이름을 사용한다.

```powershell
.venv-tests/Scripts/python.exe tests/dynamic_play_tests.py
.venv-tests/Scripts/python.exe tests/dynamic_play_state_tests.py
.venv-tests/Scripts/python.exe scripts/check_dynamic_play.py --output build/dynamic-play/new-comparison --reference-profile docs/checks/2026-10-21-m2-foundation/opponents/stockfish18-profile.json
.venv-tests/Scripts/python.exe scripts/audit_dynamic_play_records.py --records build/dynamic-play/new-comparison/records.jsonl --positions tests/data/dynamic_play_positions_v1.json --output build/dynamic-play/new-comparison/independent-audit.json
node tests/think_time_web_tests.js
```

`final-trial/`은 원본 기록·조건·실행 소스 스냅샷, `application-v2/`·`ui/`·`audit-validation/`은 회귀 검사 로그다. `production-smoke/production_smoke.py`는 원래 `build/dynamic-play/production_smoke.py`에서 실행한 검사 원본이므로 재실행 시 그 위치에 복사한다. 개인 기보나 인증 토큰은 포함하지 않았다.

`artifact-manifest.json`은 증거 파일의 원시 바이트 SHA-256과 제품 소스의 LF 정규화 SHA-256을 구분한다. 측정 시 원시 소스 해시는 각 trial의 manifest 및 스냅샷과 대조할 수 있다. 최종 커밋 전 Git에 저장될 바이트도 검사한다.
