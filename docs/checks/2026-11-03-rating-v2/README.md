# 스파링 사용자 레이팅 추정 v2

2026-11-03. 실제 레이팅을 입력해도 추정치가 크게 높은 문제를 조사하고 보정·관측·표시를 수정했다. 실제 수를 고르는 C++ 엔진과 바이너리는 그대로다. 개인 기보·실제 점수 원본은 수정하거나 이 디렉터리와 Git에 복사하지 않았다. 여기의 자료는 합성 입력과 직접 작성한 국면만 사용한다.

## 원인

v1은 평균 손실을 `2400 − 400 × log(1 + 손실/20)`으로 바꾸는 가설적 척도다. 80cp의 초기 가정을8개 표본만큼 계속 남겨두고, 최근40개 손실은400cp에서 잘랐다. 그 결과 첫 관측은 손실에 따라 약1635~1793, 같은 결과가 오래 반복되어도 약1304~2054에 갇혔다. 이는 Chess.com 데이터로 학습한 관계가 아니다.

실제 레이팅 보정도 가상의10대국을 둬서, 일반적인 한 판 정답은 오차의1/11, 두 판은2/12만 반영했다. 게임 끝의 편향 하나로 초반 추정까지 보정했다. 얕은 탐색의 정답·외운 오프닝·어려운 방어를 거의 같은 증거로 취급했고, 메이트 허용 수는 CP(폰100분의1점) 비교에서 빠졌다. 빠른 자동 착수에서는 기준 검색600ms 미만이라는 이유만으로 관측도 꺼졌다.

## 변경

**실제 점수 보정.** 전역 변환식의 계수를 임의로 낮추지 않고, 개인이 입력한 실제 점수의 영향력을 높였다. 가상 대국은0.25판으로 줄이고 한 판의 비중은 `min(1, 유효 관측수/8)`로 제한한다.8개 이상 관측된 한 판이면 오차의80%, 두 판이면 평균 편향의88.9%를 반영한다. 짧은 한 판을 길고 충분한 한 판과 똑같이 취급하지 않는다.

관측수1~40 단계마다 각 라벨 대국의 그 시점 추정과 실제 점수 차이를 집계한다. 짧은 대국은 마지막 관측을 사용하고40개 이후에는 마지막 보정을 유지한다. 한 대국은 단계마다 한 번만 기여하며, 적은 라벨로 기울기를 학습하지 않는다.3판 이상에서는 잔차의 중앙값 주변으로 극단값을 제한한다. 잔차의 중앙 절대편차(MAD)는 자료의 퍼짐이며 통계적 신뢰구간이 아니다.

**수의 정보량.** 깊이4/5/6/7/8 이상에0.4/0.6/0.8/0.9/1의 가중치를 쓰고, 안정 근거가 부족하거나 과거 방식의 관측이면 절반으로 줄인다. 실제로 익숙한 후속 수·명백한 퀸 포획·안전한 되잡기를 정확히 둔 경우는 추가로0.2배다. 그 위치에서 큰 실수를 한 경우에는 쉬운 정답 할인을 적용하지 않는다. 최선수와 실제 수의 평가가 모두 같은 방향으로±600cp 이상이면 이미 기운 형세의 정보량을0.25배로 줄인다.

최근40개 정보 관측의0.94 감쇠는 유지하되, 초기 가정의 무게를 `8 × exp(−누적 정보량/12)`로 줄이고 손실 상한은1200cp로 넓혔다. 표시 숫자는 검증된 판단마다 갱신하지만, 자료가 없을 때 숫자를 만들거나 억지로 움직이지 않는다. 기존 전역 척도가 검증된 Chess.com 환산식이 된 것은 아니다.

**엄격한 관측과 메이트 사건.** 같은 착수 전 국면·완료 깊이·정확한 원시 점수 패킷·실제 선택 수·올바른 흑백 관점·합법 수순을 확인한다. 단일 얕은 결과는 제한된 근거이고, 공통된 연속 깊이에서 수와 점수가 일치해야 안정 근거로 쓴다. 새로운 근거가 무효이면 오래된 CP 필드로 우회하지 않는다. 시간 초과 결과도 버린다.

메이트 허용/메이트 기회 놓침은 별도 사건이다. 가짜 CP를 만들지 않고 각각400/250을 정보량·최근성으로 줄인 별도 레이팅 감점으로 사용하며 합계600 상한을 둔다. 이 값도 직접 정한 가설이며 인간 데이터에서 학습하지 않았다. 이미 패배한 메이트 진행과 메이트 유지에는 새 실력 정보가 없다고 보고 관측·감쇠·보정 단계를 진행시키지 않는다. 합법 메이트 수순 검사는 그 수순의 정합성이며 모든 방어에 대한 증명은 아니다.

**빠른 착수의 관측.** 기준 검색이600ms 미만이거나 전체 양보 탐색을 넣기 어려운 시간에도, 처음 정한 검색 예산이 남아 있으면100~500ms의 사용자 수 분석만 수행한다. 실제 경과시간과 최신 시계 경과량 중 큰 값을 차감하고25ms 여유를 남긴다. 잔여10초 이하·강제/핸디캡·사용자 수 없는 상태·종료/다른 대국에서는 실행하지 않는다. 이 경로는 현재 선택 수를 기준수 그대로 유지하며 전체 할당시간을 늘리지 않는다. 시간 부족으로 분석 근거를 얻지 못하는 경우는 여전히 있다.

**호환성과 화면.** v1 기보는 당시 공식을 그대로 재생한다. 기존 v1/v2 정답 라벨은 같은 실행 파일·평가 설정의 기록만 메모리에서 재계산하고 원본 DB는 읽기 전용으로 연다. 현재 판의 정답으로 그 판의 추정 곡선을 다시 맞추지 않으며 다음 판부터 사용한다. 화면 숫자와 마지막 변화량은 유지하고, 정보량이 적으면 `표본 적음`을 표시한다. 설명에는 분석한 수와 실제 점수 보정 판수를 보여준다.

## 검증

- [단위·호스트250개](unit/validation.json) 통과. 신규 모델21개·관측22개·빠른 착수 호스트11개를 포함한다. 분석 분리, 예산, 모드, 시계, 저장·무르기, 보정, 잘못된 근거 배제를 확인했다.
- [Godot77개](godot.log)와 [브라우저 검사](browser.log) 통과. 실제 UI 코드의 자동 입력/상태 검사이며 사람이 직접 대국한 평가는 아니다.
- [독립 감사](independent-audit.json)에서 v1 원본 커밋 `32d9e644bd0c971c332ecbded47debe0404784d4`와129개 색상·보정·기보 접두 구간이 정확히 같음을 확인했다. 미래 관측 차단, 라벨 DB 불변, 손상 자료와 다른 평가 설정 배제, 정보0 사건의 점수 불변도 검사했다. 감사에 포함된 호스트11개는 위250개와 겹친다.
- [실제 자체 엔진 관측](native-evidence/validation.json): 기존500ms 예산에서 `f3 e5 g4`의 메이트 허용을 깊이5·222.518ms에, `e4`의 CP 비교를 깊이6·320.362ms에 얻었다. [첫 사례 원시 자료](native-evidence/allowed_fools_mate.json)와 [둘째 자료](native-evidence/ordinary_opening.json), UCI 로그를 보존했다. 원시 PV26개가 모두 합법임을 별도로 재생 확인했다.
- [실제 HTTP 연결](http/validation.json): 자동 스파링의600ms 미만 기준 검색에서도 별도 관측을 얻고, 기준 착수를 유지하며 v2 숫자를 표시했다. 합성 정답 저장은 현재 곡선을 바꾸지 않고 다음 대국부터 반영되었다. 기록 재생과 실제 정답 비공개 저장도 확인했다. 표시 대기는 정식 즉시 착수 기능으로 생략했으므로 착수 간격 측정은 아니다.

개인 기록에 대해서는 이전 판의 라벨만으로 이후 판을 다시 계산하는 읽기 검사도 수행했다. 세부 점수·기보·정답은 저장소에 공개하지 않는다. 소수 로컬 대국의 재계산과 학습에 사용한 대국의 오차는 일반화 정확도 증거가 아니다. 독립된 다수 사용자·대국에 대한 오차, 기력별 편향, Chess.com 래피드와의 일치율은 아직 검증하지 않았다. 봇이 제공한 쉬운 국면, 얕은 엔진 판단, 시간 부족에 따른 관측 누락은 남은 한계다.

실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`로 동일하다. [검증 소스 일치](source-verification.json)와 [근거 파일 해시](artifact-manifest.json)를 보존한다. 진행 중인 사용자 게임을 종료하거나 개인 라벨을 덮어쓰지 않았다. 원격 CI 실행 완료를 주장하지 않는다.

## 재현

```powershell
.venv-tests/Scripts/python.exe tests/sparring_rating_tests.py
.venv-tests/Scripts/python.exe tests/sparring_rating_v2_tests.py
.venv-tests/Scripts/python.exe tests/sparring_rating_state_tests.py
.venv-tests/Scripts/python.exe tests/rating_evidence_tests.py
.venv-tests/Scripts/python.exe tests/rating_observation_host_tests.py
.venv-tests/Scripts/python.exe tests/rating_evidence_integration.py --output build/rating-evidence-repeat
.venv-tests/Scripts/python.exe tests/sparring_rating_integration.py --output build/rating-http-repeat
```

새 출력 경로를 사용한다. [당시 실행한 독립 감사 스크립트](independent_model_audit.py)는 저장된 원본이다. 재실행할 때 `build/rating-audit-repeat/`를 만들고 그 안으로 복사하여 실행한다. 해당 스크립트는 실행 위치 두 단계 위를 저장소로 사용하고, 옆에 새 결과를 쓴다. 개인 DB가 아닌 임시 합성 DB만 사용한다.
