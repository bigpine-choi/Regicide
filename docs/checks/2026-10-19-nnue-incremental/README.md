# NNUE 증분 평가 구현·검증

## 범위

- 기준: `feat/endgame-learning-scale`의 `3c3d4b4526e1fa0c927347d9974534e4385ea601`.
- 결과: v0.6.6, 선택적 고정소수 첫 층과 탐색별 증분 누산기. 기존 768→32→16→1의 V1/V2 파일·double 경로·수식 평가·채택 기준 보존.
- 새 학습, 후보 채택, 강도 대국, 사용자 OMEN 설치는 수행하지 않았습니다. 아래 결과는 개발 환경의 정확성·실행 비용 검사입니다.

## 검증

Linux x86-64, AMD EPYC 9V74로 표시되는 공유 개발 환경, GCC 13.3.0, CMake Release의 기본 `-O3 -DNDEBUG`와 엄격한 경고 설정입니다. 전용 SIMD·네이티브 CPU 플래그·LTO를 추가하지 않았습니다. Python 3.12, chess 1.11.2를 사용했습니다.

| 검사 | 결과 |
|---|---|
| CMake Release 빌드 및 CTest | 8/8 통과 |
| 새 NNUE C++ 검사 | 9개 묶음, 219,178개 확인 통과 |
| NNUE UCI/CLI 통합 | 6/6 통과 |
| 기존 신경망 통합 | 15/15 통과, Python/C++ 46국면×6모델 포함 |
| 기존 엔진 통합 | 27개 묶음 통과 |
| python-chess 규칙 대조 | 2,997국면 통과 |
| NNUE ASan+UBSan | 통과, 환경의 프로세스 검사 제한으로 LeakSanitizer만 비활성 |
| 변경 공백·Python 문법 검사 | 통과 |

새 기준 계산은 모델 파일의 행렬 순서에서 정수 첫 층과 뒤층을 직접 계산합니다. 양 관점, 반올림 경계, ReLU 전후, ±100 극값, 백·흑 캐슬링/앙파상/4종 승격/승격 포획, 무작위 이동·되돌리기·형제 가지를 포함합니다. 독립 minimax와 quiescence를 실제 탐색과 비교하고 정지·모델 교체·모드 변경·재사용 탐색 문맥도 확인합니다.

별도로 기준 커밋을 같은 컴파일러로 빌드하고 10국면×수식/기존 신경망을 각 10,000노드에서 비교했습니다. 시간과 TT 저장 바이트를 제외한 CLI 결정·통계는 20/20쌍 같았습니다. [기준 호환 기록](baseline-compatibility.json).

## 실제 모델과 비용

모델은 기존 `docs/checks/2026-10-19-neural-cost-quality/run/model/small-v2.nn`입니다. SHA-256은 `5b363fa05487d7707d943c26c8a8343c86122315ecd61f88003692ff449291b3`이며 이번에 새로 학습하거나 채택한 모델이 아닙니다. 측정 바이너리 SHA-256은 `e154c308073c6352f8a66514b75fd7673adc251bf6cad072faf4bfbfed558334`입니다.

정적 측정은 고정 시드의 256개 합법 이동 전후 국면, 방식당 500,000회×3라운드의 중앙값입니다. 순서를 회전하며 이동 생성과 로딩은 제외합니다. NNUE 비용에는 부모 복사·양 관점 갱신·자식 평가가 포함됩니다.

| 방식 | 평가 1회 중앙값 |
|---|---:|
| 기존 double 전체 계산 | 654.089 ns |
| 양자화된 모델 전체 재계산 | 979.465 ns |
| NNUE 증분 갱신+평가 | 582.263 ns |

이 표본에서 증분 계산은 기존 경로보다 약11.0% 짧았고, 256국면의 정적 cp 차이는 0이었습니다. [정적 측정 원자료](profile-v2.json).

전체 탐색은 기존 `tests/data/profile_positions.json`의 10국면×5회, 순서를 섞은 50쌍입니다. 각 쌍은 같은 바이너리·모델로 NNUE만 켜고 끕니다. 외부의 다른 테스트나 벤치마크와 동시에 실행하지 않았습니다.

| 예산 | NNUE/기존 시간 비율의 쌍별 중앙값 | 결정·완료 깊이·노드·qnodes·PV 차이 |
|---|---:|---:|
| 10,000노드 | 1.0000 | 0/50쌍 |
| 100,000노드 | 0.9864 | 0/50쌍 |

100,000노드의 합산 시간은 기존17,954ms, NNUE17,662ms입니다. 전체 탐색 이득은 이 환경에서 약1%대로 작고, 공유 CPU와 밀리초 측정의 변동이 있습니다. 반복 하드웨어 검증이나 통계적 성능 보증으로 해석하지 않습니다. [10k 원자료](search-v2.json), [100k 원자료](search-v2-100k.json). 저장 JSON에는 모델·바이너리·국면 파일 해시, 고정 시드, 실행 순서를 포함합니다. 실행 순서는 당시 코드의 고정 시드에서 재구성했고 저장된 쌍 순서와 일치함을 확인했습니다.

작은 네트워크에서 양 관점 유지·부모 복사·모든 실제 자식의 갱신 비용이 이득을 줄입니다. 지연 갱신, 정수 폭/SIMD, 특징·용량 변경은 후속 실험 과제입니다. 이번 결과로 기력이나 Elo가 올랐다고 결론 내리지 않습니다. 대국으로 검증할 때는 `UseNNUE=true`를 포함한 조건을 기록해야 하며 기존 arena는 이를 자동 활성화하지 않습니다.
