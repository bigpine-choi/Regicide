# 오프닝 다양성 검증

## 달라진 동작

일반 대국의 처음 6번 착수에 한해 오프닝 후보를 고르고 자체 Regicide로 검토한다. 기본 1초 설정에서는 자유 검색 500ms와 후보 제한 검색 최대 500ms를 사용한다. 최소 깊이 3의 같은 완료 깊이에서 35cp 이내이고, 합법 수순·정확한 점수·추가 깊이의 불리한 결과 없음 조건을 만족할 때만 대안을 채택한다. 다른 경우 기존 합법 수로 복귀한다. C++ 탐색·평가식과 기본 UCI 선택은 바꾸지 않았다.

첫 후보 목록은 프로젝트에서 정했고, 이후 후보는 고정된 CC0 오프닝 자료에서 실제 전체 수순과 일치하는 바로 다음 합법 수다. 후보 자료는 강도 평가로 취급하지 않는다. Stockfish는 선택과 검증에 사용하지 않았다. [정책 상세](../../OPENING_VARIETY.md)

## 실제 엔진 실행

Regicide 0.7.0-dev의 기본 공식 평가, 한 수 총 예산 1000ms로 임시 게임 20개를 실행했다. 바이너리 SHA256은 `edd950fb673cfca4134968b64cc5ef0f3d77eda698e9f40d2965170f143d6e6a`로 기존 실행 파일과 같다.

| 국면 | 실제 선택된 수 |
|---|---|
| 백 첫 수 | c4, d4, e4, Nf3 |
| 1.e4 뒤 흑 | c5, c6, e5, e6 |
| 1.d4 뒤 흑 | d5, e6, f5, Nf6 |
| 1.c4 뒤 흑 | c5, e5, e6, Nf6 |
| 1.Nf3 뒤 흑 | c5, d5, g6, Nf6 |

각 후보가 제안되는 고정 seed를 하나씩 골라 모든 경로를 검사했다. 위 수가 각각 한 번씩 나왔다는 것은 균등한 실제 선택 빈도를 측정했다는 뜻이 아니다. 기본 동작은 대국마다 새로운 seed를 만들므로 같은 오프닝이 연속으로 나올 수도 있다.

대안으로 채택한 모든 실행에서 비교 깊이는 6, 손실 허용 기준은 35cp 이내였다. 양 검색 예산의 합이 1000ms를 넘지 않고, 실제 선택 수와 저장 기록이 일치하며, PGN 보관함 내보내기에 seed와 정책이 남는 것을 확인했다. `1.e4` 응수 4개는 무른 뒤 같은 수순을 다시 두어 동일 선택과 memo 재사용을 확인했다. 100ms 설정은 전액 일반 검색으로 돌아가는 것도 확인했다.

전체 합법 수순·비교 점수·깊이·선택 이유는 [live-evidence.json](live-evidence.json)에 있다. 모두 합성한 표준 초기 국면이며 사용자 기보나 실행 중인 게임을 사용하지 않았다. 임시 기보는 검사 종료 후 정리했다.

## 회귀 검증과 한계

- 정책/활성 대국 검사 23개: 35/36cp 경계, 흑 점수, 같은 깊이, 깊은 불리한 결과, 합법 수순, 메이트·경계값 제외, 예산 변경, 후보 실패·시간 초과 복귀, 후보 점수 표시 차단, 무르기·새 대국·핸디캡·흑 선택 첫 수 보존을 포함한다.
- 기존 회귀 60개 통과: 평가 상태 21개, 시간 설정 스트림 1개, 추천 상태 14개, 일반 대국 24개. 별도 바이너리 옵션이 필요한 선택 검사 2개는 이 mock 실행에서 건너뛰었다. 실제 엔진 활성 정책은 아래 20개 실행으로 별도 검증했다.
- 기보 보관함 검사: 24개 중 22개 통과, 2개 선택 검사 건너뜀(이 계정의 심볼릭 링크 권한 및 별도 바이너리 옵션 검사). seed/정책 내보내기와 비정상 metadata 차단을 추가했다.
- 실제 엔진 경로 20개, 응수 되돌리기 4개, 초고속 예산 예외 1개 통과.

평가 후보를 비교하므로 한 번의 전체 시간 탐색과 검색 경로·깊이가 다르다. 경기력 향상이나 동일 경기력은 입증하지 않았고, 35cp는 자체 제한 탐색의 허용 기준이지 객관적인 무손실 보장이 아니다. 기본 분석·코칭·추천 수에는 이 선택 정책을 호출하지 않는다.

재현:

```text
python tests/opening_variety_tests.py
python tests/game_archive_tests.py
python docs/checks/2026-11-02-opening-variety/verify_live.py
```

마지막 명령은 저장소의 `build/regicide.exe`를 사용하고 `build/opening-variety-replay/`에 결과를 기록한다. 외부 부하는 통제하지 않았으므로 결과의 실행 시간은 속도 비교 자료로 사용하지 않는다. 시간 제한 검색은 부하에 따라 완료 깊이가 달라질 수 있으며, seed만으로 검색 결과 전체가 결정되지는 않는다.
