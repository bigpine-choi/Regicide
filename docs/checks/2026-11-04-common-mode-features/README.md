# 모든 대국 모드의 시계 조절과 실제 레이팅 기록

기본·갬빗·스파링에 같은 시계 조절과 실제 상대 레이팅 입력을 제공한다. 시계는 양쪽 각각 −1분·−10초·+10초·+1분으로 조절하며, 진행 중인 AI 착수의 시간 목표도 다시 계산한다. 시계 편집은 체스판 수정 번호를 바꾸지 않으며, 별도의 시계 수정 번호로 오래된 요청과 동시 클릭을 구별한다. AI 시간이 소진되어 확정된 패배는 시간을 추가해도 되살리지 않는다.

실제 Chess.com 래피드 레이팅 입력은 완료된 대국에서 받으며 기존 스파링 경로와 새 공통 경로를 모두 지원한다. 입력값은 개인 로컬 DB에만 기록하고 공개 JSON·PGN에는 넣지 않는다. 기본·갬빗에서 검증된 관측이 없으면 추정치를 만들지 않고, 그 기록을 추정 보정 자료로 사용하지 않는다. 저장 실패·오래된 대국 요청·잘못된 숫자를 거부하며, 무르기로 대국을 재개하면 이전 입력을 무효화한다.

## 검증

`host-regression.json`에 실제 수행 결과와 소스 해시를 보존했다. 시계 호스트 14개·레이팅 상태 및 HTTP 14개·공통 시간 관리 호스트 6개, 총 **34개 통과**, 실패·스킵 0이다.

양쪽 색 및 세 모드의 시계 상대 역할, 실제 HTTP의 공통 레이팅·시계 경로, AI 탐색/대기 중 편집, 편집 후 시간 목표, 동시 요청, 만료 시 늦은 착수 차단, 무르기·핸디캡 경계, 실제 레이팅 수정 및 공개 기록 비포함을 확인했다. 엔진 응답과 시계를 통제한 기능 검증이며 실제 엔진 대국 성능 측정과 구분한다. 실제 엔진을 사용한 세 모드 HTTP 통합 검증은 [Stockfish 게이지 검증](../2026-11-04-stockfish-gauge/README.md)과 함께 기록한다.

일반 기보 목록도 부모 영역까지 세로 확장을 전달하도록 고쳐 남는 높이를 채운다. 실제 렌더에서 1760×960은 19행, 1240×860과 900×680은 11행이 보였다. [창 크기별 렌더 및 공통 UI 검증](../2026-11-04-shared-game-ui/README.md)을 참고한다.

`analysis-coaching-web.json`은 분석 45개·코칭 95개·Stockfish 코칭 참고 8개 웹 동작 검사 결과를 기록한다. Stockfish와 자체 엔진의 점수를 다르게 넣어 출처를 확인하고, 미준비·실패·다른 위치에서는 게이지가 중립인지 확인한다. 규칙으로 확정된 종료 결과는 그대로 표시한다.

함께 적용한 변경의 상세 근거: [공통 착수 시간 관리](../2026-11-04-common-human-pacing/README.md), [3회 반복 조기 종료 수정](../2026-11-04-repetition-draw/README.md), [모든 모드 Stockfish 게이지](../2026-11-04-stockfish-gauge/README.md). 공통 UI는 Godot 836개 검사와 12장 실제 렌더를 통과했다. 각 결과의 통제된 검사·실제 엔진·화면 렌더 범위와 스킵 수는 개별 기록에 명시했다.
