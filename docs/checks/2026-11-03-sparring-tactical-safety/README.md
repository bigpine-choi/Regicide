# 스파링 나이트 헌납 재현 및 최종 수 안전 검증

## 재현 대상과 원인

사용자가 지적한 대국의 첫 16 ply를 재생했다. 원본 개인 기보는 수정하지 않았으며 재현에는 이 수순만 사용한다.

`b1c3 e7e5 g1f3 b8c6 d2d4 e5d4 f3d4 c6d4 d1d4 g8f6 c3b5 f8e7 c1f4 d7d6 e1c1 e8g8`

문제 수순은 `9.Nxa7 c5 10.Qa4 Bd7 11.Qb3 Rxa7`. Nxa7 직후에는 퀸이 a7을 지켜 단순한 한 수 교환 검사를 통과하지만, 보호선 차단과 퀸 공격으로 나이트를 잃는다. 원래 깊이 5 탐색의 Nxa7/+17cp를 실제 Regicide 실행으로 재현했다. 기존 경로는 기본 수가 접전 범위이면 양보 후보 검사를 건너뛰고, 외부 심판도 비교 후보가 없으면 기본 수를 유지했다.

## 변경

- `sparring_safety.py`는 최종 선택된 수가 즉시 기물 헌납, 즉시 메이트 허용, 잡힐 수 있는 고가 기물의 저가 기물 포획에 해당하는지 검사한다. 모양만으로 희생을 금지하지 않는다.
- 최종 심판 선택 이후, 실제 수 적용 전에 검사하여 기본 수와 양보 수 모두 포함한다.
- 원래 수 뒤 상대의 자유 응수 → 자체 엔진의 대안 탐색 → 대안 뒤 독립 응수 탐색을 수행한다. 새로운 수는 Regicide가 선택하며 외부 엔진을 수 선택에 추가하지 않는다.
- 대안 루트는 완료 깊이 5 이상, 두 응수 탐색은 깊이 6 이상을 요구한다. 대안 루트와 응수 모두 원래 응수 평가보다 최소 100cp 좋아야 하며, 대안의 두 평가 차이는 120cp 이하여야 한다. 완전한 합법 PV, 동일 패킷의 점수·깊이, 관점, 반환 수 일치를 검사한다.
- 보상이 확인된 위험 포획과 검증된 자기 승리 메이트는 유지한다. 직접 기물 헌납은 전체 형세가 아직 양수여도 더 나은 대안을 비교한다.
- 기본 추가 예산은 최대 12초이며 30/40/30%로 나눈다. 남은 시간이 3분 아래이면 제곱 비율로 줄이고, 10초를 보호한다. 부족한 예산·취소·시간 초과·불완전한 분석에서는 기존 합법 수를 보존하고 미검증으로 기록한다.
- 검증 뒤 별도 대기를 추가하지 않는다. 기보에는 이전 선택과 세 단계의 근거를 보존하며, 상대 실력 추정용 관측값도 유지한다. 응수에서 불리함이 확인되면 기존의 접전 충족 표시를 그대로 두지 않는다.

## 검증

최종 실제 엔진 결과와 실행 조건, 소스·실행 파일 SHA-256은 `native-host.json`에 기록한다. 재현 스크립트는 `tests/sparring_safety_native_integration.py`다. 고정 깊이 5는 기록된 오판을 재현하기 위한 통제이며, 이후 검증은 실제 시간 제한을 사용한다. 개인 대국 저장 폴더 대신 임시 폴더에서 실제 호스트를 실행한다.

최종 시험은 통과했고 실행 전후 소스 해시가 일치했다. 모두 백 기준이며, Stockfish 18 평가는 수 선택 이후 독립적으로 수행했다(1스레드, Hash 32MiB, 2초). Regicide의 별도 사후 평가는 새 엔진에서 3초를 사용했다.

| 조건 | 실제 선택 | Regicide 별도 평가 | Stockfish 별도 평가 |
|---|---|---:|---:|
| 안전 검사 비활성 대조군 | Nxa7 | -1.60 | -4.51 |
| 수정 후 반복 1 | Qc4 | -0.30 | -0.80 |
| 수정 후 반복 2 | Qc4 | -0.30 | -0.75 |

수정 후 두 번 모두 실제 보드에 Qc4가 적용되고 ±1.00 이내로 평가됐다. 전체 호스트 처리 시간은 각각 약 12.94초, 12.93초이며 추가적인 대기 시간은 0이었다. 이 위치에서 기존 전술 실수를 회피했다는 근거이며 모든 국면의 균형을 보장하는 결과는 아니다.

실행한 자동 회귀 검증은 중복을 제외해 266개다.

| 묶음 | 통과 수 |
|---|---:|
| 안전 검증 모듈 | 20 |
| 최종 호스트 안전 검증 | 8 |
| 기존 회복 호스트 | 14 |
| 기존 스파링 상태·평정 상태·평가 상태 | 31 |
| 스파링 정책·페이싱·심판·후보군·회복 정책·엔진 페이싱 | 193 |

9초 예산에서는 마지막 응수의 최소 깊이가 확보되지 않아 원래 수를 유지한 실패도 확인했다. 이를 `9000ms-failed-diagnostic.json`에 남기고 12초 상한으로 최종 검증했다. 초기 탐색 실험 파일은 진단 자료이며, 소스가 동결된 최종 검증과 구분한다.

## 한계

이 검증은 같은 위치의 단일 수 선택 회귀 시험이다. 전체 대국의 접전 유지, 승률, Elo 향상, 모든 장기 전술의 예방을 증명하지 않는다. 위험 징후와 제한된 탐색으로 놓치는 수가 있을 수 있으며 시간 부족에서는 추가 검증을 생략한다. 실제 화면에서 사람이 대국한 수동 검증은 수행하지 않았다. 실행 중인 앱에는 재시작이 필요하다.
