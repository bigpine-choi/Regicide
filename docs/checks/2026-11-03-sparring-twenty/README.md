# 스파링의 접전 구간을20수로 단축

2026-11-03. 새 정책 `regicide-sparring-play-v4`는20수까지 접전을 목표로 조절하고,21~69수에 양보를 선형으로 줄이며, 백·흑 각각70번째 착수부터 기준 최선수를 유지한다. 초기 관측 수집과 기물 부족 위험 시 양보 중단은 계속 적용된다.

강화 진행도는 `clamp((현재 fullmove − 20) / 50, 0, 1)`이다. 백과 흑에 같은 값을 적용하며 매 수2%p씩 증가한다. 기존 상대 관측에 따른 양보량에는 남은 비율을 곱하고, 형세 목표와 후보 압박 가중치도 같은 진행도를 사용한다.

| 착수 번호 | 강화 진행도 | 일정 |
|---|---:|---|
| 20수 | 0% | 접전 조절 마지막 수 |
| 21수 | 2% | 강화 시작 |
| 30수 | 20% | 강화 중 |
| 45수 | 50% | 강화 중 |
| 69수 | 98% | 강화 중 |
| 70수 이후 | 100% | 양보 없이 기준 최선수 |

이는 정책의 전환 계수다.20수의0%가 엔진 기력0을 뜻하지 않으며, 실제 Elo·형세·착수 품질이 등차수열로 변한다는 주장도 아니다.70수 이후에도 사용 가능한 시간 안에서 자체 엔진이 찾은 기준수를 사용하며 승리를 보장하지 않는다.

큰 기물 손실의 새 보정 사건을 받아들이는 구간과 조기 자원 보호의 발동 구간도20수까지로 맞췄다.20수 이전에 발생한 손실의 기존4회 보정은 잠시 이월될 수 있으나 강화 진행도에 따라 감쇠한다. 저장된 과거 사건·개인 라벨·실행 중인 게임은 수정하지 않았다.

## 호환성과 검증

- 새 v4를 추가하고 v1/v2/v3의 단계·프로필 해석을 보존했다. 과거 v3는30수까지 접전,31~69수 강화로 계속 읽는다. 레이팅 관측, PGN, 대국 진단과 요약 도구에도 v4를 추가했다.
- 현재 대국 진단의 기본 집계 구간은20수다. 과거 보고 구간은 유지하며, 서로 다른 정책 결과를 자동으로 합치지 않는다. 화면 안내와 툴팁도20수 기준으로 변경했다.
- [핵심·상태 검사119개](core/validation.json)와 [레이팅·대국 진단·집계53개](consumers/validation.json), 총172개 통과.20~70수의 백흑 모든 착수에서2%p 증가,20/21·69/70 경계, 과거 정책, 손실 보정·자원 보호, 저장과 관측을 검사했다. 일부 단계 검사는 반복 가능한 합성 수순을 사용하며 실제 완주 대국이 아니다.
- [Godot77개 및 브라우저 검사](ui/validation.json) 통과. 수동 GUI 대국 검사는 아니다.
- [실제 자체 엔진 HTTP 연결](native/result.json)에서 양색의 스파링 착수·형세 분석·저장 정책을 확인했다. 이는 연결 기능 검사이며,70수 완주·승률·기력 향상 검사는 아니다. 실행 파일 SHA256은 `5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba`다.

[검증한 소스](source-verification.json)와 [산출물 해시](artifact-manifest.json)를 보존했다. 오프닝 시간 상한과 잔여4분 시간 관리는 유지했다. Regicide를 재실행하고 새 대국을 시작하면 적용된다.
