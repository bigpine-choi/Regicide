# 갬빗 이론 학습·신규 수순 연구: 개발 검증

기준은 `bigpine-choi/Regicide`의 `059f7f70ba25ff3c616b081c99a310e1adf9e583`이다. 자체 엔진의 오프닝 분석을 재현 가능한 학습 자료로 만들고, 같은 기점에서 새 희생 후보를 조사하는 오프라인 도구를 구현했다. 실제 착수의 핵심 엔진은 자체 Regicide를 사용한다. 외부 엔진의 수나 평가를 학습 목표에 넣지 않았다.

## 구현과 검증 경계

에번스·스미스 모라·알빈·벤코에서 각 8개, 총 32개 국면을 고정했다. 공격 진영 차례 17개·방어 진영 차례 15개이며, 제안 직전 4개·상대 응수 4개·후속 분기 16개·자료 종료 8개다. 원자료의 이름은 최선 수의 정답이나 실제 포획의 증명이 아니다.

훈련은 에번스·모라, 검증은 알빈, 보류는 벤코다. 현재 위치와 모든 합법적인 직후 위치에 대한 교차 분리 중복은 0개다. 전체 이력을 표준 시작판에서 재생하고, 자료의 합법 EP FEN과 UCI의 raw EP FEN을 각각 같은 재생 상태와 대조한다.

신규성 인덱스는 갬빗 1,315개와 전체 정식 오프닝 3,865개 수순에서 7,983개 위치·8,192개 전이를 구성한다. 원본 commit은 `a6189a30dc273ccb21fc2536a9a2fefd5592a67a`, 라이선스는 CC0-1.0이다. a~e·LICENSE의 SHA256을 검증한다. 추가 실전 PGN은 이번 실행에 제공하지 않았으므로 신규성의 범위는 이 고정 자료뿐이다.

Python 관련·기존 회귀 106개와 CTest 12개가 모두 통과했다. 원문은 `python-tests.txt`, `ctest.txt`, 환경과 집계는 `validation.json`에 있다. 패치는 기준 README와 신규 파일에 실제 적용한 뒤 모든 바이트가 변경 파일과 같은지도 확인했다.

## 최종 실험과 감사

최종 근거는 `native-v4/`이며, `independent-audit.json`은 실제 UCI 송수신과 결과 파일을 별도로 재생한 감사다. 원시 질의의 전체 이력·노드 요청·CP 관점·완료 깊이·PV·반환 수, 두 계산 예산의 목표값, 분리 누수, 학습 가중치와 검증 선택 및 보류 결과를 확인한다. 발굴 후보의 모든 합법적인 첫 방어, 포획 후 기물 균형과 되잡기, 신규성 범위, PGN 재생도 대조한다.

실행 조건은 Linux x86_64, g++ 13.3.0 Release, Python 3.12.14, python-chess 1.11.2다. 바이너리 SHA256은 `ea3fbfcf84c724f22a80c2ef28c40d04b6631ccb1b858fcec685000a16d36fe7`이다. 현재 자체 엔진 기본 옵션으로 복원하고 `UsePieceActivity=true`, Hash 기본 16MiB를 썼다. 모든 질의는 새로운 UCI 대국과 전체 이력을 사용한다. 기본 100,000노드·심층 400,000노드, 후보 최대 3개, 발굴 기점 4개, 전체 벽시간 상한 600초다. 계산 예산은 같지만 완료 깊이가 다를 수 있다.

가중치를 생성해도 평가기 학습이나 기력 향상을 증명한 것은 아니다. 실험 모델은 기존 후보 순서와 자체 기준 수보다 나아지는지 따로 비교하며, 검증·보류 각 2계열 이상이라는 채택 범위도 충족해야 한다. 이번 네 계열 구성은 해당 범위가 부족하다. 기존 대국 정책 `data/gambits/policy.json`과 C++ 엔진은 변경하지 않았다.

최종 실행은 실제 요청·처리 노드 모두 80,100,000개, 질의 513개다. 510개는 최소 깊이와 정확한 점수 조건을 충족했고 3개는 불충분한 분석으로 구분했다. 두 예산에서 안정적인 학습 자료는 30국면·90후보이며, 훈련 14·검증 8·보류 8국면이다. 훈련 분리만으로 순위 모델을 실제 학습했다.

책 후보의 기존 순서보다는 개선됐지만 자체 기준 수를 넘지 못했고 검증·보류의 계열 폭도 부족하므로 채택하지 않았다. 모델은 `trained=true`, `status=experimental`, `active=false`로 보존했다.

발굴은 4기점에서 12후보를 조사했고, 품질·지속적인 기물 투자 조건을 모두 통과한 후보는 0개다. 9개 실제 기물 제안에서는 모든 합법적인 첫 방어를 조사했다. 나머지 후보는 실제 기물 제안이 없는 자체 기준 수였다. 원시 수순 12개는 `discovery.pgn`에 결과 `*`로 남겼다. 완주 대국이나 신규 갬빗 발견 실적으로 집계하지 않는다.

최종 실행 중 소스와 바이너리의 지문은 같았고, 소유한 엔진의 정상 종료 및 반환 코드 0을 확인했다. 질의 벽시간 합은 341.881초이며 준비·파일 처리 시간은 별도다. 앞선 일부 실험이 병행됐으므로 속도 비교로 사용하지 않는다. 최종 기록은 메모리·JSON 배열·JSONL의 513개 질의와 원시 UCI를 대조한다. 중간 체크포인트는 511행이었으며 이 차이를 숨기지 않고 보존한다.

발굴은 한정된 계산량의 후보 조사다. 상대의 모든 첫 응수를 검사해도 이후 모든 수순의 건전성을 증명하지는 못한다. 단순 되잡기·맞교환 제외는 보수적이며, 전술적으로 나쁜 되잡기만 가능한 진짜 희생도 탈락할 수 있다. 후보가 자료에 없다는 사실도 세계 최초의 근거가 아니다.

## 수정·미채택 기록

`native-v1/`, `native-v2/`는 앞선 연동 실행이다. 실행 중 연구 소스가 바뀌었고, 이론 자료의 legal EP 표기와 발굴기의 raw EP 비교가 달라 알빈 기점이 잘못 거절되는 문제도 있었다. 실제 네 기점의 연동 회귀를 추가해 수정했다. 이 실행을 최종 성과 근거로 쓰지 않는다.

중간 `queries.jsonl`에는 v1의 19·20·136·137번, v2의 101·189·213·242·243번 행이 빠졌으나 일부 학습 결과의 내장 원본과 raw UCI에는 대응 근거가 남아 있었다. 원본을 복원해 성공으로 표시하지 않고 그대로 보존했다. 원인은 확정하지 않았다. 최종 구현은 메모리의 전체 기록을 종료 시 `queries.json`과 원자적 `queries.jsonl`로 다시 저장하고, 기존 중간 체크포인트는 `queries.incremental.jsonl`로 남긴다. 일부 행 삭제·마지막 행 잘림을 재현한 테스트에서 최종 기록의 완전성과 원본 보존을 확인했다.

`native-v3/`는 FEN 수정 후의 발굴만 재실행했다. 289개 질의 모두 완료했고, 네 기점의 12개 후보 중 통과는 0개였다. 원시 15,213줄과 PGN 12개의 합법성을 별도로 대조했다. 최종 종료 기록 보강 전이므로 최종 통합 실험과 표본을 합치지 않는다.
