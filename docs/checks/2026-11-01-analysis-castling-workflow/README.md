# 분석 대국 중 캐슬링 드래그 수정 · 2026-11-01

사용자가 지적한 조작은 **분석 시작 후 왕을 두 칸 드래그하는 것**이었다. 기존 빈 경로 FEN과 버튼 검사만으로 실제 사용 흐름의 문제가 해결됐다고 판단한 것은 충분하지 않았다.

## 재현과 수정

표준 시작에서 정상 수순을 진행하면 캐슬링은 가능했다. 반면 자유 편집에서 폰 하나를 지웠다가 같은 칸에 놓는 등 왕·룩과 무관한 수정에도 모든 캐슬링 권리가 `-`로 지워졌다. 이 배치로 분석을 시작하면 대국 중 왕 두 칸 드래그가 막혔다.

기존 권리를 해당 왕·룩의 원래 칸 변경 여부에 따라 선택적으로 보존하도록 수정했다. 폰·나이트·비숍·퀸 편집은 다른 권리를 없애지 않는다. 왕·해당 룩을 옮기거나 제거하면 관련 권리를 해제하며, 원위치에 놓거나 빈 판에서 기물을 추가했다고 없던 권리를 자동으로 만들지는 않는다.

진행 중 캐슬링 조작은 판 위쪽으로 옮겼다. 관리기는 현재 위치의 합법 수를 기준으로 가능 여부와 권리 누락·이력상 소멸·막힌 칸·체크·공격받는 통과/도착 칸을 설명한다. 퀸사이드 b열의 기물 막힘과 공격은 구분한다. 왕↔자기 룩 조작도 실제 합법 캐슬링일 때 표준 왕 두 칸 이동으로 연결한다. 브라우저는 진행 중 합법 수 드래그도 지원하며, 판 밖에 놓아도 기물을 삭제하지 않는다.

## 실제 Windows 마우스 검수

사용자의 기존 대국 창은 조작하지 않고, 별도 Godot 창·관리기·`build/castling-workflow-manual/games/`를 사용했다.

1. 표준 배치에서 실제 편집 함수를 통해 f1·g1·f8·g8의 비숍·나이트를 지웠다. 권리가 자동으로 `KQkq`로 유지되는 것을 확인하고 분석을 시작했다. 권리 체크를 다시 켜지 않았다.
2. OS 마우스로 **백 왕 e1→g1**, 이어서 **흑 왕 e8→g8**을 드래그했다. 두 번 모두 왕·룩이 함께 이동했다. 실제 화면과 API 상태를 확인했고 두 번의 무르기로 시작 FEN과 권리가 정확히 복원됐다. `native-manual-result.json`, `native-two-square-castling.jpg`.
3. 새 표준 시작에서 `e4 e5 Nf3 Nc6 Bc4 Nf6`을 생산용 착수 API로 진행했다. 여기서 OS 마우스로 **백 왕 e1→g1**을 드래그해 캐슬링했다. 이후 API로 `...Bc5 d3`를 진행하고 OS 마우스로 **흑 왕 e8→g8**을 드래그했다. 최종 두 왕 g1/g8, 두 룩 f1/f8, 전체 10반수와 권리 소모를 API로 다시 확인했다. `native-normal-opening.json`, `native-normal-opening.jpg`.

위 3번에서 캐슬링 두 수는 실제 OS 드래그이고 준비 수순은 API 착수다. 자동 입력이나 버튼 클릭을 실제 마우스 캐슬링으로 보고하지 않는다. 원래 검수용 대국은 계속 최초 배치·수정 번호 1·착수 0개였다. 개인 보관함은 사용하지 않았다. 관리기·Godot 오류 출력은 비어 있었다.

## 자동 검증

- Godot 합성 88개·입력 디스패처 44개·실제 관리기/엔진 연동 71개 통과. 정상 흐름 114개 검사는 전체 오프닝을 실제 Viewport 클릭으로 진행한 뒤 백·흑 × 두 시점 × 일반/상대 이동량0 입력에서 왕 두 칸 드래그를 수행한다. 폰 편집 후 복원한 배치에서도 반복한다. 기록은 인접한 `../2026-11-01-analysis-castling/godot/`의 최종 로그와 검증 문서에 있다.
- 브라우저 분석 42개·추천 10개·오프닝 8개·시간 설정 검사 통과. 정상 수순, 양쪽 캐슬링 드래그와 시점, 권리 보존, 연결 오류·오래된 드래그 거절, 진행 중 삭제 금지와 기존 형세 기능을 포함한다. `final-web-*.txt`.
- 관리기 새 워크플로 10개, 기존 캐슬링 7개·평가 16개·분석 22개 통과. 실제 엔진 정상 수순, 권리 진단, 체크·막힘·공격, 무르기와 대국·기보 보존을 포함한다. `backend-*.txt`.

기존 분석의 FEN에 이미 없어진 권리를 이 수정이 소급해서 부여하지는 않는다. 변경한 코드는 새 실행에 반영된다. 실행 중인 사용자 창이나 그 개인 기보는 재시작·수정하지 않았다. C++ 규칙·수 선택 코드와 실행 파일은 변경하지 않았으며 경기력 변화에 대한 검증이 아니다. 최종 구현 지문은 `source-manifest.json`에 보관한다.
