# 패배 기보에서 찾은 탐색 개선: v0.5.0

안정화 탐색은 정해진 깊이 끝에서도 전술이 진행 중이면 조금 더 읽는 방법이다. v0.4.1은 잡기·승격과 체크 회피를 연장했다. 그런데 **아무 기물도 잡지 않는 체크**도 상대의 응수를 강제한다. 이 수를 읽지 않으면 안전해 보이는 기물 획득이 실제로는 손해일 수 있다.

## 기보의 작은 예

이전 100ms 비교의 11번 대국에서 백은 `30.Nxe7`로 비숍을 잡았다. 당시 자체 탐색은 +98cp였고 더 깊은 자체 탐색도 이 수를 좋아했다. 실제로는 흑의 `...Nf3+` 뒤 `...Nxd2+`, 다시 `...Nf3+`와 `...Rxe7`이 이어졌다. 첫 `...Nf3+`는 잡기가 아니므로 기존 안정화 탐색의 범위 밖이었다. 별도 Stockfish 16 진단도 이 기물 획득을 큰 실수로 평가했다. 외부 엔진의 유한 탐색은 정답 증명은 아니며, 실제 수순·자체 탐색과 함께 원인을 검토하는 근거로 사용했다.

13번 대국에서는 긴 캐슬링 뒤 조용한 `...Ng4`가 `...Nxf2` 포크를 준비했다. 체크가 아닌 위협까지 모두 안정화 탐색에 넣으면 가지가 너무 많아진다. 이런 수는 일반 탐색이 더 깊게 도달하도록 **수 순서**를 개선하는 것이 이번 가설이다.

## 구현

- 안정화 경로마다 비캡처 체크 한 번을 추가로 허용한다. 잡기·승격은 이 예산을 소비하지 않는다. 체크 중에는 예산이 없어도 모든 합법 회피를 읽는다. 비캡처 역체크는 남은 예산이 있으면 소비한다. 전체 안정화 연장 한도는 기존 32반수다.
- `Board::gives_check_generated()`는 직전에 생성한 합법 수를 임시 배치에 적용해 체크 여부만 확인한다. 원래 배치·해시·반복 이력은 바꾸지 않는다. 외부에서 입력한 수의 합법성 검증은 그대로다.
- 일반 탐색에서 같은 깊이의 다른 가지를 빨리 잘랐던 일반 수 두 개를 먼저 시도한다. 이를 killer 수라고 부른다. 색·출발·도착 칸별로 조용한 수의 가지치기 성공을 기록하는 history 점수도 사용한다. 점수는 상한을 두고 매 검색 초기화한다.
- 전이표의 수가 가장 앞서고, 잡기·승격, killer/history 일반 수 순이다. 동일 우선순위의 순서는 좌표로 고정한다. 탐색 가지를 새로 생략하는 규칙은 추가하지 않는다.
- 시간·노드 예산, 취소, 마지막 완료 깊이 복구, 메이트 우선 판정, 현재/예정 수 무승부 청구, 검색별 전이표 세대 격리를 유지한다. 안정화 점수는 여전히 전이표에 저장하지 않는다.

수 순서만 바꾸면 완전 탐색의 최종 점수는 같아야 한다. 먼저 강한 응수를 찾으면 alpha-beta가 나머지 가지를 일찍 잘라 같은 답까지 필요한 계산을 줄인다. 비캡처 체크 연장은 탐색하는 전술의 범위를 바꾸므로 점수·노드·주요 수순이 달라질 수 있다. 두 효과를 구분해 검증한다.

## 켜고 끄기

UCI의 `UseQuietMoveOrdering`, `UseQuiescenceChecks`는 기본 `true`다. `UseQuiescence=false`이면 체크 연장 옵션도 적용되지 않는다. 옵션 변경은 진행 중 작업을 중지·합류한 뒤 적용한다. killer/history는 검색 사이에 공유하지 않는다.

```text
setoption name UseQuietMoveOrdering value false
setoption name UseQuiescenceChecks value false
```

콘솔에서도 각각 `--no-quiet-ordering`, `--no-quiescence-checks`로 끌 수 있다. 기존 `--no-quiescence`, `--no-tt`와 함께 개발용 비교에 사용할 수 있다.

## 검증과 남은 가설

기존 규칙·특수 수·perft와 외부 라이브러리 교차 검증을 유지한다. 체크 감지의 특수 수·발견 체크·상태 보존, 작은 독립 탐색과의 점수 일치, 일반 수 정렬 켬/끔 점수 일치, 중단과 반복 이력·옵션 전환을 검사한다. 기존 캡처 전용 안정화 오라클은 새 옵션을 꺼서 계속 검사한다.

패배 위치는 개발 회귀 자료다. 같은 시간의 이전 버전 대국은 기존 시작 위치와 사전에 새로 고정한 위치를 나눠 수행한다. [사전 계획](experiments/2026-10-17-loss-guided-plan.md)과 [실행 결과](experiments/2026-10-17-loss-guided.md)에 버전·조건·원시 기보를 남긴다.

한 번의 체크 연장이 모든 전술을 해결하지는 않는다. 체크가 아닌 포크 준비, 킹 주변 공격, 갇힌 기물과 폰 구조는 이후 검토할 가설이다. 이 기능은 자체 구현이며 외부 엔진의 탐색 코드·평가 표·신경망 가중치를 가져오지 않았다.
