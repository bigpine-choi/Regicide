# 갬빗 연구 기억을 원본 보존하며 병합하기

2026-11-05. `scripts/merge_gambit_memory.py`는 검증된 여러 분석 메모리를 새 폴더에 모은다. 엔진 검색을 수행하거나 활성 기억을 자동 설치하지 않는다. 기존 `data/gambits/operations_memory.json`도 읽기 기준으로 지정할 수 있으며 원본 바이트를 변경하지 않는다.

저장소 루트에서 실행한다. `--input`은 필요한 만큼 반복한다. `--base`를 생략하면 기존 활성 메모리를 기준으로 읽는다.

```powershell
.\.venv-tests\Scripts\python.exe scripts/merge_gambit_memory.py --base data/gambits/operations_memory.json --input build/gambit-research/kings-01/operations_memory.json --input build/gambit-research/evans-01/operations_memory.json --output build/gambit-memory-merged/review-01
```

입력은 모두 기존 로더의 구조·체크섬·합법 수순 검사를 통과하고 `status=approved`, `acceptance.passed=true`여야 한다. 실행 파일 SHA256과 평가기 식별자도 같아야 한다. 다른 엔진·평가기의 숫자는 섞지 않는다. 메모리 파일의 검증된 내용과 출처를 보존하는 도구이며, 원시 연구 로그를 새로 감사하거나 기존 승인 자체의 기력 주장을 증명하는 기능은 아니다.

## 기준과 충돌 처리

상태는 전체 FEN과 시작판부터의 전체 수 이력으로 구분한다. 같은 FEN이라도 이력이 다르면 별개다. 같은 상태의 계열 이름이 다르면 뒤의 행을 보류한다.

기준 메모리가 가장 먼저 처리되고, 나머지는 명령에 지정한 순서로 처리된다. 각 입력 안에서는 기존 로더처럼 `record_id` 순서를 사용한다.

- 같은 상태·같은 수의 후보 JSON이 완전히 같으면 하나로 합치고 모든 출처를 남긴다.
- 후보의 점수·깊이·PV·목표·질의 식별자 등 어느 근거라도 다르면 먼저 채택한 후보를 유지하고 뒤의 근거를 충돌 목록에 보류한다. 점수가 높거나 더 깊다는 이유로 바꾸지 않는다.
- 새로운 수는 기존 근거와 함께 담되 로더의 상태별 최대 8개 한도를 유지한다. 초과 후보는 입력 우선순위에 따라 보류하며 점수 경쟁으로 기존 후보를 밀어내지 않는다.
- 모든 입력의 검증 보류 계열과 위치 키를 합친다. 이 합집합에 행의 계열·시작 위치·후보 직후 위치가 걸리면 행 전체를 제외한다. 기준 메모리도 예외가 아니다.

같은 상태의 행은 하나로 정리하며 `merged-<전체상태해시>` 식별자를 부여한다. 원래 `record_id`, `case_id`, 후보의 `query_id`와 출처 연결은 보존한다. 후보 JSON은 선택한 원본 그대로 유지한다. 서로 다른 상태에서 같은 원래 식별자를 사용해도 충돌하지 않는다.

새로운 후보도 기존과 동일한 `candidate_only` 제안이다. 실전에서는 신선한 자체 탐색과 손실 상한 검사를 계속 거친다. 병합된 메모리의 `approved`는 구조·입력 출처·보류 영역 검사가 통과했다는 뜻이며, 새 희생이 건전하다거나 기력·일반화·Chess.com 등급이 좋아졌다는 뜻이 아니다.

## 저장 자료와 복구

| 파일 | 내용 |
| --- | --- |
| `operations_memory.json` | 기존 로더에서 읽을 수 있는 병합 메모리 |
| `merge-report.json` | 마지막 완료 표시, 채택·중복·충돌·제외·식별자 대응 기록 |
| `inputs.json` | 원본 경로·파일 SHA256·메모리 ID·원래 소스와 교육 자료 해시 |
| `inputs/000-base.json` 등 | 각 입력의 바이트 그대로인 복구·재현용 사본 |

소스나 교육 자료가 다른 입력도 엔진·평가기 식별자가 같으면 합칠 수 있다. 하나의 원래 교육 자료 해시로 가장하지 않고 `source_inputs`, `derived_source_inputs_sha256`, `derived_curriculum_inputs_sha256`로 구분한다. 병합 도구 자체의 해시도 별도로 기록한다. 이미 병합된 입력의 자세한 이전 출처는 그 입력 사본에서 확인할 수 있다.

입력과 활성 기억은 수정하지 않는다. 기존 출력 폴더, 활성 경로, 읽기 전용 `sources/` 경로는 거부한다. 각 파일은 완성된 바이트를 flush·fsync한 후 기존 목적지를 덮어쓰지 않는 방식으로 발행한다. 쓰는 도중 실패하면 새 출력 폴더에 일부 파일만 남을 수 있으므로 **`merge-report.json`이 있는 완성 결과만 사용**한다. 실패한 폴더를 덮어쓰며 재시도하지 말고 새 출력 경로를 고른다. 모든 행이 제외되면 로더용 빈 메모리를 만들지 않고 보류한다.

원래 기준 메모리는 기존 경로에서 계속 읽을 수 있다. 되돌리기 위해 활성 파일을 교체할 필요도 없다. 이 도구의 결과를 실전에 설치할지는 별도 결정이다.

검증 명령:

```powershell
.\.venv-tests\Scripts\python.exe tests/gambit_memory_merge_tests.py -v
```

개발 시 병합 테스트 16개와 기존 `gambit_practice_memory_tests.py` 10개가 통과했다. 원본 바이트·복구 사본, 중복·충돌·계열 불일치, 전체 이력 구분, 엔진 불일치, 보류 영역 합집합, 후보 상한, 기존 로더 제안 호환성과 동시 파일 발행 충돌을 확인했다. 이는 모의 입력을 사용한 기능 검증이며 실제 엔진 검색이나 기력 비교를 수행한 결과가 아니다.
