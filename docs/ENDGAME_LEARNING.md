# 종반 진단과 자료량 비교

v0.6.5는 학습용 패배의 종반을 진단하고, 독립적으로 구성한 종반 시작 위치에서 실제 대국을 수집해 기존 자료를 보강한다. 평가 함수·탐색·체스 규칙·100cp 보정 한도와 모델 채택 기준을 유지한다.

## 어떤 실수를 찾는가

종반에서 룩·통과폰·무방비 기물이 자주 보인다는 사실은 위치 문맥이다. 진단기는 실제 수와 자유롭게 찾은 대안을 같은 완료 깊이에서 비교하고, 두 깊은 자체 검색의 안정성까지 확인해 손실 근거를 분리한다. 이미 크게 불리한 위치의 추가 손실은 별도 표시한다. 메이트를 임의 점수로 바꾸지 않으며, 자체 엔진의 유한 분석을 객관적 정답으로 단정하지 않는다.

예약된 채택 대국은 학습이나 자료 구성의 피드백으로 사용하지 않는다. 기존 train 계열의 완료 대국만 진단한다. 새 시작 위치는 직접 작성한48개 합법 FEN이며 룩과 통과폰, 폰 경주, 킹 활동과 기물 안전 문맥을 담는다.24개 위치 계열의 train/validation/test 배분은 결과를 보기 전에 고정한다. 두 색의 실제 차례를 포함하며 라벨의 색만 바꾼 복제 자료를 만들지 않는다.

## 자료와 정답을 늘리는 절차

1. 새 종반 보류 계열을 먼저 실제 자가대국으로 수집한다. 최초 정답 정의에서만 자체 교사10k/50k/200k노드의 정확 유한 점수·마지막 두 추천수 일치·30cp 이내 차이·깊이3이상 조건으로 걸러 동결한다.
2. 학습 계열의 실제 대국을 수집한다. 새 보류 대국의 전체 궤적, 기존 검증/시험, 예약 시작 위치 및 과거 예약 대국의 입력을 학습에서 제외한다. 끝나지 않은 대국에 정답이나 무승부를 만들어 넣지 않는다.
3. 새 train 라벨은 기존 `teacher_quality.py`의 같은 안정성 기준으로 정제한다. 기존1,071개 quality train에 새 자료0/128/512/1,024개 중 가능한 사전 규모를 중첩해 더한다. 기존 검증96개·시험125개와 원본 게임/PGN은 보존한다.
4. 각 규모를 같은 V2 구조·초기화 시드2개·학습 설정에서 훈련한다. epoch 선택은 기존 bootstrap validation만 사용한다. 새 종반 보류 자료와 test는 고정 모델의 평가용이다.
5. 첫 시드의 가장 큰 실행 가능한 사전 규모를 후보로 고정한다. 규모별 개발 대국은 같은 종반 시작 위치·시간·선후공을 사용하지만 후보를 바꾸는 근거로 쓰지 않는다. 고정 후보는 기존 예약 아레나와 통계 기준을 통과해야만 채택된다.

같은100epoch라도 큰 자료는 더 많은 연산을 사용한다. 기록에 갱신 수를 남기고, 기준 자료만 더 반복해 큰 자료와 갱신 수를 가깝게 맞춘 보조 모델도 평가한다. 오차·위치 판단·개발 대국·채택 대국은 서로 다른 근거다. 소표본의 성적 상승을 전체 기력이나 Elo 상승으로 바꾸지 않는다.

## 실행

원래 `Learn-Regicide.cmd`의 일반 순환은 계속 사용할 수 있다. 이번에 완료한 학습 대국은 영속 catalog의 datasets에 등록돼 이후 일반 순환에도 누적된다. 새 보류 대국은 별도 endgame_holdouts에 신원과 함께 등록하며, 일반 수집과 corpus 구성 모두에서 계속 보호한다. 기존 자료의 행이나 파일을 지워 시도 횟수를 초기화하지 않는다.

연구용 전체 실행은 준비와 자원 통제 대국으로 나뉜다. 준비 중에는 시간제 기력 비교를 하지 않는다. 준비가 끝나면 출력한 run 경로로 검증을 이어간다. 다른 학습 작업을 같은 저장소에서 동시에 실행할 수 없다.

```powershell
./.venv-tests/Scripts/python.exe scripts/endgame_study.py prepare --binary build/regicide.exe
./.venv-tests/Scripts/python.exe scripts/endgame_study.py validate --binary build/regicide.exe --run runs/000005-실제로_출력된_식별자
```

검증 동안 알려진 브라우저·외부 엔진 CPU 또는 감시 공백이 있으면 비교를 무효 처리한다. 규칙·자료·모델·코드·실행 파일 변경도 채택을 막는다. 시도 번호는 준비 시작 전에 소비하며 실패해도 되돌리지 않는다. 실패한 후보는 기본 모델을 교체하지 않는다. Windows의 임시 절전 요청은 각 실행 종료 시 복원한다.

세부 조건과 판단 기준은 [사전 계획](experiments/2026-10-19-endgame-learning-scale-plan.md)을 따른다.

## PC 사용을 멈추지 않는 검증

사용자 요청으로 [학습 전 수정 계획](experiments/2026-10-19-endgame-validation-revision.md)을 추가했다. `prepare --remote-validation`으로 고정한 연구는 `develop`에서 수당1,000노드로 규모별 실제 종반 대국을 비교하고, `export-remote`로 정확한 Windows 실행 파일·모델·소스 신원을 내보낸다. 이 두 단계에서 브라우저 종료를 요구하지 않는다. 고정 노드 결과를 같은 시간의 기력 증명으로 해석하지 않는다.

새 `remote-request.json`을 GitHub에 커밋·푸시하면 별도 Windows Actions 작업이 수당100ms의 기존 예약 대국을 실행한다. 원격 장비에서 같은 실행 파일로 양쪽을 비교하므로 사용자 PC의 다른 작업은 이 측정에 섞이지 않는다. 원격 하드웨어의 결과를 사용자 PC의 절대 성능으로 표현하지 않는다.

완료된 선후공 쌍마다 남은 모든 쌍에서 만점을 얻어도 기존 최종 채택 공식을 통과할 수 없는지 검사한다. 불가능하면 `rejected_early_futile`로 끝내며 실제 점수·기보에는 가상 승리를 넣지 않는다. 오염·미완료는 별도 실패다. 조기 채택은 없고, 통과 후보는 기존 최소32쌍·100ms와 모든 규칙·자원·통계 검사를 충족해야 한다.

원격 실행기는 모델을 채택하지 않는다. 결과는 요청 커밋의 자식인 별도 검증 브랜치에 기록하며, API로 확인한 작업 신원·Git 이력·요청 해시·모든 파일·전체 기보와 자원 기록을 로컬에서 다시 확인한 뒤 `import-remote`가 기존 등록부를 사용한다. 원래 원격 근거를 보존하고, 설치 위치가 달라진 경로만 파생 로컬 명세에 치환한다. 점수·수순·옵션·시간·기준은 바꾸지 않는다.

```powershell
python scripts/endgame_study.py prepare --binary build/regicide.exe --remote-validation
python scripts/endgame_study.py develop --binary build/regicide.exe --run runs/실제로_출력된_식별자
python scripts/endgame_study.py export-remote --binary build/regicide.exe --run runs/실제로_출력된_식별자 --request-directory docs/checks/해당연구/remote-input
# 출력된 요청과 입력을 커밋·푸시한 뒤, 원격 검증 브랜치와 작업 신원을 확인한다.
python scripts/endgame_study.py import-remote --binary build/regicide.exe --run runs/실제로_출력된_식별자 --remote-results 원격결과폴더 --workflow-receipt 검증한작업신원.json
```

학습 전에 실패한 이전 시도의 완료 자료는 `prepare --reuse-data-run runs/이전식별자`로 신원·정답 정책·등록 해시를 다시 확인해 재사용할 수 있다. 이전 실패 자료나 시도 번호를 덮어쓰지 않으며, 이미 모델을 학습한 시도를 이 옵션으로 다시 고르지 못한다.
