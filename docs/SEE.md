# SEE: 한 칸의 교환 손익으로 수 정렬

v0.5.2는 **SEE(Static Exchange Evaluation, 정적 교환 평가)**를 자체 구현한다. 한 칸에서 서로 잡고 되잡는 기물 손익을 추정해 이익이 남는 교환을 먼저 읽는다. SEE는 수의 순서에만 쓰며, 손해로 보이는 수를 제거하거나 평가 점수에 더하지 않는다. 실제 좋은 수인지 판단하는 책임은 기존 PVS/alpha-beta와 안정화 탐색에 있다.

[고정 깊이 비용·100ms·1초 개발 비교와 독립 감사 결과](experiments/2026-10-18-see.md)에 측정 조건·기보와 한계를 기록했다.

[새 시작 위치·외부 CPU 증가 0의 재현 비교](experiments/2026-10-18-see-replication.md)는 100ms 7승 5무 4패, 1초 3승 6무 7패였다. 탐색 비용 감소와 경기력은 별도이며, SEE의 일반적인 강도 향상은 확인되지 않았다.

## 작은 체스 예

백 퀸 d1, 흑 룩 d5, 흑 폰 e6이면 `Qxd5 exd5`는 룩 500점을 얻고 퀸 900점을 잃어 **−400**이다. 다른 곳에서 공짜 폰을 잡는 **+100**의 수가 있다면 그 교환부터 탐색한다. 단순히 가장 비싼 기물을 잡는 수부터 읽는 방식보다 유망한 첫 후보를 찾을 수 있다는 가설이다. 계산량 감소와 실제 경기력은 [사전에 고정한 계획](experiments/2026-10-18-see-plan.md)으로 각각 검증한다.

반대로 기물을 희생해야 메이트가 되는 위치도 있다. `5rnk/6pp/7N/3Q4/8/8/8/K7 w - - 0 1`에서 `Qxg8+ Rxg8 Nf7#`는 첫 교환의 기물 손익이 음수여도 승리다. 이 수를 일반 탐색과 안정화 탐색에서 계속 읽는 회귀 검사를 둔다.

## 계산 방법과 한계

현재 64칸과 왕 위치를 작은 지역 복사본에 담는다. 최초 수를 적용하고, 목적지를 공격하는 기물 중 **가장 싼 합법 공격자(LVA, Least Valuable Attacker)**를 골라 번갈아 되잡는다. 같은 값이면 칸 번호가 작은 기물을 고른다. 마지막부터 거꾸로 계산할 때 각 쪽이 교환을 중단할 선택도 반영한다. 원본 보드·반복 이력과 적용/되돌리기 상태는 건드리지 않는다.

- 매 재캡처 뒤 공격선을 다시 확인해 가려져 있던 룩·비숍·퀸의 공격을 찾는다.
- 자기 왕을 노출하는 핀 기물의 재캡처를 제외한다. 왕은 상대가 공격하지 않는 칸에서만 잡을 수 있다. 왕 안전성에는 핀된 상대 기물의 기하학적 공격도 포함한다.
- 앙파상은 목적지 밖에서 잡힌 폰도 제거한다. 최초 승격은 선택한 네 종류를 따르고, 후속 재캡처 승격은 이 지역 기물 모델에서 퀸을 사용한다. 승격 기물이 남으면 최대 이득이며 다시 잡히면 승격 증가와 손실이 상쇄된다.
- 64칸에 맞춘 고정 배열을 사용한다. SEE 호출 자체에는 동적 메모리 할당이 없다.

이 값은 **LVA를 따르는 지역 기물 손익 추정**이다. 모든 공격자 선택의 분기를 완전 탐색하지 않으며, 다른 칸의 위협이나 체크 때문에 강제로 이어지는 전체 수순을 증명하지 않는다. 양수여도 좋은 수를 보장하지 않고 음수여도 나쁜 수를 확정하지 않는다.

## 탐색과의 연결

정렬 우선순위는 전이표/직전 완료 탐색의 최선 수 → SEE 0 이상인 캡처·승격 → 일반 수 → SEE 음수인 캡처·승격이다. 같은 그룹에서 SEE, 기존 캡처 우선값 또는 killer/history, 좌표 순으로 동점을 처리한다. 첫 반복의 임시 합법 fallback은 아직 읽어본 최선 수가 아니므로 SEE 정렬보다 앞세우지 않는다. 깊이 2부터는 완료된 직전 주요 수순(PV)을 우선한다.

한 정렬에서 전술 수당 SEE를 한 번만 계산해 저장한다. 비교 함수가 같은 계산을 반복하지 않는다. 안정화 탐색의 기존 캡처·승격·제한된 비캡처 체크와 체크 회피 범위는 유지한다. SEE 때문에 수를 생략하거나 깊이를 줄이지 않는다. 기존 평가·규칙·전이표의 검색별 격리 정책·시간 관리도 유지한다.

## 사용과 검증

기본값은 켬이며 UCI에서 `setoption name UseSEE value false`, 콘솔에서 `search 4 --no-see`로 끈다. 끈 경로는 v0.5.1의 기존 정렬을 그대로 사용한다. 검색 중 옵션 변경은 기존 작업을 중지하고 합류한 뒤 적용한다. `see_calls`/`info string see calls`는 미완료 반복의 작업까지 포함한 계산 횟수다. python-chess는 마지막 `info string`만 유지하므로 공통 대국/벤치마크 JSON에는 이 별도 계측을 보존하지 않는다. 노드·시간·기존 전이표 계측은 그대로 기록한다.

`tests/see_tests.cpp`는 별도의 합법 수 생성·적용·되돌리기 재귀와 LVA 결과를 비교한다. 수작업 교환, 핀·왕·공격선·앙파상·승격·반복 이력을 검사한다. `tests/search_tests.cpp`는 실제 정렬 효과와 음수 SEE 승리 수의 보존, 작은 완전 탐색 점수 일치, PVS/전이표/SEE 옵션 조합·중단·컨텍스트 재사용을 검사한다. 기존 규칙 차등 검증과 UCI·대국·Godot 검증도 유지한다.
