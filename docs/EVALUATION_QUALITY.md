# 형세 평가 개선과 비교 방법

게임의 수식 평가는 기물 가치, 기물 위치, 전개, 왕 앞 폰 방패와 폰 구조에 기물 활동성 항목을 더한다. 이 값은 탐색의 끝에서 국면을 판단하는 재료다. 화면의 게이지 눈금과 실제 평가·탐색 품질은 별개이며, 이번 작업은 게이지 배율을 바꾸지 않는다.

## 대국 중 평가 갱신

사람 차례의 독립 평가 도우미는 `max(3000, 설정된 생각 시간)` 밀리초를 읽는다. 완료한 얕은 탐색 결과부터 바로 전달하고, 같은 국면을 더 깊게 읽으면 갱신한다. 수를 두거나 되돌리거나 새 대국을 시작하면 이전 탐색을 취소하고 대국 ID·국면·수정 번호가 맞는 결과만 표시한다.

AI가 실제 수를 고르는 시간은 사용자의 설정을 유지한다. AI 차례에는 실제 착수 탐색의 평가를 사용하며, 오프닝 다양성 검사를 위한 제한 탐색은 게이지에 발표하지 않는다. 추천수와 분석 모드의 예산도 별도로 유지한다. 사람 차례에는 기본 설정 기준 최대 약 2초의 추가 연산이 발생하며, 이는 같은 연산량의 엔진 성능 향상이 아니다.

## 기물 활동성 항목과 호환성

UCI `UsePieceActivity`를 추가했다. 프로토콜 기본값은 `false`로 유지하고, 게임 앱이 이 옵션을 지원하는 바이너리에 `true`를 설정한다. 일반 대국·추천수·화면 평가·분석·코칭에 동일하게 적용하며 기존 바이너리와 명시적인 신경망 모델은 기존 경로를 유지한다. 계수는 자체 작성한 초기값으로, 외부 엔진의 코드·모델·가중치를 가져오지 않았다.

| 항목 | 중반 | 종반 |
| --- | ---: | ---: |
| 나이트 활동 칸 1개, 기준 4칸 | 3cp | 2cp |
| 비숍 활동 칸 1개, 기준 7칸 | 3cp | 3cp |
| 룩 활동 칸 1개, 기준 7칸 | 2cp | 3cp |
| 퀸 활동 칸 1개, 기준 14칸 | 1cp | 1cp |
| 서로 다른 색 칸의 비숍을 모두 보유 | 20cp | 30cp |
| 룩의 세로줄에 자기 폰이 없음 | 10cp | 8cp |
| 룩의 세로줄에 양쪽 폰이 모두 없음 | 18cp | 12cp |

활동 칸은 해당 기물의 공격 경로에서 자기 기물과 상대 폰이 공격하는 칸을 제외해 센다. 상대 기물을 잡을 수 있는 마지막 칸은 세고 그 뒤는 세지 않는다. 핀이나 다른 상대 기물의 공격은 완전히 판정하지 않으므로 합법적·안전한 이동 수와 같지 않다. 룩의 열린 파일 점수는 반열린 파일 점수와 중복되지 않으며, 비숍 두 개가 같은 색 칸을 다니면 비숍 쌍 보너스를 주지 않는다. 기존 국면 진행도에 따라 중반·종반 값을 섞는다.

예를 들어 `r5k1/3p4/8/8/8/8/3P4/3R2K1 w - - 0 1`과 백 폰을 d2에서 e2로 옮긴 국면은 기존 정적 평가가 모두 +6cp다. 새 항목은 d파일의 길이 열린 룩을 구분할 수 있다. 이러한 작은 예시의 의도대로 작동하는 것과 대국 강도 향상은 별도 검증 대상이다.

`evaluate_position()`과 Python `classical_cp_stm()`의 선택 인자 기본값은 계속 꺼짐이다. 기존 residual 신경망의 기준 점수를 바꾸지 않기 위한 계약이다. residual·NNUE·기물 가치 전용 탐색에는 이 옵션을 적용하지 않는다. 평가 probe의 기존 13열 출력도 유지하고, `--piece-activity`를 명시한 경우에만 4개 활동성 조합을 더해 17열로 출력한다.

## 비교 원칙

기존·후보를 같은 공개 국면과 같은 제한 시간으로 비교하고, 1초에서 3초로 늘린 효과는 따로 집계한다. Stockfish 18은 고정된 오프라인 비교 도구이며 실제 착수 엔진에 연결하지 않는다. 서로 다른 엔진의 cp를 빼서 정확도나 Elo로 부르지 않는다. 선택이 달라진 경우 같은 Stockfish 설정으로 두 수를 각각 제한 탐색해 비교하지만, 그 결과도 유한한 탐색의 추정이다.

점수의 의미와 서로 다른 엔진의 탐색 깊이를 단순 비율로 비교할 수 없다는 설명은 [Stockfish 공식 FAQ](https://official-stockfish.github.io/docs/stockfish-wiki/Stockfish-FAQ.html)를 참고했다(2026-11-02 확인). 여기서 사용하는 로컬 Stockfish 18은 비교 버전을 고정한 것이며 Chess.com의 현재 서버 설정을 재현한 것은 아니다.

공개 개발 국면 22개와 단위·통합 검사는 독립적인 대규모 기력 검증을 대신하지 않는다. 구현 정확성, 평가 호출 비용, 제한 시간의 판단, 실제 대국 결과를 구분한다. [이번 조건·결과·재현 기록](checks/2026-11-02-evaluation-quality/README.md)에 실행한 검사와 한계를 남긴다.

## 실행 중인 게임을 유지하는 설치

`scripts/runtime_engine.py --install <후보>`는 검증된 바이너리를 `build/runtime-engines/<SHA256>/regicide.exe`에 별도로 저장하고 다음 실행용 manifest만 원자적으로 바꾼다. Godot·브라우저 실행기는 시작할 때 선택한 파일의 SHA256을 확인한다. 실행 중인 게임의 파일이나 프로세스는 교체하지 않는다. 화면에서 새 대국을 누르는 것과 달리 앱을 다음에 열 때 새 바이너리가 선택된다.

`--resolve`는 다음 실행 파일의 경로를 출력하고, `--deactivate`는 다음 실행을 기본 `build/regicide.exe`(비 Windows는 `build/regicide`)로 되돌린다. 명시적으로 활성화한 manifest가 우선하므로 기본 경로를 다시 빌드한 것만으로 선택이 바뀌지는 않는다. 개발자가 새 빌드를 사용할 때는 다시 설치하거나 선택을 해제한다. `play_human.py --binary <경로>`는 이 선택보다 우선한다.
