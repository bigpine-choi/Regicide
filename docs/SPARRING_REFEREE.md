# 로컬 Stockfish 심판을 사용하는 스파링

스파링의 수와 후보는 기존 Regicide가 만듭니다. 별도 Stockfish는 현재 형세를 평가하고, 자체 후보 중 균형에 가까운 수를 선택하는 데 관여합니다. C++ 자체 엔진·평가 함수·학습 모델은 바꾸지 않았습니다. 이 모드는 **Stockfish 보조 스파링**이며, 독립 Regicide의 경기력 측정과 구분합니다. [접전 효과 비교와 후보 부족 개선](matches/2026-11-03-sparring-referee-close/README.md)에 실제 측정과 한계를 기록했습니다.

## 사용하기

현재 개발 PC에서는 기존 공식 Stockfish 18 패키지를 자동으로 찾습니다. 실행 중인 대국은 그대로 두고, 다음에 Regicide를 다시 열어 **새 대국 설정 → 스파링 · Stockfish 심판**을 선택합니다. 이번 심판 기능에는 인터넷 연결·리체스 로그인·토큰이 필요하지 않습니다.

형세 막대는 **모든 모드에서 Stockfish**가 평가한 현재 위치를 표시합니다. `+`는 백, `−`는 흑 기준이며, 계산 중·실패·다른 위치의 응답은 중립 막대와 상태 안내로 표시합니다. 형세 값은 사람의 실제 승률이나 승패 보장이 아닙니다. 실제 착수와 추천 수는 기존 Regicide가 선택합니다. [공통 형세 게이지 검증](checks/2026-11-04-stockfish-gauge/README.md).

설치 파일을 찾지 못하면 자체 스파링으로 계속 두며 형세 게이지는 Stockfish를 사용할 수 없다고 표시합니다. 이미 연결된 심판의 후보 검사가 실패하면 해당 수는 Regicide의 원래 기준수로 복귀합니다. 심판이 직접 찾은 다른 수를 대신 두지 않습니다.

## 후보를 확인하는 방법

Regicide의 기준수와 자체 후보를 **총 4개까지** 모아, Stockfish의 같은 탐색·같은 완료 깊이에서 비교합니다. 선택 후보를 둔 뒤에는 상대의 제한 없는 반격도 다시 확인합니다. 두 검사를 통과해야 다른 수를 허용합니다. Stockfish의 자유 탐색 결과를 실제 착수로 사용하지 않습니다.

기존 자체 탐색에서 완료된 후보를 먼저 재사용합니다. 자체 기준수와 같은 깊이에 도달하지 못했더라도 개별적으로 완료된 깊이 4 이상의 후보라면 별도 출처로 구분해 심판 비교에 넣습니다. 서로 다른 깊이의 자체 점수를 빼서 손실을 계산하지 않습니다. 그래도 후보가 부족하면 양쪽의 4수 이후부터 20수까지 최대 600ms 동안 **Regicide 자체 탐색**으로 대안을 더 찾습니다. 핸디캡·자원 보호 상황이나 잔여시간 3분 미만에서는 추가 탐색을 하지 않습니다.

평가의 단위와 기준이 엔진마다 다르므로 Regicide 점수에서 Stockfish 점수를 빼지 않습니다. 심판 내부의 판단은 모두 Stockfish 점수끼리 비교합니다. 초반 목표는 자기 쪽 기준 +20cp, 접전 범위는 ±80cp입니다. 큰 격차를 한 번에 이 범위까지 줄이지 못해도, 안전 하한과 후속 검사를 지키며 격차를 줄이는 후보를 허용합니다. 이미 불리하면 기준수보다 더 악화시키는 양보를 허용하지 않습니다. 이는 제한된 심판 분석의 판단이며 실제 승패 보장이 아닙니다. 21~49수에는 기준수의 Stockfish 평가를 향해 목표를 옮기고, 각 진영의 **50번째 착수부터는 의도적 양보를 중단**합니다. 이후에도 아래 최종 검사는 계속합니다.

심판은 1스레드·Hash 32MiB·Skill Level 20·기력 제한 해제로 실행합니다. 대국의 표시용 평가·스파링 후보 검사·분석·코칭은 별도 작업자로 관리해, 화면 이동이나 평가 갱신이 다른 검사를 취소하지 않게 합니다. 각 작업자는 동시에 하나의 평가 프로세스를 사용합니다.

| 용도 | 기본 계산 시간 | 처리 |
| --- | --- | --- |
| 현재 위치의 형세 | 500ms | 백그라운드에서 별도 채널로 갱신 |
| 부족한 자체 후보 추가 발견 | 최대 600ms | 깊이 4, 새 후보 최대 3개; 조건을 충족한 첫 20수에서만 |
| 최대 네 자체 후보와 착수 후 반격 확인 | 총 1,500ms 이내 | 후보 공통 깊이 6 이상, 착수 후 깊이 4 이상 요구 |
| 남은 시간 3분 미만 | 최대 800ms | 추가 자체 후보 발견 중단, 심판 비교 예산 축소 |
| 남은 시간 1분 미만 | 최대 350ms | 검증이 완성되지 않으면 기준수 |
| 남은 시간 10초 미만 | 추가 후보 검사 생략 | 기준수 보존 |

형세 조회는 기동에 최대 1.5초를 별도로 허용하고, 준비가 끝난 뒤 500ms를 분석합니다. 분석 종료 여유는 기본 350ms로 제한하며 기동·분석 경과 시간을 구분해 기록합니다. 후보 검사에는 기동·정리 비용도 총 시간에 포함됩니다. 후보가 기준수 하나뿐이거나 50수 이후면 **양보 후보 간 비교**를 생략하지만 최종 검사는 생략하지 않습니다. 현재 위치·대국·수정 번호·전체 수순·실행 파일 해시가 맞아야 결과를 적용합니다. 새 위치·무르기·종료·‘지금 두기’와 시계 만료는 늦은 응답을 무효화합니다. 충분한 시간이 있어도 짧은 분석만으로 모든 전술적 손해를 배제할 수는 없습니다.

## 기본 수까지 확인하는 최종 검사

전술 검사 이후 실제로 둘 수를 한 번 더 확인합니다. Stockfish가 **제한 없이 읽은 현재 국면**과 **선택한 수를 둔 뒤의 국면**을 비교하므로, 잘못된 자체 기준수의 낮은 점수를 안전 기준으로 삼지 않습니다. 둘 다 완료 깊이 10 이상인 정확한 점수가 필요하며, 실제 종료된 국면은 체스 규칙으로 판정합니다.

20수까지는 버틸 수 있는 국면을 자기 쪽 −1점보다 나쁘게 만드는 수를 거릅니다. 21~49수에는 현재 국면의 독립 평가를 기준으로 기존 양보 상한을 매 수 줄이며, 50수부터는 40cp 손실 상한을 적용합니다. 제한된 탐색의 변동을 고려한 20cp 허용 오차가 있습니다. 이미 나쁜 국면이거나 상대가 크게 실수한 국면을 반드시 ±1점으로 되돌린다는 뜻은 아닙니다.

문제를 발견하면 그 수를 제외한 **Regicide 자체 탐색**으로 대안을 찾고 각각 다시 검사합니다. 전체 후보 탐색 슬롯 사이에 아직 검토하지 않은 나이트·비숍별 탐색을 최대 두 번 넣고, 중앙 파일의 미검토 룩이 있으면 두 번째 전체 탐색을 해당 룩 탐색으로 바꾸어, 비슷한 후보만 반복해서 고르는 상황을 줄입니다. 기물 선택과 허용 수는 자체 국면에서 정하며 Stockfish의 최선수를 후보에 넣지 않습니다. 깊이 1~3의 유망한 자체 후보는 같은 수를 자체 엔진으로 다시 읽어 깊이 4 이상을 확인하는 것이 기본입니다. 재확인 예산은 최대 1200ms이며 전체 8초 안에 포함합니다. 아래의 제한된 얕은 후보 확인 경로는 별도로 표시합니다. 각 국면 검사의 분석 예산은 650ms이고, 첫 검사에는 엔진 기동을 위해 최대 1.5초를 추가 배정합니다. 같은 착수의 재검사에는 이미 켜진 엔진을 재사용합니다. 기동·검사·자체 대안 탐색을 합친 전체 예산은 최대 8초입니다. 남은 시간이 5분 이하부터 이 예산을 연속적으로 줄이고 10초 이하에서는 생략합니다. 대안을 찾느라 더 계산한 뒤에는 연출용 대기를 추가하지 않습니다.

안전 하한을 통과한 대안을 우선합니다. 원래 수의 손실이 150cp 이상이며 다른 자체 후보가 검증된 손실을 100cp 이상 줄인다면, 하한에 조금 못 미쳐도 그중 가장 나은 후보를 `mitigated`로 선택할 수 있습니다. 이미 확인한 큰 실수로 돌아가는 일을 줄이기 위한 처리이며, 접전이나 안전 하한 통과로 표시하지 않습니다. 이 근거조차 없거나 검사가 실패하면 합법적인 기존 선택을 유지하되 `unverified`로 남깁니다. 따라서 이 기능도 모든 헌납을 막는 보장은 아닙니다. [기존 불일치 국면 재현·수정 후 검증](checks/2026-11-03-sparring-disagreement/README.md)에서 실제로 교체된 수와 남은 한계를 확인할 수 있습니다.

## 기록과 재현

JSON의 `sparring_referee`에는 심판 이름·실행 파일 SHA256·정책·설정 여부와 판정을 따로 기록합니다. `sparring_play.decisions[].regicide_proposal`은 원래 자체 판단, 같은 항목의 `referee`는 심판의 근거입니다. 실제 선택과 일치하는 증거만 보관함의 `referee_decisions`에 노출합니다. 심판 오류로 자체 기준수를 둔 경우에도 해당 대국의 외부 보조 모드 표시는 유지합니다.

`referee.native_pool`과 `native_discovery`에는 후보의 출처·깊이·위치·예산을 기록합니다. 자체 기준수와 같은 깊이의 비교가 없으면 `native_comparison_available=False`, `loss_cp=None`으로 남깁니다. 원래 제안수의 자체 후속 검사를 새 선택의 검사로 표시하지 않으며, 심판의 후속 점수는 `referee.postmove`에만 보존합니다. 현재 정책은 `regicide-stockfish-referee-v3`이고 이전 v1/v2 기보도 실제 저장된 정책으로 복원합니다.

PGN은 기존 `EngineSHA256`을 Regicide 신원으로 유지하고 `SparringReferee`, `RefereeBinarySHA256`, `RefereePolicy`, `AssistedSparring`을 추가합니다. 보관함 재생·다시 내보내기에도 보존합니다. 이전 기보에 심판 정보를 만들어 붙이지 않습니다. 외부 평가를 자체 평가 기록이나 신경망 학습 목표에 섞지 않습니다.

최종 검사 정책은 `regicide-sparring-quality-v5`입니다. `sparring_play.decisions[].quality_guard`에 검사 전후 국면 평가·대안별 자체 증거·검사 결과·생략/실패 이유를 저장합니다. 교체 전 선택은 `pre_quality_selection`에 보존하며, 외부 점수로 자체 `selected_cp_own`을 덮어쓰지 않습니다. 검증되지 않은 수를 접전 유지 성공으로 집계하지 않습니다.

## 20수 이전 접전 복구 보완

표준 시작의 20수 이전에는 큰 우세·승리 메이트도 접전 목표와 따로 비교합니다. 자기 쪽 +80cp를 넘으면 합법 후보를 자체 엔진으로 넓게 읽고, 목표 +30cp에 더 가까운 후보만 다시 검증합니다. 직접적인 기물 헌납·즉시 메이트 허용을 거르는 검사는 물질 반환 예외 없이 적용합니다. 재포획의 재포획까지 합법 수로 확인하며, 계산 한도를 넘긴 부분 점수를 보상으로 쓰지 않습니다. 바로 직전의 입증된 동가 교환을 상대가 한 번 미뤘을 때만 같은 기물·칸을 유지하고 원래 재포획 가능성과 현재 후보 이전부터의 합법 재포획이 확인된 정상 교환 근거를 별도로 기록합니다. ±80cp 복귀는 `balanced`, 격차만 줄인 경우는 `balance_improved`로 남기고 접전 성공과 구분합니다. 원래 +90cp를 −95cp로 바꾸는 것처럼 목표에서 멀어지는 선택도 거부합니다.

자기 쪽 −80cp 아래에서는 양보하지 않고 더 나은 자체 저항 수를 찾습니다. 현재 위치가 이미 불리하거나 상대의 실수로 기물 차이가 크게 벌어졌다면, 헌납 없이 정확히 ±100cp로 돌아갈 수 있다는 보장은 없습니다. 목표를 못 맞췄다면 미충족으로 남깁니다. 21수 이후의 양보 축소와 강제 승리 보존 규칙은 유지합니다.

자체 탐색의 긴 전술 수순 보호 장치 때문에 완료 깊이 2에서 반복해서 멈추는 실제 사례가 있었습니다. 표준 시작·20수 이전·처음 검사에서 위험한 수가 확인된 수리에서만, **복수 후보에서 발견한 자체 수**와 같은 수의 정확한 재탐색 결과(깊이 2 이상·점수 차이 40cp 이내)를 출처로 보존할 수 있습니다. 직접 헌납 검사를 통과하고 새 Stockfish 현재/착수 후 분석을 두 번 모두 깊이 10 이상 완료해야 하며, 두 착수 후 점수가 각각 ±80cp이고 변동·원래 안전 하한도 확인합니다. 두 번째 확인까지 전체 예산 안에 끝나지 않으면 적용하지 않습니다.

이 경우 실제 자체 깊이는 2 그대로 기록하고 `reference_confirmed_native_candidate` 및 두 외부 확인을 별도로 남깁니다. 깊이 4 자체 검증을 통과했다고 표시하지 않습니다. 같은 자체 탐색을 반복한 사실 자체가 전술 검증 강화를 뜻하지 않으며, 추가 안전 근거는 외부 완료 평가입니다. 우세를 일부 양보하는 경로와 21수 이후에는 이 예외를 적용하지 않습니다.

[실패 대국 재현·수정·검증 기록](checks/2026-11-04-early-balance/README.md)을 참고합니다.

## 다른 컴퓨터의 설정

자동 조회 위치는 다음 두 곳이며, Windows 공식 고정 패키지의 바이너리와 원본 라이선스 해시를 확인합니다. 자동 다운로드는 하지 않습니다.

```text
build-m2-opponents/stockfish18/package/stockfish/stockfish-windows-x86-64.exe
build/referee/stockfish18/package/stockfish/stockfish-windows-x86-64.exe
```

다른 로컬 Stockfish는 `REGICIDE_REFEREE_ENGINE` 환경변수 또는 Python 실행기의 `--referee-engine`으로 지정할 수 있습니다. 잘못 지정한 경로를 다른 엔진으로 자동 대체하지 않습니다. Windows에서는 `.exe`, Linux/macOS에서는 해당 OS의 실행 파일이 필요합니다. 시작할 때 Stockfish UCI 이름과 필수 옵션도 확인합니다. `--no-referee`는 외부 심판을 완전히 끕니다. 직접 생성하는 `HumanGame`과 기존 단위 테스트는 심판을 명시적으로 연결하지 않으면 자체 엔진만 사용합니다.

## 21~49수 압박과 5분 시간 제어

21~49수의 의도적 양보 상한은 `min(120cp, 현재 양의 우세 × 0.35) × (1−진행률)²`다. 작은 우세를 반복해서 동점 근처로 되돌리는 선택을 줄이고, 수가 진행될수록 기존 기준수의 힘을 더 많이 보존한다. 열세에서는 의도적으로 더 양보하지 않는다. 같은 루트 평가가 비슷한 검증 후보들 사이에서 상대 비폰 기물의 활동과 왕의 탈출로를 제한하는 수를 우선한다. 이 기하학적 보조 점수는 장기적 질식 전략이나 승리를 증명하지 않는다.

우세한 국면에서 실제 반복·스테일메이트·50수 규칙에 따른 무승부를 허용하는 후보는 안전한 비무승부 대안이 있으면 피한다. 열세에서 기존 기준수가 제공하는 무승부 방어는 보존한다. 50번째 착수부터 의도적 양보를 중단하는 경계는 유지한다.

스파링의 시간 제어는 남은 시간 **5분 이하**부터 연속적으로 적용한다. 착수 목표와 장고·회복·품질·전술 검사 예산을 함께 줄이며, 실제 잔여 시간과 10초 예비 시간을 우선한다. 최소 검사 예산으로 검증을 마치지 못하면 미확인으로 남기고 안전 확인이나 후보 교체 근거로 삼지 않는다. 일반 시간제 모드는 기존 3분 기준을 유지한다. [검증 조건과 결과](checks/2026-11-04-sparring-pressure-clock/README.md).
