# 브라우저 부하 제거 후 v0.5.7/v0.5.8 재대국

[사전 고정 계획](../../experiments/2026-10-18-lmr-idle-rematch-plan.md)에 따라 같은 실행 파일·같은8시작점·선후공16판·200ms/수·Hash16MiB·Move Overhead20ms·claim·최대300반수를 유지했다. 엔진 코드는 바꾸지 않았다. 결과와 해석은 [재대국 기록](../../experiments/2026-10-18-lmr-idle-rematch.md)을 읽는다.

## 채택 자료와 제외 자료

이 폴더 최상위의 `match-200ms.json/pgn`과 `match-200ms-lmr.json`, `preflight-load.json`, `match-load.json`은 브라우저 제거 기준을 통과한 두 번째 시도의 자료다. `independent-rematch-audit.*`는 그 기보·검색 통계·해시·조건·부하의 독립 감사다.

`excluded-attempt-1/`은 중간에 Whale이 다시 실행되어 사전 규칙에 따라 제외한 첫 시도다. 이 시도의4승6무6패를 채택 결과와 합산하지 않는다. `exclusion-decision.json`과 원자료를 보존한다. 이 폴더 안 감사의 `failed`는 브라우저 기준 위반을 뜻한다. PGN/종료/설정/검색 통계의 다른 오류는 없었다. 부하와 무관하게 유리한 결과만 선택한 것이 아니다.

이전 최초 비교는 [기존 원자료](../../checks/2026-10-18-lmr/README.md)의4승6무6패이며 브라우저1,265.14 CPU초가 관측됐다. 최초 비교·제외된 첫 재시도·채택된 재시도는 세 실행으로 구분한다. 이전과 새 결과 차이를 브라우저만의 인과 효과로 단정하지 않는다.

## 부하 관측 범위

일반 브라우저(Whale/Chrome/Edge/Firefox/Brave/Opera/Vivaldi/Arc 등)는 실행 전20초, 대국 중 목표500ms, 종료 후4표본에서 프로세스 수0·CPU 증가0을 요구했다. 어느 표본에서든 감지되면 전체16판을 성적과 관계없이 제외한다. 사용자 대국 엔진과 예상치 못한 Regicide도 함께 관찰한다.

다른 앱에 포함된 `msedgewebview2`는 별도 프로세스 수와 CPU 항목으로 공개한다. 해당 프로세스의 존재를 일반 브라우저 실행으로 간주해 강제 종료하지 않았다. 모든 앱 내 웹 렌더러나 전체 컴퓨터가 완전 무부하였다는 뜻은 아니다. CPU 표본은 신규/종료·접근 불가·짧게 실행된 프로세스, GPU·온도·클럭·예약 작업을 완전히 관찰하지 못한다.

## 공개 사본 정책

원자료의 지정된 최상위 JSON/PGN/로그/재현/감사 스크립트만 선택했다. 실행 파일·개인 기보·토큰·앱 세션·프로세스 ID와 개인 앱 경로 목록은 포함하지 않는다. 경로와 호스트명은 `$REPO`, `$BASELINE_REPO`, `$WSL_REPO`, `$USERPROFILE`, `$HOSTNAME`으로 치환했다. 숫자·수순·옵션·선택 정책·엔진/원본 해시는 유지한다.

각 감사의 내부 `evidence_sha256`은 당시 읽은 사본의 해시다. 공개 경로 치환과 개행 정규화로 달라진 현재 파일의 바이트 해시는 최상위 [sha256.json](sha256.json)을 사용한다. 이 목록은 최상위 자료와 `excluded-attempt-1/`의 공개 파일을 모두 포함하며 자기 자신은 제외한다. `.gitattributes`가 자동 개행 변경을 막는다.

## 재현

원래 코드 커밋과 실행 파일 SHA는 `provenance.json`에 기록한다. 같은 소스에서 새로 빌드해도 PE 링크 메타데이터와 도구 버전에 따라 SHA가 달라질 수 있다. 기존 규칙/탐색 회귀와 고정 깊이 비용 검증은 앞선 v0.5.8 기록을 참조하며 이번에 다시 수행했다고 주장하지 않는다.

`run-match.ps1`, `run-monitored.ps1`을 저장소의 새 `build/<실험 폴더>/`로 복사하고 경로·출력 폴더를 자신의 새 위치로 바꾼 뒤 실행한다. 기존 출력은 덮어쓰지 않는다. Python은 저장소의 테스트 의존성 `chess==1.11.2`를 사용한다. 대국 중 컴파일·다른 대국·독립 감사는 겹치지 않는다.

공개 자료 재감사는 저장소 안에서 아래처럼 새 출력 이름으로 실행한다. 감사는 기존 `docs/checks/2026-10-18-lmr/audit-lmr.py`의 기보/검색 검증 함수를 재사용하고, 이번의 조건/부하/짝별 점수를 별도로 검사한다. Git 계획 객체와 기존 원자료가 필요하다. 공개 사본 자체에는 실행 파일이 없다. 같은 checkout의 `$REPO/build/...`에 해당 파일이 있으면 바이트 해시도 확인하고, 없으면 선언된 SHA 일관성만 확인하며 `bytes_available=false`로 한계를 기록한다.

보존한 `public-replay-audit.*`는 이 컴퓨터에서 경로를 치환한 공개 사본을 다시 검사한 결과다. 로컬의 두 실행 파일 바이트도 찾았으므로 채택 시도13,594항목·실패0을 재현했고, 제외 시도는 원래와 같은 브라우저 기준109실패를 재현했다.

```powershell
python docs/matches/2026-10-18-lmr-idle-rematch/audit-rematch.py --evidence docs/matches/2026-10-18-lmr-idle-rematch --output-prefix public-replay-audit
```

같은 명령에 `--evidence .../excluded-attempt-1`을 주면 의도적으로 브라우저 기준 실패를 재현한다. 이 실행을 정상 채택 감사와 혼동하지 않는다.
