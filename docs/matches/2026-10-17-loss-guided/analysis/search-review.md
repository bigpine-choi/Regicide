# 코드 리뷰: 조용한 수 정렬과 제한된 체크 안정화 탐색

2026-10-17 변경된 `src/search.cpp`, 공개 옵션과 탐색 검증을 읽기 전용으로 검토했다. **수정이 필요한 정확성 결함이나 진행을 막는 문제는 발견하지 못했다.** 이 리뷰에서는 추가 경기력 실험이나 같은 시간 대국을 실행하지 않았다.

## 확인한 탐색 불변 조건

- killer/history는 Searcher가 소유하며 검색마다 0으로 초기화된다. 반복 심화 사이에는 유지하되 SearchContext 재사용으로 다음 검색에 넘기지 않는다. 정상 탐색의 합법 수를 제거하지 않고 순서만 바꾼다.
- killer 접근은 남은 깊이가 양수인 정상 노드뿐이다. 최대 루트 깊이 64라면 ply는 0~63이며, 배열은 97칸이다. from/to는 합법 수의 0~63, 색 인덱스는 0/1이다.
- history의 깊이 제곱 보상은 최대 4,096이고, 누적값은 비음수 16,384 이하로 유지된다. 최대 곱 16,384×4,096=67,108,864와 수 정렬 점수 약 1,100만은 int 범위 안이다. 캡처·승격은 조용한 수로 학습하지 않으며 캐슬링은 합법적인 조용한 수로 취급할 수 있다.
- 정상 탐색의 깊이 0에서 안정화로 진입할 때 선택적 조용한 체크 예산을 0 또는 1로 시작한다. 조용한 체크만 예산 1을 소모하고, 캡처·앙파상·승격은 소모하지 않는다.
- 체크 중에는 현재 평가로 멈추지 않고, 예산이 0이어도 모든 합법 회피 수를 탐색한다. 조용한 맞체크 회피 수는 남은 예산이 있을 때만 소모한다. 따라서 제한은 '선택적으로 추가하는 체크 1회'이며 강제 회피의 맞체크 전체를 1회로 제한하지 않는다. 공개 주석도 이 의미로 수정됐다.
- `gives_check_generated()`는 Position만 복사해 기존 apply/checked를 사용한다. 원래 Board의 위치·이력·반복 횟수·해시·캐슬링/앙파상 상태를 바꾸지 않는다. 캐슬링 룩 이동, 발견 체크, 앙파상, 각 승격을 보드 검증으로 확인했다.
- 안정화 깊이 상한 32를 유지한다. 상한에 도달해도 메이트·스테일메이트를 먼저 확정하고, 해결하지 못한 체크라면 반복을 중단해 직전 완료 결과를 유지한다. 전체 최대 ply는 64+32=96이다.

## 무승부·메이트·전이표·중단

- 합법 수가 없을 때의 메이트·스테일메이트는 자동 무승부와 정적 평가보다 먼저 처리해 기존 우선순위를 유지한다.
- 현재 및 예정 수의 반복·50수 청구는 기존의 전체 Board 이력을 사용한다. 새 체크 분류는 이력을 추가하거나 삭제하지 않는다.
- TT는 정상 탐색에만 쓰고 안정화 점수는 저장하지 않는다. 새 체크 예산은 안정화 내부 상태이며 각 정상 탐색의 같은 남은 깊이는 같은 예산으로 시작한다. 따라서 기존 위치·전체 반복 문맥·반수 카운터·남은 깊이 키에 경로 의존 예산이 빠지는 문제가 없다.
- 옵션은 검색 중 고정되고 다음 검색은 새 TT 세대를 사용한다. 조용한 수 정렬이나 체크 옵션을 바꿔도 이전 점수·수를 재사용하지 않는다.
- TT 수의 합법성 확인, 메이트 거리 보정, 완료한 정상 노드만 저장, 루트의 명시적 탐색은 변경하지 않았다.
- 새 경로도 기존 총 노드 예산·시간·중지 확인과 AppliedMove의 복원을 공유한다. 판정 필터는 유한한 합법 수 목록에만 적용된다. 중단된 부분 반복을 완료 결과로 공개하지 않는다.

## 검증 코드의 독립성과 범위

새 제한 체크 기준 탐색은 생산 체크 예측 함수를 호출하지 않고, 합법 수를 실제 play한 뒤 in_check를 조사한다. 수 정렬·alpha-beta·TT가 없는 완전 탐색과 비교한다. 다음 항목을 코드에서 확인했다.

- 예산 0에서 회피 수와 조용한 맞체크를 실제로 방문했음을 요구한다.
- 캡처·승격이 예산을 유지하는 분기를 실제로 방문했음을 요구한다.
- killer/history 켬·끔을 독립 minimax와 비교해 같은 깊이의 값을 유지한다.
- TT 켬·끔, 메모리 재사용, 옵션 전환, 중단 뒤 새 검색과의 일치를 확인한다.
- 캡처 전용 안정화가 놓치는 조용한 메이트를 실제 합법 PV로 검증한다.
- Caro-Kann 패배의 Nxe7에 대한 ...Nf3+ 계열 응수, 총 100노드 중단과 전체 상태 복원을 확인한다.
- 보드 예측 함수는 리뷰 담당자가 직접 엄격 Release와 Debug ASan/UBSan으로 실행해 **10그룹 18,974검사** 통과를 확인했다. 일반·발견·캐슬링·앙파상·각 승격·맞체크와 깊이 2의 전체 합법 수를 실제 적용 뒤 in_check와 대조한다.

탐색 담당자가 MSVC 엄격 Release의 **30그룹 4,906검사** 통과와 파일 고정을 보고했다. 리뷰 담당자는 그 탐색 바이너리를 다시 실행하지 않았으므로 이 항목은 담당자의 실행 결과로 구분한다.

## 남는 실험적 한계

이 변경은 선택적 조용한 체크 1회 추가이며 ...Ng4처럼 체크하지 않는 포크 준비나 조용한 메이트 위협 전체를 읽는 변경은 아니다. 13번 캐슬링 문제가 남는 것은 이 범위와 모순되지 않는다. 추가 후보 판정과 탐색은 비용을 늘리므로 같은 시간에서 경기력이 개선되는지는 별도 실험이 필요하다. 고정 깊이의 값이 맞는 것과 강한 수를 안정적으로 고르는 것은 별개 검증이다.
