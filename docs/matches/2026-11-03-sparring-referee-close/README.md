# Stockfish 보조 스파링: 접전 효과 비교와 후보 발견 개선

2026-11-03. **새 오프닝의 12구간 비교에서 첫 20수의 ±1점 유지 비율은 기존 62.5%, 심판 v1 65.0%, 개선 v3 81.9%였다. v3를 로컬 대국 프로그램에 반영했다.** 각 방식 4구간인 소규모 관측이며 접전 보장은 아니다. 초기 개선안 v2는 개발 대국에서 나빠져 보류했고, 후보 부족을 보완한 v3를 수정에 사용하지 않은 시작 수순과 시드로 검증했다. 실패한 v2 소스와 원본도 함께 보존한다.

평가 대상은 외부 도움을 받는 연습 모드다. 후보는 Regicide 자체 엔진이 만들고, 별도 Stockfish가 그 후보 중 실제 수를 고르는 데 관여한다. 자체 Regicide의 기력·Elo, 사람과 둘 때의 자연스러움, 승리 보장을 입증하는 실험은 아니다.

| 구간 종료 | 최대 44반수에서 중단. 상한 도달은 결과 `*`인 미완료이며 인위적 무승부로 계산하지 않음 |

약화 Stockfish의 설정 숫자는 사람의 Chess.com 또는 Lichess 레이팅이 아니다. 보조 심판을 추가한 비교군은 전체 계산량도 더 쓰므로 동일 CPU 비용의 기력 비교가 아니다. 작업 수와 단계 분리는 기록했지만 외부 시스템 부하가 전혀 없었다는 증명은 아니다.

실행 파일 SHA256은 다음과 같다. 상대·보조 심판·사후 평가자는 같은 Stockfish 바이너리를 서로 다른 용도로 실행한다.

```text
Regicide:  5011da4c5e6ef01c452bd7125e4e22b372d2c9cfb858ed8759057325acb0e6ba
Stockfish: 9bde420202717ce083412027fbfb8c5c935b537591d712be8a8a8bae92f6e8d6
```

주지표는 **실제 착수 직후 위치 1~40반수 중 사후 평가가 ±100cp 안인 비율**이다. 화면에서는 `100cp`를 1점으로 표시한다. Stockfish의 정규화 점수이며 실물 폰 한 개의 가치와 정확히 같다는 뜻은 아니다. 여기서 반수는 한쪽의 착수 한 번이며, 40반수는 백·흑이 20수씩 둔 구간이다. 봇 혼자 40번 착수한 창과 혼동하지 않는다. 시작 위치는 제외하고, 양쪽 착수 뒤 위치를 모두 센다. ±200cp도 함께 집계하고, 평가 불명·메이트·누락은 따로 남겨 분모에서 조용히 빼지 않는다. 44반수까지 둔 나머지 위치는 보조 진단에 쓴다.

최종 별도 검증은 고정 시작 수순 `d2d4 d7d5 c2c4 e7e6`을 포함한다. 전체 첫 40위치와 함께, 고정된 4반수를 제외한 **5~40반수의 36위치**도 따로 비교해야 한다. 비교군별 4판이면 두 분모는 각각 160·144다. 40위치가 전부 ±100cp 안인 판의 수는 개별 위치 비율과 별도의 엄격한 연속 유지 지표다.

## 초기 8판 비교: 관측 상승과 인과 해석의 한계

초기 비교는 표준 시작 위치에서 before·v1 각 4판, 총 8판이다. 상대 설정·선후공·시작 위치·스파링 시드를 맞춘 4쌍이며, 시드는 `sparring-close-primary-2026-11-03`이다.

| 지표 | before | v1 |
| --- | --- | --- |
| 첫 40위치 중 ±100cp | 117/160, 73.125% | 131/160, 81.875% |
| 첫 40위치 중 ±200cp | 145/160, 90.625% | 147/160, 91.875% |
| 모든 40위치가 ±100cp 안인 판 | 0/4 | 0/4 |
| 첫 40반수의 실제 비기준수 심판 선택 | 0 | 5 |
| 봇 차례 평균 벽시계 시간, 판별 평균의 평균 | 약 3324ms | 약 3123ms |

±100cp 비율의 관측 차이는 +8.75%p지만 이를 심판의 인과적 개선 효과로 확정하지 않는다. 약화 Stockfish의 내부 무작위 시드는 제어할 수 없어 조건을 맞춰도 수순이 달라진다. 네 쌍 모두 실제 심판의 비기준수 선택보다 앞선 상대 착수에서 첫 수순 차이가 발생했다. 특히 순증 14위치 중 12위치를 기여한 한 쌍은 첫 실제 심판 수 변경이 39반수였다. 앞선 차이 전체를 그 한 번의 개입으로 설명할 수 없다.

위치는 같은 대국 안에서 서로 연관되어 있고 비교쌍도 4개뿐이다. 관측된 비율 상승과 별개로 엄격한 연속 유지 성공은 두 군 모두 0/4판이다. 기록된 호스트 시간도 실제 진행 수순과 보조 작업량이 달라, 속도 개선의 근거로 쓰지 않는다. [독립 집계](primary-independent-summary.json), [원본 재생 감사](primary-independent-audit.json)에 조건·분모·단계 장벽과 쌍별 차이가 있다.

## v2 개발 실패와 원인 진단

v1은 자체 기준수와 원래 제안수만 비교했고, 둘 다 심판의 접전 범위 밖이면 기준수를 유지했다. 실제 진단에서 심판 기준 +254cp인 기준수보다 +135cp인 자체 대안이 덜 벌어진 위치였는데도, 둘 다 ±80cp 밖이라는 이유로 변경하지 않는 병목이 보였다. 이 ±80cp는 내부 선택 범위이며 보고 지표 ±100cp와는 다르다.

v2는 원래 자체 탐색에서 이미 합법성·자연스러움·같은 완료 깊이 점수가 검증된 후보를 총 4개까지 재사용했다. 또 안전 하한을 지키면서 목표와의 거리가 줄면 범위 밖에서도 점진 회복을 허용했다. 그러나 재사용한 개발 설정·시드의 4판은 다음과 같았다.

| 지표 | v2 개발 결과 |
| --- | --- |
| 첫 40위치 중 ±100cp | 110/160, 68.75% |
| 첫 40위치 중 ±200cp | 133/160, 83.125% |
| 모든 40위치가 ±100cp 안인 판 | 0/4 |
| 첫 40반수의 심판 비기준수 선택 | 14 |
| 44반수까지 부분 회복 승인 | 6 |
| 봇 차례 평균 벽시계 시간, 판별 평균의 평균 | 약 5325ms |
| 개발 판정 | 채택 보류, 소스·실패 원본 보존 |

심판이 수를 더 바꿨다는 사실만으로 전체 구간 접전이 개선되지는 않았다. 같은 개발 시드를 다시 써도 상대의 무작위 수순은 재현되지 않아 초기 결과와의 차이 전부를 v2 탓으로 돌릴 수도 없다. 다만 이 결과는 v2 채택 근거로 부족했고, [개발 감사](candidate-v2-independent-summary.json)에 실패를 그대로 남겼다.

구체적으로 첫 개발 판 35반수의 `Qg8xa8`은 자체 깊이 7에서 +200cp였지만, 실제 착수 뒤 깊이 14 사후 평가는 -385cp였다. 당시 다른 자체 후보들은 공통 깊이 7을 완료하지 못해 후보군에 들어가지 못했고, 후보 1개인 `baseline_only`로 심판 비교를 건너뛰었다. 이것은 심판이 그 기준수의 안전을 검증했다는 뜻이 아니다. 기록에는 `Qc4`가 자체 깊이 6, +54cp인 합법 후보로 이미 존재했다.

실패 위치를 따로 진단하자, 자체 깊이 4의 제외식 추가 탐색 세 번이 `Qg7/Qc4/Qf7`을 총 약 246ms에 찾았다. 동일 부모 위치에서 Stockfish 깊이 16으로 네 후보를 함께 비교한 값은 `Qc4` +43cp, `Qxa8` -911cp였다. 이 값은 앞서 실제 착수 뒤 위치를 깊이 14에서 평가한 -385cp와 탐색 위치·깊이가 다르므로 같은 측정으로 섞지 않는다. [표적 진단 원본](baseline-blunder-diagnosis.json)은 이미 실패를 본 위치의 설명 자료이며 별도 검증 표본이 아니다.

## 같은 부모 위치의 선택 효과 진단

전체 대국의 무작위 경로 차이와 수 하나의 선택 효과를 분리하기 위해, 첫 40반수에서 **실제 수가 원래 Regicide 제안수와 달라진 모든 위치**를 선택했다. 심판 승인만 골라내지 않아 제안을 거절하고 기준수를 유지한 경우도 포함한다. 각 부모 위치에서 실제 수와 원래 제안수를 Stockfish 깊이 16의 같은 MultiPV 탐색으로 비교했고, 29위치 모두 같은 완료 깊이의 유한 exact 점수를 확보했다.

`exact`는 UCI 상·하한 점수가 아닌 완료 점수라는 뜻이며 정답 보증이 아니다. `D=max(|cp|-100, 0)`는 ±100cp 밖으로 벗어난 양이다. 실제 수의 D 또는 절대 CP가 원래 제안수보다 작으면 개선으로 집계했다.

| 대상 | 위치 수 | D 개선 / 악화 / 동률 | 절대 CP 개선 / 악화 / 동률 |
| --- | --- | --- | --- |
| v1 선택 변경 | 7 | 4 / 3 / 0 | 4 / 3 / 0 |
| v2 개발 선택 변경 | 22 | 12 / 2 / 8 | 19 / 3 / 0 |
| 합계 | 29 | 16 / 5 / 8 | 23 / 6 / 0 |

후보 비교가 일부 같은 위치에서 차이를 줄이는 기전을 뒷받침하지만 악화도 있었고, 다른 수를 둔 뒤의 전체 대국은 재현하지 않았다. 서로 독립적인 29경기도 아니며 v3의 새 검증 결과도 아니다. [선택 효과 원본](counterfactual-development.json)에 필터·두 PV·깊이·입력 및 실행 파일 해시가 있다.

## v3 수정 원리와 검증 범위

1. **기존 자체 후보를 먼저 살린다.** 공통 기준 깊이에 못 미쳤더라도 깊이 4 이상에서 개별 완료된 정확한 유한 점수와 전체 합법 PV, 자연스러움이 있는 후보를 별도 출처로 재사용한다. 깊이 7 기준수와 깊이 6 후보의 점수를 빼서 손실로 주장하지 않으며 `native_comparison_available=False`, `loss_cp=None`으로 구분한다.
2. **후보가 부족하면 짧게 더 찾는다.** 8~39반수, 사용자가 수를 바꾼 핸디캡 이력과 자원 보호가 없고 심판을 쓸 수 있는 경우에만 기존 Regicide 탐색으로 깊이 4 후보를 추가한다. 시계가 있으면 180초 이상 남아야 하며, 호출 때 현재 시계에서 500ms를 남기는 예산 상한을 적용한다. 후보 제외를 반복하되 추가 자체 탐색은 총 600ms, 새 후보 최대 3개, 기준수를 포함한 최종 심판 후보는 총 4개다.
3. **부분 회복에도 후속 검증을 유지한다.** 같은 부모 위치의 완료된 공통 깊이로 비교하고, 선택 후보를 둔 자식 위치에서 상대 응수를 제한 없이 검사한다. 안전 하한·기준수보다 나은 목표 거리·부모/자식 점수 불일치 상한을 유지한다. 메이트를 CP로 바꾸지 않고, 동률이면 기준수를 우선한다. 40반수부터 기준수 쪽으로 돌아가는 전환과 98반수 이후 자체 전력 유지도 보존한다.
4. **늦은 결과와 평가 출처를 분리한다.** 추가 탐색은 전역 예산 +100ms 감시와 취소 감시를 두고, 실패 시 모은 후보를 폐기한다. 과거 대기·회복 목표는 새 제한 탐색과 분리하지만 실제 시계 만료, 대국 ID·수정 번호·위치 변경, 취소는 유지한다. 자체 점수를 Stockfish 점수로 덮지 않으며, 원래 제안수의 자체 후속 검사 완료 표식을 새 선택에 옮기지 않는다. 심판의 후속 평가는 별도 `referee.postmove`에만 남긴다. 과거 v1/v2 기보의 실제 정책과 심판 출처도 복원한다.

알려진 `Qxa8` 실패 원본을 재사용한 회귀에서는 v3가 저장된 깊이 6의 `Qc4` 후보를 살려 선택했고, 별도 심판의 후속 값은 +45cp였다. 자체 값 +54cp와 `loss_cp=None`을 유지했고 추가 자체 탐색은 하지 않았다. [알려진 실패 회귀](v3-known-failure-reuse.json)는 수정 동작을 확인한 사례이며, 같은 위치를 고친 뒤 다시 검사한 것이므로 일반화나 대국 개선의 독립 근거로 쓰지 않는다.

최종 후보의 [자동 회귀 결과](final-regression.json)는 13묶음 267검사 중 265통과·2건너뜀이다. 후보 출처·합법 PV·점수 부호·깊이·취소·시간 만료·호스트 기록·기보 복원 경계를 검증한 기능 검사다. 이 통과를 접전 효과나 자체 엔진 기력 향상으로 해석하지 않는다.

## 최종 별도 검증과 채택

수정에 사용하지 않은 수순 `d4 d5 c4 e6`, 새 시드 `sparring-close-heldout-2026-11-03`로 before/v1/v3 각 4판, 총 12구간을 비교했다. 상대 설정과 선후공 네 조건은 각 군에 동일하게 적용했다. 12개 플레이 작업 종료 후 12개 사후 평가 작업을 시작했고, [독립 감사](holdout-final-independent-audit.json)에서 조건·원본·평가 출처·분모·기보 재생·소스/바이너리 불변을 모두 통과했다. v3 보관함 재생 90프레임도 확인했다.

모든 구간은 44반수 상한까지 진행해 결과는 미완료 `*`다. 승패·Elo로 집계하지 않았다. v3의 ±100cp 변화는 before 대비 **+19.375%p**, v1 대비 **+16.875%p**다. before와의 네 쌍 차이는 +12.5·+15·+42.5·+7.5%p로 모두 양수였다. v1과 비교하면 한 쌍은 −5%p였고 나머지 세 쌍이 높았다. 같은 길이·누락 없는 구간이므로 이 비율은 판별 비율을 동일 가중한 평균과도 같다. [대국별 집계·불확실성](holdout-final-independent-summary.json)에 각 쌍을 남겼다.

대불균형 증가 3/4/1건은 모두 **상대 착수 직후 AI 우세가 커진 경우**다. 이를 자체 엔진의 실수 감소 횟수로 부르지 않는다. v3에도 −200cp 미만 위치 2개와 엄격한 연속 유지 실패가 남았다. 평균 소요 시간은 실제 서로 다른 수순에서 관측한 벽시간이며 계산 속도 비교가 아니다. v3는 후보 확보와 심판 실행을 더 사용한다. [실행 공정성 감사](holdout-final-fairness-audit.json)에서 공통 조건·전체 단계 분리·동시 2작업·기록된 소유 엔진 104개 종료를 확인했다. 전체 desktop CPU는 평균 17.1%, 5초 구간 평균 최대 46.0%였으며 외부 부하와 프로세스별 CPU를 분리하지 못했다.

최종 원본의 모든 선택 변경 위치를 같은 부모에서 깊이 16으로 다시 비교했다. v3의 변경 24건은 절대 평가값이 모두 더 균형에 가까웠으며, D는 9건 감소·15건 동률·악화 0건이었다. ±100cp 안인 후보는 원래 제안 15/24에서 실제 선택 22/24로 늘었다. v1의 6건은 D 감소 2·동률 3·악화 1, ±100cp는 3/6에서 3/6이었다. [동일 위치 선택 진단](counterfactual-holdout.json)은 30건 모두 유효한 같은 완료 깊이·합법 PV를 확보했다. 이 24건은 4개 대국에서 나온 상관된 조건부 사례이며 독립적인 24경기가 아니다.

**판정:** 이 조건의 소표본에서 접전 빈도 상승과 같은 위치의 선택 개선을 함께 관측했고, 기능·원본 감사도 통과해 v3를 채택했다. C++ 자체 엔진·실행 파일·평가 함수·학습 모델은 변경하지 않았다. 사용자는 Regicide를 다시 열어 기존 Stockfish 심판 스파링을 시작하면 된다. 추가 인증은 필요 없다.

표본은 군별 4개 구간뿐이고 약화 상대의 내부 무작위성은 남는다. 조건을 맞췄어도 수순은 심판 개입 전부터 갈라질 수 있어 전체 비율 차이를 순수한 인과 효과로 확정하지 않는다. 사후 고정 깊이 14·선택 진단 깊이 16이 실시간 심판보다 항상 깊지는 않다. 평가자는 같은 Stockfish 계열이므로 독립 엔진 계열의 판정도 아니며, 깊이와 탐색 범위에 따른 오차가 있다. 44반수 상한은 종국·승패나 50수 전력 전환을 대국 결과로 검증하지 못한다. 접전 보장·사람 상대 체감·Elo·장기 승률은 별도 과제다.
