# 초반 접전 재검증 계획

기존 `2026-11-04-sparring-quality-v2`의 세 대국은 모두 보존한다. 새 코드는 그때 접전에서 벗어난 위치를 고정 기보로 재현한 뒤 검증한다. 이 파일을 준비한 시점에는 새 대국을 실행하지 않았다.

## 새 대국 조건

- 표준 시작 배치, Regicide 스파링 백·흑 각 2판, 총 4판.
- 이전 시드 입력 `2026-11-03-quality-guard`와 새 시드 입력 `2026-11-04-early-balance-v3`를 각각 선후공에 배분한다.
- 실제 `HumanGame` 경로, 10+0. Regicide 요청 3000ms, 상대 300ms, 최대 220ply.
- 상대 Stockfish 18: `UCI_LimitStrength=true`, `UCI_Elo=1700`, Threads 1, Hash 16MiB.
- 형세 심판 Stockfish 18: 제한 없음, Threads 1, Hash 32MiB. 실제 수 후보는 Regicide에서 생성한다.
- 실제 탐색 시간은 게임 시계에 그대로 부과한다. 연출용 대기만 수면 없이 같은 시간을 게임 시계에 부과한다. 동일 시드라도 상대의 확률적 선택과 시간제 탐색이 같다는 보장은 없다.
- 최대 두 판만 병렬 실행한다. 고정 재현·대국·감사를 합해 무거운 엔진 작업은 동시에 두 개 이하로 유지한다.
- 소스 동결 전에는 대국을 시작하지 않는다. 시작 전후 Python 소스와 양 엔진 실행 파일 해시를 비교한다.
- 실제 기보와 진행·원본 탐색 기록을 보관하고 합법 수순·PGN·최종 결과 일치를 검사한다. 평가로 조기 승패 판정을 하지 않는다. 수 제한·시간패·오류·중단을 정상 종국과 구분한다.

## 독립 평가와 접전 지표

모든 초기·착수 후 국면을 별도의 전력 Stockfish로 각 200000노드 새 탐색한다. 기존 감사의 모든 의심 장면은 전후 국면을 각 3000ms 추가 평가한다. 감사 개수 상한은 두지 않는다.

1. 초기부터 20수까지 41개 위치의 `|cp| ≤ 100` 연속 유지. 20수 전에 끝난 대국은 통과로 세지 않는다.
2. 스파링 직후와 상대 직후의 접전 비율을 따로 집계한다. 상대 실수로 이미 생긴 격차를 스파링 자신의 착수 오류와 구분한다.
3. 스파링 착수 후 우세가 남은 경우, 열세가 남은 경우, 메이트·종국·미확인을 각각 기록한다. 큰 우세를 안전하게 접전으로 되돌린 수와 열세로 붕괴시킨 수는 따로 해석한다.
4. 기물 노출과 후속 4ply 기물 감소는 의심 신호다. 큰 평가 손실과 겹치면 원래 수·대안·회수·강제 수순을 검토하고, 보상이 있는 교환·희생을 무조건 헌납으로 세지 않는다.
5. 최종 품질 검사 기록의 적용 여부와 실제 native 탐색의 반환 수·위치·전체 기보를 대조한다. 미확인·생략·검사 누락과 손실 축소를 접전 성공으로 세지 않는다.
6. 21~49수의 양보 축소 및 50수 이후도 관측한 범위에서 함께 보고한다. 새 초반 정책 때문에 후기 안전 검사·시계·취소가 약화되지 않았는지 자동 검사와 연결한다.

네 판은 기능 진단이며 Elo·전체 기력·인간 체감 또는 모든 대국의 접전 보장이 아니다. 기존 세 판과 새 네 판 모두 결과표에 포함하되 승률의 직접 비교로 해석하지 않는다.

## 중간 4판 보존과 추가 2판 — 실행 전 결정

첫 시드 쌍은 스파링 직후 각각 20/20 접전이었으나 새 시드 쌍은 각각 16/20이었다. 새 흑의 17...Bf5(ply 34)·18...h5(ply 36)에서는 후속 기물 감소와 독립 평가 손실이 겹치는 신호도 나왔다. 이 네 판·280ply를 성공 표본으로 대체하거나 삭제하지 않고 중간 구현 결과로 전부 보존한다.

이 실패 위치를 고정 기보로 재현해 추가 수정과 회귀 검사를 수행한 뒤, 실패했던 새 시드 `2026-11-04-early-balance-v3`를 백·흑 각 1판 더 실행한다. 조건은 위의 1700·3000/300ms·10+0·220ply·표준 시작·전위치 200000노드·의심 전후 3000ms와 같다. 출력은 `pair3-1700-white`, `pair3-1700-black`으로 분리한다. 총 여섯 판 전부 보고하고, 각 구현의 파일별 해시와 요약의 소스 지문으로 버전을 구분한다. 추가 두 판도 실패하면 통과로 바꾸거나 원본에서 제외하지 않는다.

## 6판 뒤 남은 이탈과 추가 2판 — 실행 전 결정

v3 구현의 `pair3`은 백 79ply·흑 100ply로 정상 종료했다. 독립 평가의 스파링 직후 접전은 흑 20/20, 백 16/20이며 기물 손실 의심은 양쪽 0이었다. 백의 네 이탈은 우세 +139/+150/+317/+283cp였다. 15.Bxb5(ply 29)의 국소 기물 노출은 강제 체크와 다른 칸의 룩 회수로 보상이 있음을 별도로 확인했으며 원래 `unverified` 판정은 보존한다.

원래 교환을 상대가 이미 다른 공격자로 이어가도록 바꾼 경우의 좁은 이력 증거와, 초기 엄격 기물 검사에서 거부된 수의 접전 대안 탐색 누락을 추가 수정한 뒤 같은 실패 시드로 선후공 각 1판을 더 실행한다. 출력은 `pair4-1700-white`, `pair4-1700-black`이다. 고정 국면 재현과 회귀 검사·소스 동결을 완료한 뒤 시작하고 위와 동일한 대국·감사 조건을 유지한다. 중간 6판·459ply와 새 2판을 모두 보존하여 총 8판을 보고하며, 가장 최근 구현의 2판은 소스 지문으로 따로 집계한다.
