## 너무 일찍 봐주기를 중단하는가

기물 양보만 막는 주의는 전체246/580회, 첫40수26/320회였다. 위치 양보는 계속 허용한다. **완전히 양보를 중단하는 critical 보호는0회**였다. 따라서 이번 표본에서 보호 문턱 때문에 일찍 전력으로 고정된 사례는 없다. 이 사실이 모든 종반에서 기준이 최적이라는 증거는 아니다. 자세한 두 단계 문턱은 [기능 기록](../../checks/2026-11-03-sparring-v2/README.md)에 있다.

큰 기물 손실 뒤 지연 회복은2사건·8착수에서 발동했다. 두 사건 모두 네 번째 단계에서 엄격한 ±100cp 복원에 실패했다. 첫 판은71~77반수에 선택 평가가 +846,+664,+665,+257cp로 남았고79반수도+554cp였다. 6번 판은 첫 세 단계는 범위 안이었지만 네 번째 단계는 범위 밖이었다. 임시 완화 목표를 만족했다는 표기와 엄격한 접전 복원 성공을 혼동하지 않는다.

실제 지연 기물 반환 예외와 이기는 메이트 회피는 이번8판에서 각각0회다. 전자는 합성 정책 검사, 후자는 별도 실제 엔진 Fool's Mate 위치에서 `Qh4#` 대신 `d6`(+27cp)을 택하는 동작을 검증했다. 이 단일 위치를 대국에서 자연스러운 반환을 관측한 증거로 쓰지 않는다.

## 레이팅·기록·재현

유효 상대 관측493개. 모든 판은 보정 데이터0개인 휴리스틱 사전값으로 시작했으며 Stockfish 설정을 실제 사용자 레이팅 라벨로 저장하지 않았다. 실제 Chess.com 래피드 대응 정확도에 대한 실험은0회다. 새 UI의 숫자 변화·종료 후 라벨 저장/정정·다음 판 보정은 별도 기능 검사로 검증했다.

8판1160반수의 PGN/JSON/JSONL/저장 sidecar를 독립 재생했다. 시작 기록을 포함한16sidecar를 실제 GameArchive로 전프레임 로드해 미래 레이팅 관측 누출이 없고, 가장 큰 파일2,790,232bytes가4MiB 제한 안임을 확인했다. 소스/실행 파일 해시는 시작·끝 일치. ZIP60파일을 다시 열어 개별 SHA256 확인. 비공개 레이팅 DB 디렉터리와 SQLite 파일은 제외했다.


재현은 기록된 커밋의 별도 체크아웃에서 수행한다. 기존 작업 폴더를 되돌리지 않는다. 감사 스크립트의 상대 경로 계산은 실행 당시 build 구조를 보존한다. 재실행할 때 저장소의 새 build/<진단 폴더>/에 감사 스크립트를 복사하고 그 폴더에 원본 ZIP을 푼 뒤 실행한다. 다른 위치를 쓸 경우 ROOT와 BASE를 둘 다 맞춰야 한다. 기록의 절대 경로와 Git 표시는 당시 원본을 그대로 보존했다.
