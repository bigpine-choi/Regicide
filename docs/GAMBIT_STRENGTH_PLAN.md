착수일: 2026-11-04, 한국 시간. 연구 분기: `experiment/gambit-strength-m1`.

현재 상태: **M1 완료, M2 후보 비교·실제 평가 호출 진단 완료**. 단순 재시작·일괄 시간 증액은 미채택이다. M2의 4국면·84회 비교에서 LMR on/off의 최종 점수와 수는 모두 같았고, King's의 퀸 위협 위치에서 실제 정적 평가 호출을 확인했다. 다음은 비체크 퀸 위협에 대한 정지 탐색 가설 구현과 검증이다. 핵심 엔진 수정·같은 시간 비교는 아직 남아 있다. [M1 결과](checks/2026-11-04-gambit-strength-m1/README.md), [M2 구현·진단 결과](checks/2026-11-04-gambit-strength-m2/README.md).

목표는 **갬빗을 제안하고 공격을 이어가는 특성을 유지하면서, 정확한 방어를 만났을 때의 불필요한 손실을 줄이는 것**이다. 실제 착수는 자체 Regicide가 선택한다. 의도한 희생의 비용, 그 뒤의 전술 실수, 최종 대국 성적을 구분한다.

사용자의 추가 요청에 따라 정책 v8에 [체스닷컴 `!`·`!!`를 목표로 하는 전술·희생 선호](checks/2026-11-04-gambit-chesscom-target/README.md)를 구현했다. 이는 자체 후보 선택 정책 개선이며, M2의 핵심 정지 탐색 수정이나 체스닷컴 실제 등급 증가를 완료한 것으로 집계하지 않는다.

## 첫 문제와 가설

[기존 희생 후 운영 실험](checks/2026-11-04-gambit-operations/README.md)의 최종 120착수 중 외부 감사 손실이 150cp를 넘은 네 수는 모두 갬빗 정책의 교체수가 아니라 **자체 기본 탐색의 수**였다. cp는 폰을 100으로 둔 평가 단위로 승률이 아니다.

| 개발 국면 | 기존 선택 | 자체 완료 깊이 | 기존 외부 손실 |
| --- | --- | ---: | ---: |
| kings-accepted:9 | Bb5 | 5 | 165cp |
| kings-accepted:11 | Nc3 | 5 | 259cp |
| morra-developed-defense:25 | Ne6 | 4 | 167cp |
| budapest-accepted:16 | Nb4 | 4 | 154cp |

이 국면들의 추가 예산은 최대 1000ms였으나 실제 사용은 약 103~285ms였다. 후보를 기본 탐색과 같은 깊이에서 확인한 뒤 끝내므로 남는 시간이 있다. 첫 가설은 **남는 시간을 제한 없는 자체 탐색에 쓰면 더 깊은 완료 결과를 얻을 수 있는가**이다. 탐색을 다시 시작하면 이전의 미완료 계산은 이어지지 않으므로, 단순한 반복 호출의 이득을 가정하지 않는다.

## M1: 재현과 시간 배분 진단

`scripts/check_gambit_search_budget.py`는 네 알려진 실패를 원본 보고서에서 전부 추출한다. 대조군은 같은 기존 자료에서 미리 정한 순서로 뽑으며, 새로운 결과를 보고 고르지 않는다. 둘 다 이전 개발자료로서 미학습 평가 자료가 아니다.

1. 새로운 자체 엔진에서 1000ms를 계산한다.
2. 같은 국면·엔진·게임 식별자를 유지하고 750ms를 다시 계산한다.
3. 별도 새 엔진에서 연속 1750ms를 계산해 총 요청 시간이 같은 대조군을 만든다.
4. 모든 자체 선택이 끝난 뒤에만 별도 Stockfish로 같은 루트에서 비교한다. 모든 비교가 공통으로 완료한 정확한 깊이만 사용한다.

실행 파일·원본 자료·검증 코드 해시, 전체 수 이력, 원시 UCI, 요청/실제 시간, 완료 깊이, 선택 수와 종료 상태를 보존한다. 외부 감사 수를 실제 착수 선택에 입력하지 않는다. 같은 최대 시간과 같은 실제 CPU 사용량을 동일시하지 않는다. 이 진단은 앱의 갬빗 정책 전체를 실행하는 대국 실험이 아니다.

소스 확인 결과 현재 전이표는 검색마다 세대 번호를 바꾸어 이전 점수·최선 수를 무효화한다. 같은 엔진과 게임 식별자를 유지해도 저장 공간만 재사용하며, 이전 탐색 결과나 미완료 깊이를 이어받지 않는다. 따라서 두 번째 호출은 **같은 세션에서의 재시작**으로 해석한다. [전이표의 실제 수명](HASH_MEMORY_REUSE.md)을 참고한다.

M1 완료 기준은 합법 위치 재현, 세 검색의 실제 완료 기록, 알려진 실패와 대조군의 분리, 독립 감사의 비교 가능성 확인, 가설의 채택·보류 사유 기록이다. 결과는 [첫 실행 기록](checks/2026-11-04-gambit-strength-m1/README.md)에 남긴다.

| 단계 | 실행 과제 | 완료 기준 |
| --- | --- | --- |
| M2 | 지평선 부족·반복 계산 비용·평가기 오판을 분리하고 가설 하나를 구현 | 관련 정확성 검사와 같은 시간 국면 비교 통과. 실패 가설도 기록 |
| M3 | 개발에 쓰지 않은 갬빗 계열과 수락·거절·강한 방어 위치에서 비교 | 새 피메이트 및 큰 추가 악화 경고가 없고 기풍 동작 유지 |
| M4 | 기준과 후보의 선후공 교대 대국 | 전체 계산 상한·스레드·Hash·시작판·색·시드 고정. 미완료는 `*`, 소표본은 선별 근거로만 해석 |
| M5 | 충분한 대국 근거를 확보한 후보 반영 | 결과 불확실성을 함께 보고하고 실행 파일/정책 버전·복구 자료 확인 |

큰 추가 악화 경고는 동일 루트 외부 감사에서 **최선 대비 손실 >150cp이고 기존 자체 기준수보다 >=100cp 악화**한 경우다. 개발 국면 개선만으로 전체 기력 향상을 선언하지 않는다. 대국에서는 갬빗 제안·실제 수락·공격 유지와 최종 승점을 별도로 센다.

[빠른 비교 원칙](EXPERIMENT_POLICY.md)의 기본 16판·100ms는 핵심 엔진 선별에 사용할 수 있다. 현재 갬빗 정책의 최소 기준 시간은 500ms여서, 100ms 대국은 실제 갬빗 정책 강화의 증거가 될 수 없다. 정책 A/B의 첫 대국은 실행 전 정책이 발동하는 시간과 동일한 전체 예산을 정하고 예상 소요 시간을 알린다. 먼저 짧은 선별 비교를 하고, 새 근거가 필요할 때만 확대한다.
