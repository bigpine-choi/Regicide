# 위치 평가와 안정화 탐색

## 기물 가치가 같은 두 수를 구분하기

이전 평가는 기물의 개수만 같으면 같은 점수를 주었다. 초기 나이트를 중앙으로 전개하는 수와 룩을 왕복하는 수를 구별할 근거가 부족했다. 새 평가는 **기물 가치에 현재 배치의 작은 점수를 더한다.**

예를 들어 초기 `Nf3`/`Nc3`는 위치 점수 +30cp, `Nh3`/`Na3`는 +18cp, `e4`/`d4`는 +17cp다. 전개한 나이트를 이유 없이 원래 칸으로 돌려놓으면 전개 점수를 잃는다. 이 숫자는 자체 설계한 첫 계수이며 학습하거나 최적이라고 입증한 값이 아니다. 반복 이력에 임의 벌점을 주어 정당한 반복까지 금지하지 않는다.

`evaluate_position()`은 기존 P100/N320/B330/R500/Q900에 다음 자체 좌표 수식을 더한다. 백·흑의 전진 방향을 거울처럼 맞춰 계산하고, 현재 둘 차례가 유리하면 양수다. 외부 기물 위치 표나 학습 모델은 사용하지 않는다.

| 기물 | 중반의 기준 | 엔드게임의 기준 |
| --- | --- | --- |
| 폰 | 전진과 중앙 파일 | 전진, 특히 승격에 가까운 폰 |
| 나이트·비숍 | 중앙화와 홈 랭크를 벗어난 전개 | 중앙화 |
| 룩 | 7번째 랭크, 경미한 중앙 파일 점수; 소기물 미전개 상태의 조기 진출 감점 | 7번째 랭크와 파일 위치 |
| 퀸 | 중앙화, 소기물 미전개 상태의 조기 진출 감점 | 완만한 중앙화 |
| 킹 | 중앙 노출을 피하고 홈 랭크의 측면 배치를 선호 | 중앙 활동 |

국면 가중치는 양쪽 나이트/비숍=1, 룩=2, 퀸=4를 더해 최대 24로 제한한다. 중반 점수에 `국면/24`, 엔드게임 점수에 `(24-국면)/24`를 곱해 섞는다. 양쪽의 점수 차이를 먼저 계산한 뒤 정수 나눗셈을 해 색상 반전 시의 대칭성을 보존한다. 정확한 식과 계수는 `src/evaluation.cpp`에 있다. 이동성·폰 방패·공격 지도·패스폰의 완전 판정은 아직 평가하지 않는다.

## 기물 교환이 끝나기 전에 평가하지 않기

백 퀸 d1, 흑 룩 d5, 흑 폰 e6인 예에서 깊이 1만 읽으면 `Qxd5`로 룩을 공짜로 얻었다고 착각한다. 흑의 `exd5`까지 읽으면 퀸을 잃는다는 사실이 드러난다. **안정화 탐색(quiescence search)은 원래 깊이 끝에 도착해도 즉시 잡기·승격을 더 읽어 이런 평가 중단을 줄인다.**

체크가 아닌 위치에서는 현재 위치 점수를 탐색의 출발 하한으로 사용하고, 잡기·앙파상·모든 승격을 조사한다. 체크 상태에서는 가만히 있을 수 없으므로 그 출발 점수를 쓰지 않고 **조용한 킹 이동·차단을 포함한 모든 합법 회피 수**를 조사한다. 체크메이트·스테일메이트와 자동 무승부는 항상 정적 평가보다 먼저 확인한다. 현재/예정 수의 무승부 청구도 기존처럼 고려한다.

안정화 노드 `qnodes`는 전체 `nodes`의 일부다. 예산 1,000노드라면 일반 탐색과 안정화 탐색을 합쳐 1,000을 넘어서 새 노드에 들어가지 않는다. 깊이 끝을 두 번 세지 않으며, 중단 시 보드·반복 이력을 복원하고 마지막으로 완료한 반복의 수·점수·주요 수순을 반환한다.

연장은 최대 32반수다. 그 경계에서 체크가 계속되면 해당 반복을 버리고 이전 완료 결과를 사용한다. 체크가 아니면 경계의 정적 점수로 멈출 수 있어 깊은 교환 전체의 해결을 보장하지 않는다. 선택적 최대 탐색 반수는 96이며 일반 점수와 메이트 거리 점수의 구간을 분리한다. 출력 `depth`는 원래 반복 심화 깊이, `seldepth`는 안정화와 미완료 작업까지 포함해 방문한 가장 깊은 반수다. 따라서 주요 수순이 `depth`보다 길 수 있다.

조용한 포크·메이트 위협, 추크츠방처럼 실제로 수를 두어야 해서 불리해지는 위치까지 해결하는 알고리즘은 아니다. 같은 1,000노드에서도 위치 평가와 안정화 처리의 시간 비용이 늘었으므로 같은 시간의 비교를 따로 수행한다.

## 기능을 나눠 실행하기

기본은 두 기능 모두 켜짐이다.

```powershell
.\build\regicide.exe search 2
.\build\regicide.exe search 2 --no-position
.\build\regicide.exe search 2 --no-quiescence
.\build\regicide.exe search 2 --no-position --no-quiescence
```

마지막 명령은 이전의 기물 가치·정적 깊이 끝 평가 동작이다. 별도 빌드한 v0.2와 12개 깊이/노드 검사를 대조해 선택 수·점수·주요 수순·완료 깊이·노드 수가 일치하는 것도 확인했다.

UCI 옵션:

```text
setoption name UsePositionalEvaluation value true
setoption name UseQuiescence value true
```

검증은 기존 규칙·외부 기준을 그대로 실행하고 새 C++ 평가/탐색 검사, UCI 옵션 검사, 비교 도구 회귀 검사를 추가했다. `scripts/build.ps1 -Test` 또는 CMake/CTest로 C++ 규칙·평가·탐색을 함께 실행한다.

## 같은 조건으로 이전 버전과 비교하기

`scripts/compare_engines.py`는 실행 파일 두 개에 같은 제한을 주고, 고정한 시작 수순에서 선후공을 바꿔 대국한다. 새 엔진과 이전 엔진을 각각 빌드한 뒤 Python 3.11 이상과 기존 `requirements-test.txt`를 사용한다.

```powershell
.\.venv-tests\Scripts\python.exe scripts/compare_engines.py build-baseline/source/build/regicide.exe build/regicide.exe --nodes 1000 --baseline-commit 6dc69292baa5da0aeb61a66bd25ab016ef3c6272 --candidate-commit 7f23bf161b3312aeb582a819b9aab00f8b94b7d9 --pgn games/comparison.pgn
```

`--movetime 40` 또는 `--depth 2`로 제한을 바꿀 수 있으며 셋을 혼합하지 않는다. 같은 명목 깊이는 안정화 연장 때문에 같은 연산 비용을 뜻하지 않는다. 기본 시작 목록은 `tests/data/comparison_openings.json`이며 시작 수순 전체를 두 엔진에 전달한다. 최대 500반수는 안전장치이고 도달 시 미완료 `*`로 남긴다. 오류로 실행하지 못한 예정 대국도 별도 집계한다.

왕복 지표는 **같은 쪽의 연속된 엔진 선택 수가 둘 다 잡지 않는 폰 이외의 수이고 체크 회피가 아닐 때**를 기회로 센다. 같은 기물이 바로 직전 A→B를 다음 차례 B→A로 되돌리면 왕복 1회다. 정해진 시작 수순은 제외한다. 전략적으로 타당한 왕복도 있으므로 이 지표가 곧 나쁜 수의 비율은 아니다.

전체 수순·결과·종료 사유·버전·실행 파일 해시·옵션·수별 노드/시간·왕복 집계는 PGN과 JSON에 저장한다. 실제 계획과 결과는 [사전 계획](experiments/2026-10-17-position-quiescence-plan.md), [64판 기록](experiments/2026-10-17-position-quiescence.md)을 참고한다.

확인일: 2026-10-17. 안정화 탐색의 일반적인 개념을 확인할 1차 자료로 [Stockfish 공식 탐색 소스](https://github.com/official-stockfish/Stockfish/blob/effdc3fd3f6de6e75fe1374a51a7a7eed66f880b/src/search.cpp)를 참고했다. GPL-3.0의 해당 엔진 코드·평가 표를 복사하지 않았다. Regicide의 좌표 수식·탐색·검증 구현은 자체 작성했으며, Python 패키지의 역할과 이용 조건은 [엔진 문서](ENGINE.md)에 기록했다.
