# v0.4.0: 병목 측정과 전이표

평가 수식·안정화 탐색의 대상은 v0.3 그대로 두고, 같은 계산을 수행하는 비용과 중복 탐색을 줄인다. [사전 계획](experiments/2026-10-17-profile-transposition-plan.md)과 [실측 결과](experiments/2026-10-17-profile-transposition.md)를 함께 읽는다.

이 문서의 검색별 새 버퍼 방식은 v0.4.0 기준이다. 현재 v0.4.1에서는 [메모리 재사용](HASH_MEMORY_REUSE.md)을 추가해 버퍼를 유지하고 검색별 기록만 무효화한다. 아래 당시 측정과 점수 정책은 그대로 보존한다.

## 원리와 작은 예

전이표(transposition table)는 앞서 계산한 위치의 결과를 저장하는 제한된 메모리다. 예를 들어 `1.Nf3 Nf6 2.Nc3 Nc6 3.e4`와 `1.Nc3 Nc6 2.Nf3 Nf6 3.e4`는 같은 위치에 도달한다. 마지막 폰 수 이후에는 이전 위치가 반복될 수 없으므로, 이 예의 반복 맥락도 같다. 같은 남은 깊이의 계산이 이미 끝났다면 그 점수나 가지치기 근거를 사용할 수 있다. 더 얕거나 깊은 기록의 최선 수는 먼저 살펴볼 후보로만 사용한다.

같은 기물 배치라도 과거에 몇 번 나왔는지에 따라 무승부 선택이 달라진다. 따라서 기물 배치만으로 결과를 재사용하면 위험하다. Regicide는 말 배치·차례·캐슬링 권리·실제로 가능한 앙파상, 되돌릴 수 있는 과거 위치 전체의 출현 횟수, 50수 카운터를 함께 구분한다. FEN으로 가져온 위치에는 이전 이력이 없다는 기존 의미도 유지한다.

## 실제로 줄인 비용

v0.3의 600,000노드 프로파일에서 합법 수 생성은 5,807,712회 호출됐다. 탐색이 이미 합법 수 목록에서 고른 수를 적용할 때도 `Board::play()`가 목록 전체를 다시 만들었고, 아직 반복 청구가 불가능한 위치에서도 예정 수를 여러 번 검사했다. 반복 상태를 저장할 때는 FEN 문자열도 만들었다.

- 탐색 내부의 `play_generated()`는 방금 만든 합법 수를 적용한다. 디버그 빌드에서는 전제를 다시 검사하며, UCI·외부 입력은 계속 `play()`의 검증을 받는다.
- 반복 판정은 정확한 67바이트 상태를 비교한다. 탐색용 해시만으로 무승부를 판정하지 않는다. 합법 앙파상만 정규화하며 최대 두 캡처 후보의 킹 안전성을 확인한다.
- 바뀐 칸만 반영하는 Zobrist 키를 유지하고, 되돌리면 키·반복 횟수·이력 맥락도 함께 복원한다. 고정 상수를 사용해 플랫폼마다 같은 키를 만든다.
- 아직 어떤 과거 위치도 두 번 나오지 않았고 50수 카운터가 99 미만이면, 다음 수에 의한 반복/50수 청구가 불가능하므로 추가 수 검사를 생략한다.

평가를 손실 없이 바꿨다는 주장은 고정 깊이 점수 일치 검사로, 규칙의 정확성은 기존 규칙·외부 기준 검사로 각각 확인한다. 수 순서가 바뀌므로 동점 최선 수와 노드 수는 달라질 수 있다.

## 전이표 구현의 경계

| 항목 | 선택과 이유 |
| --- | --- |
| 수명·크기 | 검색마다 새 표, 기본 16 MiB, 1..256 MiB. 반복 심화와 하위 트리끼리 재사용; 대국·옵션 사이 오래된 기록을 공유하지 않음 |
| 식별 | 64비트 위치 키 + 64비트 전체 반복 맥락 키 + halfmove. 슬롯 주소가 같아도 모든 키 필드를 다시 비교 |
| 깊이 | 점수·경계값은 남은 깊이가 정확히 같을 때만 재사용. 고정 깊이에서 다른 수평선의 값을 섞지 않음 |
| 값의 종류 | EXACT는 정확한 값, LOWER는 최소 보장값, UPPER는 최대 가능값. 현재 alpha/beta 범위를 만족할 때만 탐색 차단 |
| 교체 | 한 슬롯 방식, 더 깊은 완료 기록을 우선 보존; 같은 깊이의 정확한 값을 경계값으로 낮추지 않음 |
| 메이트 | 루트에서의 거리가 아닌 해당 노드에서의 거리로 저장하고, 조회한 경로의 거리에 맞춰 복원 |
| 종료·중단 | 종료 규칙부터 확인. 중단으로 미완료인 노드는 저장하지 않으며 마지막 완료 반복 결과 유지 |
| 최선 수·PV | 캐시 수의 합법성 확인, 루트는 직접 탐색. 캐시 차단 시 PV는 짧아질 수 있으며 전체 깊이 수순을 보장하지 않음 |
| 안정화 | 연장 예산까지 포함한 별도 설계 전에는 안정화 노드 점수를 캐시하지 않음 |

테이블의 키는 확률적 해시이므로 서로 다른 상태가 같은 해시가 되는 이론적 가능성은 있다. 슬롯 충돌은 전체 키 검사로 구분하고, 규칙 코어의 반복 판정은 정확한 상태 비교를 유지한다. 전체 이력을 구분하는 보수적인 선택은 캐시 적중률을 줄일 수 있다.

시간은 테이블 할당 전부터 잰다. 짧은 탐색에서는 할당·초기화가 절약한 계산보다 비쌀 수 있다. 당시 다음 최적화 후보였던 메모리 재사용은 v0.4.1의 별도 실험으로 구현했다. v0.4.0 결과를 본 뒤 이 실험의 기본값을 바꾸지는 않았다.

## 실행과 검증

```powershell
.\build\regicide.exe search 4
.\build\regicide.exe search 4 --no-tt
.\build\regicide.exe search 4 --hash 1
.\build\regicide.exe search 4 --no-fast-moves
```

UCI에는 `UseTranspositionTable`(기본 true), `Hash`(기본 16), `UseFastMoves`(기본 true)를 추가했다. 예: `setoption name UseTranspositionTable value false`. 콘솔과 UCI의 TT 통계는 조회·일치·차단·저장 횟수를 보여준다. 차단 횟수는 점수 재사용을 뜻하며 단순 적중과 구분한다. 시간/노드가 부족해 깊이 1을 끝내지 못한 합법 대체 수는 기존처럼 완료 깊이 0이다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Test
.\.venv-tests\Scripts\python.exe tests/differential.py build/regicide.exe
.\.venv-tests\Scripts\python.exe tests/engine_integration.py build/regicide.exe
.\.venv-tests\Scripts\python.exe tests/benchmark_search_tests.py build/regicide.exe
```

기존 규칙 검사를 유지하면서 해시 재계산·특수 수·이력 구분·전체 undo, 슬롯 충돌·경계·메이트 보정, TT 켬/끔 점수 일치·실제 차단·중단·검색 격리를 추가했다. 상세 수치와 외부 비교의 한계는 실험 기록에 남긴다.

이 구현은 자체 작성했다. 원리 검토에는 [Stockfish의 TT 자료형](https://github.com/official-stockfish/Stockfish/blob/effdc3fd3f6de6e75fe1374a51a7a7eed66f880b/src/tt.h)을 참고했으며 GPL 코드·표·모델을 복사하지 않았다. 계측 해석은 [GNU gprof flat profile 문서](https://sourceware.org/binutils/docs/gprof/Flat-Profile.html)를 참고했다. gprof 표본 시간의 분해능과 계측 비용 때문에 비계측 벽시계 비교를 별도로 수행한다. 자료 확인일: 2026-10-17.
