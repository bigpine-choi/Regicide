# 대국 중 실시간 형세 막대

Godot 대국 창과 브라우저 체스판에서 흑백 막대와 백 기준 점수로 형세를 확인한다. 백 시점에서는 흰 부분이 아래, 흑 시점에서는 위다. 점수 부호는 항상 백 기준이다.

- `+0.80`: Regicide가 백 쪽을 폰 0.8개에 해당하는 평가 단위만큼 유리하게 추정한다.
- `−0.80`: 같은 기준에서 흑 쪽이 유리하다는 추정이다.
- `0.00`: 해당 탐색의 균형 평가다. 미분석 위치는 숫자 0 대신 회색 막대와 대기 문구를 표시한다.
- `M3`: 해당 색이 메이트할 수 있다고 탐색한 것이다. 자체 엔진의 제한된 수읽기 결과다.
- `≥`/`≤`: 정확한 점수 대신 탐색의 하한/상한이다.

막대 길이는 `0.5 + 0.5 × cp / (|cp| + 400)`으로 압축한 시각적 척도다. 승률이나 인간 Elo가 아니다. 종국에는 실제 승리·무승부 결과를 우선 표시한다.

## 갱신과 출처

Regicide가 실제 응수를 고르는 한 번의 탐색에서 완료한 깊이마다 나오는 UCI 점수를 사용한다. 화면은 별도 인증 경로 `/api/evaluation`을 약 0.2초마다 조회해 엔진 응수 대기 중에도 갱신한다. 새 깊이 계산 중에는 마지막 완료 점수를 유지한다. 추가 분석 엔진이나 별도 자기 탐색은 실행하지 않는다.

엔진이 선택한 수를 둔 뒤에는 해당 수의 직전 루트 점수를 **직전 탐색**으로 표시한다. 새 위치를 다시 분석한 값으로 꾸미지 않고 `source_fen`과 현재 `fen`을 구분한다. 평가 수순의 첫 수와 실제 착수가 다르거나 완료 평가가 없으면 점수를 보존하지 않는다.

첫 배치, 인간 착수 직후 새 값이 없는 순간, 무르기·새 대국·핸디캡 분기 변경 뒤에는 대기 상태다. 오류가 나면 이전 숫자를 지운다. 현재 엔진의 평가에는 한계가 있으므로 우세 표시가 실제 승리나 최선 수를 보장하지 않는다.

## 상태 일치와 복기

대국 ID·revision·FEN이 화면과 모두 맞는 응답만 반영한다. 이전 대국이나 무르기 전의 늦은 응답은 버린다. 흑 기준 UCI 점수는 부호와 상하한 방향을 함께 바꾼다. `mate 0`은 무승부가 아니므로 별도의 승리 색을 유지한다.

기존 기보에는 위치별 평가가 없다. 복기에서는 진행 중인 대국의 점수를 가져오지 않고 평가 없음으로 표시한다. 기보 소급 분석과 평가 학습은 이번 범위에 포함하지 않는다.

## 검증

- `python tests/evaluation_state_tests.py`: 점수·경계 변환, 부분 메시지, 상태 무효화, 결과·오류·시간 초과, 탐색 중 HTTP 조회.
- `python tests/human_play_tests.py build/regicide`: 기존 사람 대국과 실제 엔진 연결, 새 평가 검사 포함.
- `python tests/godot_integration_tests.py --godot GODOT --binary REGICIDE`: 평가 표시·시점·오래된 응답·복기 격리 및 실제 엔진 사고 중 갱신.

Godot 입력 검증은 자동 입력을 사용하며 수동 대국 검증과 구분한다. 핵심 C++ 탐색·평가식과 시간 제한은 변경하지 않았다. 분석 스트림이 멈추면 기존 전송 제한에 준한 watchdog으로 프로세스를 닫는다.
