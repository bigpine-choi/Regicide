# 갬빗 모드

새 대국 설정에서 **갬빗 모드**를 선택한다. 일반 모드가 기본값이며, 선택은 새 대국부터 적용된다. 시간제 대국은 기본·갬빗·스파링 공통의 AI 시간 관리를 사용한다. 익숙한 전개와 명백한 수는 짧게, 복잡한 국면은 더 고민하며 남은 시간이 5분 이하이면 점차 빠르게 둔다.

이 모드의 정체성은 **갬빗 전문 엔진**이다. 폰이나 기물을 내주고 공격과 함정을 만드는 오프닝을 사용한다. 최선의 방어를 상대할 때 손해가 나는 수라도, 상대가 탐나는 기물을 잡으면 강한 응징이 성립하는 미끼를 선택한다. 상대가 함정을 거절하면 갬빗 모드가 실제로 불리해질 수 있다.

갬빗 오프닝은 중반 미끼의 시도 빈도와 분리해 검토한다. 중반 기물 미끼는 처음에 상대를 강하다고 가정하고, 대국 중 상대 착수의 자체 평가를 비교해 실수가 누적되면 시도 빈도를 올린다. 정확한 수가 이어지면 다시 줄인다. 상대에게 맞춰 탐색 강도를 낮추거나 일부러 지는 방식은 사용하지 않는다.

## 수를 고르는 원리

먼저 설정한 시간 전체로 자체 Regicide의 기준 수를 찾는다. 그다음 같은 완료 깊이에서 후보의 최선 방어를 확인해 감수하는 평가 손실을 기록한다. **위험한 갬빗·미끼를 시도하는 턴에는 유한한 평가 손실의 상한을 두지 않는다.** 실제 손해를 숨기거나 형세 평가를 바꾸지 않는다.

등록된 갬빗 개시는 중반 미끼의 초기 10% 허용률에 막히지 않고 항상 자체 엔진으로 검토한다. 성립 전 준비 수는 같은 완료 깊이와 최종 점수 모두에서 기준 수와의 손실이 35cp 이내일 때만 선택한다. 갬빗 성립 수는 기존처럼 유한한 평가와 같은 완료 깊이를 확인하고 감수한 비용을 기록한다. 이 희생을 단순 준비 수로 처리하거나 중반 미끼 빈도로 건너뛰지 않는다.

미끼 후보에서는 상대가 합법적으로 폰·기물을 잡는 분기를 따로 읽는다. 그 이후 최대 8플라이, 즉 최대 네 번의 자기 착수 안에 메이트나 순기물 이익을 얻을 수 있는지 검증한다. 엔진의 예상 수순 하나만 믿지 않고, 시간·노드 제한 안에서 상대의 모든 합법적인 방어를 다시 확인한다. 증명이 끝나지 않으면 해당 미끼를 채택하지 않는다.

미끼를 먹지 않는 대응까지 패배로 강제한다는 뜻은 아니다. **처음 포획은 상대가 선택해야 하는 실수이고, 그 실수 이후의 응징만 검증한다.** 검증된 전략의 깊이도 체스 전체에서 가장 빠른 메이트라는 뜻은 아니다.

눈에 띄는 기물 이득, 새롭게 노출된 기물, 먹고 나서 열리는 비숍·룩의 길, 즉각적인 되잡기보다 늦게 나타나는 대가를 후보의 특징으로 사용한다. 이 특징은 사람의 실제 실수 확률을 학습한 모델이 아니다.

기물 이득은 미끼를 내주기 전보다 최소 150cp의 순이익이 있어야 한다. 예를 들어 나이트 300을 내주고 룩 500을 얻는 조합은 순이익 200으로 통과한다. 상대가 그다음 수에 회수 기물까지 잡아 이득을 없앨 수 있으면 통과하지 않는다. 이미 불리한 형세에서도 이 조건을 만족할 수 있다.

## 갬빗 성립 후 공격 전개

정책 v5에서 실제로 선택한 갬빗 성립 기록을 현재 기보와 대조하고, 그 뒤 최대 20반수 동안 공격 전개를 이어간다. 상대가 제안을 실제로 잡았는지와 현재 순기물 투자는 별도로 기록한다. 갬빗 이름이나 성립 표시만으로 상대가 희생을 받아들였다고 세지 않는다. 무르기 후 지워진 성립 수나 과거 v3·v4의 대국에 새 공격 상태를 임의로 붙이지 않는다.

기준 탐색의 수와 같은 완료 깊이에서 평가가 비슷한 자체 후보 중, 상대의 실제 예상 응수 뒤에도 유지되는 전개·중앙 돌파·열린 기물 길·여러 기물의 왕 압박을 선호한다. 새 후보의 비교 점수와 최종 점수는 기준 수에서 35cp 이내여야 한다. 공격적으로 보인다는 이유만으로 큰 새 기물 헌납이나 확인되지 않은 메이트 수순을 허용하지 않는다. 상대 응수가 없는 한 수짜리 구상은 공격 유지 근거로 쓰지 않는다.

이 경로는 중반 미끼의 10% 제한과 별개지만 기존 추가 시간 상한을 공유한다. 시간·근거가 부족하면 기준 수를 보존한다. 이 공격 점수는 기하학적 선호이며 상대의 응수를 강제하거나 실제 기력 상승을 보장하는 평가값은 아니다.

상대가 등록된 수순을 벗어나도, 실제로 선택했던 준비 수를 기준으로 최대 20반수 동안 같은 공격 선호를 이어간다. 이 경우는 `preparation` 단계이며 갬빗 성립·희생 수락으로 집계하지 않는다. 이미 성립한 갬빗은 `offered`로 구분한다. 현재 기보에 더 짧은 갬빗 성립 수가 있으면 긴 준비 수보다 먼저 검토하고, 성립 전에는 처음 붙인 라인 이름에 얽매이지 않고 실제 분기에 맞는 경로를 다시 선택한다.

## 희생 후 운영 연습과 분석 기억

정책 v7은 **실제로 제안 기물이 잡힌 전체 수순**을 확인한 뒤 운영을 이어간다. 이름에 Gambit이 있다는 이유만으로 희생 수락을 가정하지 않는다. 12계열·48개 연습 시작 국면에서 제안 기물의 실제 포획, 순기물 손해와 자기 차례를 확인했다. 스코치처럼 일반 오프닝과 희생 수순이 겹치면 갬빗을 확정하는 후속 착수까지 확인한다. 연습 위치의 출처와 직접 작성한 응수는 구분한다.

오프닝 목록이나 기존 20반수 공격 창이 끝난 뒤에도, 희생 수락 후 최대 48반수 동안 **전개·공격 유지·기물 격차 회복·수비 전환·정리**를 검토한다. 현재 재료와 기물·왕 주변의 형태를 기준으로 목표를 정한다. 이 목표는 실험적 계획 신호이며 최적 전략의 판정은 아니다. 체크 회피, 반복, 강제 수, 단순한 종반, 시간 부족에는 자체 기본 탐색을 사용한다.

24개 분기에서 실제 자체 엔진과 상대 엔진이 각각 수를 두어, 갬빗 진영 192착수·전체 384반수를 연습했다. 훈련·개발 계열의 160개 위치·460개 후보 분석을 별도 기억에 저장했다. Benko·From 계열의 연습 결과는 보류 기록으로만 남겨 실행용 기억에 넣지 않았다. 이 계열은 이전 실험에서도 사용한 적이 있어, 체스 엔진 개발 전체에서 한 번도 본 적 없는 오프닝이라는 뜻은 아니다.

기억은 **정확히 연습한 FEN과 전체 수 이력**이 같은 경우의 자기 분석이다. 실행 파일과 평가기 신원이 일치해야 하며, 오프라인 점수를 현재 형세 평가로 대신 사용하지 않는다. 기억이 없으면 현재 목표에 맞는 합법 후보를 자체적으로 생성한다. 후보는 같은 완료 깊이의 현재 탐색·추가 기물 헌납 검사·실제 상대 응수 뒤의 목표 진전을 확인한 뒤 채택한다. 책·연습 기억이 있는 후보는 수비·정리에서 기본 수 대비 손실 상한이 15cp, 나머지 운영에서는 35cp다. 별도 지식 없이 형태만으로 새로 만든 후보는 기본 수보다 평가가 낮아지면 채택하지 않는다. 기존 추가 시간 상한 1초 안에서 최대 두 후보를 확인하며, 검증 실패 시 기본 수를 보존한다.

이번 분석 기억과 이전의 미채택 선형 순위 모델은 별도다. 이전 `policy.json`은 계속 실험 상태로 비활성이다. [실제 운영 연습·분석 기억](checks/2026-11-04-gambit-operations-learning/README.md), [전후 실제 엔진 검증](checks/2026-11-04-gambit-operations/README.md)을 참고한다. 짧은 연습 분기의 완료를 완주한 대국 성적이나 Elo 향상으로 표시하지 않는다.

## 실제로 선택한 위험한 퀸 미끼

다음 국면을 사용했다.

`1.e4 e5 2.Nf3 Nc6 3.Bc4 d6 4.Nc3 Bg4`

실제 실행에서 일반 탐색은 `5.O-O`를 골랐지만, 갬빗 모드는 `5.Nxe5`를 선택했다. 같은 깊이 6에서 자체 평가는 백 기준 **+51cp → −228cp**, 손실은 **279cp**였다. cp는 폰을 100으로 둔 엔진 평가 단위이며 확정된 승률이나 실제 기물 손실은 아니다.

- 흑이 정확히 `5...Nxe5`로 대응하면 백이 불리하다.
- 흑이 퀸에 끌려 `5...Bxd1`을 두면 `6.Bxf7+ Ke7 7.Nd5#`가 된다.
- 실제 갬빗 모드 실행 경로에서 기준 수와 다른 `Nxe5`를 선택했고, 퀸 포획 이후의 강제 메이트를 독립 검사로 확인했다.

이는 알려진 Légal 계열 패턴을 이용한 개발 사례다. 새로운 체스 이론을 발명했다거나 사람이 반드시 속는다는 주장은 아니다.

별도의 작은 구도에서는 `Ng6 f7xg6 Bxg8`로 나이트를 잡은 폰이 비숍 길을 열어 룩을 잃는 사례를 검사했다. 순이익 200을 확인했고, 흑 킹이 비숍을 다시 잡을 수 있는 반례는 거절했다. 이 사례는 즉시 회수하는 패턴으로, 3~4수짜리 조합을 실증한 것은 아니다.

3~4수 지연 응징은 별도의 합성 비숍 미끼 구도에서 확인했다. 기물을 잡은 뒤 질식 메이트로 이어지는 모든 방어를 검사했다. 이미 공격망이 있던 작은 시험 위치이며, 실전에서 새 조합을 스스로 창작했다는 증거와는 구분한다. 알빈 구도에서 짧은 획득을 증명하지 못한 결과도 함께 남겼다.

## 대국 중 상대 관찰

사람이 두기 직전의 **같은 국면**에서 자체 엔진의 기준 수와 사람이 실제로 둔 수를 탐색한다. 양쪽에 공통으로 완료된 깊이의 정확한 점수만 비교한다. 갬빗 모드가 일부러 감수한 손실과 사람의 실수를 섞지 않는다. 비교가 부족하거나 강제로 하나만 둘 수 있는 수는 관측에서 제외한다.

중반 기물 미끼의 시도 빈도는 강한 상대라는 가정에 무게를 두어 10%로 시작한다. 이 값은 등록된 갬빗 개시와 성립 후 공격 전개에는 적용하지 않는다. 비교 손실 30cp 이하는 정확한 수, 150cp 이상은 실수 증거로 가중하며, 중간은 선형으로 반영한다. 한 수가 전체 추정을 뒤집지 않도록 관측 하나의 영향에 상한을 두며, 실제 기보의 관측을 다시 읽어 추정하므로 무르기 후에는 취소한 수의 영향도 사라진다. 수의 질에 대한 추정과 실제 미끼를 먹었는지는 별도로 기록한다. 미끼를 안 먹었다고 자동으로 정답을 찾았다고 판정하지 않는다.

이 값은 현재 대국에서 얻은 **미보정 실수 성향 추정**이며 Chess.com·Lichess Elo가 아니다. 미끼 시도 빈도 역시 정책이 정한 확률이지 상대가 그 미끼를 먹을 실제 확률이 아니다. 실제 사람의 반응 확률을 검증하려면 별도의 인간 대국 데이터와 평가가 필요하다. 실력별 인간 착수 예측의 연구 사례로 [Maia-2 원논문](https://proceedings.neurips.cc/paper_files/paper/2024/hash/250190819ff1dda47cd23cecc0c5a69b-Abstract-Conference.html)을 참고했으며, 외부 모델·가중치·착수 선택 코드는 사용하지 않았다.

## 갬빗 레퍼토리

정책 v6은 짧은 개시 수순에 더해 **갬빗별 후속 국면 연결망**을 사용하고, 학습 후보 순위를 연동할 수 있다. 고정 버전의 CC0 Lichess 자료에서 1,315개 이름·수순을 읽어 3,411개 위치와 3,467개 연결을 만들었다. 630개는 이름에 따른 분류 그룹 수이며, 그만큼의 갬빗을 숙달했다는 의미가 아니다. 자료의 가장 긴 수순은 28반수이고, 자료가 끝나거나 상대가 이탈하면 현재 국면의 자체 탐색을 계속한다.

수락·거절·방어 분기를 같은 국면에 연결하고, 차례·캐슬링 권리·합법 앙파상이 일치하는 전치를 인식한다. 수순이 달라도 실제 갬빗의 기준 국면에 도달했는지 전체 기보로 확인한다. 이름에 Accepted/Declined가 있다고 실제 희생 수락으로 집계하지 않으며, 기준 기물이 실제로 잡혔는지는 별도로 확인한다. 기준 기물을 움직여 제안을 철회한 뒤 같은 칸에서 다른 기물이 잡혀도 수락으로 세지 않는다.

외부 자료는 검토할 후보를 제공한다. 새 연결망의 준비·후속 후보는 Regicide의 동일 완료 깊이에서 기본 수 대비 **35cp 이내**여야 하고, 추가로 큰 기물을 내주는지와 상대 응수 뒤의 국면을 확인한다. 후보 순위 학습은 이 제한을 바꾸거나 형세 점수를 부풀리지 않는다. 최대 두 후보만 기존 추가 1초 예산 안에서 검사하며, 시간이 부족하거나 확인되지 않으면 기본 수를 사용한다. 기존에 명시적으로 등록한 갬빗 성립 수의 위험 정책은 유지한다.

순위 모델은 자체 Regicide의 고정 노드 분석으로 학습하는 작은 선형 모델이다. 기물 활동·전개·열린 길·왕 주변 압박·상대의 즉시 응수 같은 특징으로 검토 순서를 정하며, 외부 엔진의 착수를 대신 선택하지 않는다. 학습·검증·최종 평가의 오프닝 계열과 중복 국면을 분리한다. 사전 검증 기준을 통과해 채택된 모델만 사용하고, 실행 파일·평가기·특징 구현이 다르거나 모델이 실험 상태이면 원래 후보 순서를 유지한다. [자료와 출처](../data/gambits/README.md), [학습·통합 검증](checks/2026-11-04-gambit-knowledge/README.md)을 참고한다.

이 선형 모델의 실제 학습은 79국면·474개 후보 목표값으로 수행했지만, 미학습 계열의 후보 선택 손실이 악화되어 **모델을 실전에 채택하지 않았다**. `experimental` 산출물과 원본을 보존하고 이 모델에 따른 후보 순위 변경을 적용하지 않는다. 위의 희생 후 운영 분석 기억은 별도 경로다. [학습 과정·미채택 근거](checks/2026-11-04-gambit-learning/README.md).

짧은 도입 수순은 갬빗 성립 지점까지만 제공한다. 잉글런드·부다페스트·알빈·스태퍼드·라트비안·엘리펀트·킹스·대니시·스미스 모라·에번스·블랙마 디머에 비엔나·스코치·제롬·할로윈·팔크비어·트랙슬러·피싱 폴·프롬을 더한 기존 19개에 Tennison·von Hennig를 추가해 21개 명명 패턴을 사용한다. von Hennig의 `1.d4 c6` 전치 진입을 별도로 포함해 총 22개 진입 수순이며, 전치본은 원 카탈로그 수순과 별도 메타데이터로 구분한다.

상대의 수를 대신 정하거나 수순을 강제로 따라가지 않는다. 갬빗 성립 전에 상대가 다른 분기를 선택하면 실제 기보와 맞는 다른 갬빗으로 전환할 수 있다. 맞는 수순이 없거나 갬빗이 성립한 뒤에는 현재 국면에서 기물 미끼를 탐색한다. 같은 후보 수를 공유하는 이름들은 중복 가중하지 않고, 대국별 시드로 여러 구상을 고른다. 등록된 모든 갬빗이 매번 채택되는 것은 아니다.

명칭과 짧은 수순은 저장소에 포함된 [Lichess 카탈로그의 고정 버전](https://github.com/lichess-org/chess-openings/tree/a6189a30dc273ccb21fc2536a9a2fefd5592a67a)과 대조했다. 해당 자료는 CC0이며 [로컬 라이선스](../data/openings/LICENSE)와 각 수순의 출처는 [레퍼토리 코드](../scripts/boss_openings.py)에 보관한다. 외부 엔진이나 온라인 승률은 실제 착수 선택에 사용하지 않는다.

## 시간과 기록

시간제 실제 대국은 공통 인간형 시간 배분을 사용한다. 갬빗 검증에 필요한 계산은 같은 전체 예산 안에서 예약하고, 이미 소모한 계산 시간을 착수 후 대기에 포함한다. 다음 표는 시간제 UI가 아닌 무시계 연구 API에서 고정 기준 시간을 명시했을 때의 기존 계약이다.

| 설정 시간 | 기준 탐색 | 상대 관찰과 미끼 검증을 합친 추가 상한 |
| --- | --- | --- |
| 0.1초 | 0.1초 | 없음 |
| 1초 | 1초 | 1초 |
| 3초 | 3초 | 1초 |
| 5초 | 5초 | 1초 |

화면은 `갬빗 준비`, `공격 전개`, `전술 사냥`, `전력 대국`을 구분한다. 체크 회피·강제 수·반복·기물이 적은 종반·짧은 시간·검증 실패 상황에서는 기준 탐색의 수를 사용한다. 추가 검증의 제한 탐색 점수를 실제 형세 게이지에 섞지 않는다.

JSON 기보의 `boss_play`에는 시드, 정책 버전, 기준 수와 선택 수, 최선 방어의 점수, 포획 분기, 검증 수순, 실제 검증 비용을 남긴다. PGN에도 갬빗 모드 정책과 시드를 보존한다. 무르기·핸디캡 취소는 해당 분기의 기록을 복원하며, 보관함은 각 시점의 수순과 생각 시간으로 단계를 재구성한다.

## 검증과 한계

[실행 기록](checks/2026-11-02-boss-openings/README.md)에서 정책·상태·기보·화면 검사와 실제 엔진 전술 검사를 확인할 수 있다. 일반 모드의 기존 검사도 유지한다.

[앱 기본 모드와의 직접 비교](experiments/2026-11-02-boss-v-normal.md)에서는 양쪽 기준 1초·선후공 교대 16판에서 갬빗 모드 7승 7무 2패(65.625%)였다. 이 표본에서는 갬빗 모드가 앞섰지만, 8개 시드 쌍의 작은 실험이므로 일반적인 기력 우세를 확정하지 않는다. 실제 갬빗 희생·검증 미끼 선택은 0회였으며, 함정 효과를 입증한 결과는 아니다.

[Stockfish 18 제한 강도와의 20판 실험](experiments/2026-11-02-boss-strength.md)에서는 1320·1700·2100 설정에 각각 4승, 2500에 3무 1패, 2800에 1무 3패였다. 해당 시간 조건의 설정값 기준으로 대략 2400~2500 부근이며 사람의 온라인 Elo가 아니다. 실제 갬빗 희생 성립은 0회, 검증 미끼는 3회 선택됐지만 상대가 먹은 경우는 없어 함정의 승률 효과를 입증한 결과는 아니다.

이 기능은 제한된 후보와 짧은 전술 증명을 이용하는 갬빗 모드의 수 선택 정책이다. 모든 희생·조용한 수·장기 보상을 발견하지는 못한다. 작은 개발 문제 통과는 전체 기력 향상이나 Elo 증거가 아니다. 소규모 기본 모드 맞대결 결과는 위에 기록했으며, 더 넓은 조건에서의 기력 우위나 사람이 더 자주 속는지는 아직 입증하지 않았다. 의도적으로 불리한 미끼를 선택하므로 정확한 상대에게는 일반 모드보다 약할 수 있다.
