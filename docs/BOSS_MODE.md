# 갬빗과 기물 미끼를 선택하는 보스 모드

새 대국 설정에서 **보스 모드**를 선택한다. 일반 모드가 기본값이며, 선택은 새 대국부터 적용된다. 생각 시간은 1초 이상을 권장한다.

이 보스의 정체성은 **갬빗 전문 엔진**이다. 폰이나 기물을 내주고 공격과 함정을 만드는 오프닝을 사용한다. 최선의 방어를 상대할 때 손해가 나는 수라도, 상대가 탐나는 기물을 잡으면 강한 응징이 성립하는 미끼를 선택한다. 상대가 함정을 거절하면 보스가 실제로 불리해질 수 있다.

처음에는 상대를 강하다고 가정한다. 대국 중 상대의 착수를 자체 엔진의 기준 수와 비교하고, 실수가 누적되면 위험한 갬빗과 미끼의 시도 빈도를 올린다. 정확한 수가 이어지면 다시 줄인다. 상대에게 맞춰 탐색 강도를 낮추거나 일부러 지는 방식은 사용하지 않는다.

## 수를 고르는 원리

먼저 설정한 시간 전체로 자체 Regicide의 기준 수를 찾는다. 그다음 같은 완료 깊이에서 후보의 최선 방어를 확인해 감수하는 평가 손실을 기록한다. **위험한 갬빗·미끼를 시도하는 턴에는 유한한 평가 손실의 상한을 두지 않는다.** 실제 손해를 숨기거나 형세 평가를 바꾸지 않는다.

미끼 시도를 쉬는 턴에도 갬빗 도입 수순으로 들어갈 수 있다. 다만 이때는 갬빗 성립 전의 후보를 같은 깊이에서 비교해 기준 수와의 손실이 35cp 이내일 때만 선택한다. 이 별도 조건으로 초반의 신중함을 유지하면서 갬빗 레퍼토리로 접근한다. 위험을 허용한 갬빗과 중반 미끼에 이 제한을 다시 적용하지 않는다.

미끼 후보에서는 상대가 합법적으로 폰·기물을 잡는 분기를 따로 읽는다. 그 이후 최대 8플라이, 즉 최대 네 번의 자기 착수 안에 메이트나 순기물 이익을 얻을 수 있는지 검증한다. 엔진의 예상 수순 하나만 믿지 않고, 시간·노드 제한 안에서 상대의 모든 합법적인 방어를 다시 확인한다. 증명이 끝나지 않으면 해당 미끼를 채택하지 않는다.

미끼를 먹지 않는 대응까지 패배로 강제한다는 뜻은 아니다. **처음 포획은 상대가 선택해야 하는 실수이고, 그 실수 이후의 응징만 검증한다.** 검증된 전략의 깊이도 체스 전체에서 가장 빠른 메이트라는 뜻은 아니다.

눈에 띄는 기물 이득, 새롭게 노출된 기물, 먹고 나서 열리는 비숍·룩의 길, 즉각적인 되잡기보다 늦게 나타나는 대가를 후보의 특징으로 사용한다. 이 특징은 사람의 실제 실수 확률을 학습한 모델이 아니다.

기물 이득은 미끼를 내주기 전보다 최소 150cp의 순이익이 있어야 한다. 예를 들어 나이트 300을 내주고 룩 500을 얻는 조합은 순이익 200으로 통과한다. 상대가 그다음 수에 회수 기물까지 잡아 이득을 없앨 수 있으면 통과하지 않는다. 이미 불리한 형세에서도 이 조건을 만족할 수 있다.

## 실제로 선택한 위험한 퀸 미끼

다음 국면을 사용했다.

`1.e4 e5 2.Nf3 Nc6 3.Bc4 d6 4.Nc3 Bg4`

실제 실행에서 일반 탐색은 `5.O-O`를 골랐지만, 보스는 `5.Nxe5`를 선택했다. 같은 깊이 6에서 자체 평가는 백 기준 **+51cp → −228cp**, 손실은 **279cp**였다. cp는 폰을 100으로 둔 엔진 평가 단위이며 확정된 승률이나 실제 기물 손실은 아니다.

- 흑이 정확히 `5...Nxe5`로 대응하면 백이 불리하다.
- 흑이 퀸에 끌려 `5...Bxd1`을 두면 `6.Bxf7+ Ke7 7.Nd5#`가 된다.
- 실제 보스 실행 경로에서 기준 수와 다른 `Nxe5`를 선택했고, 퀸 포획 이후의 강제 메이트를 독립 검사로 확인했다.

이는 알려진 Légal 계열 패턴을 이용한 개발 사례다. 새로운 체스 이론을 발명했다거나 사람이 반드시 속는다는 주장은 아니다.

별도의 작은 구도에서는 `Ng6 f7xg6 Bxg8`로 나이트를 잡은 폰이 비숍 길을 열어 룩을 잃는 사례를 검사했다. 순이익 200을 확인했고, 흑 킹이 비숍을 다시 잡을 수 있는 반례는 거절했다. 이 사례는 즉시 회수하는 패턴으로, 3~4수짜리 조합을 실증한 것은 아니다.

3~4수 지연 응징은 별도의 합성 비숍 미끼 구도에서 확인했다. 기물을 잡은 뒤 질식 메이트로 이어지는 모든 방어를 검사했다. 이미 공격망이 있던 작은 시험 위치이며, 실전에서 새 조합을 스스로 창작했다는 증거와는 구분한다. 알빈 구도에서 짧은 획득을 증명하지 못한 결과도 함께 남겼다.

## 대국 중 상대 관찰

사람이 두기 직전의 **같은 국면**에서 자체 엔진의 기준 수와 사람이 실제로 둔 수를 탐색한다. 양쪽에 공통으로 완료된 깊이의 정확한 점수만 비교한다. 보스가 일부러 감수한 손실과 사람의 실수를 섞지 않는다. 비교가 부족하거나 강제로 하나만 둘 수 있는 수는 관측에서 제외한다.

초기에는 강한 상대라는 가정에 무게를 두고 위험한 미끼의 시도 빈도를 10%로 시작한다. 비교 손실 30cp 이하는 정확한 수, 150cp 이상은 실수 증거로 가중하며, 중간은 선형으로 반영한다. 한 수가 전체 추정을 뒤집지 않도록 관측 하나의 영향에 상한을 두며, 실제 기보의 관측을 다시 읽어 추정하므로 무르기 후에는 취소한 수의 영향도 사라진다. 수의 질에 대한 추정과 실제 미끼를 먹었는지는 별도로 기록한다. 미끼를 안 먹었다고 자동으로 정답을 찾았다고 판정하지 않는다.

이 값은 현재 대국에서 얻은 **미보정 실수 성향 추정**이며 Chess.com·Lichess Elo가 아니다. 미끼 시도 빈도 역시 정책이 정한 확률이지 상대가 그 미끼를 먹을 실제 확률이 아니다. 실제 사람의 반응 확률을 검증하려면 별도의 인간 대국 데이터와 평가가 필요하다. 실력별 인간 착수 예측의 연구 사례로 [Maia-2 원논문](https://proceedings.neurips.cc/paper_files/paper/2024/hash/250190819ff1dda47cd23cecc0c5a69b-Abstract-Conference.html)을 참고했으며, 외부 모델·가중치·착수 선택 코드는 사용하지 않았다.

## 갬빗 레퍼토리

짧은 도입 수순은 갬빗 성립 지점까지만 제공한다. 잉글런드·부다페스트·알빈·스태퍼드·라트비안·엘리펀트·킹스·대니시·스미스 모라·에번스·블랙마 디머에 비엔나·스코치·제롬·할로윈·팔크비어·트랙슬러·피싱 폴·프롬을 더한 19개 후보다.

상대의 수를 대신 정하거나 수순을 강제로 따라가지 않는다. 갬빗 성립 전에 상대가 다른 분기를 선택하면 실제 기보와 맞는 다른 갬빗으로 전환할 수 있다. 맞는 수순이 없거나 갬빗이 성립한 뒤에는 현재 국면에서 기물 미끼를 탐색한다. 같은 후보 수를 공유하는 이름들은 중복 가중하지 않고, 대국별 시드로 여러 구상을 고른다. 등록된 모든 갬빗이 매번 채택되는 것은 아니다.

명칭과 짧은 수순은 저장소에 포함된 [Lichess 카탈로그의 고정 버전](https://github.com/lichess-org/chess-openings/tree/a6189a30dc273ccb21fc2536a9a2fefd5592a67a)과 대조했다. 해당 자료는 CC0이며 [로컬 라이선스](../data/openings/LICENSE)와 각 수순의 출처는 [레퍼토리 코드](../scripts/boss_openings.py)에 보관한다. 외부 엔진이나 온라인 승률은 실제 착수 선택에 사용하지 않는다.

## 시간과 기록

| 설정 시간 | 기준 탐색 | 상대 관찰과 미끼 검증을 합친 추가 상한 |
| --- | --- | --- |
| 0.1초 | 0.1초 | 없음 |
| 1초 | 1초 | 1초 |
| 3초 | 3초 | 1초 |
| 5초 | 5초 | 1초 |

화면은 `변칙 오프닝`, `전술 사냥`, `전력 대국`을 구분한다. 체크 회피·강제 수·반복·기물이 적은 종반·짧은 시간·검증 실패 상황에서는 기준 탐색의 수를 사용한다. 추가 검증의 제한 탐색 점수를 실제 형세 게이지에 섞지 않는다.

JSON 기보의 `boss_play`에는 시드, 정책 버전, 기준 수와 선택 수, 최선 방어의 점수, 포획 분기, 검증 수순, 실제 검증 비용을 남긴다. PGN에도 보스 정책과 시드를 보존한다. 무르기·핸디캡 취소는 해당 분기의 기록을 복원하며, 보관함은 각 시점의 수순과 생각 시간으로 단계를 재구성한다.

## 검증과 한계

[실행 기록](checks/2026-11-02-boss-openings/README.md)에서 정책·상태·기보·화면 검사와 실제 엔진 전술 검사를 확인할 수 있다. 일반 모드의 기존 검사도 유지한다.

이 기능은 제한된 후보와 짧은 전술 증명을 이용하는 보스의 수 선택 정책이다. 모든 희생·조용한 수·장기 보상을 발견하지는 못한다. 작은 개발 문제 통과는 전체 기력 향상이나 Elo 증거가 아니며, 일반 Regicide보다 항상 강하거나 사람이 더 자주 속는다는 결과는 아직 측정하지 않았다. 의도적으로 불리한 미끼를 선택하므로 정확한 상대에게는 일반 모드보다 약할 수 있다.
